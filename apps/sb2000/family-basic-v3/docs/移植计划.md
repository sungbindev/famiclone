# Family BASIC v3 移植到 SB2000 的计划

把 `reference/nes-games/Family BASIC (Japan) (v3.0).nes` 原生移植成 SB-DOS 程序（`.EXE`，6576 模式）。原生的意思是：改写依赖 FC 机器的部分（画面、键盘、声音、手柄、程序存储器、退出），直接使用 SB2000 的硬件与 SB-DOS，不做 NES 兼容层，也不是 FC 模式程序。BASIC 解释器本身与数据不改。

本文是计划，每个阶段完成后更新“进度”。

## 已知事实

| 项 | 内容 | 来源 |
| --- | --- | --- |
| 卡带 | mapper 0，PRG 32768 字节（`$8000-$FFFF`），CHR 8192 字节，带电池的 8K 程序存储器（`$6000-$7FFF`） | iNES 头 |
| 向量 | RESET `$80BA`，NMI `$00ED`（NMI 在 RAM 里，启动时写入），IRQ `$80BA` | ROM 末尾 |
| 已识别代码 | PRG 32768 字节中代码 18185 字节（8595 条指令）、数据 14583 字节；PPU 访问 80 处、声音 21 处、`$4016/$4017` 19 处、`$6000-$7FFF` 21 处 | `node tools/stats.mjs` |
| 运行环境 | Ember 能运行原版：有 Family BASIC 键盘与磁带机（FC 模式），用来对照 | Ember 文档与测试 |

## 已定的边界

- 6576 原生 EXE，整机接管：运行时窗口 0-7 映射成程序自己的 8 页（PRG 与地址一一对应，不分页），NMI 向量在自己的页里，不用内核的 NMI 与钩子；IRQ 只开键盘，由自己的 IRQ 处理程序读码；调用 SB-DOS 服务（文件、退出）时经“DOS 入口门”换回 DOS 现场与窗口。细节与内存布局见 [移植对照表](移植对照表.md) 第 1 节。
- 外壳（加载器与 ERAM 小段）为 Family BASIC 单独写，按它自己的内存布局（程序文本在 ERAM `$6000-$6FFF`，入口门多换 DOS 的 ERAM 状态）。
- SAVE/LOAD 按文件名是否带盘符分流：带盘符的（如 `SAVE "A:/TEST.BS"`、`LOAD "A:/TEST.BS"`）存取软盘上的文件；只有文件名的走磁带。磁带做成独立模块，只留“送出 1 位电平”和“读入 1 位电平”两个入口，现在留空，调用时返回“设备未就绪”；SB2000 的磁带接口没有资料，见对照表 2.4。
- 磁盘一侧经 SB-DOS 文件服务读写：路径写入 `PATH_BUFFER`，SB-DOS 认 `A:` 与 `\`，所以字符串里的 `/` 要先换成 `\`；文件名遵守 8.3；只有一个软驱，`B:` 与 `A:` 是同一张盘。
- 磁盘文件的内容是 BASIC 源码文本，一行一条，如 `10 CLS`、`30 PLAY "CDE"`；`LOAD` 读入后直接 `RUN` 就能运行。`SAVE` 把程序按 `LIST` 的写法逐行写出，`LOAD` 先清空程序，再把每行当作键入的一行插入。
- 原版靠电池保存的程序文本，在 EXE 里不再持久；要保存就用 SAVE。
- 程序提示文字与字库保持原样（日文）。
- 键盘：原生版用 SB2000 自己的键盘（扫描码译成原版内部用的键码），不模拟 Family BASIC 键盘的矩阵；Family BASIC 键盘只在 Ember 的 FC 模式里运行原版时使用。STOP、CLR/HOME、INS、DEL、GRPH、KANA 对应到 SB2000 键盘的哪些键，做键盘时再定表。

## 已定的事项

1. 目录与名称：`apps/sb2000/fbasic`，程序名 `fbasic`。
2. 调试脚本开机进 SB-DOS 一律用 fcdev 公共版的 `enterProgram`（开机 900 帧后直接按两次回车）。
3. 程序文本不持久，退出即丢；保存靠 SAVE（带盘符存磁盘）。
