# Family BASIC v3 移植对照表

原版里每处依赖 FC 机器的地方在 SB2000 上怎么原生改写，以及内存怎么放。数据来自阶段 1 的分类结果（`node tools/stats.mjs`、`node tools/inventory.mjs --callers`）和对代码的阅读。只读过代码、没在机器上核对的结论，在“状态”一栏写“代码阅读”；还没查的写“待查”，不当作已知。

**方案**：整机接管，和 FC 原版、步步高的运行机制一样。运行时窗口 0-7 全部映射成程序自己的 8 页，不用内核的 NMI 与钩子，也不分页；外壳（加载器与 ERAM 小段）为 Family BASIC 单独写。

## 结论摘要

- PRG 32768 字节：代码 18185（8595 条指令），数据 14583。依赖 FC 机器的访问点集中在 54 个例程里：PPU 80 处、声音 21 处、`$4016` 13 处、`$4017` 6 处、程序存储器 `$6000-$7FFF` 21 处。
- 解释器本身不碰硬件：语句、表达式、行编辑都经少数几个例程访问画面（`$B52E` 设显存地址、`$896A` 触发 NMI 里的命令、`$B53C` 写滚动）、键盘（`$B958` 扫描）、声音（`$A0B9`、`$BCD5`）和磁带（`$BEC9` 起），改写面小。
- PRG 与地址一一对应：窗口 0-7 各映射一页，`$8000-$FFFF` 原样放进去，原版的地址常量不用改，只改平台相关的指令。
- 程序文本用原版的位置 `$6000-$6FFF`（ERAM，任何窗口映射下都可见）。它与 SB-DOS 在 ERAM 里的状态 `$6000-$65FF` 重叠，所以 DOS 入口门要多换这一段。
- PRG 32768 字节当初占满，新写的平台代码没有空地。已经腾出的位置：磁带例程换成桩；键盘矩阵扫描与键码表由 SB2000 键盘的驱动取代（`image/keyboard.inc`）；内置程序 GAME 0-3 的数据（原 `$D400-$FFF9`，11258 字节）搬到程序文件的扩展 RAM 页（`image/game.s`，BANK11-BANK13），运行 GAME 命令时用通用 DMA 搬进程序区，映像里 `$D400` 之后空出来放新代码。
- 键盘不走 DOS：原版扫描 Family BASIC 键盘矩阵，原生版用 SB2000 自己的键盘（码集 1 的扫描码，IRQ 里读 `$4020`），按 SB2000 键盘的位置与字符试译成原版内部键码。磁带接口没有资料，SAVE/LOAD 先做磁盘，见第 4 节。

## 1. 运行方案

### 1.1 内存

| 地址 | 运行时 | 说明 |
| --- | --- | --- |
| `$0000-$07FF` | 程序独占 | 零页与 `$0200-$07FF` 全是原版自己的变量，内核的 NMI、IRQ 不运行；进入时存 DOS 现场，退出时还原 |
| `$6000-$6FFF` | 程序文本 | 原版位置不变；`$6000-$6005` 是标记与指针，程序从 `$6006` 起，`$6C00-$6FFF` 在 BG 画面备份时当 1K 缓冲 |
| `$7000-$7DFF` | 现场交换缓冲 | 14 页（3584 字节）：零页到 `$07FF` 共 8 页（含栈页）加 DOS 的 ERAM 状态 `$6000-$65FF` 共 6 页，入口门就地交换 |
| `$7E00-$7FFF` | ERAM 小段 | `$7E00-$7F9F` 是代码（进入、入口门、退出，现在 395 字节），`$7FA0-$7FFF` 是变量区与请求块，窗口怠么换它都可见，常量见 `image/shell.inc` |
| `$8000-$FFFF` | PRG 32K | 窗口 0-7 各映射一页，地址与原版一致；`$FFFA-$FFFF` 是自己的向量 |

用 `node tools/scan-text-area.mjs` 复核过：原版对 ERAM 只访问 `$6000-$6FFF`（`$ADC8` 的 GAME 拷贝以 `$70` 作终点，`$B1BD` 等处用 `$6C` 作缓冲上界），`$7000` 以上没有访问。

### 1.2 入口门

调用 SB-DOS 服务（文件、退出）时：关 NMI 与 IRQ，把零页、`$0100-$07FF` 与 ERAM `$6000-$65FF` 同 `$7000-$7DFF` 里的 DOS 那份就地交换，窗口 0-3 换回 DOS 记的程序页、窗口 4-7 换回 ROM 页 4-7，调用，再反向换回；交换代码不能用 `jsr`、`pha` 之类动栈的指令（栈页也在换）。服务的参数与结果单元（如 `ALLOC_COUNT`、`DOS_ERROR`、`PATH_BUFFER`）都在被交换的区域里，映像不能直接写读，所以调用前在请求块里列出“要写的单元与值”和“要读的单元”（各最多 8 个），入口门在换入 DOS 现场后代为执行，读到的值放在结果区。返回时 `$2000` 是 0（NMI 关），映像自己按它的值写回，显示寄存器也要映像自己恢复。

### 1.3 启动与退出

加载器（SB-DOS 的 EXE，32K 映像放在它后面的页里）把 ERAM 小段复制到 `$7E00`，填窗口页号表，进入映像；映像退出时还原现场、窗口与 DOS 的显示状态，回到加载器。DOS 在 BIOS 的 ROM 里，窗口 4-7 换回 ROM 页 4-7 就能回去。

### 2.2 画面（PPU）

6576 模式的做法已在 Ember 里验证（见 `packages/fcdev/docs/sb2000/03-硬件说明.md`、`apps/sb2000/bbk-bios/src/hal-ppu.asm`）：

- 名称表在 CRAM，每个图块 2 字节：低字节图案号，高字节高 4 位调色板组、低 4 位图案表位（背景图案放扩展显存 `$8000` 起，图案号加 `$800`）；NES 名称表 0、1 对应 6576 的页 0、1（`$2000` 位 1-0 选页，CRAM 地址 = `(NES 地址 & $FFF) × 2`）。
- 精灵图案表只能放在字符 RAM `$0000-$3FFF`（`$2008` 位 3-2 选起点）；调色板 `$2040-$207F`，值与 NES 同构，可直接用原版的颜色数据。
- 4 色背景（`$2008` 位 7 为 0），与原版 2 位图案一致。
- 写文字只写图案号并跳过高字节（写完 `bit $2007` 把地址移到下一个图块），这样不会改变那个位置的调色板组。

### 2.4 磁带（SAVE/LOAD 用）

原版磁带例程：`$BEC9`、`$BEE3`、`$BEF7`、`$BF1F`、`$BF30`、`$BFB3`、`$BDCE` 起。读 `$4016` 位 1 得到边沿，用空转循环量脉宽（`$BEE8` 起 `ldy #$4E`），写 `$4016` 位 0 输出；读写过程中每圈查 `$883A` 的 STOP 键。

SB2000 的磁带接口目前没有可用的资料，不能直接接入：

- 芯片资料、系统调用手册与 BIOS 源码里都没有磁带接口：声音输出有 PSG 与 `$4027` 的 8 位 DAC（要同时设定时器，BIOS 播放 WAV 就是这样），没有音频输入寄存器，也没有 ADC。
- 可用的线只有扩展 I/O `$4026`（EIO7-EIO0，每位可设输入或输出）。已知占用：位 0 RTC 片选、位 1 鼠标复位、位 2 打印机选通、位 3-5 打印机状态输入、位 6 语音端口复位；其余位的接线没有记录。`$4016` 位 0-2 与打印机线共用，原版的写法不能用。
- Ember 的磁带机目前只接在经典 FC 的磁带接口上，学习机机型没有接（Ember 待办备忘“学习机的磁带接口”）。

做法：磁带做成独立模块，只留“送出 1 位电平”和“读入 1 位电平”两个入口，调用时返回“设备未就绪”。要真正接入，先在真机上实测 `$4026` 的各位（接音频输入线，看哪一位随信号变化），再用 DAC 或 PSG 方波输出并按 SB2000 的 CPU 时钟重新标定脉宽常数，最后在 Ember 里把学习机也接到磁带机做回放测试。

## 3. 内存使用

| 区域 | 用途 | 访问 |
| --- | --- | --- |
| 零页 `$00-$FF` | 解释器工作单元 | 223 个单元；`$1B/$1C` 是 NMI 分发的间接跳转，`$52/$53` 是字符串指针，`$63` 是 NMI 命令号，`$ED-$EF` 是 NMI 入口的 JMP |
| `$0200-$02FF` | 精灵缓冲（`$4014` DMA 的源）、精灵参数 | 24 个地址 |
| `$0300-$03FF` | 行缓冲：词法分析的输出、直接执行的文本 | 经指针访问 |
| `$0400-$04FF` | 变量栈与参数 | 4 个地址 |
| `$0500-$05FF` | 行输入缓冲（`$0500`、`$0580`） | 13 个地址 |
| `$0600-$06FF` | 键盘状态（`$0634-$063B`，新键盘驱动的变量）、精灵标志（`$0645`、`$06C0-$06C7`） | 23 个地址 |
| `$0700-$07FF` | 输出行缓冲、字符串临时区 | 5 个地址 |
| `$6000-$6FFF` | 程序文本 | 21 处访问 |

程序运行期间不依赖内核：原版用到的零页与 `$0200-$07FF` 单元一律原样使用，不需要改址。新增的零页单元必须避开原版直接引用的单元，也要避开它按下标访问的范围（`$34-$45` 的数值工作区、`$B9-$DA` 的声道表），现在用 `$93-$96`、`$DE`、`$DF`、`$E6`（见 `image/platform.inc`）。GAME 0-3 的起点表在 `$800B-$8012`，现在存的是它们在 GAME 数据里的偏移（`$0000`、`$07FE`、`$1282`、`$1F08`），`$AD96` 的 GAME 拷贝改成 DMA（数据在扩展 RAM 页，通用 DMA 的源不能跨 4K 页，所以按页分段搬）。

## 5. v3 的语句、运算符与函数

关键字表在 `$CCAB-$CEBE`（记号在前、文字在后），共 110 项。语句记号 `$80-$C0`：`GOTO GOSUB RUN RETURN RESTORE THEN LIST SYSTEM TO STEP SPRITE PRINT FOR NEXT PAUSE INPUT LINPUT DATA IF READ DIM REM STOP CONT CLS CLEAR ON OFF CUT NEW POKE CGSET VIEW MOVE END PLAY BEEP LOAD SAVE POSITION KEY COLOR DEF CGEN SWAP CALL LOCATE PALET ERA TR FIND GAME BGTOOL AUTO DELETE RENUM FILTER CLICK SCREEN BACKUP ERROR RESUME BGPUT BGGET CAN`（`ERA`、`TR`、`CAN` 在表里就是这么写，全名以代码里的实际文字为准）；运算符 `$EF-$FD`：`XOR OR AND NOT <> >= <= = > < + - MOD / *`；函数 `$CA-$E6`：`ABS ASC STR$ FRE LEN PEEK RND SGN SPC TAB MID$ STICK STRIG XPOS YPOS VAL POS CSRLIN CHR$ HEX$ INKEY$ RIGHT$ LEFT$ SCR$ INSTR CRASH ERR ERL VCT`。语句记号 T 的处理例程在地址表 `$CEBF` 的第 T-`$80` 项。

静态统计里除 PPU、声音、`$4016/$4017`、`$6000-$7FFF` 外没有别的硬件访问（`$4018-$5FFF` 没有访问点）。这些语句在阶段 1 的覆盖脚本里都键入过，但语法不一定写对，各命令的实际行为在阶段 4 对照原版逐条核对。
