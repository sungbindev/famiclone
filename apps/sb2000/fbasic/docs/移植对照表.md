# Family BASIC v3 移植对照表

阶段 2 的成果：原版里每处依赖 FC 机器的地方在 SB2000 上怎么原生改写，以及内存怎么放。数据来自阶段 1 的分类结果（`node tools/stats.mjs`、`node tools/inventory.mjs --callers`）和对代码的阅读。凡是只读过代码、没在机器上核对的结论，在“状态”一栏写“代码阅读”；还没查的写“待查”，不当作已知。

## 结论摘要

- PRG 32768 字节：代码 18185（8595 条指令），数据 14583。依赖 FC 机器的访问点集中在 54 个例程里：PPU 80 处、声音 21 处、`$4016` 13 处、`$4017` 6 处、程序存储器 `$6000-$7FFF` 21 处，见第 2 节。
- 解释器本身不碰硬件：语句、表达式、行编辑都经少数几个例程访问画面（`$B52E` 设显存地址、`$896A` 触发 NMI 里的命令、`$B53C` 写滚动）、键盘（`$B958` 扫描）、声音（`$A0B9`、`$BCD5`）和磁带（`$BEC9` 起），所以改写面小。
- 键盘不走 DOS：原版用 `$4016/$4017` 扫描 Family BASIC 键盘矩阵（9 行 × 2 列 × 4 位，结果存 `$0634-$063C`）。原生版用 SB2000 自己的键盘，见 2.3。
- SAVE/LOAD 原来存磁带；原生版先做磁盘（带盘符的路径），磁带模块留空，见第 4 节。
- NMI 向量在 RAM：启动时往 `$ED-$EF` 写 `JMP $8971`；NMI 例程是“命令处理器”（`$63` 存命令号，经 `$89A3` 的 15 项表分发），和内核 NMI 的钩子 5 对得上，见 2.1。
- 内存：零页用到 223 个单元（几乎占满）；`$0200-$07FF` 用到 69 个地址（`$02xx` 24、`$04xx` 4、`$05xx` 13、`$06xx` 23、`$07xx` 5）；程序文本在 `$6000-$7FFF`。PRG 的 32K 超过一个 16K 窗口，要分页，见第 3 节。

## 3. 内存

### 3.1 原版的使用

| 区域 | 用途 | 访问 |
| --- | --- | --- |
| 零页 `$00-$FF` | 解释器工作单元 | 223 个单元；`$1B/$1C` 是 NMI 分发的间接跳转，`$52/$53` 是字符串指针，`$63` 是 NMI 命令号，`$ED-$EF` 是 NMI 入口的 JMP |
| `$0200-$02FF` | 精灵缓冲（`$4014` DMA 的源）、精灵参数 | 24 个地址 |
| `$0400-$04FF` | 变量栈与参数 | 4 个地址 |
| `$0500-$05FF` | 行输入缓冲（`$0500`、`$0580`） | 13 个地址 |
| `$0600-$06FF` | 键盘状态（`$0634-$063C`）、精灵标志（`$0645`、`$06C0-$06C7`） | 23 个地址 |
| `$0700-$07FF` | 输出行缓冲 | 5 个地址 |
| `$6000-$7FFF` | 程序文本（电池 RAM） | 21 处访问 |

### 3.2 与 SB-DOS 的关系

沿用计划文档“已定的边界”：独占零页与 `$0200-$07FF`；内核 NMI 只开钩子 5 与精灵 DMA；让出零页 `$1E/$1F`、`$0300-$0306`、`$0329`、`$062A-$062F`、`$0630`、`$0639-$063C`。对这个 ROM 的具体冲突：

- 零页 `$1E/$1F`（钩子 5 地址）：原版有没有用，要对 `$1E`、`$1F` 的访问点逐个看，用到的改用空闲单元（待查）。
- `$0634-$063C`（键盘状态）与内核的窗口页影子 `$0639-$063C`、`PPU_CTRL_SHADOW`（`$062A`）等重叠：键盘状态改放别处（重写键盘时一并处理）。
- 其余 `$0400-$07FF` 的单元与内核符号重叠的，要按内核符号表逐个核对（待做）。

### 3.3 代码放哪里

- 阶段 3 定的页布局（fcdev 的多页配置，`targetOptions.banks`）：文件页 0、1 常驻（窗口 0、1，`$8000-$9FFF`，放入口、NMI 钩子、入口门、跨页调用与常用例程），页 2 是库页 1（窗口 2，启动时就在），页 3 是窗口 3（`$B000-$BFFF`）作程序文本页，页 4 起是库页 2 到 N（换入窗口 2）。NMI 钩子 5 由内核把窗口 0-3 换成程序前 4 页后调用，所以钩子与它用到的代码都放常驻页。
- 解释器代码加表 18185 + 数据超过常驻的 8K，哪些例程放哪个库页要先画调用图（阶段 4.1）；`$CCAB` 以上的 13K 数据里，关键字表与处理例程地址表（约 1K）要常驻，其余（文字、调色板、内置程序的背景画面与记号化的 BASIC 程序）只在少数时刻读，放库页。
- 程序文本区：原版 `$6000-$7FFF` 有 8K，但从 `lda #$6F`、`cmp #$70` 和开机显示的 4086 BYTES FREE 看，文本区上界在 `$6FFF`，只需要 4K（待核对：阶段 4.1 逐处看 `$6xxx`、`$7xxx` 的用法），放窗口 3 的页里（地址 `$B000-$BFFF`，原版里高字节 `$60-$6F` 的常量都要加 `$50`）；`$6000-$6008` 的指针初值相应改。
- 内置程序：GAME 0-3 的起点在 `$800B-$8012`（指向 `$D400`、`$DBFE`、`$E682`、`$F308`），读入文本区的方式要对 `$9DE1` 一带核对。

### 3.4 分页方案（阶段 4.1）

工具：`node tools/callgraph.mjs`、`node tools/plan-banks.mjs`，结果在 `analysis/banks.txt`。

- **块**：把代码切成 255 个可独立搬动的块（共 18190 字节，最大 459 字节，中位数 31 字节）：块尾是无条件跳转或返回，且没有相对分支跨过边界。阶段 1 的重排测试已经证明这样的块可以任意重排。
- **分配**：常驻页约 5.5K 给解释器的块（常驻页共 8K，其余给骨架代码、跳板与变量），按被引用的次数挑常驻的块；剩下的按块之间调用的强弱合并成不超过 4K 的簇再装箱，得到 4 个代码库页（4095、4095、4091、451 字节）。跨页引用 121 处，需要跳板的目标 55 个。
- **跳板**：任何转向不在常驻页的目标（`jsr`、`jmp`、地址表里的地址）都经常驻页里的跳板：保存寄存器与标志，记下当前库页，切到目标库页，用 `jsr` 调用目标，返回后切回原库页并恢复寄存器、标志，再 `rts`。`jmp` 和表分发也走同一个跳板（目标以 `rts` 结束时行为与原来一致）。每个跳板 6 字节（`jsr` 共用进入例程，后面跟目标地址与库页号）。库页窗口只用窗口 2，窗口 3 固定是程序文本页。
- **NMI**：静态可达的块达 141 个、共 10713 字节，放不进常驻页。所以钩子 5 的入口（常驻）负责：保存跳板用的临时变量与当前库页号、调用 NMI 例程（经跳板进入库页）、还原这些变量；窗口寄存器与影子由内核在 NMI 结束时从栈里还原。原版 NMI 例程里的 `rti` 改成 `rts`，`pha`/`pla` 保持成对。
- **数据**：小的数据块（文字、关键字表、处理例程地址表、小表）放常驻页，因为经指针打印文字、查表的例程在任何库页里都要能读到；`$CFAE-$FFF9` 的 12.5K（调色板、BG 默认画面、四个内置程序）按内容拆成几个数据库页（每页不超过 4K），读它们的例程（BG 画面拷贝、GAME）先把对应数据库页换进窗口 2，源指针不能跨过 `$AFFF`（再往后是程序文本页），这几处要按页分段拷贝（阶段 4.1 后段实现）。
- 文件页数估算：常驻 2 + 程序文本 1 + 代码库页 4 + 数据库页约 4 = 11 页（44K）。现有骨架里的两份现场缓冲（各 1792 字节）不再放常驻页，改放专用库页。

| 磁带写 | `$9D96` 起：显示 `WRITING`，经 `$BF1F`（文件头）、`$BF30`（正文）写入 | 整段并入磁带模块 | 代码阅读 |
| 磁带读 | `$9DF5` 起：显示 `LOADING`/`SKIP`，经 `$BE53`、`$BE1C`、`$BE24` 读入，校验头里的类型 `$02` | 同上 | 代码阅读 |
| 磁盘 | 无 | 带盘符（如 `SAVE "A:/TEST.BS"`）：路径写进 `PATH_BUFFER`（SB-DOS 认 `A:` 与 `\`，字符串里的 `/` 先换成 `\`），文件名遵守 8.3；文件内容是 BASIC 源码文本，一行一条（如 `10 CLS`）：`SAVE` 按 `LIST` 的写法逐行写出，`LOAD` 先清空程序，再把每行当作键入的一行插入，读完即可 `RUN`；经“DOS 入口门”调 SB-DOS 的文件服务 | 待做：LIST 与行输入两条路径怎样被复用，出错处理（文件不存在等）的提示文字 |

`SAVE "A:/TEST.BS"` 里的盘符判断要加在 `$9E52` 一带的参数分析里：原版里这一步读到的是哪种字符串（带不带引号、能不能用字符串变量）要对 `$9E52` 逐行看（待查）。

## 5. v3 的语句、运算符与函数

关键字表在 `$CCAB-$CEBE`（记号在前、文字在后），共 110 项。语句记号 `$80-$C0`：`GOTO GOSUB RUN RETURN RESTORE THEN LIST SYSTEM TO STEP SPRITE PRINT FOR NEXT PAUSE INPUT LINPUT DATA IF READ DIM REM STOP CONT CLS CLEAR ON OFF CUT NEW POKE CGSET VIEW MOVE END PLAY BEEP LOAD SAVE POSITION KEY COLOR DEF CGEN SWAP CALL LOCATE PALET ERA TR FIND GAME BGTOOL AUTO DELETE RENUM FILTER CLICK SCREEN BACKUP ERROR RESUME BGPUT BGGET CAN`（`ERA`、`TR`、`CAN` 在表里就是这么写，全名以代码里的实际文字为准）；运算符 `$EF-$FD`：`XOR OR AND NOT <> >= <= = > < + - MOD / *`；函数 `$CA-$E6`：`ABS ASC STR$ FRE LEN PEEK RND SGN SPC TAB MID$ STICK STRIG XPOS YPOS VAL POS CSRLIN CHR$ HEX$ INKEY$ RIGHT$ LEFT$ SCR$ INSTR CRASH ERR ERL VCT`。语句记号 T 的处理例程在地址表 `$CEBF` 的第 T-`$80` 项。

表里的 `LINPUT`、`FILTER`、`CLICK`、`SCREEN`、`BACKUP`、`ERROR`、`RESUME`、`BGPUT`、`BGGET`、`DELETE`、`RENUM`、`AUTO`、`BGTOOL`、`GAME`、`FIND`、`PALET`、`CSRLIN`、`INSTR`、`CRASH`、`ERR`、`ERL` 等是 v3 的功能。静态统计里除 PPU、声音、`$4016/$4017`、`$6000-$7FFF` 外没有别的硬件访问（`$4018-$5FFF` 没有访问点）。这些语句在阶段 1 的覆盖脚本里都键入过，但语法不一定写对，各命令的实际行为在阶段 4 对照原版逐条核对。
