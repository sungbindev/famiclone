# Family BASIC v3 移植到 SB2000 的计划

把 `reference/nes-games/Family BASIC (Japan) (v3.0).nes` 原生移植成 SB-DOS 程序（`.EXE`，6576 模式）。原生的意思是：改写依赖 FC 机器的部分（画面、键盘、声音、手柄、程序存储器、退出），直接使用 SB2000 的硬件与 SB-DOS，不做 NES 兼容层，也不是 FC 模式程序。BASIC 解释器本身与数据不改。

本文是计划，每个阶段完成后更新“进度”。

## 已知事实

| 项 | 内容 | 来源 |
| --- | --- | --- |
| 卡带 | mapper 0，PRG 32768 字节（`$8000-$FFFF`），CHR 8192 字节，带电池的 8K 程序存储器（`$6000-$7FFF`） | iNES 头 `4E 45 53 1A 02 01 03` |
| 向量 | RESET `$80BA`，NMI `$00ED`（NMI 在 RAM 里，启动时写入），IRQ `$80BA` | ROM 末尾 |
| 存储器 | 开机时试探 `$6000` 能否写（`$81F3`），`$6000-$6008` 一带是程序文本的指针与长度 | 部分反汇编 |
| 已识别代码 | 阶段 1 结束时：PRG 32768 字节中代码 18185 字节（8595 条指令）、数据 14583 字节；其中 PPU 寄存器访问 80 处、声音 21 处、`$4016/$4017` 19 处、`$6000-$7FFF` 21 处 | `node tools/stats.mjs` |
| 运行环境 | Ember 能运行它：有 Family BASIC 键盘与磁带机，`core/test/runtime/family-basic-test.cpp` 已用它跑通键入、SAVE、LOAD | Ember 文档与测试 |

## 已定的边界

- 6576 原生 EXE，不接管窗口 4-7。内核 NMI 继续运行，只开钩子 5（每帧的工作放进钩子）与内核的精灵 DMA；程序独占零页与 `$0200-$07FF`，只让出内核 NMI 要用的单元（零页 `$1E/$1F`、`$0300-$0306`、`$0329`、`$062A-$062F`、`$0630`、窗口页影子 `$0639-$063C`）；IRQ 保持关闭，键盘自己轮询 `$4033`、`$4020`；调用 SB-DOS 服务（文件、退出）时经“DOS 入口门”临时换回 DOS 现场。骨架已有现成实现（已在 Ember 里验证），复制到 `fbasic/exe` 起步。
- SAVE/LOAD 按文件名是否带盘符分流：带盘符的（如 `SAVE "A:/TEST.BS"`、`LOAD "A:/TEST.BS"`）存取软盘上的文件；只有文件名的（如 `SAVE "TEST"`、`LOAD "TEST"`）走磁带。磁带做成独立模块，只留“送出 1 位电平”和“读入 1 位电平”两个入口，现在先留空，调用时返回“设备未就绪”；等学习机的音频接口寄存器核实、Ember 里学习机也绑上磁带机后再填（见 Ember 待办备忘“学习机的磁带接口”）。
- 磁盘一侧经 SB-DOS 文件服务读写：路径写入 `PATH_BUFFER`，SB-DOS 认 `A:` 与 `\`，所以字符串里的 `/` 要先换成 `\`；文件名遵守 8.3；只有一个软驱，`B:` 与 `A:` 是同一张盘。
- 磁盘文件的内容是 BASIC 源码文本，一行一条，如 `10 CLS`、`20 BEEP`、`30 PLAY "CDE"`；`LOAD` 读入后直接 `RUN` 就能运行。`SAVE` 把程序按 `LIST` 的写法逐行写出，`LOAD` 先清空程序，再把每行当作键入的一行插入。
- 原版靠电池保存的程序文本，在 EXE 里不再持久：它放在我们自己的页里，退出即丢，要保存就用 SAVE。
- 程序提示文字与字库保持原样（日文）。

| 阶段 | 内容 | 完成标准 | 验证 |

| 1 | 还原成可重定位的符号源码：在 Ember 的 FC 模式里用 Family BASIC 键盘按脚本运行（覆盖关键字表里的全部命令），记录指令轨迹与截图；发现代码、分类数据、地址表与地址常量转标签；CHR 另存为数据文件 | 每个字节恰好属于一段代码或一段数据，没有未分类；汇编后与 PRG 逐字节一致；重新统计总量 | 回读一致；分块置换测试（见下）；单元测试 |
| 2 | 移植对照表：每处依赖 FC 机器的例程（键盘矩阵、录音机、PPU 含属性表、APU、手柄、程序存储器、RAM 里的 NMI、CHR 布局）的作用与 SB2000 做法，内存使用图，v3 的功能清单（按关键字表），SAVE/LOAD 现有的参数写法与改成按盘符分流要动的位置，`LIST` 与行输入两条路径怎么被磁盘存取复用 | 依赖清单覆盖全部访问点，“待查”事项列全并各有查法 | 与阶段 1 的访问点统计逐项对照 |
| 3 | EXE 骨架：复制现有骨架，加多页（32K 解释器与表放进库页，窗口里放常驻部分），程序文本的页，启动与退出，空壳 | 在 Ember 的学习机里启动、返回 DOS，页不泄漏 | 钩子每帧运行、入口门往返、退出后 DOS 正常、重复运行页号不变 |
| 4 | 原生改写，按依赖顺序：4.1 内存与系统（程序文本搬出 `$6000`、NMI 改钩子 5、启动与退出）→ 4.2 画面文字（名称表 2 字节项、属性表改每格调色板、CHR 用 DMA 送入扩展显存）→ 4.3 键盘（SB2000 的键盘，不用 Family BASIC 键盘的矩阵）→ 4.4 图形与精灵 → 4.5 声音（写 PSG，去掉 DMC 与帧计数器）→ 4.6 手柄 → 4.7 存取：磁盘（带盘符的 SAVE/LOAD 经入口门调 SB-DOS 文件服务）、磁带模块留空（只有文件名时返回“设备未就绪”） | 每个子步骤结束，BASIC 对应的命令在 Ember 的学习机里可用 | 子步骤各自的脚本与截图 |
| 5 | 验证：同一份按字符写的按键脚本分别在 FC 模式（原版，经 Family BASIC 键盘）与学习机（新版，经 SB2000 键盘）里运行，比较截图与程序文本区的内容；磁盘存取另做往返（`SAVE` → `NEW` → `LOAD` → `LIST`） | 逐命令结果一致，往返后程序文本与存之前一致；磁带路径没做，不验证 | 截图与内存转储比较 |

分块置换测试：本 ROM 的 PRG 占满 32K，不能整体平移加载地址来查漏掉的地址常量。改为把相邻的几段数据或代码互换位置（总长不变），重新汇编后在 Ember 的 FC 模式里运行，漏掉的地址常量会让行为变化。

## 已定的事项

1. 目录与名称：`apps/sb2000/fbasic`，程序名 `fbasic`（用户已定）。
2. 工具：把已有的还原工具（现在在 `apps/sb2000/gbasic/tools`）复制到 `fbasic/tools` 并参数化（基地址、输入文件、输出名），之后本项目不再依赖那个目录。
3. 键盘：原生版用 SB2000 自己的键盘（扫描码译成字符与功能键，再交给解释器原来用的键码），不模拟 Family BASIC 键盘的矩阵；Family BASIC 键盘只在 Ember 的 FC 模式里运行原版时使用。原版键盘上专有的键（STOP、CLR/HOME、INS、DEL、GRPH、KANA）对应到 SB2000 键盘的哪些键，阶段 4.3 再定表。
4. 程序文本不持久，退出即丢；保存靠 SAVE（带盘符存磁盘），不另做自动存取。
