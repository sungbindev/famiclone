# hwprobe

在小霸王学习机 SB2000（SB-DOS）下运行的补测程序：在真机上补测 `hwtest` 还没弄清楚的三处读回，结果用来对齐模拟器。用 fcdev 开发，C 语言。`hwtest` 的程序窗口已经装满，所以补测单独成一个程序。

## 使用

```bash
npm run build    # 生成 build/sb2000/HWPROBE.EXE
npm run start    # 在模拟器里运行
npm run disk     # 生成含 HWPROBE.EXE 的软盘镜像 build/sb2000/HWPROBE.img
```

把 `build/sb2000/HWPROBE.EXE` 复制到 SB-DOS 的软盘，在 `A:\>` 下输入 `hwprobe`，按 Enter 运行（Esc 退出）。测试在关 NMI、关中断的状态下一次跑完，结果写成软盘当前目录下的 `HWPROBE.TXT`，屏幕上显示“Saved HWPROBE.TXT”；显示 `Save failed` 时，后面的数是错误码，请记下来。把 `HWPROBE.TXT` 取回。

## 测试内容

| 节 | 内容 |
| --- | --- |
| P1 | OAM 属性字节：精灵 56-63 的属性字节（地址 `E2`、`E6`、…、`FE`，地址的位 4-2 依次为 0-7）写 `FF` 读 4 遍、写 `00` 读 1 遍；再把读之前最后写的 PPU 端口换成 `$2005`，看读回的位 4-2 是否跟着它的值走 |
| P2 | `$4015`：依次写 `00`、单独的一位、单独一位的反码、`FF`，各读回一次，连做两遍 |
| P3 | `$4023`：测前的值，再依次写 `00`、`01`、`80`、`81`、`FE`、`FF`、`80`、`00` 各读回一次 |

## 注意

- 精灵 56-63 的属性字节测完不恢复，DOS 的下一次 NMI 与重绘会覆盖它们；`$4015` 与 `$4023` 测完都恢复。
- 传给 DOS 服务的字符串必须在 `$8000-$AFFF` 或 ERAM，所以程序先复制到 ERAM 暂存区（`$7400-$743F`、行缓冲 `$7440-$746F`）再传出去，这两块 ERAM BIOS 不用。
- 背景与结论见 `vscode/docs/sb2000/03-硬件说明.md` 的“真机与模拟器仍有差异的行为”。
