# hwtest

在小霸王学习机 SB2000（SB-DOS）下运行的硬件测试程序：在真机上实测 memtest 没有覆盖的硬件行为，用来核对模拟器与真机是否一致。用 fcdev 开发，C 语言。

## 使用

```bash
npm run build    # 生成 build/sb2000/HWTEST.EXE
npm run start    # 在模拟器里运行
npm run disk     # 生成含 HWTEST.EXE 的软盘镜像 build/sb2000/HWTEST.img
```

把 `build/sb2000/HWTEST.EXE` 复制到 SB-DOS 的软盘，在 `A:\>` 下输入 `hwtest`：

1. 屏幕显示“auto tests”，约十几秒内不要碰键盘，程序在关 NMI、关中断的状态下自动跑完全部自动测试。
2. 结果写成软盘当前目录下的 `HWTEST.TXT`，屏幕上只显示“Saved HWTEST.TXT”与文件大小；显示 `Save failed` 时，后面的数是错误码，请记下来。
3. 按 Enter 进入看图场景 V1-V8，任意键翻到下一屏，Esc 提前结束。V7、V8 会改调色板，看完后需要重启 DOS。

把 `HWTEST.TXT` 取回，并附上看图场景的答案（或拍照）。

## 测试内容

自动测试的结果都在 `HWTEST.TXT` 里，每节有一行说明：

| 节 | 内容 |
| --- | --- |
| R1 | 图形端口的读回：`$2008`、OAM、调色板，以及各只写端口读到什么 |
| R2 | 外设寄存器的读回：`$4015`、`$4022`、`$4023`、`$4026`、手柄口、`$4032`-`$4036`、实时时钟 |
| R3 | 定时器：单次计数、下溢标志、屏蔽，以及三组设置下 120 帧内的下溢次数 |
| D1 | DMA 与 `$4020` 各值、不同模式、不同目标的关系 |
| D2 | DMA 长度对实际复制字节数的影响，以及长度 `$8010` 的扩展显存目标 |
| G1 | 每次垂直消隐读到的 `$2002`（位 7、6、5） |

看图场景只在屏幕上显示，问题写在 `HWTEST.TXT` 末尾：

| 场景 | 看什么 |
| --- | --- |
| V1 | 精灵属性位 7、6、5：翻转与优先级 |
| V2 | `$2001` 位 1、2：最左 8 像素的背景与精灵是否显示 |
| V3 | `$2001` 位 0、5、6、7：灰度与着色 |
| V4 | `$2000` 位 1-0：背景所在的名称表 |
| V5 | `$2008` 位 0 |
| V6 | 8×16 精灵的图块号 |
| V7 | 调色板 |
| V8 | 16 色模式 |

## 注意

- 传给 DOS 服务的字符串与数据必须在 `$8000-$AFFF` 或 ERAM，不能在窗口 3（`$B000` 以上），而程序的常量与变量可能落在那里，所以程序先复制到 ERAM 暂存区（`$7400-$74BF`）再传出去；`$6C00-$73FF` 保存显存、`$7C00` 起是 DMA 测试用的单元，这些 ERAM 区域 BIOS 都不用。
- `sb_puts` 从行首显示，同一行上接着显示要用 `sb_print`。
- 模拟器没有实现的项（如 `$2002` 位 6、5）在模拟器里的结果与真机不同，登记在 `packages/fcdev/docs/待办备忘.md`。
