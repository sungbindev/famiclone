# 目标规范

一个“目标”对应一种机型。目标是主包里 `packages/fcdev/targets/<名>/` 下的一个目录，由 `target.json` 描述；新增机型只加目录，不改 `build` 的流程。本文说明目标的目录、`target.json` 的字段、打包器和新增机型的步骤。已有目标的文档在 [nes/](../packages/fcdev/docs/nes/01-开发指南.md) 与 [sb2000/](../packages/fcdev/docs/sb2000/01-开发指南.md) 下。

## 1. 目标目录

```text
targets/<名>/
  target.json          目标定义
  include/             C 头文件
  asminc/              汇编引入文件
  src/                 目标自己的运行库与启动代码源码
  lib-build.json       运行库的构建清单（没有要编译的库时可省略）
  lib/                 运行库的编译结果（构建生成，不入库）
  link.cfg 等          目标自带的链接配置（也可以直接用工具链 cfg 里的）
  link-banked.cfg 等   多页（换页）程序的链接配置模板，见第 2.3 节
```

目录名必须与 `target.json` 里的 `name` 一致；目标名只能用小写字母、数字和连字符。

## 2. `target.json`

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name`、`title` | 是 | 标识与显示名 |
| `cpu` | 是 | CPU 型号，传给 `cc65` 与 `ca65`；首批目标都是 `6502` |
| `cc65Target` | 是 | 传给 `cc65`、`ca65` 的目标名（`-t`），如 `none`、`nes` |
| `linkConfig` | 是 | 链接配置，路径值 |
| `packager` | 是 | 程序打包器名，见第 3 节 |
| `extension` | 是 | 产物扩展名，含点，如 `.nes` |
| `startup` | 否 | 启动代码目标文件列表，路径值；空表示用 `cc65` 目标库自带的 |
| `forceImports` | 否 | 链接时用 `-u` 强制引入的符号；用于让库里的启动代码一定被链接，纯汇编程序也不例外 |
| `libraries` | 否 | 链接的库，按顺序，路径值 |
| `include`、`asminclude` | 否 | 头文件与汇编引入目录，路径值 |
| `defines` | 否 | 预定义宏，值为字符串或数字 |
| `packagerOptions` | 否 | 传给打包器的选项 |
| `nameRule` | 否 | 程序名规则；空表示不限制 |
| `disk` | 否 | 磁盘镜像能力，含 `packager`（磁盘打包器名） |
| `run` | 否 | 运行方案，含 `emulator` 与 `mode` |
| `options` | 否 | 目标专用选项，见第 4 节 |
| `banked` | 否 | 多页（换页）程序的定义，见第 2.3 节 |
| `sourceCharset` | 否 | 机器用的文字编码，目前只有 `gb2312`；见第 2.4 节 |

路径值有两种写法：

- 相对目标目录，如 `lib/crt0.o`。
- 以 `toolchain:` 开头，表示相对工具链根目录，如 `toolchain:cfg/nes.cfg`。

缺少必填字段、字段类型不对时，报 `TARGET_INVALID`。

### 2.1 程序名规则

`nameRule` 目前只有 `dos-8.3`：主名为 1 到 8 个字母、数字、下划线或连字符，产物名转为大写；不符合时报错，不截断。写了未登记的规则也报错。规则在 `targets/name-rules.mjs` 登记。

### 2.2 运行方案

`run.mode` 取值：

| 值 | 含义 |
| --- | --- |
| `rom` | Ember 直接加载产物 |
| `firmware-disk` | 加载 `fcdev.json` 里 `firmware` 指定的固件，把程序做成磁盘镜像挂到软驱并开机，再在 SB-DOS 里输入程序名运行（经 Ember 的调试服务，见 [02-模拟器与调试](../packages/fcdev/docs/02-模拟器与调试.md) 第 3 节）；没有设置 `firmware` 时 `fcdev run` 报错 |

`run.emulator` 必须是字符串，标识要用的模拟器，目前写 `ember`，主包总是用 Ember 运行（Ember 程序由配置项 `emulator` 或环境变量 `FCDEV_EMULATOR` 指定，都没有时用随包的 Ember），该字段只做校验。没有 `run` 的目标运行 `fcdev run` 时报错。

### 2.3 多页（换页）程序

目标的程序可以超过一个窗口时，用 `banked` 说明怎么生成链接配置。程序按“库页”换页，库页个数由 `options` 里的一个数字选项决定。`banked` 的字段：

| 字段 | 说明 |
| --- | --- |
| `option` | 数字选项名，值是库页个数；值为 0 时不用多页，按 `linkConfig` 链接，打包器选项不变 |
| `linkConfig` | 多页链接配置的模板，路径值；模板里单独一行的 `%BANK_MEMORY%` 与 `%BANK_SEGMENTS%` 由 fcdev 展开，缺少时报 `TARGET_INVALID` |
| `generatedFrom` | 模板里已经写出这一页之前的库页，从这一页起按个数生成 |
| `maxBanks` | 库页个数的上限；选项值超过上限、不是整数或小于 0 时报 `TARGET_OPTION_INVALID` |
| `memory`、`segment` | 一个库页的内存区行与段行，`{n}` 换成库页号 |

选项值大于 0 时，fcdev 把模板展开成 `<中间文件目录>/<程序名>.cfg` 交给 `ld65`，并去掉打包器选项里的 `maxSize`（大小由库页个数决定）。`ld65` 报某个库页的段没有内存区时，提示加大库页个数。`option` 必须是 `options` 里的数字选项，`generatedFrom` 与 `maxBanks` 是不小于 1 的整数，否则报 `TARGET_INVALID`。目前只有 `sb2000` 声明了 `banked`，用法见 [sb2000/01-开发指南](../packages/fcdev/docs/sb2000/01-开发指南.md) 第 3.1 节。

### 2.4 源文件编码

机器的字库不认 UTF-8 时，目标用 `sourceCharset` 声明机器用的编码（目前只有 `gb2312`，写了别的报 `TARGET_INVALID`）。声明了的目标在编译每个 `.c`、`.s`、`.asm` 之前，把源文件从 UTF-8 转成该编码，写成中间文件目录里的副本 `<名>.gb2312.c`（汇编是 `.gb2312.s`、`.gb2312.asm`）交给工具：

- 整个文件一起转，注释里的汉字也转。GB2312 的第二个字节不小于 `0xA1`，不会和反斜杠、引号冲突。
- 只收 GB2312 的 1-9 区（符号）与 16-87 区（汉字），机器的字库就这些；其他字符报 `SOURCE_CHAR_UNSUPPORTED`，写出文件、行、列与字符。编码表用 Node 自带的 `gb18030` 解码器反推，不引入依赖。
- 文件不是合法的 UTF-8 时视为已经是目标编码，原样使用；开头的 BOM 去掉。
- C 副本开头加 `#line 1 "原文件"`，编译错误与调试信息仍指向原文件与原行号；汇编没有这个指令，改为把工具输出里的副本路径换回原文件。
- 头文件由 cc65 直接读取，不转换，汉字要写在 `.c` 文件里。

转码在 `src/build/source-charset.mjs`，没有声明的目标（如 `nes`）不受影响。

## 3. 打包器

链接得到 `.bin`，再由打包器做成最终产物。打包器在 `packagers/index.mjs` 登记。

| 打包器 | 类别 | 作用 | 选项 |
| --- | --- | --- | --- |
| `flat-exe` | 程序 | 平铺映像：校验文件头与大小，写成产物文件 | `header`：十六进制字符串，`??` 表示任意字节；`maxSize`：映像大小上限，字节 |
| `ines` | 程序 | 校验 iNES 头与文件长度，写成 `.nes` | 无 |
| `fat-floppy` | 磁盘 | 把一组文件放进 1.44MB 的 FAT12 软盘镜像根目录 | `label`：卷标 |

- 程序打包器接收 `{ binaryFile, outputFile, options }`，返回 `{ outputFile, size }`。
- 磁盘打包器接收 `{ files, outputFile, options }`，输入是一组 `{ name, data, mtime }`，输出一个镜像文件。
- `fat-floppy` 的几何参数是 512 字节扇区、2 面、80 磁道、每磁道 18 扇区，共 2880 个扇区，与模拟器的软驱控制器一致；文件只写在根目录，每簇 1 个扇区，文件名必须符合 8.3，不支持子目录；引导扇区只有 BIOS 参数块与签名，没有启动代码，镜像只用作数据盘。

## 4. 目标专用选项

`options` 里每一项是一个选项，字段：

| 字段 | 说明 |
| --- | --- |
| `type` | `boolean`、`string` 或 `number` |
| `default` | 默认值，类型必须与 `type` 一致 |
| `links` | 只用于布尔选项：值为 `true` 时额外链接的目标文件，路径值 |

用户在 `fcdev.json` 的 `targetOptions` 里设置；没有定义的选项或类型不对时报错。额外链接的目标文件排在用户目标文件之后、库之前。

## 5. 运行库的构建

目标自带的运行库与启动代码用 C 或汇编写，发布前编译好随包发布。`lib-build.json` 的字段：

| 字段 | 说明 |
| --- | --- |
| `libraries` | 库路径到源文件列表；每个源文件编成一个 `.o`（`.c` 先用 `cc65` 编成汇编，再汇编），用 `ar65 a` 合成库，再删除临时 `.o`；列表里以 `/` 结尾的项是目录，递归收录其中全部 `.c` 与 `.s`；同名文件报错 |
| `objects` | 目标文件路径到源文件，直接汇编成 `.o` |
| `binIncludeDirs` | `.incbin` 的搜索目录，相对目标目录 |

汇编时固定给 `-I <目标>/asminc`，`-t` 与 `--cpu` 取目标的定义；`.c` 用 `cc65 -t <cc65Target> --cpu <cpu> -Oirs`，头文件目录取目标的 `include`，并带上目标的 `defines`。一个函数一个源文件，库里就是一个函数一个目标文件，链接时只带入程序用到的函数。命令 `node tools/build-libs.mjs [目标名…]` 编译；不带参数时编译全部目标。`fcdev` 的 `prepack` 与根目录 `npm test` 的 `pretest` 都会自动运行它。

## 6. 新增机型的步骤

1. 在 `packages/fcdev/targets/` 下新建目录，写 `target.json`、链接配置、启动代码、头文件与运行库源码。头文件里的函数用 `/** */` 文档注释（说明、`@param`、`@return`），`fcdev api` 直接读它们作为接口文档，见 [01-命令行与构建](../packages/fcdev/docs/01-命令行与构建.md) 第 5.1 节。动手前先用资料与模拟器确认程序格式、内存布局、系统调用与固件要求，不凭猜测实现。
2. 需要新的打包器或程序名规则时，在 `packagers/index.mjs` 或 `targets/name-rules.mjs` 登记。
3. 有运行库要编译时写 `lib-build.json`，运行 `node tools/build-libs.mjs <目标名>`。
4. 在 `create-fcdev` 里加 C 与汇编两个模板，见第 6.1 节。
5. 补测试，见 [04-测试与验证](04-测试与验证.md)，并在主包的 `docs/<目标名>/` 下新增该目标的使用说明文档，更新 [01-软件架构设计](01-软件架构设计.md) 第 9 节的两份文档清单与 `src/docs/doc-topics.mjs` 的主题登记。

### 6.1 模板

模板内置在创建包里，每个模板是 `packages/create-fcdev/templates/<目标>-<语言>/` 目录，包含：

| 文件 | 说明 |
| --- | --- |
| `template.json` | `target`、`language`、`title`，可选 `scripts`（额外的 npm 脚本）与 `notes`（创建完成后提示的说明）；目录名必须等于 `<target>-<language>` |
| `README.md` | 生成项目的说明，可用 `{{name}}`；末尾有“文档”一节，写明使用文档随 `fcdev` 安装在 `node_modules/fcdev/docs/`，并给出对应目标的 `npx fcdev docs <主题>` |
| `src/hello.c` 或 `src/hello.s` | 示例程序 |

目录名以 `_` 开头的是公共文件目录，不是模板，目前只有 `_common/gitignore`。

新增机型的目标后，在 `templates/` 下加 `<目标>-c` 与 `<目标>-asm` 两个目录，写 `template.json`、`README.md` 与示例程序；目标需要额外脚本或提示时写进 `template.json`。模板必须能用 `fcdev build` 构建成功，`npm run release:verify` 会逐个验证，见 [05-发布](05-发布.md)。使用文档里模板的说明见 [04-创建包与模板](../packages/fcdev/docs/04-创建包与模板.md)。
