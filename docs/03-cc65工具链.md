# cc65 工具链

扩展用 cc65 编译与链接，不使用使用者机器上自带的 cc65，也没有自备 cc65 的设置。cc65 的源码在扩展目录的 `vscode/third_party/cc65/`，由本仓库维护；构建脚本把它编成工具与运行库，组装到扩展目录的 `vscode/toolchain/`，随 `.vsix` 发布。扩展经“扩展资源位置”抽象找到它（`vscode/src/infra/toolchain/bundled-toolchain-locator.ts`），找不到时报错并说明原因，不去 `PATH` 里猜。

## 1. 源码目录 `vscode/third_party/cc65/`

- 最初导入自上游 [cc65/cc65](https://github.com/cc65/cc65) 的提交 `357f64e4e3c733d54b82bc155afc841fd8d9ee8d`（2025-08-24）。导入后由本仓库维护，可以直接修改。
- 是删减版，只保留扩展构建 `cc65`、`ca65`、`ld65`、`ar65`、`da65`，以及 `none`、`nes` 两个目标的运行库所需的文件。`vscode/third_party/cc65/README-FCDEV.txt` 写明“本目录为删减版”并给出导入的提交，这是 zlib 许可证对修改版的要求。
- 许可证为 zlib，见 `vscode/third_party/cc65/LICENSE`。

保留的内容：

| 位置 | 内容 |
| --- | --- |
| `src/` | `cc65`、`ca65`、`ld65`、`ar65`、`da65` 与共用的 `common` |
| `libsrc/` | `common`、`runtime`、`none`、`nes`，以及它们的公共部分依赖的 `conio`、`dbg`、`em`、`joystick`、`mouse`、`serial`、`tgi`、`zlib` |
| `include/`、`asminc/` | 头文件与汇编引入文件 |
| `cfg/` | `none.cfg`、`nes.cfg`、`module.cfg` |
| 各级 `Makefile`、`LICENSE` | 构建与许可 |

已删除：`test/`、`targettest/`、`doc/`、`samples/`、`util/`、持续集成与贡献说明文件、其他机型的库与头文件，以及 `co65`、`od65`、`sp65`、`grc65`、`chrcvt65`、`cl65`、`sim65`、`dbginfo` 等不用的工具。删减后必须仍能编出 `none.lib` 与 `nes.lib`；缺什么就从上游补回。

## 2. 构建

```bash
node vscode/tools/build/build-cc65.mjs      # 或在 vscode/ 里 npm run build:toolchain
```

`vscode/tools/build/build-cc65.mjs` 做的事：

1. 把 `vscode/third_party/cc65/` 整个复制到 `build/vscode/cc65`，在副本里构建，不污染源码目录。
2. 在 `src` 里构建 `ar65`、`ca65`、`cc65`、`da65`、`ld65`，版本串显式传 `BUILD_ID=Git <提交前 7 位>`；不传时 `Makefile` 会取当前目录所在仓库的提交号，版本输出会指向错误的提交。
3. 在 `libsrc` 里构建 `none` 与 `nes` 两个运行库。
4. 组装工具链：`vscode/toolchain/bin/` 放五个可执行文件，另有 `include/`、`asminc/`、`cfg/`、`lib/none.lib`、`lib/nes.lib`、`LICENSE`。
5. 写 `manifest.json`（上游地址、提交、各文件的 SHA-256）。

环境变量 `MAKE_PROGRAM` 可指定 make 程序，默认 `mingw32-make`，编译器用 `gcc`。`vscode/toolchain/` 是生成物，不入库；`.vscodeignore` 不排除它，所以随 `.vsix` 发布，`check:package` 核对清单里的文件与 SHA-256 一致，见 [05-发布](05-发布.md)；`.vscodeignore` 排除 `third_party/`，源码不随 `.vsix` 发布。

上游提交号常量 `CC65_COMMIT` 写在构建脚本里。

## 3. 工具链在扩展里

- 位置是 `vscode/toolchain/`；`bin/`、`include/`、`asminc/`、`lib/`、`cfg/`、`LICENSE`、`manifest.json` 都是生成物，由 `.gitignore` 排除。
- 扩展找不到工具链（目录不存在或不完整）时，构建报错并说明先运行 `npm run build:toolchain`；不提供指向自备 cc65 的设置，也不使用 `PATH` 里的 cc65。
- `check:package` 校验 `.vsix` 里的工具链与清单一致，且没有清单之外的文件；源码目录里的路径和清单由 `vscode/tools/test/cc65-tools.test.mjs` 检查，见 [04-测试与验证](04-测试与验证.md)。

## 4. 升级与修改

- 修改 `vscode/third_party/cc65/` 里的源码后，重新运行 `node vscode/tools/build/build-cc65.mjs`，再在 `vscode/` 里运行 `npm run build:libs` 与 `npm run check`。
- 要换到上游的新提交时：从上游取回上面“保留的内容”对应的文件，更新 `vscode/tools/build/build-cc65.mjs` 里的 `CC65_COMMIT` 和 `vscode/third_party/cc65/README-FCDEV.txt` 里的提交号，重新构建并运行全部测试。
- 统一换行符的脚本不要扫描 `vscode/third_party/cc65/`：里面有 Latin-1 和 Shift-JIS 编码的文件，按 UTF-8 读写会损坏。
