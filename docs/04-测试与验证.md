# 测试与验证

本文说明测试的分层、运行方法和用到的环境变量。测试用 Node 内置的 `node:test`，不引入测试框架。

## 1. 运行

| 命令 | 作用 |
| --- | --- |
| `npm test` | 运行全部测试；运行前自动执行 `npm run build:libs` 编译各目标的运行库 |
| `npm run boundaries` | 检查主包的分层依赖，见 [01-软件架构设计](01-软件架构设计.md) 第 5 节 |
| `npm run check` | 依赖边界检查加测试 |
| `npm run release:check` | 发布前检查，见 [05-发布](05-发布.md) |
| `npm run release:verify` | 打包后在临时目录里创建、安装并构建四个模板 |

测试文件在 `packages/fcdev/test/`、`packages/create-fcdev/test/` 与仓库根的 `test/`，文件名以 `.test.mjs` 结尾。

VS Code 扩展是独立的 npm 项目，测试在 `vscode/test/`，用 vitest；在 `vscode/` 目录运行 `npm run check`，见 [06-VS Code扩展](06-VS%20Code扩展.md) 第 5 节。

找不到 cc65 工具链时，需要真实工具的用例会跳过，并在跳过说明里写明原因；纯逻辑的用例不受影响。

## 2. 环境变量

| 变量 | 作用 |
| --- | --- |
| `FCDEV_CC65_HOME` | 指向自备的 cc65 目录；没有工具链包时用它跑集成测试 |
| `FCDEV_EMULATOR` | 指向 Ember 的可执行文件（如 `build/ember/win32/app/Release/ember-win.exe`）；设置后额外运行“真实 Ember”的用例（还需要 cc65 与已构建的调试 SDK） |
| `FCDEV_TEST_FIRMWARE` | 指向 SB2000 的 BIOS 文件，用于“SB2000 程序在 Ember 里运行”的用例；没有设置时用仓库里的 `reference/rom/SB2K_BIOS.NES` |
| `FCDEV_TEST_NES_ROM` | 指向一个 NROM 的 `.nes` 文件；设置后额外对它做完整反汇编与回读 |
| `FCDEV_SKIP_GUI_TESTS` | 设为 `1` 时跳过会打开 Ember 窗口的用例 |

## 3. 测试分层

| 层次 | 文件 | 内容 |
| --- | --- | --- |
| 单元测试 | `args-parser`、`config`、`build-helpers`、`targets-packagers`、`fat12-image` | 参数解析、配置查找与未知项报错、源文件收集、依赖文件解析、工具参数、目标字段校验、程序名规则、各打包器、FAT12 镜像 |
| 命令行与构建 | `cli`、`build`、`toolchain`、`source-charset` | 帮助、版本、错误输出与退出码、`build`、`info`、`sync`；构建计划的路径规则；增量与错误提示；工具链定位的优先级与不完整报错；源文件 UTF-8 转 GB2312 的规则、不在 GB2312 里的字符报错（含文件、行、列）、`sourceCharset` 的校验，以及用真实 cc65 构建学习机的 C 与汇编程序时汉字变成 GB2312 字节、错误信息仍指向原文件 |
| 目标 | `sb2000`（主包） | 构建 C 与汇编程序，文件头、大小与内存布局，运行库一个函数一个目标文件、链接只带用到的函数，多页程序的文件页序、库页不够与超过上限的提示，`disk` 命令，缺少固件的提示 |
| 模拟器 | `emulator`、`sb2000`、`sb2000-library` | Ember 定位、端口检查、调试用户数据目录与环境变量、学习机程序名的按键、`run` 对学习机目标没有固件时报错、找不到 Ember 时报错、`debug` 把参数交给 `ember-debug`（需要调试 SDK 已构建）；真实 Ember 里调试模式载入 NES 程序、运行 60 帧、截图，并用 `debug` 命令连到同一个 Ember。SB2000 运行库的测试程序（约 15 个用例，共数百项检查）在 `sb2000-library`，经 Ember 的调试服务运行整机（需要 Ember、cc65、已构建的调试 SDK 与 BIOS，缺一就整组跳过），见 [sb2000/01-开发指南](../packages/fcdev/docs/sb2000/01-开发指南.md) 第 12 节 |
| 反汇编 | `disasm` | 映像读取、CDL 与轨迹解析、静态追踪、信息文件、回读校验；对 `fcdev` 自己构建的 NES 与 SB2000 程序做完整反汇编；设置 `FCDEV_TEST_NES_ROM` 时对真实游戏做反汇编 |
| 创建包 | `create`（`create-fcdev`） | 参数解析、模板列表、项目生成、目录检查、交互选择、安装流程；四个模板都能用 `fcdev` 构建 |
| 接口文档 | `api-command`（主包）、`sb2000-api`（仓库） | `fcdev api` 命令的各种查询与错误提示、头文件文档注释的解析、系统调用标签的匹配；SB2000 接口检查（函数文档完整、有且只有一处实现、每个功能号被封装或写明不封装的原因）；入库的 `api-reference.md` 与头文件生成的结果一致 |
| 仓库 | `cc65-tools`、`sb2000-header`、`sb2000-symbols-doc`、`sb2000-examples-doc`、`structure` | `cc65/` 里的必要路径与工具链包的校验值；入库的 `sb2000-symbols.h` 与生成结果一致；入库的 `symbols-reference.md` 与 `sb2000.inc` 的生成结果一致、符号个数相符；入库的 `examples-source.md` 与示例项目的生成结果一致、每个示例都有一节且源码完整；分层检查对违规的识别 |
| 文档 | `docs-command`（主包） | `fcdev docs` 命令的列表、按主题名、文件名与关键词查询、`--json`、错误提示；文档主题登记与主包 `docs/` 目录里的文件一一对应（包内其他位置的登记项文件必须存在），主题名合法且不重复，架构文档的使用文档清单列全了每个主题 |

集成测试用真实的 cc65 构建四个模板，检查产物头部与大小。

## 4. 模拟器验证

- NES hello 在 Ember 里运行：`emulator` 测试的真实 Ember 用例把程序载入调试模式的 Ember，运行 60 帧后用 `output.screenshot` 与 `fcdev debug screenshot` 截图并核对 PNG 文件头。
- SB2000 的 C、汇编 hello 曾在旧模拟器里运行并截图核对屏幕文字（显示 `Hello, SB2000!` 与“你好，小霸王！”并能返回 DOS），这部分用例已删除；现在由 `sb2000-library` 的文字输出、显示等用例在 Ember 里覆盖运行与屏幕显示，没有单独核对 hello 的屏幕文字。
- `fcdev run` 在 Ember 里运行学习机程序的完整流程（构建、打包镜像、添加固件、开机、输入程序名、运行）已用 `apps/sb2000/hwtest` 实际运行并截图核对，没有做成自动测试用例。
- SB2000 的程序运行环境验证（V01 到 V10）的结论见 [sb2000/02-系统调用手册](../packages/fcdev/docs/sb2000/02-系统调用手册.md) 第 9 节。
- 运行库测试程序的停靠点用写断点实现（对全局变量 `sb_test_stop` 设断点），不对函数入口设执行断点，原因见 [08-目标运行库维护](08-目标运行库维护.md) 第 2.4 节。
- 用调试服务验证时一律显式指定端口，避免连到别的 Ember；只结束本仓库启动的 Ember 进程。

## 5. 反汇编验证

`fcdev` 自己构建的 NES hello 与 SB2000 的 `.EXE`，以及一个真实的 NROM 游戏（超级马里奥，由环境变量 `FCDEV_TEST_NES_ROM` 提供）回读都与原文件逐字节一致。静态追踪追不到表驱动之外的间接调用，所以马里奥只追到约 2320 字节代码，其余按数据输出，回读仍一致；补充 CDL 或 `trace` 能扩大覆盖。步步高 DOS 下的 GBASIC（`.CMD`，26896 字节，平铺二进制加载地址 `$7B00`）加入地址表识别后，代码从 6905 字节增到 8980 字节，再加一个经人工确认的入口 `$880F` 增到 10361 字节；再用模拟器的 `trace ... unique` 记录下运行 BASIC 语句、图形编辑与退回 DOS 时执行过的地址，并补三个经单独追踪确认的入口，增到 14843 字节（剩余约 12000 字节主要是图形数据与关键字表），回读一致。

使用上的限制见使用文档 [03-反汇编](../packages/fcdev/docs/03-反汇编.md) 第 4 节。

## 6. 安装验证

`npm run release:verify`（`tools/verify-install.mjs`）：

1. 把四个包用 `npm pack` 打成 `.tgz`。
2. 在临时目录里从本地 `.tgz` 安装 `create-fcdev`，不访问 npm 仓库，也不执行 `npm publish`。
3. 对四个模板分别：用 `create-fcdev` 创建项目（`--no-install`），从本地 `.tgz` 安装 `fcdev`、工具链包与调试 SDK（`fcdev` 依赖它们，不访问 npm 仓库时要一并给出），运行 `npm run build`，检查产物头部：NES 为 iNES 文件头，SB2000 为 `4C ?? ?? AA 55`。
4. 调试 SDK 单独装进临时目录，确认 `ember-debug-sdk` 与 `ember-debug-sdk/node` 两个入口能加载，`dist/cli.js`、`dist/mcp.js` 在。
5. 结束后删除临时目录；加 `--keep` 可保留，便于查看。

只验证构建，不启动模拟器。

## 7. 注意事项

- 真实 Ember 的用例用系统临时目录下的 `fcdev-ember/<端口>` 做用户数据目录，结束时按进程号结束自己启动的 Ember 并删除该目录，不碰平时在用的 Ember。
- 没有目测的界面输出，汇报时写明。
