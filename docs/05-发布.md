# 发布

本文说明 VS Code 扩展 fcdev 的打包、检查与发布。登录市场与 `vsce publish` 由用户执行，不在代码或文档里记录任何凭据。

## 1. 版本与元数据

- 扩展在 `vscode/`，包名 `fcdev`，发布者 `sungbin`，扩展 ID `sungbin.fcdev`；版本取 `vscode/package.json` 的 `version`。
- 只发布 Windows 64 位版（工具链是 Windows 可执行文件），打包目标是 `win32-x64`；`engines.vscode` 为 `^1.101.0`（扩展宿主的 Node 要达到 22，调试客户端用全局 `WebSocket`）。
- 更新记录写在 `vscode/CHANGELOG.md`：标题 `## <版本号>`，只写面向使用者的功能性变化，按功能分组，一条一句话；已发布版本的一节不修改，新版本在顶部新增一节，只放本次的改动。Ember 自己的更新记录在它的帮助文档里，与扩展无关。
- 许可证 Apache-2.0；扩展里的 cc65 工具链是 zlib，见 [01-软件架构设计](01-软件架构设计.md) 第 7 节。扩展不含 Ember，也不含任何 BIOS 或 ROM。

## 2. 打包前提

1. 所有改动已提交。
2. 工具链已构建：在 `vscode/` 里 `npm run build:toolchain`，输出到 `vscode/toolchain/`。
3. 各目标的运行库已构建：`npm run build:libs`；SB2000 的生成文档已更新：`npm run gen:docs`。
4. `npm run check` 通过（类型检查、lint、测试、构建、工具测试）。
5. `CHANGELOG.md` 里已经写好本版本的更新说明，`package.json` 的版本已升。

## 3. 打包

```bash
cd vscode
npm run package
```

`npm run package` 运行 `vsce package --target win32-x64 --allow-missing-repository --out ../build/vscode/`，先经 `vscode:prepublish` 运行 `npm run build`，生成 `build/vscode/fcdev-win32-x64-<版本>.vsix`（`*.vsix` 已被 `.gitignore` 与 `.vscodeignore` 排除，不入库）。`.vscodeignore` 排除源码、测试、配置与 `node_modules`，保留编译产物 `out/`、`toolchain/`、`targets/`、`templates/`、`docs/`、`debug/`、`chat/`、`syntaxes/`、`resources/`。

## 4. 检查

`npm run check:package`（`vscode/tools/check/check-package.mjs`）核对 `.vsix` 的内容，只检查，不修改任何文件：

- 含编译产物 `out/bootstrap/extension.js`，`package.json` 的 `main` 指向它。
- 含工具链：`toolchain/manifest.json` 记录的每个文件都在，且 SHA-256 一致，没有清单之外的文件。
- 含每个目标的运行库（`targets/<名>/lib/*.lib`）、目标定义（`target.json`）、四个项目模板与 `_common`。
- 含使用文档：`docs/topics.json` 登记的每份文档都在。
- 含调试接口描述 `debug/openrpc.json`。
- 不含测试、`node_modules`、源码 `src/`、`.env`、密钥与证书文件、`.tgz`、`.vsix`。
- `.vsix` 里没有 Ember 与任何 BIOS、ROM 文件。

## 5. 发布到市场

在 `vscode/` 里用发布脚本 `vscode/tools/release/release.mjs`：

```bash
npm run release              # 只检查与打包，不上传
npm run release -- --publish # 检查、打包并上传到市场
```

- 脚本依次检查：`CHANGELOG.md` 里有当前版本的一节；运行 `npm run check`（含编译）；运行 `npm run package`；核对 `.vsix`（同第 4 节）。加 `--publish` 时再用 `vsce publish` 上传刚打好的 `.vsix`。
- 脚本不重新构建工具链、运行库与生成文档（第 2 节第 2、3 步），这些产物不全时核对会报错并停止。
- 上传时令牌按这个顺序取：环境变量 `VSCE_PAT`；文档仓库的 `01-文档/密钥/vscode-publish-token.txt`；没有时提示输入（输入不显示）。令牌只用于本次运行，脚本不输出内容。令牌由用户保管，不写进本仓库。也可以在市场的管理页面上传 `.vsix`。

发布后在一台干净的 VS Code 里安装，核对：打开含 `fcdev.json` 的文件夹能构建；设置 `fcdev.emulator.path` 后能运行与调试运行；Copilot 里能看到全部工具。这部分是手动验证。

## 6. 包的体积

`.vsix` 的体积主要来自 `toolchain/`（五个可执行文件与两个库）与各目标的运行库；以实际 `npm run package` 的输出为准。
