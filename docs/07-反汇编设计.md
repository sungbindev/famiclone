# 反汇编设计

`fcdev disasm` 的实现思路与内部结构。命令、输入格式与限制见使用文档 [03-反汇编](../packages/fcdev/docs/03-反汇编.md)。代码在 `packages/fcdev/src/disasm/`。

## 1. 做法

指令解码与源码文本输出交给 cc65 自带的 `da65`，不改 `da65` 的 C 代码；前端脚本负责分析，并把分析结果写成 `da65` 的信息文件。只有实测发现信息文件无法表达时，才修改 `da65` 的 C 源码，并把每处修改写进 `cc65/README-FCDEV.txt`。

流程（`disassembler.mjs`）：

1. 读取输入，判断格式，取出映像（字节、第一个字节的地址、中断向量）。
2. 收集入口：中断向量、`--entry`、`--trace` 里的地址、CDL 里每段连续代码的起点。没有任何入口时报错。
3. 静态追踪，标出每个字节是指令的操作码、操作数还是未知。
4. 生成 `da65` 信息文件。
5. 运行 `da65 -i <信息文件> --multi-pass`，得到 ca65 源码。
6. 回读校验：用 `ca65`、`ld65` 重新汇编，与原映像逐字节比较；不一致就报错，指出第一个差异的偏移与地址，不输出“成功”。

## 2. 源文件

| 文件 | 作用 |
| --- | --- |
| `disassembler.mjs` | 总流程，见第 1 节 |
| `analysis.mjs` | 静态追踪，规则见使用文档的“静态追踪”一节 |
| `address-tables.mjs` | 经地址表分发的跳转的识别 |
| `opcode-table.mjs` | 指令表，共 151 条官方指令，数据取自 `da65` 的 `cc65/src/da65/opc6502.c`；非官方（非法）操作码不在表里 |
| `info-writer.mjs` | 写 `da65` 的信息文件，见第 3 节 |

## 3. 信息文件

`info-writer.mjs` 把整个映像划分成首尾相接、互不重叠的段，没有遗漏，否则 `da65` 会把没说明的字节默认当成代码：

| 段类型 | 用于 |
| --- | --- |
| `Code` | 追踪到的指令 |
| `ByteTable` | 没被追到的字节 |
| `AddrTable` | iNES 末尾 6 字节的中断向量表，以及识别出的字表 |

另有 `GLOBAL`（输入输出文件名、起始地址、CPU）、`ASMINC`（符号定义文件）与 `LABEL`（用户符号与中断向量名）。

## 5. 新核心（逐阶段加入，阶段 4 完成重写）

第 1 节到第 4 节是基于 `da65` 的旧实现。新核心按 [09-AI 反汇编工具](09-AI反汇编工具.md) 的计划，放在同一目录的子目录里，阶段 4 让 `fcdev disasm` 改用它后，删除上面的旧文件并重写本文。目前已有：

| 目录 | 作用 |
| --- | --- |
| `cpu/` | 6502 指令表（`opcodes.mjs`，151 条官方指令，按助记符与寻址方式登记）、解码（`decode.mjs`：操作数、分支与跳转的目标、引用的地址，非官方操作码与截断的指令返回失败原因）、汇编文字（`format.mjs`：ca65 写法，绝对寻址的地址小于 `$100` 时加 `a:`；`isAssemblable` 指出 ca65 拒绝的 `jmp ($xxFF)`，生成时要改写成 `.byte`） |
| `model/` | 映像布局（`layout.mjs`：段的文件偏移、长度、CPU 地址、bank、是否可写，段在文件里不重叠，地址重叠时必须是不同的 bank；地址与文件偏移的换算、未覆盖字节的查找）、区域（`regions.mjs`：code、bytes、words、string、graphics、padding 六种类型及各自的参数，区域互不重叠、必须落在一个段里，盖住旧区域时裁剪或拆开，地址表只能在表项边界上切开；没有标注的字节是 unknown）、入口（`entries.mjs`：段号加 CPU 地址，来源为向量、手工、跟踪、CDL、调用记录） |
| `formats/` | 映像格式解析器：`flat`（给加载地址或完整的段列表）、`ines`（iNES 与 NES 2.0 文件头，NROM 生成布局并读出中断向量，其他映射器报 `DISASM_MAPPER_UNSUPPORTED`）；结果里的 `unmapped` 列出文件头、trainer、CHR 等不在 CPU 地址空间里的字节，统一入口 `parseImage(格式名, 文件, 选项)` |
| `view/` | 十六进制与字符视图（`hex-view.mjs`：按 CPU 地址对齐，范围头尾补空位，可带符号标注，换页的段写 bank） |
| `analysis/` | 地址空间（`address-space.mjs`：CPU 地址解析成段，换页窗口里来源所在的 bank 优先，否则 ambiguous）、入口生成（`entry-points.mjs`：由地址或中断向量生成入口）、静态追踪（`tracer.mjs`：从入口沿控制流标出指令，分类按文件偏移索引；目标不在任何段里记入 `outside`，间接 JMP 与跨 bank 转移记入 `unresolved`，可多次追踪累积）、地址表识别（`tables.mjs`：字表、RTS 表、低高字节分开的两张表）、由追踪结果生成区域（`build-regions.mjs`）、交叉引用（`xrefs.mjs`：调用、跳转、分支、读、写、先读后写、取地址、地址表）、候选识别（`detect.mjs`：填充、地址表、字符串、图形，只返回候选与依据；图形要给出图形数据端口） |

测试在 `packages/fcdev/test/` 的 `disasm-cpu.test.mjs`（指令表、解码、格式化，以及把 151 条指令各取多个操作数、解码格式化后用 `ca65` 重新汇编的字节对照）、`disasm-layout.test.mjs`、`disasm-formats.test.mjs`、`disasm-hex-view.test.mjs`、`disasm-trace.test.mjs`（与旧实现在同一批夹具和 fcdev 构建的程序上逐字节对照，换页窗口与跨 bank）、`disasm-regions.test.mjs`、`disasm-xrefs-detect.test.mjs`。
