# 反汇编设计

命令“FCDEV：反汇编映像文件”与 Copilot 反汇编工具共用的核心的实现思路与内部结构。命令、输入格式与限制见使用文档 [03-反汇编](../vscode/docs/03-反汇编.md)，工具与计划见 [09-AI 反汇编工具](09-AI反汇编工具.md)。

代码按扩展的分层放在 `vscode/src/shared/disassembly/`（纯函数）、`vscode/src/logic/disassembly/`（读写文件与运行汇编链接的部分）与 `vscode/src/contracts/disassembly/`（契约）。下文的目录名指 `shared/disassembly/` 下的同名子目录，文件名省略扩展名 `.ts`；`workspace/`、`operations/` 与 `verify/roundtrip` 在 `logic/disassembly/` 下，文件读写经 `contracts` 的文件系统与工具运行接口。

## 1. 做法

反汇编的对象是“反汇编工程”，不是源码文本：工程记录映像、布局、入口、区域、符号、注释、操作数提示、模块与符号集；源码由工程加映像生成，每次生成结果确定。源码由自己写的生成器输出（不经 `da65`），所以能按功能分文件、控制注释与逐字节形式；回读校验用 `ca65`、`ld65` 重新汇编链接，再与映像逐字节比较。

命令“反汇编映像文件”的流程（`workspace/pipeline` 的 `disassemble`）：

1. 读取输入，判断格式（`formats/` 的 `detectFormat`），解析成布局；平铺二进制没有布局信息，要给加载地址（命令缺少时向用户询问）。
2. 收集入口：中断向量、给定的入口、指令轨迹里的地址、CDL 里每段连续代码的起点；去重后没有入口时报错。符号集文件登记进工程，工程目录在这时创建。
3. 符号文件里的符号定义进工程（同一地址只用第一个名字）。
4. 静态追踪（`traceProject`），把结果并入区域，并留下未解析的间接跳转与跨 bank 转移。
5. 自动命名（`ensureAutoSymbols`），符号集里已有的名字不再生成。
6. 生成源码工程（`generateProject`），得到全部文件的内容；写盘，再保存一次 `disasm.json`。
7. 回读校验（`verifyRoundtrip`）：重新汇编链接，逐段比较；把结果记入工程并再次保存。不一致时抛出错误，指出第一处差异的段与地址，工程目录保留。
8. 返回报告：描述、字节数、指令条数、警告与进度报告。

Copilot 工具不走这个总流程，而是按步骤调用 `operations/` 里的操作（见第 2 节）：每个操作从工程目录读出 `disasm.json`、映像与符号集，用内存里的工程做完事情，需要时再写回；不在内存里留状态，每次调用都重新读，所以工程文件被 git 比较、回退都不会和运行中的状态不一致。

## 2. 目录

| 目录 | 作用 |
| --- | --- |
| `cpu/` | 6502 指令表（`opcodes`，151 条官方指令，按助记符与寻址方式登记）、解码（`decode`：操作数、分支与跳转的目标、引用的地址，非官方操作码与截断的指令返回失败原因）、汇编文字（`format`：ca65 写法，绝对寻址的地址小于 `$100` 时加 `a:`；`isAssemblable` 指出 ca65 拒绝的 `jmp ($xxFF)`，生成时改写成 `.byte`） |
| `model/` | 映像布局（`layout`：段的文件偏移、长度、CPU 地址、bank、是否可写，段在文件里不重叠，地址重叠时必须是不同的 bank；地址与文件偏移的换算、未覆盖字节的查找）、区域（`regions`：code、bytes、words、string、graphics、padding 六种类型及各自的参数，区域互不重叠、必须落在一个段里，盖住旧区域时裁剪或拆开，地址表只能在表项边界上切开；没有标注的字节是 unknown）、入口（`entries`：段号加 CPU 地址，来源为向量、手工、跟踪、CDL、调用记录）、符号（`symbols`：符号、注释、操作数提示、模块的规范化与校验）、工程（`project`：创建、序列化、解析，映像与回读的过期判断，带版本号）、编辑（`edits`：`applyEdits` 一次提交一批编辑操作，全部成功才生效，任一项出错则整批不改） |
| `formats/` | 映像格式与运行记录的解析器：`flat`（给加载地址或完整的段列表）、`ines`（iNES 与 NES 2.0 文件头，映射器 0、3、2、1、7、4 按默认模式把 PRG 划成固定与可换页的段并读出中断向量，其他映射器报 `DISASM_MAPPER_UNSUPPORTED` 并提示用模拟器的地址解析查布局）、`sbdos`（SB-DOS 程序的文件头与页布局，入口是文件头的 JMP）、`paged`（按页排列的 ROM，选项给页大小、固定映射与窗口，用来读学习机的 BIOS）；结果里的 `unmapped` 列出文件头、trainer、CHR 等不在 CPU 地址空间里的字节；统一入口 `parseImage(格式名, 文件, 选项)`，`detectFormat` 按文件头判断；`cdl` 读 CDL（含 Mesen 的 CDLv2 头，可指定保留的标志位：代码、数据、跳转目标、子程序入口），`trace-log` 读 Ember 的指令轨迹，`call-log` 读调用记录（被记录的指令地址，以及由栈顶两个字节换算出的 JSR 返回地址） |
| `view/` | 十六进制与字符视图（`hex-view`：按 CPU 地址对齐，范围头尾补空位，可带符号标注，换页的段写 bank） |
| `analysis/` | 地址空间（`address-space`：CPU 地址解析成段，换页窗口里来源所在的 bank 优先，否则 ambiguous）、入口生成（`entry-points`：由地址或中断向量生成入口；`record-entries`：由一组地址或按字节的代码标志生成入口，代码标志可指定额外的起点位（跳转目标、子程序入口），`dataRunsFromFlags` 找出只被当数据读取的字节段；不在映像里的地址返回在 `skipped` 里）、静态追踪（`tracer`：从入口沿控制流标出指令，分类按文件偏移索引；目标不在任何段里记入 `outside`，间接 JMP 与跨 bank 转移记入 `unresolved`，可多次追踪累积）、地址表识别（`tables`：字表、RTS 表、低高字节分开的两张表）、由追踪结果生成区域（`build-regions`）、交叉引用（`xrefs`：调用、跳转、分支、读、写、先读后写、取地址、地址表）、候选识别（`detect`：填充、地址表、字符串、图形，只返回候选与依据；图形要给出图形数据端口）、工程级追踪（`project-trace`：`traceProject` 由工程的入口追踪并把结果并入区域，手工区域不被覆盖）、指令扫描（`code-scan`：`scanCode` 按区域逐条解码，给生成与自动命名用）、自动命名（`auto-symbols`：`ensureAutoSymbols` 为调用目标、跳转与分支目标、被读写的数据地址生成 `sub_`、`loc_`、`data_`、`var_` 加地址的符号并标记为自动；目标落在指令中间时符号放在那条指令的开头；已有符号与符号集里已有的名字不再生成，重复运行不增加） |
| `profile/` | 符号集（`symbol-set`：`parseSymbolSet` 解析 ca65 `.inc` 里的 `NAME = 值`、`.define`、`.importzp` 等常量，`indexByValue` 按值建立索引，生成时用它给布局外的地址写名字）与符号文件（`symbol-file`：每行“名字 地址”） |
| `generate/` | 工程到 ca65 工程的生成（纯函数，不写盘）：`pieces` 把每个段按模块与连续区域切成“块”，一块一个 ca65 段，名字 `SEG<段号>_<4 位十六进制偏移>`；`source` 输出每块的源码（指令、`.byte`、`.word`、字符串、`.res`、块注释与行尾注释、操作数提示，跨块的分支、`jmp ($xxFF)`、非官方操作码一律写 `.byte` 并在注释里写反汇编文字）；`link-config` 按布局生成 `link.cfg`，一个段一个 MEMORY 区；各段按文件偏移排序后在映像里首尾相接时，所有区都写到同一个输出文件（`file = %O`，按偏移顺序拼接，产物就是映像本身，可以直接作为 FC Dev 的 `rom` 目标项目的链接配置），否则每段输出到自己的 `seg<段号>.bin`；`index` 的 `generateProject` 返回全部文件（`src/<模块>.s`、`include/globals.inc`、`include/constants.inc`、复制的符号集、`link.cfg`）。生成出的源码用 `ca65 -I include` 汇编 |
| `verify/` | 回读（`roundtrip`：`writeGeneratedFiles` 写盘，`verifyRoundtrip` 用 `ca65`、`ld65` 重新汇编链接并逐段比较输出（拼成一个文件时按段的起始位置取出，否则读 `seg<段号>.bin`）与映像字节，`recordVerification` 把结果记入工程，工程之后再被改动即算过期）、进度报告（`status`：`buildStatus` 统计各类区域字节数、自动符号数、没有注释的过程数、未解析项、回读状态） |
| `workspace/` | 工程在磁盘上的读写（`project-store`：`disasm.json`，映像与符号集的路径相对工程目录并用 `/` 分隔，读映像时核对摘要）、由映像创建工程（`open-project`：解析格式与布局、登记入口（向量、格式自己声明的入口、手工、轨迹、CDL）与符号集、读入符号文件；工程里还记着创建时用的目标描述（名字、输入名、图形数据端口，`detect` 用它找图形数据））与一次完成的反汇编（`pipeline`，见第 1 节） |
| `query/` | 给查看与查询用的纯函数，不读写磁盘、不改工程：符号索引（`symbol-index`：按名字、按位置查符号，把一个 CPU 地址落实成符号名）、清单（`listing`：带符号与注释的反汇编，有行数上限）、例程（`routines`：例程是“过程”符号开始、到下一个过程符号为止的连续指令；调用者、被调用者、读写的地址、可能的入口与出口寄存器（按指令顺序线性推测，不跟踪分支），调用图）、搜索（`find`：字节模式、文本、指令序列，分页）、分类列表（`lists`：入口、例程、未解析项、没有识别的字节、自动符号、没有说明的例程）、布局替换（`layout-edit`：用新段列表重建布局，仍有效的入口、符号、注释、提示保留，区域清空） |
| `operations/` | Copilot 反汇编工具对应的 18 个操作（`disasm_build` 由 `logic/disassembly/build-service-comparer` 完成，不在这里）：`open`、`status`、`layout`、`hex`、`find`（工程与映像），`trace`、`list`、`view`、`xrefs`、`routine`、`callgraph`、`detect`、`reference`（分析），`apply`、`symbols`、`importRecord`（编辑），`generate`、`verify`（生成与校验）。`runOperation(名字, 参数)` 按名字调用，参数与结果都是可序列化的普通对象；地址参数可以写整数或 `"$C000"`；列表类结果带 `limit` 与 `nextCursor`。操作由扩展的入口层经 `contracts` 的 `DisasmOperations` 调用。`trace` 追踪后自动命名；`importRecord` 把指令轨迹、调用记录或 CDL 导入工程（执行过的地址成为入口；调用记录里对照映像核实过“返回地址减 3 处是 JSR 且操作数是被记录的地址”的调用者也成为入口；CDL 里代码段的起点、跳转目标与子程序入口成为入口，只被当数据读取的字节段成为来源为 cdl 的 bytes 区域，不盖住已有的手工区域，以后的追踪也不会盖住它们；记录文件按路径读取，不在映像里的地址忽略并汇总）；`verify` 记录回读结果并给出差异所在的符号、区域与例程 |

各目录的 `index` 是对外入口，其他目录只经它引用。

## 3. 生成与回读的规则

- 每个段一个 ld65 内存区。段按文件偏移排序后首尾相接（第一段可以不从 0 开始）时，所有内存区都写到同一个输出文件（`file = %O`），回读按段的起始位置取出对应的字节；有空隙时每段一个输出文件 `seg<段号>.bin`。两种情况回读都是逐段与映像里对应的字节比较，所以重叠的换页窗口也能回读；拼成一个文件的工程，`link.cfg` 可以直接给 FC Dev 的 `rom` 目标用（`fcdev.json` 的 `linkConfig`）。
- 段内每个“模块乘连续区域”是一个 ca65 段，按地址顺序列入 `link.cfg`；符号用 `include/globals.inc` 的 `.global` 与 `.globalzp` 共享，映像外的常量与符号集放在 `include/constants.inc`。
- 绝对寻址的操作数落在零页时，用 `a:` 强制绝对寻址，不让 `ca65` 缩成零页寻址。
- 官方指令之外的操作码、`ca65` 不接受的写法（`jmp ($xxFF)`）、跨块的分支，一律输出 `.byte`，并在注释里写出反汇编文字。
- 分支与跳转目标落在指令中间时写成“符号加偏移”；符号落在指令中间时写成 `名字 = * + 偏移`。
- 长重复字节用 `.res 数量, 值`，其余数据按区域参数输出 `.byte`、`.word`、字符串。
- 回读失败时报告第一处差异所在的段、地址、文件偏移、两边的字节，以及它前面最近的符号。

## 5. 依赖与结构检查

- `shared/disassembly` 只能引用 `shared`；`logic/disassembly` 只能引用 `contracts`、`shared` 与 `platform`（见 [01-软件架构设计](01-软件架构设计.md) 第 5 节），由 `test/structure.test.ts` 检查。
- 反汇编不引用 `emulator` 功能目录：记录文件由 Ember 写在它的调试输出目录，`importRecord` 按路径读取，两边只通过文件交接。
- 核心不绑定机型：除 `formats/` 外，源码（含注释）里不出现 `NES`、`iNES`、`Famicom`、`SB2000`、`SB-DOS`（不分大小写），由结构测试检查。机型差异（映像怎么对应到 CPU 地址、硬件符号、启动步骤）都以数据传入，见 09 的第 5 节。
