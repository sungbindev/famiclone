# 反汇编设计

`fcdev disasm` 的实现思路与内部结构。命令、输入格式与限制见使用文档 [03-反汇编](../packages/fcdev/docs/03-反汇编.md)。代码在 `packages/fcdev/src/disasm/`。

## 1. 做法

指令解码与源码文本输出交给 cc65 自带的 `da65`，不改 `da65` 的 C 代码；前端脚本负责分析，并把分析结果写成 `da65` 的信息文件。只有实测发现信息文件无法表达时，才修改 `da65` 的 C 源码，并把每处修改写进 `cc65/README-FCDEV.txt`。

流程（`disassembler.mjs`）：

1. 读取输入，判断格式，取出映像（字节、第一个字节的地址、中断向量）。
2. 收集入口：中断向量、`--entry`、`--trace` 里的地址、CDL 里每段连续代码的起点。没有任何入口时报错。
3. 静态追踪，标出每个字节是指令的操作码、操作数还是未知。
4. 生成 `da65` 信息文件。
5. 运行 `da65 -i <信息文件> --multi-pass`，得到 ca65 源码。
6. 回读校验：用 `ca65`、`ld65` 重新汇编，与原映像逐字节比较；不一致就报错，指出第一个差异的偏移与地址，不输出“成功”。

## 2. 源文件

| 文件 | 作用 |
| --- | --- |
| `disassembler.mjs` | 总流程，见第 1 节 |
| `analysis.mjs` | 静态追踪，规则见使用文档的“静态追踪”一节 |
| `address-tables.mjs` | 经地址表分发的跳转的识别 |
| `opcode-table.mjs` | 指令表，共 151 条官方指令，数据取自 `da65` 的 `cc65/src/da65/opc6502.c`；非官方（非法）操作码不在表里 |
| `info-writer.mjs` | 写 `da65` 的信息文件，见第 3 节 |

## 3. 信息文件

`info-writer.mjs` 把整个映像划分成首尾相接、互不重叠的段，没有遗漏，否则 `da65` 会把没说明的字节默认当成代码：

| 段类型 | 用于 |
| --- | --- |
| `Code` | 追踪到的指令 |
| `ByteTable` | 没被追到的字节 |
| `AddrTable` | iNES 末尾 6 字节的中断向量表，以及识别出的字表 |

另有 `GLOBAL`（输入输出文件名、起始地址、CPU）、`ASMINC`（符号定义文件）与 `LABEL`（用户符号与中断向量名）。
