# 目标运行库维护

各目标运行库的构建、接口文档、符号头文件与测试，供维护运行库的人使用。使用运行库开发程序的说明见使用文档 [nes/01-开发指南](../vscode/docs/nes/01-开发指南.md) 与 [sb2000/01-开发指南](../vscode/docs/sb2000/01-开发指南.md)。目标目录是 `vscode/targets/<名>/`，目标定义的字段见 [02-目标规范](02-目标规范.md)。

## 1. 通用规则

运行库由 `node vscode/tools/build/build-libs.mjs [目标名…]` 按各目标的 `lib-build.json` 编译：`.c` 先用 `cc65` 编成汇编再汇编，每个源文件编成一个目标文件，再用 `ar65` 合成库；在 `vscode/` 里 `npm run build:libs` 等同于不带参数运行它，需要先 `npm run build` 与 `npm run build:toolchain`；打包 `.vsix` 前必须运行，见 [05-发布](05-发布.md)。`lib-build.json` 的字段见 [02-目标规范](02-目标规范.md) 第 5 节。

## 2. SB2000

### 2.1 源码组织

- 一个函数一个源文件，放在 `src/lib/<模块>/sb-<函数名>.c`（或 `.s`）；库内部用的辅助函数以 `sbi_` 开头，声明在 `src/lib/sb-internal.h`，不对外。
- 运行库由 `vscode/tools/build/build-libs.mjs` 编译：`lib-build.json` 里以 `/` 结尾的项展开成目录下全部 `.c` 与 `.s`；`.c` 用 `cc65 -t none --cpu 6502 -Oirs` 编译再汇编，同名文件报错。链接只带入程序用到的函数。

### 2.2 接口文档

- [api-reference.md](../vscode/targets/sb2000/api-reference.md) 是接口文档的整本 Markdown，由 `node vscode/tools/gen/gen-sb2000-api-doc.mjs` 从头文件生成，末尾有“系统调用覆盖表”。改头文件注释后重新生成，测试会核对。头文件里的 `/** */` 注释是接口文档的唯一来源。
- [api-unwrapped.json](../vscode/targets/sb2000/api-unwrapped.json) 登记没有封装的功能号与子功能及原因（`functions` 是整个功能号不封装，`partial` 是封装了一部分）。`node vscode/tools/check/check-sb2000-api.mjs` 检查：头文件里每个函数有说明、`@param`、`@return`，有且只有一处实现，库里没有头文件之外的公开函数，BIOS 里有处理例程的每个功能号（`KNOWN_FUNCTIONS`）要么被某个函数的 `@syscall` 涉及、要么在 `functions` 里写明原因。

### 2.3 符号定义

- [asminc/sb2000.inc](../vscode/targets/sb2000/asminc/sb2000.inc) 是汇编用的符号定义，只含符号，不占空间。分节：系统调用、零页单元、不经 `SYSCALL` 直接调用的内核入口、功能号、子功能号（按功能分组）、变量（出错码与显示、文件与目录、内存页、磁盘、键盘手柄鼠标、参数单元）、硬件寄存器与位（`HW_` 开头）、文件打开方式、出错码、运行库入口。每个符号的行尾都有注释，说明含义。
- [include/sb2000-symbols.h](../vscode/targets/sb2000/include/sb2000-symbols.h) 是 C 用的同一份符号，每个符号对应一个 `SB_` 前缀的数值宏。它由 `node vscode/tools/gen/gen-sb2000-header.mjs` 从 `sb2000.inc` 生成，不要手工修改；改 `sb2000.inc` 后重新运行，测试会检查入库的头文件与生成结果一致。`sb2000.inc` 里符号的行尾注释，会变成宏上方的 `/** */` 文档注释，编辑器悬停时显示；分组标题变成普通的 `/* */` 注释。
- 新增的服务先在 `sb2000.inc` 里加符号（功能号、子功能号、参数与结果单元、出错码），再重新生成；各模块头文件里的函数用 `/** */` 与 `@param`、`@return`、`@syscall` 写文档。
- [symbols-reference.md](../vscode/targets/sb2000/symbols-reference.md) 是符号的整本参考文档，由 `node vscode/tools/gen/gen-sb2000-symbols-doc.mjs` 从 `sb2000.inc` 生成：按分节列出每个符号的汇编名、C 名（`SB_` 前缀）、值与说明，说明只来自 `sb2000.inc` 的行尾注释，不手写。改 `sb2000.inc` 后依次运行 `gen-sb2000-header.mjs` 与它，测试会核对入库的文档与生成结果一致。
- [examples-source.md](../vscode/targets/sb2000/examples-source.md) 是示例程序的源码文档，由 `node vscode/tools/gen/gen-sb2000-examples-doc.mjs` 从 `apps/sb2000/examples/<名>/` 的 `fcdev.json` 与 `src/` 生成：每个示例一节，写程序名并附完整源码，说明只来自源码文件头的注释。新增或修改示例后重新运行，测试会核对；示例的顺序在脚本的 `EXAMPLE_ORDER` 里，没列出的按名字排在最后；示例的作用与用法写在使用文档 sb2000/01-开发指南 第 10 节。

### 2.4 运行库的测试

运行库的每个函数都在模拟器里测过：`vscode/test/real-emulator/sb2000-library.test.ts` 按模块运行 `vscode/test/fixtures/sb2000/` 下的测试程序（`system.c`、`memory.c`、`text.c`、`input.c`、`file-read.c`、`file-write.c`、`dir.c`、`disk.c`、`math.c`、`sound.c`、`display.c`、`peripheral.c`，以及直接操作硬件的 `dma.c`、`ppu.c`、`timer.c`，以及换页的 `bank.c`、`bank-pages.c`、`bank-top.c`），公共部分是 `vscode/test/support/real-emulator.ts`（`Sb2000Session`、`startSb2000Program`）与 `sb-test.h`、`sb-test.c`。测试程序用 `SB_CHECK`、`SB_CHECK_EQ` 记录检查结果，结束时调用 `sb_test_done`，需要宿主操作（按键、手柄、鼠标）时调用 `sb_test_sync` 停下等脚本；脚本读出结果并断言，文件与磁盘类测试还把镜像读回，用独立的 FAT12 解析核对。测试经 Ember 的调试服务运行：`real-emulator.ts` 随机取空闲端口启动 Ember，依次添加 BIOS（环境变量 `FCDEV_TEST_FIRMWARE`，没有时用仓库里的 `ember/roms/sb2000_bios.rom`）、开机、放入镜像，运行到 SB-DOS 询问日期，回车跳过后输入程序名；按键用 `input.key`，手柄与鼠标用 `input.pad`、`input.mouse`，读内存用 `inspector.readMemory`，存回镜像用 `media.floppySave`，截图用 `output.screenshot`，结束时只结束自己启动的 Ember。需要 Ember（环境变量 `FCDEV_TEST_EMULATOR`）与 cc65，缺一整组跳过。

停靠点用写断点实现：`sb_test_done`、`sb_test_sync` 往全局变量 `sb_test_stop` 写 1、2，脚本对这个地址设写断点（`inspector.addBreakpoint kind=write`），再读它的值判断停在哪里。不对函数入口设执行断点，是因为 DOS 外壳的某个等待循环可能正好经过同一地址，每转一圈停一次，模拟器几乎不前进（实测遇到过，表现为程序像是没启动）。窗口里的文件头不是 `AA 55` 时的停止（DOS 外壳写同一地址）会被忽略，`crt0.s` 清 `BSS` 时写的 0 也会被忽略。

接口检查与参考文档的测试在 `vscode/tools/test/sb2000-api.test.mjs`，命令“FCDEV：查询 C 接口”的测试在 `vscode/test/logic/c-api/target-c-api-service.test.ts` 与 `vscode/test/shared/c-api/api-functions.test.ts`。

## 3. NES

[vscode/targets/nes](../vscode/targets/nes) 的运行库很小：

- `src/fcnes.s` 编成 `lib/fcnes.lib`（`nes_*` 函数），头文件是 `include/fcnes.h`，汇编符号是 `asminc/fcnes.inc`。
- `src/nes-font.s` 编成 `lib/nes-font.o`（字库），`.incbin` 的搜索目录是 `chr`。
- 字库数据来自公有领域的 `font8x8_basic`（Daniel Hepper，源自 IBM 公共领域 VGA 字体），原文件保留在 `chr/font8x8_basic.h`，已转成 `chr/ascii-8x8.chr`（ASCII `$20` 到 `$7F` 的 8×8 字模，共 1536 字节）。

## 4. 步步高（BBG）

[vscode/targets/bbg](../vscode/targets/bbg) 的运行库是汇编库，C 库与头文件还没有做。使用说明见 [bbg/01-开发指南](../vscode/docs/bbg/01-开发指南.md) 第 4 节。

### 4.1 源码组织

- 一个函数一个源文件，放在 `src/lib/<模块>/` 下，文件名是函数名把下划线换成连字符（如 `file/bbg-file-open.s`），模块有 `dos`、`file`、`bios`、`text`；每个文件有文件头，标号前有 `; 函数名`、`;   说明：`、`;   入口：`、`;   出口：` 四行注释。库内部的函数与单元以 `bbgi_` 开头：`src/lib/bbgi-zeropage.s`（零页参数单元 `bbg_arg0`、`bbg_arg1` 与内部单元）、`src/lib/file/bbgi-file-call.s`（文件调用的公共入口）。
- `lib-build.json` 的 `libraries` 把 `src/lib/` 编成 `lib/bbg.lib`，`objects` 把 `src/crt0.s` 编成 `lib/crt0.o`；`node vscode/tools/build/build-libs.mjs bbg` 构建，`target.json` 的 `libraries` 引用它。
- 调用约定、各函数的入口与出口见 [api-reference.md](../vscode/targets/bbg/api-reference.md)（由 `node vscode/tools/gen/gen-bbg-api-doc.mjs` 从源码注释生成，末尾有 DOS、文件、BIOS 功能号的覆盖表）。

### 4.2 符号文件

- 符号只在 `machines/bbg/src/include/` 下的 `system-entries.inc`、`bios-calls.inc`、`dos-calls.inc` 里改（它们也是反汇编工程的符号集，行尾注释写含义与验证状态）；[asminc/bbg.inc](../vscode/targets/bbg/asminc/bbg.inc) 由 `node machines/bbg/tools/gen-bbg-inc.mjs` 把这三个文件与库函数的 `.global` 声明合并生成，不手工修改。改了符号或增删库函数后重新生成，接口检查会核对。
- 符号参考文档 `machines/bbg/docs/api/symbols-reference.md` 由 `machines/bbg/tools/gen-symbols-doc.mjs` 生成。

### 4.3 接口检查与不封装清单

- [api-unwrapped.json](../vscode/targets/bbg/api-unwrapped.json) 登记没有封装的功能号及原因，分 `dos`、`file`、`bios` 三类，键是功能号的十进制数。`node vscode/tools/check/check-bbg-api.mjs` 检查：每个函数的文件名与说明注释合规、有且只有一处定义、有测试程序用到它，`bbg.inc` 与源码一致；DOS 功能号（不含 `DOS_ENTRY`）、文件功能号（不含 `FILE_ENTRY`）与 `bios-calls.inc` 里“BIOS 1.0 实现的功能号”一节的每个功能号，要么被某个函数的源码引用了它的符号名，要么在清单里写明原因，两者不能同时成立。
- 测试在 `vscode/tools/test/bbg-api.test.mjs`，同时核对入库的 `api-reference.md` 与生成结果一致。

### 4.4 运行库的测试

`vscode/test/real-emulator/bbg-library.test.ts` 按模块运行 `vscode/test/fixtures/bbg/` 下的测试程序（`bios.s`、`file.s`、`text.s`、`dos.s`、`run.s`）：整机用 Ember 的 `bbg1` 机型、`ember/roms/bbg1_bios.rom` 与 `BBGDOS.IMG`（程序放进它的副本），公共部分是 `vscode/test/support/real-emulator.ts` 的 `startBbgProgram` 与 `bbg-test.inc`、`bbg-test.s`。需要 Ember（环境变量 `FCDEV_TEST_EMULATOR`）与 cc65，固件取环境变量 `FCDEV_TEST_BBG_FIRMWARE`，没有时用仓库里的；缺一整组跳过。

- 检查结果：测试程序用 `CHECK_` 开头的宏记录，`bbg_test_count`、`bbg_test_ok`、`bbg_test_line`（检查编号）、`bbg_test_value`（实际值）由脚本读出；编号在同一个程序里唯一，失败时按“检查 N”报告。
- 停靠点：与 SB2000 不同，不设写断点，而是电平触发：`bbt_sync` 把 `bbg_test_stop` 写成 2 并等待脚本把它清零，`bbt_done` 写 1 后停住；脚本每运行 20 帧读一次这个单元（`runToStopPolled`），在 sync 处截图、按键，再调用 `resume` 让程序继续。不用断点是因为输入程序名之后、设断点之前，程序可能已经跑过了停靠点。
- 文字输出的内容用截图核对：每组先清屏，用库函数显示一次并停靠，再清屏，用 DOS 直接显示等价的字符串并停靠，两张截图必须相同。
- 文件类测试在系统盘的副本上读、建立、写、改名、删除文件与目录，并读写引导扇区（原样写回）；运行程序的测试（`run.s`）让测试程序运行自己的副本，副本建立 `CHILD.TXT` 后以退出码 7 返回。
