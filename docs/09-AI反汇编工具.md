# AI 反汇编工具

给 VS Code 的 Copilot 提供一套通用的 6502 反汇编工具：模型通过工具调用多轮完成“映像到可汇编源码工程”的全过程，并可连接 Ember 运行、调试、记录，补全静态分析看不到的部分。工具放在 `vscode/` 扩展里，用 VS Code 的语言模型工具接口注册，不使用 MCP。

本文是开发计划，标为“拟定”的内容实现前先向用户确认。

## 1. 目标

输入一个 6502 程序的二进制映像：NES 卡带、学习机 BIOS、SB-DOS 的 `.EXE`，或任意平铺二进制。输出一个 ca65 汇编工程，满足：

- 重新汇编链接后与原映像逐字节一致。
- 符号有语义名称与说明，不是地址编号；代码有注释。
- 按功能分层拆成多个源文件（可选）。
- 能被 `fcdev build` 构建的目标，用 `fcdev build` 构建出的产物同样与原映像一致。

工具不绑定机型：地址布局、硬件符号与开机步骤都是传给工具的数据（第 5 节）。

## 3. 与现有部分的关系

| 现有部分 | 关系 |

| `machines/sb2000/disassembly/tools` | SB2000 BIOS 专用的命令行脚本；本工具的目标描述与回读思路可参考它的做法，但不引用它的代码 |
| Ember 调试服务 | 本工具经 SDK 调用其中的运行、单步、断点、内存、反汇编、CDL、指令跟踪、调用记录、截图、输入请求 |
| `vscode/src/shared/assembly/ca65-parser.ts` | 解析符号集文件（`.inc`）里的常量与行尾说明，直接复用 |
| `FcdevCliRunner`、`locateFcdevScript` | 找到工作区里安装的 fcdev，取得工具链位置 |

## 4. 工作模型

工具修改的对象是“反汇编工程”，不是源码文本。源码由工程加映像生成，每次生成结果确定，可重复。

### 4.1 工程内容

| 项 | 内容 |
| --- | --- |
| 映像 | 源文件路径、大小与摘要（摘要变化时提示工程已过期） |
| 布局 | 一组段：段号、文件偏移、长度、CPU 地址、可选的 bank 号、只读或可写；同一个 CPU 地址窗口可以有多段（换页） |
| 入口 | 地址（段号加 CPU 地址）、来源（向量、手工、跟踪、CDL、调用记录）、说明 |
| 区域 | 按段内偏移标注类型：`code`、`bytes`、`words`（地址表）、`string`、`graphics`、`padding`、`unknown`，以及每种类型的参数（每行字节数、字符串编码、表项含义） |
| 符号 | 名称、地址、种类（过程、标签、变量、常量、数据）、说明、所属模块、是否自动命名 |
| 注释 | 块注释与行尾注释，按地址 |
| 操作数提示 | 某条指令的操作数如何写：符号、低字节、高字节、十进制、二进制、字符、符号加偏移 |
| 模块 | 功能分层：名称、说明、包含的地址范围；每个模块生成一个 `.s` 文件 |
| 符号集 | 引用的硬件符号文件（`.inc`），生成时复制到工程的 `include/` 目录（见第 12 节） |

自动命名用 `sub_`、`loc_`、`data_`、`var_` 加地址，并标记为自动；进度报告把它们算作未完成。

### 4.2 生成的工程

```text
<工程目录>/
  disasm.json         工程文件
  src/<模块>.s        每个模块一个源文件
  include/            符号集与生成的符号常量
  link.cfg            由布局生成的链接配置
  verify/             回读用的目标文件与产物（不入库）
```

生成规则保证逐字节一致：

- 绝对寻址的操作数落在零页时，用 `a:` 强制绝对寻址，不让 `ca65` 缩成零页寻址。
- 官方指令之外的操作码、与 `ca65` 的编码不一致的字节，一律输出 `.byte`，并在注释里写出反汇编文字。
- 分支与跳转目标落在指令中间时写成“符号加偏移”，落在数据里时在该处切开数据并生成符号。
- 长重复字节用 `.res 数量, 值`，其余数据按区域参数输出 `.byte`、`.word`、字符串。

### 4.3 地址与换页

静态分析里的地址是“段号加 CPU 地址”，不只是 CPU 地址，所以同一个窗口里不同 bank 的代码不会混在一起。从一个窗口跳到另一个可换页窗口时，目标 bank 追踪不出来，工具把它登记为“待确认的跨 bank 转移”，由模型通过运行记录或手工入口补上。

## 5. 通用性

“不绑定机型”的含义：核心逻辑层只处理布局、区域、符号，代码里不出现机型名与文件格式名。差异只在三处，都以数据传入：

| 差异 | 做法 |
| --- | --- |
| 字节怎么对应到 CPU 地址 | 格式解析器把文件解析成布局。解析器是独立的小模块，目前计划有 `flat`（平铺，调用时给出布局）、`ines`（NES）、SB-DOS 程序；新格式只需新增一个解析器 |
| 硬件寄存器叫什么 | 符号集文件，格式同 ca65 的 `.inc`；NES 与 SB2000 的符号集直接取自 fcdev 目标（`fcnes.inc`、`sb2000.inc`） |
| 开机与载入步骤 | 目标描述里的启动步骤：运行若干帧、按键序列、载入文件；SB2000 的步骤是开机后跳过日期与时间、输入程序名 |

“目标描述”是一个 JSON：名称、格式解析器、符号集、启动步骤。内置 NES 与 SB2000 两份，其余由用户或模型在工程里自带。结构检查保证 `logic` 层不出现机型判断。

## 6. 工具清单

工具名用 `disasm_` 与 `emu_` 前缀，每个工具声明 `toolReferenceName`。每次返回的数据都有上限，列表类工具带 `limit` 与游标，先给摘要，再给明细。

### 6.1 工程与映像

| 工具 | 作用 |
| --- | --- |
| `disasm_open` | 新建或打开工程：映像路径加格式，或加布局、或加目标描述 |
| `disasm_status` | 进度报告：各类型区域的字节占比，自动命名符号数，无注释例程数，未解析的间接跳转与跨 bank 转移，最近一次回读的结果与是否过期 |
| `disasm_layout` | 查看或修改布局 |
| `disasm_hex` | 十六进制与字符视图，可带符号与区域标注 |
| `disasm_find` | 搜索字节序列、操作码模式、文本 |

### 6.2 分析

| 工具 | 作用 |
| --- | --- |
| `disasm_trace` | 从入口静态追踪，更新区域，返回新增的指令数、例程数与警告 |
| `disasm_list` | 按类别列出：入口、例程、未解析间接跳转、未识别区域、自动命名符号、无注释例程 |
| `disasm_view` | 带当前符号与注释的反汇编，按地址范围或例程 |
| `disasm_xrefs` | 某地址或符号的引用，区分读、写、调用、跳转、取地址 |
| `disasm_routine` | 一个例程的上下文：代码、调用者、被调用者、读写的地址及符号、可能的入口与出口寄存器 |
| `disasm_callgraph` | 调用图，按深度限制 |
| `disasm_detect` | 识别候选：地址表、字符串、图形数据、填充；只返回候选与依据，不修改工程 |
| `disasm_reference` | 查询 6502 指令与寻址方式、符号集里的符号 |

### 6.3 编辑

| 工具 | 作用 |
| --- | --- |
| `disasm_apply` | 批量编辑：定义与重命名符号、标注区域、加注释、操作数提示、归入模块、增删入口；一次调用可含多项，任何一项出错整批不生效 |
| `disasm_symbols` | 导入符号集文件，列出与搜索符号 |

### 6.4 生成与校验

| 工具 | 作用 |
| --- | --- |
| `disasm_generate` | 生成源码工程 |
| `disasm_verify` | 回读校验；不一致时给出第一处差异的偏移、地址，以及所在的符号与区域 |
| `disasm_build` | 用 `fcdev build` 构建并与原映像比较（仅限 fcdev 支持的目标） |

### 6.5 模拟器

| 工具 | 作用 |
| --- | --- |
| `emu_connect` | 连接已运行且开启了调试服务的 Ember；找不到时说明如何开启 |
| `emu_launch` | 经 `fcdev run --debug` 启动 Ember（拟定，阶段 5 确认可行后做） |
| `emu_load` | 装入映像、BIOS 或软盘，并执行目标描述的启动步骤 |
| `emu_run` | 运行指定帧数，或直到断点；等待结束并返回原因与寄存器 |
| `emu_break` | 添加、列出、删除断点（执行、读、写） |
| `emu_step` | 按指令或帧单步 |
| `emu_inspect` | 读寄存器与状态，读写内存，反汇编，解析 CPU 地址对应的存储区与偏移（用于确定 bank 布局） |
| `emu_screen` | 截图，以图像返回 |
| `emu_input` | 按键、手柄、鼠标，带按下与松开的帧数 |
| `emu_record` | 开始与结束指令跟踪、CDL、调用记录，返回记录编号 |
| `disasm_import_record` | 把记录导入工程：执行过的地址作为入口，CDL 的代码与数据标记作为区域依据 |

## 7. 反汇编工作流

随扩展提供 Copilot 指令、skill 与自定义 agent“6502 反汇编工程师”，规定步骤与每步的完成标准：

| 步骤 | 做什么 | 完成标准 |
| --- | --- | --- |
| 1 识别 | 打开映像，确定布局与目标，导入符号集 | 布局的每个字节都在某一段里，向量与入口已登记 |
| 2 追踪 | 静态追踪；有模拟器时运行并导入记录，再追踪 | 未解析的间接跳转与跨 bank 转移都已处理，或写明无法确定的原因 |
| 3 区域分类 | 识别并确认地址表、字符串、图形数据、填充 | 没有 `unknown` 区域，或每处都写明原因 |
| 4 命名 | 从被引用最多的例程与变量开始，用语义名称替换自动命名 | 自动命名符号数为 0 |
| 5 注释 | 给例程写说明，给关键指令写行尾注释，给硬件访问写含义 | 每个例程有说明 |
| 6 分层 | 按功能划分模块 | 每个例程属于一个模块 |
| 7 生成与校验 | 生成源码并回读 | 回读一致；任何后续编辑之后重新校验 |
| 8 构建 | 目标支持时用 `fcdev build` 构建 | 产物与原映像一致 |

agent 的指令还写明：命名与注释要依据代码行为、硬件资料与运行观察，没有依据时标注“未确认”而不是猜；每做完一批编辑就看一次 `disasm_status`。

## 8. 目录与分层

按 `vscode/` 现有分层，在各层新增 `disassembly` 功能目录；具体类只在 `bootstrap/extension.ts` 里创建。

| 目录 | 内容 |
| --- | --- |
| `src/contracts/disassembly` | 工程存取、映像读取、工具链运行、模拟器会话的接口，以及数据类型 |
| `src/shared/disassembly` | 6502 指令表（256 个操作码）与解码、布局与区域模型、格式解析器、目标描述的校验、符号集读取 |
| `src/logic/disassembly` | 静态追踪、区域识别、交叉引用、源码生成、校验流程、进度报告、工程服务 |
| `src/infra/disassembly` | 工程文件读写、映像文件读取、`ca65`/`ld65` 调用、Ember 会话（经 SDK） |
| `src/entry/disassembly` | 工具注册：每个工具一个文件，含输入检查、调用服务、结果格式化 |
| `src/bootstrap` | 组装根 |
| `skills/` 与 agent 文件 | 第 7 节的指令、skill 与 agent |

## 9. 安全与错误

- 工程文件与生成文件只写工程目录；工具收到的路径先规范化，必须在工程目录或工作区内，否则拒绝。
- 映像文件在工作区外时，工具调用前由 `prepareInvocation` 提示确认。写文件、写模拟器内存、启动进程的工具都带确认提示。
- 启动 `ca65`、`ld65`、`fcdev` 都不经 shell，带超时；超时与失败的输出放进工具结果，并写入日志。
- 连接 Ember 只用端点文件或用户给出的地址与令牌；令牌不写入日志与工具结果。

## 11. 开发计划

按依赖顺序分 8 个阶段，每阶段完成并验证后再进入下一阶段。

| 阶段 | 范围 | 完成标准 | 验证 |
| --- | --- | --- | --- |
| 1 基础 | 指令表与解码；布局模型；`flat`、`ines` 解析器；十六进制视图 | 指令表与 `ca65` 的编码逐条一致 | 指令表测试 |
| 2 分析 | 静态追踪（含 bank 窗口）；区域模型；入口；交叉引用；间接跳转、地址表、字符串、图形、填充的识别 | 对 NROM 夹具，指令覆盖不少于 `fcdev disasm` | 夹具测试与对照 |
| 3 工程与生成 | 工程文件；符号、注释、操作数提示、模块；源码与链接配置生成；回读；进度报告；工具链位置的取得 | 任意字节序列回读一致 | 回读测试 |
| 4 工具层 | 工具注册与确认提示；工程、分析、编辑、生成校验四组工具；输出大小控制 | 在真实 VS Code 里 Copilot 能发现并调用 | 工具层测试与手动核对 |
| 5 模拟器 | 会话管理；运行、断点、单步、内存、截图、输入、记录；`disasm_import_record`；SDK 引用与打包方式 | 对运行中的 Ember 完成记录、导入、再追踪的闭环 | Ember 联调 |
| 6 目标描述 | NES 其他映射器（经 `inspector.resolve` 确定布局）；SB-DOS 程序与 BIOS 页的解析器；NES、SB2000 的符号集与启动步骤 | NES 与 SB2000 各有一个端到端例子 | 端到端测试 |
| 7 指令与 agent | Copilot 指令、skill、自定义 agent；示例工程 | 完整工作流在示例上跑通，回读一致 | 手动走一遍 |
| 8 收尾 | README、`CHANGELOG`、与 01、06、待办备忘等文档同步 | 文档与实现一致；`npm run check` 通过 | 检查清单 |

阶段 3 前核对的事项：

- `fcdev info --json` 是否给出 `ca65`、`ld65` 的位置，没有时的取得方式。
- SB-DOS 程序文件的头部与装入规则，以 `packages/fcdev/docs/sb2000/01-开发指南.md` 为准。
- `fcdev build` 对大小与布局的限制：NES 目前只有 NROM，SB2000 大程序用换页；`disasm_build` 的支持范围据此确定。
