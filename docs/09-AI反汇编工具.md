# AI 反汇编工具

给 VS Code 的 Copilot 提供一套通用的 6502 反汇编工具：模型通过工具调用多轮完成“映像到可汇编源码工程”的全过程，并可连接 Ember 运行、调试、记录，补全静态分析看不到的部分。反汇编核心放在 `vscode/` 扩展里，命令“反汇编映像文件”与工具共用；工具由扩展用 VS Code 的语言模型工具接口注册，不使用 MCP。

本文是工具的设计与开发记录，各项决策已经用户确认；各阶段的已知差异写在第 11 节。

## 1. 目标

输入一个 6502 程序的二进制映像：NES 卡带、学习机 BIOS、SB-DOS 的 `.EXE`，或任意平铺二进制。输出一个 ca65 汇编工程，满足：

- 重新汇编链接后与原映像逐字节一致。
- 符号有语义名称与说明，不是地址编号；代码有注释。
- 按功能分层拆成多个源文件（可选）。
- 能被扩展构建的目标，用构建任务构建出的产物同样与原映像一致。

工具不绑定机型：地址布局、硬件符号与开机步骤都是传给工具的数据（第 5 节）。

## 4. 工作模型

工具修改的对象是“反汇编工程”，不是源码文本。源码由工程加映像生成，每次生成结果确定，可重复。

### 4.1 工程内容

| 项 | 内容 |
| --- | --- |
| 映像 | 源文件路径、大小与摘要（摘要变化时提示工程已过期） |
| 布局 | 一组段：段号、文件偏移、长度、CPU 地址、可选的 bank 号、只读或可写；同一个 CPU 地址窗口可以有多段（换页） |
| 入口 | 地址（段号加 CPU 地址）、来源（向量、手工、跟踪、CDL、调用记录）、说明 |
| 区域 | 按段内偏移标注类型：`code`、`bytes`、`words`（地址表）、`string`、`graphics`、`padding`、`unknown`，以及每种类型的参数（每行字节数、字符串编码、表项含义） |
| 符号 | 名称、地址、种类（过程、标签、变量、常量、数据）、说明、所属模块、是否自动命名 |
| 注释 | 块注释与行尾注释，按地址 |
| 操作数提示 | 某条指令的操作数如何写：符号、低字节、高字节、十进制、二进制、字符、符号加偏移 |
| 模块 | 功能分层：名称、说明、包含的地址范围；每个模块生成一个 `.s` 文件 |
| 符号集 | 引用的硬件符号文件（`.inc`），生成时复制到工程的 `include/` 目录 |

自动命名用 `sub_`、`loc_`、`data_`、`var_` 加地址，并标记为自动；进度报告把它们算作未完成。

### 4.2 生成的工程

```text
<工程目录>/
  disasm.json         工程文件
  src/<模块>.s        每个模块一个源文件
  include/            符号集与生成的符号常量
  link.cfg            由布局生成的链接配置
  verify/             回读用的目标文件与产物（不入库）
```

生成规则保证逐字节一致：

- 绝对寻址的操作数落在零页时，用 `a:` 强制绝对寻址，不让 `ca65` 缩成零页寻址。
- 官方指令之外的操作码、与 `ca65` 的编码不一致的字节，一律输出 `.byte`，并在注释里写出反汇编文字。
- 分支与跳转目标落在指令中间时写成“符号加偏移”，落在数据里时在该处切开数据并生成符号。
- 长重复字节用 `.res 数量, 值`，其余数据按区域参数输出 `.byte`、`.word`、字符串。

### 4.3 地址与换页

静态分析里的地址是“段号加 CPU 地址”，不只是 CPU 地址，所以同一个窗口里不同 bank 的代码不会混在一起。从一个窗口跳到另一个可换页窗口时，目标 bank 追踪不出来，工具把它登记为“待确认的跨 bank 转移”，由模型通过运行记录或手工入口补上。

## 5. 通用性

“不绑定机型”的含义：核心逻辑只处理布局、区域、符号，代码里不出现机型名与文件格式名。差异只在三处，都以数据传入：

| 差异 | 做法 |
| --- | --- |
| 字节怎么对应到 CPU 地址 | 格式解析器把文件解析成布局。解析器是独立的小模块，目前计划有 `flat`（平铺，调用时给出布局）、`ines`（NES）、SB-DOS 程序；新格式只需新增一个解析器 |
| 硬件寄存器叫什么 | 符号集文件，格式同 ca65 的 `.inc`；NES 与 SB2000 的符号集直接取自 FC Dev 目标（`fcnes.inc`、`sb2000.inc`） |
| 开机与载入步骤 | 目标描述里的启动步骤：接入扩展设备、运行若干帧、按键序列、载入文件；SB2000 的步骤是开机后跳过日期与时间、输入程序名。Ember 的 Family BASIC 键盘每次启动都是未接入、不保存，运行 Family BASIC 这类需要它的程序时，目标描述要在载入前写一步“接入 Family BASIC 键盘”（调试服务的 `input.setFamilyKeyboard`），不依赖 Ember 的设置 |

“目标描述”是一个 JSON（`profile.json`）：名字、符号集、图形数据端口、若干种“输入”，每种输入写明映像格式（及格式选项）与启动步骤。读取与检查在 扩展的 `shared/targets/target-profile.ts`，反汇编读格式、符号集与端口，模拟器读启动步骤。内置 `nes` 与 `sb2000` 两份，在扩展里的 `targets/<名>/profile.json`；其余由用户或模型在工程里自带（`disasm_open` 与 `emu_load` 的 `target` 给路径，工具层按工作区规则检查）。结构检查保证核心里不出现机型判断。

```json
{
  "name": "sb2000",
  "symbolSets": ["asminc/sb2000.inc"],
  "graphicsPorts": ["$2007"],
  "defaultInput": "program",
  "inputs": {
    "program": { "format": "sbdos", "boot": [ { "step": "machine", "machine": "sb2000" }, { "step": "run", "frames": 900 }, { "step": "key", "code": "Enter" } ] },
    "bios": { "format": "paged", "formatOptions": { "pageSize": 4096, "fixed": [ { "firstPage": 4, "pageCount": 4, "address": 49152 } ], "window": { "address": 32768, "pageCount": 4 } } }
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `symbolSets` | 符号集文件，路径相对描述文件；`disasm_open` 自动登记 |
| `graphicsPorts` | 图形数据端口的 CPU 地址；工程记下它，`disasm_detect` 据此识别经端口写入的图形数据 |
| `inputs.<名>.format` 与 `formatOptions` | 映像格式名（`flat`、`ines`、`sbdos`、`paged`）与格式选项，选项写进工程的格式记录 |
| `inputs.<名>.boot` | 启动步骤（给 `emu_load` 用）：`familyKeyboard`（接入或断开 Family BASIC 键盘）、`cartridge`（载入调用者给的 `file`）、`machine`（整机开机，用调用者给的 `firmware` 与 `diskImage`）、`run`（运行若干帧）、`key`（按下并松开一个键）、`type`（输入文字，`{program}` 等占位符用调用者给的同名参数代入） |

内置的输入：`nes` 有 `cartridge`、`family-basic`（先接入 Family BASIC 键盘再载入卡带）；`sb2000` 有 `program`（SB-DOS 程序，默认：固件开机、放入磁盘、跑 900 帧、回车两次跳过日期与时间、输入程序名）、`bios`（学习机的 BIOS 文件，用来开机运行要研究的 BIOS）。

分页 ROM 的初始布局只是猜测：固定映射按选项给出，其余的页按“页号对窗口页数取余”放进窗口；实际每段代码在窗口里的位置，要用 Ember 的地址解析（`emu_inspect` 的 `resolve`）核实，再用 `disasm_layout` 改。NES 内置支持映射器 0、1、2、3、4、7（按默认模式划分），其他映射器同样用 `resolve` 查出各窗口对应的 PRG 偏移，再用平铺格式的 `segments` 给出布局。

## 6. 工具清单

工具名用 `disasm_` 与 `emu_` 前缀，每个工具声明 `toolReferenceName`。每次返回的数据都有上限，列表类工具带 `limit` 与游标，先给摘要，再给明细。工具由扩展注册，能力由扩展里的核心提供（第 8 节）。

### 6.1 工程与映像

| 工具 | 作用 |
| --- | --- |
| `disasm_open` | 新建或打开工程：映像路径加格式、或加布局、或加目标描述（`target`、`input`） |
| `disasm_status` | 进度报告：各类型区域的字节占比，自动命名符号数，无注释例程数，未解析的间接跳转与跨 bank 转移，最近一次回读的结果与是否过期 |
| `disasm_layout` | 查看或修改布局 |
| `disasm_hex` | 十六进制与字符视图，可带符号与区域标注 |
| `disasm_find` | 搜索字节序列、操作码模式、文本 |

### 6.2 分析

| 工具 | 作用 |
| --- | --- |
| `disasm_trace` | 从入口静态追踪，更新区域，返回新增的指令数、例程数与警告 |
| `disasm_list` | 按类别列出：入口、例程、未解析间接跳转、未识别区域、自动命名符号、无注释例程 |
| `disasm_view` | 带当前符号与注释的反汇编，按地址范围或例程 |
| `disasm_xrefs` | 某地址或符号的引用，区分读、写、调用、跳转、取地址 |
| `disasm_routine` | 一个例程的上下文：代码、调用者、被调用者、读写的地址及符号、可能的入口与出口寄存器 |
| `disasm_callgraph` | 调用图，按深度限制 |
| `disasm_detect` | 识别候选：地址表、字符串、图形数据、填充；只返回候选与依据，不修改工程 |
| `disasm_reference` | 查询 6502 指令与寻址方式、符号集里的符号 |

### 6.3 编辑

| 工具 | 作用 |
| --- | --- |
| `disasm_apply` | 批量编辑：定义与重命名符号、标注区域、加注释、操作数提示、归入模块、增删入口；一次调用可含多项，任何一项出错整批不生效 |
| `disasm_symbols` | 导入符号集文件，列出与搜索符号 |

### 6.4 生成与校验

| 工具 | 作用 |
| --- | --- |
| `disasm_generate` | 生成源码工程 |
| `disasm_verify` | 回读校验；不一致时给出第一处差异的偏移、地址，以及所在的符号与区域 |
| `disasm_build` | 用构建服务构建并与原映像比较（仅限扩展支持的目标） |

### 6.5 模拟器

| 工具 | 作用 |
| --- | --- |
| `emu_connect` | 连接已运行且开启了调试服务的 Ember；找不到时提示用 `emu_launch` 启动设置里指定的 Ember |
| `emu_launch` | 启动 Ember 并开启调试服务（调试模式、独立的用户数据目录），不载入任何东西 |
| `emu_status` | 查看会话：是否已连接、端口、运行状态、正在进行的记录；`close` 关闭会话，再加 `terminate` 才结束自己启动的 Ember |
| `emu_load` | 装入映像、BIOS 或软盘，并执行目标描述的启动步骤 |
| `emu_run` | 运行指定帧数，或直到断点；等待结束并返回原因与寄存器 |
| `emu_break` | 添加、列出、删除断点（执行、读、写） |
| `emu_step` | 按指令或帧单步 |
| `emu_inspect` | 读寄存器与状态，读写内存，反汇编，解析 CPU 地址对应的存储区与偏移（用于确定 bank 布局） |
| `emu_screen` | 截图，以图像返回 |
| `emu_input` | 按键、手柄、鼠标，带按下与松开的帧数；接入或断开 Family BASIC 键盘 |
| `emu_record` | 开始与结束指令跟踪、CDL、调用记录，返回记录文件 |
| `disasm_import_record` | 把记录导入工程：指令轨迹、调用记录里执行过的地址作为入口；CDL 的代码标记作为入口，只被当数据读取的标记作为区域依据 |

模拟器工具共用一个会话（整个扩展主机进程里只有一个到 Ember 的连接），运行与单步返回时机器总是暂停的并带 CPU 状态。跟踪与 CDL 的文件写在 Ember 的调试输出目录，`emu_record` 结束时返回完整路径；`disasm_import_record` 按这个路径读取（允许在工作区之外，确认里写出）。调用记录要用 `stackBytes` 至少 2，导入时才能核实调用者。记录、导入、再追踪的闭环：`emu_load` 载入程序，`emu_record` 开始，`emu_run` 与 `emu_input` 让程序跑到要覆盖的代码，`emu_record` 结束得到文件，`disasm_import_record` 导入，`disasm_trace` 重新追踪。

## 7. 反汇编工作流

随扩展提供 Copilot 指令、skill 与自定义 agent“6502 工程师”（同时覆盖开发与模拟器调试），规定步骤与每步的完成标准：

| 步骤 | 做什么 | 完成标准 |
| --- | --- | --- |
| 1 识别 | 打开映像，确定布局与目标，导入符号集 | 布局的每个字节都在某一段里，向量与入口已登记 |
| 2 追踪 | 静态追踪；有模拟器时运行并导入记录，再追踪 | 未解析的间接跳转与跨 bank 转移都已处理，或写明无法确定的原因 |
| 3 区域分类 | 识别并确认地址表、字符串、图形数据、填充 | 没有 `unknown` 区域，或每处都写明原因 |
| 4 命名 | 从被引用最多的例程与变量开始，用语义名称替换自动命名 | 自动命名符号数为 0 |
| 5 注释 | 给例程写说明，给关键指令写行尾注释，给硬件访问写含义 | 每个例程有说明 |
| 6 分层 | 按功能划分模块 | 每个例程属于一个模块 |
| 7 生成与校验 | 生成源码并回读 | 回读一致；任何后续编辑之后重新校验 |
| 8 构建 | 目标支持时构建 | 产物与原映像一致 |

agent 与 skill 还写明：开始前收集映像路径、工程目录（没给时取工作区下的 `disasm/<映像主名>`）与映像种类；工程已存在时从 `disasm_status` 显示的第一个未达标步骤继续；命名与注释要依据代码行为、硬件资料与运行观察，没有依据时标注“未确认”而不是猜；每做完一批编辑就看一次 `disasm_status`，完成标准用它的数字判断；模拟器的起步与收尾按 skill `ember-emulator` 做。

文件位置与声明见 [06-VS Code扩展](06-VS%20Code扩展.md) 第 6.6 节；skill 把每步写成“做什么、用哪些工具、怎么判断做完了”，输入种类与目标的打开方式、区域类型与参数、记录闭环、提示形式放在它的 `references/` 里。

## 9. 安全与错误

- 工程文件与生成文件只写工程目录；工具收到的路径先规范化，必须在工程目录或工作区内，否则拒绝。
- 映像文件在工作区外时，工具调用前由 `prepareInvocation` 提示确认。写文件、写模拟器内存、启动进程的工具都带确认提示。
- 启动 `ca65`、`ld65` 与 Ember 都不经 shell，带超时；超时与失败的输出放进工具结果，并写入日志。
- 连接 Ember 只用端点文件或用户给出的地址与令牌；令牌不写入日志与工具结果。
- Ember 的位置只来自用户设置，模型不能指定。

## 11. 开发记录

反汇编工具按依赖顺序分阶段完成（命令行时代的阶段 0a 至 9，其后迁入扩展，见 [10-迁移到VS Code扩展计划](10-迁移到VS%20Code扩展计划.md)）。已知的差异与限制：

- 指令表与 `ca65` 的编码逐条一致；`ca65` 拒绝指针低字节为 `$FF` 的 `jmp (abs)`，生成时输出 `.byte`；跨块的分支与非官方操作码同样输出 `.byte`。
- 取地址类交叉引用是推测（标 `likely`）；图形数据只在目标描述给出图形数据端口时才识别。
- 生成的源码要用 `ca65 -I include` 汇编；块名 `SEG<段号>_<偏移>`，段在映像里首尾相接时所有段输出到同一个文件，否则每个段输出 `seg<段号>.bin`。
- 命令“反汇编映像文件”的输出是工程目录（`disasm.json`、`src/main.s`、`include/`、`link.cfg`），不复制映像；映像格式按文件头判断 iNES 或平铺二进制，SB-DOS 程序与目标描述经工具 `disasm_open` 指定。
- 工具共 36 个：反汇编 19 个（`disasm_build` 构建的是用户或模型按生成的源码整理出的 FC Dev 项目，不自动把生成的工程转成 FC Dev 项目）、模拟器 11 个（`emu_status` 查看和关闭会话）、FC Dev 6 个；反汇编核心有 18 个操作，每次调用从工程目录重新读，没有会话状态；模拟器会话整个扩展主机进程只有一个。
- 截图作为图像部分返回需要较新的 VS Code；`emu_load` 的启动步骤按目标描述执行。
- NES 内置映射器 0、1、2、3、4、7（按默认模式，MMC3 的可换 bank 只放 `$8000`），其他映射器要先用 `resolve` 查出布局再用平铺格式；SB-DOS 程序的单窗口与多页布局都已解析；学习机 BIOS 用 `paged` 格式，初始布局只是猜测，要用 `resolve` 核实；真实的 512K BIOS 能新建工程并追踪（3649 条指令），整份 BIOS 的回读没有跑。
- 指令、skill 与 agent 三类贡献点要较新的 VS Code，低版本会忽略；agent 里 `扩展标识/工具引用名` 的写法与在 Copilot 聊天里走一遍示例，要在真实 VS Code 里核对（已登记到待办备忘）。

实现前核对的事项：SB-DOS 程序文件的头部与装入规则，以使用文档 [sb2000/01-开发指南](../vscode/docs/sb2000/01-开发指南.md) 为准；构建对大小与布局的限制（NES 目前只有 NROM，SB2000 大程序用换页），`disasm_build` 的支持范围据此确定。
