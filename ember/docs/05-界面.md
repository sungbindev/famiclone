# 界面

Ember 的界面：窗口布局、页面、菜单、状态栏、画面显示和界面状态的保存。界面只做外壳和显示，运行与数据都在 C++ 核心，见 [01-软件架构设计.md](01-软件架构设计.md)。界面不做调试窗口，调试能力只经 [04-调试服务.md](04-调试服务.md) 开放。

界面效果先做成静态原型确认，见第 10 节。

状态说明同 01。

## 1. 决策

| 决策项 | 结论 | 状态 |
| --- | --- | --- |
| 调试窗口 | 界面不做；普通用户看不到调试功能 | 已定 |
| 外壳 | 沿用如见客户端的外壳：标题栏、活动栏、边栏、标签页、页面区、底部面板、状态栏；布局与尺寸取值同如见 | 拟定 |
| 组件来源 | 外壳与页面的全部组件与令牌来自 rujian-ui-kit，客户端不另写组件、不自定义令牌；缺少的组件先加到组件库 | 拟定 |
| 右边栏 | 只做一件事：查看与管理软驱里的文件，见 4.6；默认折叠，软驱里有盘片时才能打开 | 已定 |
| 设备 | 只有边栏，没有页面和标签；载入软盘、磁带等操作不切换页面区，画面一直在右边 | 已定 |
| 开机入口 | “文件”菜单的“开机…”先选机型：经典 FC 再选 NES 文件，整机机型直接用已设置的 BIOS 开机；“打开卡带…”按卡带清单的 `host` 自动装配主机，不选机型（目前只有 fc）；BIOS 在首选项的“机型与 BIOS”里添加，见 4.5 与第 5 节 | 已定 |
| 页面与对话框 | 要长时间停留、来回查看的内容做成页面；对话框只用于做完就关的操作，对话框都是独立的系统窗口 | 拟定 |
| 页面与模块 | 页面按模块登记，同如见：页面、菜单项、活动栏按钮、面板、状态项都由模块登记，外壳不写死入口 | 拟定 |
| 操作结果 | 操作结果与错误消息用通知；页面里只显示输入字段的校验提示 | 拟定 |
| 画面显示 | 核心输出完成颜色转换的帧缓冲，界面在 Worker 里用 WebGL 显示，负责比例、缩放；做界面前先测延迟与丢帧，见 01 第 7 节 | 已定 |
| 组件库位置 | `../../rujian-ui-kit`（`D:\GitCode\rujian-ui-kit`），开发与打包都直接引用本机源码 | 已定 |
| 主题 | 深色、浅色、跟随系统；在首选项的“外观”里改 | 拟定 |
| 语言 | 界面文字为中文 | 已定 |

## 2. 窗口布局

```text
┌───────────────────────────── 标题栏 ─────────────────────────────┐
│ 活动栏 │ 边栏 │ 标签栏                                      │ 右边栏 │
│        │      │ 页面区                                      │        │
│        │      │ 底部面板                                    │        │
└───────────────────────────── 状态栏 ─────────────────────────────┘
                                              通知固定在右下角，状态栏之上
```

| 区域 | 尺寸 | 内容 |
| --- | --- | --- |
| 标题栏 | 高 36px | 应用图标、名称、菜单；右侧为边栏、底部面板与右边栏的折叠按钮、系统窗口按钮 |
| 活动栏 | 宽 40px | 运行、卡带库、mapper 插件三个页面按钮，以及设备按钮（只打开设备边栏）；设备按钮的图标上有软驱指示灯，见 4.3 |
| 边栏 | 默认宽 240px | 当前页面声明的内容，或设备边栏；没有内容时不打开，折叠按钮置灰 |
| 标签栏 | 高 36px | 已打开的页面 |
| 页面区 | 其余空间 | 当前标签的页面 |
| 底部面板 | 默认高 160px | “消息”页签 |
| 右边栏 | 默认宽 340px | 软驱里的文件；与边栏等高，在页面区与底部面板的右侧；默认折叠，没有盘片时不能打开，不随页面切换 |
| 状态栏 | 高 26px | 左侧机器状态，右侧运行速度与服务状态 |

- 尺寸、颜色、交互状态全部取组件库的令牌，规则同如见的外壳文档。
- 面板向内展开与折叠，窗口大小不变：边栏、底部面板、右边栏占用页面区的空间，运行页的画面按页面区剩余空间等比缩放，不变形，所以画面会随面板开合变大变小。每次启动边栏、底部面板、右边栏都是关闭的。
- 窗口的最小尺寸是 656x605；宽度保证标题栏的图标、名称、四个菜单不被挤压或换行，菜单与右侧折叠按钮之间留出至少 48px 可拖动的空白，折叠按钮与系统窗口按钮之间留出距离；高度按画面框的 128:105 算出，使面板全部关闭时最小窗口下画面框四周的间距一样。窗口大小不记忆，每次启动都是这个最小尺寸（不恢复最大化），位置仍按上次保存的恢复。
- 边栏只放控件与简短的信息；列表和表格放在页面区；边栏里已有的按钮，页面区不再重复。右边栏是例外：它的内容就是一张文件表。
- 没有打开的页面时，页面区居中显示淡色标志和入口列表（开机、打开卡带、卡带库、设备、mapper 插件）；“开机”弹出和“文件”菜单里“开机…”一样的机型列表。

## 3. 页面与模块

| 页面 | 标识 | 所属模块 | 边栏 | 说明 |
| --- | --- | --- | --- | --- |
| 运行 | `run` | `runtime` | 有 | 机器的画面；边栏是机器信息和控制 |
| 卡带库 | `library` | `cartridges` | 有 | 卡带列表与匹配状态 |
| mapper 插件 | `mappers` | `mappers` | 有 | 插件列表与详情 |
| 首选项 | `preferences` | `preferences` | 无 | 全部设置；有自己的分组导航 |

- 单例页面，重复打开聚焦已有标签。“运行”页的标签没有关闭按钮（登记为不可关闭），其他页面可以关闭。表中的“标识”是页面在模块里的名字，登记时加模块名前缀，如“运行”页登记为 `runtime.run`。
- 设备不是页面：设备边栏由 `media` 模块登记，只经设备按钮或视图菜单的“设备”打开；打开它不新增标签，也不切换页面区。
- 切换页面（点标签、活动栏的页面按钮、视图菜单）时，边栏换成该页面的边栏；关闭当前标签时，设备边栏保持。
- 再点一次选中的活动栏按钮，折叠或展开边栏。
- 首选项页没有边栏，所以边栏自动关闭，不留空栏。
- 右边栏不是页面，也不属于边栏：它固定显示软驱的文件，由标题栏按钮、视图菜单的“右边栏”或 `Ctrl+Alt+B` 打开，切换页面时不变。

## 4. 页面

### 4.1 运行

边栏分三组：

| 分组 | 内容 |
| --- | --- |
| 机器 | 主机型号、卡带、mapper 插件、状态；只读；整机机型没有卡带，卡带显示“无（整机 BIOS）”，mapper 插件显示“—” |
| 控制 | 上电或断电、暂停或继续、软复位、硬复位 |
| 速度与声音 | 速度下拉（100%、50%、25%、200%、最快）、音量滑块与静音按钮 |

- 页面区只有画面，按比例居中显示，周围是黑底；画面左下角有“示意画面”仅在原型里出现，正式版没有。
- 电源与复位等按钮的可用状态：没有开机时全部置灰；断电时暂停与软复位置灰；硬复位只要已开机就可用。
- 画面上的提示：没有开机显示“未开机”，并指明去“文件”菜单的“开机…”（经典 FC 再选 NES 文件，整机机型用设置里添加的 BIOS）或“卡带库”；断电显示“已断电”；暂停显示“已暂停”。
- 机器带鼠标时，画面右下角提示“点击画面捕获鼠标，双击右键释放”。
- 实现范围（阶段 3b 与 3a-2）：页面区的画面已用 WebGL 实现（见第 7 节），放在外壳页面区里的“运行”页（`src/ui/runtime/`，模块 `runtime`）。阶段 3a-2 已做：边栏的机器（主机型号、卡带、mapper 插件、状态；没有卡带时卡带显示“无”，主机型号与 mapper 插件显示“—”）、控制（上电或断电、暂停或继续、软复位、硬复位，可用状态按上面的规则，按钮名称随状态在“上电”与“断电”、“暂停”与“继续”之间切换）与声音（静音按钮、音量滑块与数值；静音记住原音量）三组；画面上的“未开机”“已断电”“已暂停”提示（覆盖在画面区之上，不接收鼠标事件，不改变画面比例与键盘采集；没有开机与断电时是纯黑底，盖住画布里残留的上一帧，暂停时是半透明底，透出暂停的画面）；3b 画面下方的开发期操作条已删除，功能迁到边栏、菜单与快捷键（见第 5 节）。状态取自 `runtime.status`，收到 `runtime.stateChanged`、`cartridges.loaded` 事件以及核心进程重启（`onCoreStatusChange`）时重读，所以边栏没有打开时状态也是最新的；操作失败经通知给出，同时写一条消息（见第 6 节）。速度下拉待核心支持后做（核心目前没有速度请求），所以边栏第三组现在只叫“声音”；鼠标捕获与整机机型相关的提示（BIOS、鼠标）也没做。

### 4.2 卡带库

- 页面区是表格：名称、mapper、变体、主机型号、匹配的插件、大小、状态；状态为“可运行”或“缺少插件”。
- 双击一行运行；缺少插件时，用通知说明缺少哪个 mapper 号与变体；单击缺少插件的行，在表格下方的提示块里给出同样的说明和去处。
- 边栏：搜索框、状态筛选（全部、可运行、缺少插件）、“添加文件夹”按钮，以及已添加的库文件夹。
- 库保存的是用户的文件路径，见 01 第 9 节。
- 卡带库只放卡带（含学习卡，主机按清单的 `host` 自动装配，目前只有 fc）：学习机 BIOS 文件（mapper 171）没有匹配的插件，显示为“缺少插件”，不能在这里运行，要在“文件”菜单的“开机…”里选机型开机；选中这样的行时，提示块里写明这一点。

### 4.3 设备

设备只有边栏，没有页面和标签。点活动栏的设备按钮（或视图菜单的“设备”），边栏换成设备边栏，页面区和已打开的标签不变，所以载入软盘、磁带时运行画面一直在右边。设备的数量由当前主机型号决定，没有对应硬件的设备不显示或置灰。

设备边栏每个设备一张卡片，卡片样式同如见组件库的面板：带边框，标题行下有分割线，状态和按钮放在内容区：

| 设备 | 显示 | 按钮 |
| --- | --- | --- |
| 软驱 A、软驱 B | 盘片（镜像名或“空”）、状态（无盘片、空闲、读写中并带磁道）、写保护开关 | 载入镜像、取出、保存镜像 |
| 磁带机 | 磁带类型（数据磁带、声像磁带）、磁带（声音文件名或“空”）、状态（无磁带、已停止、播放中、录音中）、位置与进度；声像磁带再显示声音与画面两路电平 | 载入磁带、取出、播放、录音、停止 |
| 打印机 | 状态：空闲、打印中、打印完成 | 无 |

- “载入镜像”选择软盘镜像文件，“载入磁带”选择声音文件，都用系统的文件选择窗口。
- 没有盘片时，取出、保存镜像、写保护置灰；没有磁带时，取出、播放、录音置灰。磁带机播放或录音时不能载入或取出，要先停止。声像磁带只能播放，录音置灰；切换磁带类型会取出当前磁带。
- 打印机没有按钮，只显示实时状态：机器没有运行时为空闲，有数据时为打印中，输出一页后显示打印完成，下一页开始后回到打印中。每输出一页，用通知告知文件名；PNG 文件名按日期时间自动生成，不弹出保存窗口，保存位置在首选项的“打印机”里改。
- 介质的载入、取出与录放随时可以操作，与电源无关。
- 活动栏设备按钮的图标上有一个长方形的软驱指示灯，模拟真实软驱的读写灯：任一软驱正在读写时亮绿色并随读写闪动，空闲、无盘片、断电或暂停时是暗色；亮灭取自核心报告的软驱真实状态，界面不自己推测。
- 软盘里的文件在右边栏查看和管理，见 4.6。
- 实现（学习机阶段，代码在 `src/ui/media/`，登记见 06 第 3 节）：设备边栏里有软驱卡片与打印机卡片，没有磁带机卡片；软驱卡片显示“盘片”（镜像名，有未保存的修改时注明“（有未保存的修改）”，没有盘片是“空”）、“状态”（无盘片、空闲、读写中并带磁道）、“写保护”开关，按钮有“载入镜像”（经主进程的 `media.openFloppy`，弹出系统文件选择窗口）、“取出”、“保存镜像”；打印机卡片只有“状态”（空闲、打印中、打印完成）。小霸王 2000 目前只有一个软驱 A，所以只有软驱 A 一张卡片；没有开机或主机没有软驱时不显示卡片，只提示“没有设备：整机机型开机后才有软驱与打印机。”。
- 软驱与打印机的读写状态、磁道随机器运行不断变化，核心不推送，所以设备边栏显示期间每 500 毫秒读取一次（`media.floppyStatus`、`media.printerStatus`，内容没有变化时不重新渲染），隐藏后停止；盘片变化（`media.changed`）、电源或运行状态变化时立即重新读取。
- 操作结果写入底部面板的“消息”，失败时用通知给出核心返回的说明；打印机每输出一页，用通知告知“打印机输出了第 N 页：文件名”并写一条消息（`media.printed`），一页无法保存时用通知给出原因（`media.printFailed`）；这些由常驻组件接收，设备边栏没有打开时也会收到。
- 活动栏的“设备”是只有边栏的活动（外壳的 `ShellActivityDefinition.sideBar`）：点击后边栏换成设备边栏，页面区与标签不变；切到另一个标签后边栏回到页面自己的边栏；“视图”菜单的“设备”同样打开它。
- 本阶段没有做：磁带机卡片、活动栏设备按钮上的软驱指示灯（核心还没有上报读写灯的状态）、取出有未保存修改的盘片时的确认，登记在待办备忘。

### 4.4 mapper 插件

- 页面区是表格：名称、版本、匹配、主机型号、来源（预装、用户安装、开发目录）、状态；选中一行，下方显示清单摘要：标识、版本、发布者、匹配、主机型号、存储区、寄存器范围、状态声明。
- 边栏：搜索框、来源筛选、“安装插件”按钮。
- 预装插件只能停用，不能删除；用户安装的可以卸载，见 03 第 7 节。

### 4.5 首选项

左侧是分组导航，右侧是设置行（名称与说明在左，控件在右）。

| 分组 | 设置项 |
| --- | --- |
| 外观 | 主题 |
| 画面 | 画面比例（4:3、8:7）、缩放方式（适应窗口、整数倍）、显示全部 240 行 |
| 声音 | 缓冲大小（低延迟、标准、稳定）、启动时静音 |
| 输入 | 点击画面捕获鼠标；键位不在首选项里统一设置，由卡带的 mapper 脚本决定（以后需要用户自定义时，按主机型号或卡带分别覆盖，到时再设计） |
| 机型与 BIOS | 全部整机机型的 BIOS：添加、替换、移除，见下 |
| 调试服务 | 启用、端口、令牌（核心自动生成，可以改写，清空后重新生成）、调试输出目录（随写文件的请求一起做） |
| 打印机 | 图片保存位置（文本框加“选择”按钮；文件名自动生成，不可设置） |
| 路径 | 用户插件目录（只读）、开发中的插件目录 |

- 设置项由各模块登记，首选项模块汇总，规则同如见；首选项页不显示操作结果，改动立即生效并保存。
- 实现（阶段 3c）：设置项在核心里登记（`preferences` 模块提供 `PreferenceService`，其他模块取用它登记自己的设置项，取值保存在用户数据目录的 `config/preferences.json`，请求与事件见 04 第 4.8 节）；界面只经 `preferences.list`、`preferences.set`、`preferences.reset` 读取、修改与恢复默认，不自己保存任何设置。页面（`src/ui/preferences/`）左侧是分组导航，右侧是设置行（名称与说明在左，控件在右）：选择类用下拉框，开关用开关，整数用输入框（按回车或失焦提交，不是整数或超出范围时只把输入框标红并给出说明，不发请求）；修改立即保存，保存成功后才显示新值；取值与出厂默认值不同时，设置行右侧出现“恢复默认”；保存失败时用外壳通知给出核心返回的说明，控件保持原值；页面不显示操作结果。在别处改了取值（核心发 `preferences.changed`）页面立即跟着变，核心进程重启后重新读取。登记为页面 `preferences.preferences`（单例，没有边栏）与命令 `preferences.open`（`Ctrl+,`），菜单在“设置”下，没有活动栏按钮。
- 本阶段登记四个分组：外观（主题）、画面（画面比例、缩放方式、显示全部 240 行）、声音（缓冲大小、启动时静音，另有不显示的音量）、调试服务（启用、端口、令牌；令牌是文字输入框，按回车或失焦保存，规则见 04 第 4.6、4.8 节）；输入、路径等分组随各自的功能一起做，没有功能时不占位。学习机阶段又加了“打印机”分组（核心登记）与页面自己提供的“机型与 BIOS”分组（见下），“机型与 BIOS”排在“声音”之后。出厂默认值：主题跟随系统，画面比例 8:7，缩放方式适应窗口，显示全部 240 行为开，缓冲大小标准，启动时静音为关，音量 100，调试服务关闭、端口 5688，打印机图片保存位置为空（保存到用户数据目录下的 `printer-output`）。
- 声音：缓冲大小改后立即生效（低延迟、标准、稳定对应的水位见 01 第 7 节）；音量不在首选项页显示，由边栏的音量滑块修改并保存（拖动过程中每次变化都保存，重启后保持）；静音不保存，每次启动由“启动时静音”决定；调试服务的 `output.setVolume` 修改音量同样会保存。

“机型与 BIOS”分组（已实现，由页面自己提供，不是设置项，数据经 `machines` 模块，见 04 第 4.7 节；代码在 `src/ui/preferences/BiosSettings.tsx` 与 `use-bios.ts`）：

- 列出全部整机机型：小霸王 97、小霸王 2000、步步高 1.0、步步高 2.0；经典 FC 不需要 BIOS，不在列表里。每个机型一行：名称、BIOS 状态（未添加，或文件名与大小）、按钮。
- 分组上方的说明：BIOS 文件会复制到软件的 BIOS 目录，开机时直接使用，原文件可以删除或移动。
- 按钮：没有添加时是“添加 BIOS 文件”；已添加时是“替换”和“移除”。“添加 BIOS 文件”与“替换”弹出系统文件选择窗口，选定的文件复制进 BIOS 目录（替换时新文件复制成功后才删旧文件）；“移除”删除 BIOS 目录里的文件，不影响原文件，也不弹确认框。
- 尚未支持的机型整行置灰，状态处写“暂未支持”，按钮不可用；目前只有小霸王 2000 可用。
- 添加与移除的结果、文件不符合机型的错误都用通知，不在页面里显示；BIOS 变化后“文件”菜单的“开机…”立即更新。
- 原型里点击按钮只改示意数据，并用通知说明真实操作的效果，没有真实读写文件。
- 实现：添加或替换经主进程的 `machines.openBios`（弹出选择窗口，只显示 `.nes`），移除经 `machines.removeBios`；通知文字是“已添加 机型名 的 BIOS：文件名”“已替换 机型名 的 BIOS：文件名”“已移除 机型名 的 BIOS”，用户取消选择时没有通知；清单随 `machines.changed` 与核心重启后重新读取。BIOS 大小按 KB 四舍五入显示（512 KB 的 PRG 加 16 字节文件头显示为 512 KB）。

“打印机”分组（已实现，核心登记，见 04 第 4.8 节）：只有一项“图片保存位置”，是文本框加“选择”按钮；“选择”弹出系统的选择文件夹窗口（经主进程的 `preferences.pickDirectory`），选定后立即保存，取消时什么都不发生；文本框留空表示保存到用户数据目录下的 `printer-output`，也可以直接输入路径（按回车或失焦保存）。页面据设置项的 `picker` 字段（取值 `directory`）决定要不要显示“选择”按钮，不认识具体的设置项。

### 4.6 软盘文件（右边栏）

本节的功能学习机阶段没有做（软驱的盘片、状态与保存见 4.3，已实现），登记在待办备忘；下面是设计，实现时再核对。

右边栏只做一件事：查看与管理软驱里的文件。软驱里有盘片时才能打开，显示所选软驱（A 或 B）的根目录；两个软驱都没有盘片时，右边栏自动隐藏，标题栏的按钮置灰。

第一版范围：只显示文件，列出文件名、大小、修改时间；拖入、重命名、删除和与学习机的实时同步放到学习机阶段再做。原型已按完整功能画出。

| 区域 | 内容 |
| --- | --- |
| 软驱选择 | 下拉：软驱 A、软驱 B，每项带镜像名；没有盘片的软驱不能选 |
| 镜像信息 | 镜像名（有未保存的修改时注明）、已用空间与总容量、同步状态 |
| 文件表 | 名称、大小、修改时间（`2026-11-13 10:21`）；单击选中一行 |

- 拖入：把文件从系统的资源管理器拖到右边栏，添加到所选软驱，拖入时右边栏出现虚线框。名称必须符合 8.3 规则（主名 1 到 8 个字符，扩展名最多 3 个字符，小写自动转大写），不符合的拒绝并用通知说明；盘里已有同名文件时弹出确认框，确认后替换；空间不足时拒绝；文件的修改时间取源文件的修改时间。
- 右键：选中的文件弹出菜单，有“重命名”和“删除”。重命名在行内编辑，回车确认、`Esc` 取消，名称不合规则或重名时输入框标红并用通知说明；删除先弹出确认框。
- 写保护：软驱写保护时，拖入、重命名、删除都不可用，同步状态显示“写保护，不能修改”。
- 同步：右边栏的修改直接作用于模拟器里的盘片镜像，学习机运行时也一样，学习机里的 `DIR` 等操作立即看到变化，不需要换镜像或重启；学习机写盘产生的变化（新建、删除、改名）同样立即出现在右边栏，新增或改动的行短暂高亮。同步的做法与待核对的问题见 02 第 6.7 节。
- 保存：修改发生在内存里的盘片镜像上，点设备边栏的“保存镜像”才写回镜像文件，不自动落盘；有未保存的修改时，镜像名后注明。
- 通知：添加、删除、改名的结果与错误都用通知，同时写入底部面板的消息；页面里只有输入框标红。
- 现在只做根目录；子目录、新建文件夹和拖到文件夹里移动，到学习机阶段核对 SB-DOS 的做法后再定。
- 原型里学习机写盘用定时模拟，运行画面里的 `DIR` 随文件表变化。

## 7. 画面显示

- 画面由 WebGL 画布显示（在 Worker 里渲染），比例可选 4:3 与 8:7，缩放方式为适应窗口或整数倍，边缘用黑底；只影响显示，不影响模拟。阶段 3b 已实现：“4:3”是整帧的显示宽高比为 4:3，“8:7”是像素宽高比 8:7（256x240 的整帧显示宽高比约 1.219，即 128:105，对 224 行的可见区域恰好接近 4:3）；“整数倍”是画面高度取帧高度的整数倍（按设备像素算），宽度随比例，窗口放不下就取最大的整数倍，一倍也放不下时退回适应窗口；组件的三个属性（画面比例、缩放方式、显示全部行）默认是 8:7（画面不变形）、适应窗口与显示全部，运行页从首选项“画面”分组取值，改后立即生效（不需要重新开机）。“显示全部 240 行”关闭时，画面上下各裁掉 8 行（只显示第 8 到 232 行，共 224 行），显示比例、缩放与鼠标坐标都按裁剪后的 256x224 计算，鼠标坐标仍是整帧上的行号（所以最上边是 8、最下边是 232）；裁剪只影响显示，不影响模拟。渲染、背压与延迟测量见 01 第 7 节。
- 运行页在页面区里居中放一个“画面框”：框的宽高比固定为标准帧（256x240）在当前画面比例下的显示宽高比（默认 128:105；关闭“显示全部 240 行”时按 256x224 计算，8:7 为 64:49，4:3 不变），尽量放大，框外是页面底色，黑底只在框里；画面与“已暂停”等提示都在框里。画布在设备像素尺寸变化（改变窗口大小、设备像素比变化）时，渲染 Worker 立即按上一帧重画，不等下一次刷新，避免画布被清空后闪一下。
- 点击画面捕获鼠标，双击鼠标右键释放，沿用旧版的做法；只有机器带鼠标时才捕获。
- 全屏用 `F11`；全屏时只显示画面。
- 键盘、鼠标与游戏手柄按原始事件采集并上报，界面不做键位映射，也没有默认键位，由卡带的 mapper 脚本决定怎么用，见 01 第 7 节与 03 第 6.5 节。键盘按物理键位（`KeyboardEvent.code`）采集，只在画面区获得焦点时采集，页面显示时自动聚焦，操作边栏的按钮（上电、暂停、复位等）后焦点回到画面（拖动音量滑块与点静音除外）；F1 到 F24、Tab、Escape 与带 Ctrl、Alt、Meta 的组合键不上报；焦点在输入框等可编辑元素上时不采集；窗口失焦、页面隐藏、卸载时松开全部按键。鼠标事件带标准帧坐标、位移、按键位与滚轮，指针锁定（相对位移）尚未做；游戏手柄每个画面帧读一次，变化时上报。整机机型（小霸王 2000）上，同样的原始事件由主机直接处理：键盘事件按物理键位转成学习机键盘的扫描码（不认识的键丢弃），鼠标的位移与左右键交给串口鼠标（用画面坐标系下的相对位移，不足 1 个单位的小数留到下一次，离开画面时松开按键），手柄事件交给手柄口；不经 mapper 脚本，学习机的 BIOS 与程序自己决定怎么用。已在 SB-DOS 里用键盘输入命令验证（输入的文字显示在命令行里、能运行程序）；鼠标在 SB-Win98 演示盘里显示指针，未用真实鼠标操作核对。

## 8. 对话框、通知、右键菜单、主题

- 对话框、通知、右键菜单、文字选择规则同如见：对话框是独立的系统窗口，通知在右下角，外壳文字不能选中。
- “关于 Ember”对话框：标志、名称、版本、核心版本、许可证，以及“第三方依赖”小节：一行说明和表格（名称与版本、作者、许可）；清单由构建脚本从 `third-party.json` 生成，不手写，做法同如见；旧版 VirtuaNES 不在清单里。
- 主题：深色、浅色、跟随系统，在首选项的“外观”里改；系统主题变化时，跟随系统的立即生效。阶段 3a-1 只做了跟随系统：界面按系统的深浅色给 `html` 加主题类，窗口底色与系统窗口按钮的颜色由主进程同步，系统主题变化立即生效；阶段 3c 接入首选项：主进程启动时读取 `appearance.theme` 并订阅 `preferences.changed`，把取值设为 Electron 的 `nativeTheme.themeSource`（`system`、`dark`、`light`），界面仍然只监听 `prefers-color-scheme`，所以改主题立即生效，窗口底色与系统窗口按钮的颜色随之同步；窗口创建后等第一次读到主题（最多 2 秒，读不到按跟随系统）再显示，避免先显示错误的主题再闪一下。

## 10. 界面原型

- 位置：[prototype/index.html](prototype/index.html)，用浏览器直接打开；样式在 `prototype/styles/`，脚本在 `prototype/scripts/`。
- 范围：外壳、四个页面、设备边栏和右边栏、菜单与快捷键（含“文件”菜单的“开机…”子菜单）、通知、关于对话框、深色与浅色主题。电源、复位、暂停、速度、音量、开机与卡带切换、软驱载入与取出、软盘文件的拖入与右键删除、改名、磁带载入与录放、打印机状态变化、表格筛选与选择、首选项分组切换（含“机型与 BIOS”分组里 BIOS 的添加、替换、移除）、主题切换都能操作，用来确认效果；没有真实读写文件，数据都是示意：BIOS 的添加与移除只改示意数据并用通知说明真实的效果，“开机…”里“经典 FC”只提示会打开文件选择窗口。
