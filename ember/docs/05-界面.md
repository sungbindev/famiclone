# 界面

Ember 的界面：窗口布局、各部分的内容、菜单、系统栏、画面显示和界面状态的保存。界面只做外壳和显示，运行与数据都在 C++ 核心，见 [01-软件架构设计.md](01-软件架构设计.md)。界面不做调试窗口，调试能力只经 [04-调试服务.md](04-调试服务.md) 开放。

界面效果先做成静态原型确认，见第 10 节。

状态说明同 01。

## 2. 窗口布局

```text
┌──────────────── 标题栏：图标、名称、菜单 ────────────────┐
│                                                          │
│                  显示区（运行画面）                      │
│                                                          │
├─────────────── 底部面板（点按钮才展开）──────────────────┤
│ 面板标题（加粗）                                  关闭 × │
│ 面板内容                                                 │
├──────────────────────────────────────────────────────────┤
│ [运行][设备] 卡带 mapper                 调试模式 [通知] │  系统栏
└──────────────────────────────────────────────────────────┘
                                   通知固定在右下角，系统栏之上
```

| 区域 | 尺寸 | 内容 |
| --- | --- | --- |
| 标题栏 | 高 36px | 应用图标（蓝色卡带图，与程序图标是同一张，不随主题变色）、名称、菜单；右侧是系统窗口按钮 |
| 显示区 | 其余空间 | 运行画面，画面框居中 |
| 底部面板 | 默认高 126px，也是最小高度（正好装下设备面板的三行设备，不出现滚动条） | 标题行（左边加粗的面板标题，右上角依次是“自动收缩”开关与“关闭”按钮，没有登记自动收缩的面板只有“关闭”）与面板内容；高度可拖动并保存，面板内容放不下时滚动 |
| 系统栏 | 高 32px | 左侧：运行按钮、设备按钮（只有图标）、主机型号、已载入的软盘名、卡带名、mapper 插件；右侧：调试模式、通知按钮 |

- 尺寸、颜色、交互状态全部取组件库的令牌；系统栏是组件库的大尺寸状态栏（`AppFrame` 的 `statusBarSize="large"`）。
- 底部面板只经系统栏左侧的按钮控制：面板关着时点按钮，展开并显示这个按钮对应的面板；面板开着时再点同一个按钮收起，点另一个按钮切换内容；面板标题行右上角的“关闭”也能收起。没有快捷键与菜单项。展开的按钮按下时背景变化（同组件库按钮的选中底色，不加强调线），面板收起后恢复常态；每次启动面板都是关闭的，当前面板不保存。面板收起时内容卸载，设备面板对核心的定时读取随之停止。
- 自动收缩：运行与设备两个面板的标题栏有“自动收缩”开关（只有图标的按钮，按下态表示开启，悬停提示“自动收缩”，在“关闭”按钮左边），开着时点在面板之外的地方（包括显示区的画面）就自动收起面板，在面板里操作（点按钮、载入镜像、拖音量等）不收起；不算“面板之外”的有：窗体标题栏（含菜单）、拖动面板高度的拖动条、弹层（下拉选项、通知等）与系统栏里的面板按钮（按钮按“展开、切换、收起”的规则工作）；关着时面板保持展开，要自己点系统栏的按钮或“关闭”收起；两个面板的开关各自独立、各自保存，保存在界面状态里（见第 9 节），没设置过都是关闭。
- 文件拖放：NES 卡带、软盘镜像与声音文件可以直接拖进主窗口（任何位置，没有开机、没有卡带时也可以），按扩展名（不分大小写）分别处理：`.nes` 和“文件→打开卡带”一样打开并直接开机，已选机型变成经典 FC，并记入“最近打开”；`.img`、`.ima`、`.vfd`、`.dsk`、`.flp` 载入软驱 A，替换里面的盘片；`m4a`、`mp3`、`wav`、`aac`、`flac`、`ogg`、`opus`、`mp4`、`mka` 载入磁带机（只载入，不自动播放）。一次拖入多个文件时依次处理；扩展名没有处理项认领的用通知说明“不支持拖入的文件”；处理失败（文件不是合格的卡带、镜像空的、磁带机正在播放等）的提示和“打开”系列操作一样。拖放只在主窗口里生效（对话框是独立窗口，不接收文件），没有额外的高亮提示，拖动时指针显示“复制”。实现：外壳（`ui/shell/use-file-drop.ts`）监听窗口的拖放，把拖入的文件对象交给预加载脚本的 `shell.registerDroppedFiles`——路径只能由预加载脚本用 `webUtils.getPathForFile` 从真实的文件对象取得并交给主进程登记，页面只拿到编号与显示名，不能自己填路径；再按扩展名交给模块登记的文件处理项（`fileHandlers`，见 06 第 3 节），处理项经主进程请求 `cartridges.open`、`media.openFloppy`、`media.openTape` 的 `droppedId` 参数打开（见 04）。
- 面板向内展开与收起，窗口大小不变：底部面板占用显示区的空间，运行画面按显示区剩余空间等比缩放，不变形，所以画面会随面板开合变大变小。
- 窗口的最小尺寸是 480x463，也是每次启动的大小；宽度保证标题栏的图标、名称、菜单不被挤压或换行，菜单与系统窗口按钮之间留出至少 48px 可拖动的空白，系统栏放得下左右两组项；高度按画面框的 128:105 算出，使面板关闭时最小窗口下画面框四周的间距一样。窗口大小不记忆（不恢复最大化），位置仍按上次保存的恢复。
- 系统栏里没有信息的项不显示，不用“—”或“无”占位：没有开机时没有卡带与 mapper 插件（主机型号照常显示，是“文件→选择机型”里已选的机型，开机后是运行的主机；核心状态还没读到时也没有主机型号），整机机型用 BIOS 开机时没有卡带与 mapper 插件（只显示主机型号），调试服务没有开启时没有“调试模式”。
- 页面上不画蓝色的键盘焦点框：画面区（持有焦点才能把按键转给机器，样式在 `ember-run.css`）以及组件库里的窗口框架类元素（分隔条、菜单栏、活动栏、边栏分组、系统栏按钮、通知按钮、标签栏、停靠面板标签、虚拟列表容器）都不画；按钮、输入框、下拉框、列表等控件的焦点环照常显示。

## 3. 界面与模块

| 界面 | 形式 | 标识 | 所属模块 | 说明 |
| --- | --- | --- | --- | --- |
| 运行画面 | 显示区 | `runtime`（模块的 `screen`） | `runtime` | 机器的画面，整个应用只有一个显示区 |
| 运行 | 底部面板 | `runtime.panel` | `runtime` | 控制按钮与声音；按钮是系统栏左侧的运行按钮 |
| 设备 | 底部面板 | `media.devices` | `media` | 软驱、打印机；按钮是系统栏左侧的设备按钮 |
| 首选项 | 对话框 | `preferences.preferences` | `preferences` | 全部设置；有自己的分组导航 |
| 手柄设置 | 对话框 | `input.gamepadSettings` | `input` | 手柄的键盘与实体手柄绑定，见 4.6 |
| mapper 插件 | 对话框 | `mappers.plugins` | `mappers` | 插件列表、清单摘要、安装、卸载、启停，见 4.4 |
| 关于 Ember | 对话框 | `system.about` | `system` | 版本、编译时间、作者、许可证、第三方依赖，见第 8 节 |
| 帮助文档 | 独立窗口 | `system.openHelp`（命令） | `system` | 使用说明与调试接口手册，见第 5、8 节 |

- 对话框是组件库的独立窗口对话框，同一个对话框同时只开一个，再次打开时聚焦已有的；对话框里的内容仍在主窗口的界面进程里渲染，所以能用同样的预加载接口。对话框的主题类随主窗口同步，窗口底色由主进程按主题设置。
- 卡带库不做（2026-11-15 用户决定），卡带只经“文件→打开卡带”与“最近打开”打开；4.4 原来写在边栏里的内容（搜索框、筛选、按钮）放在对话框自己的顶部。
- 外壳的命令与菜单项仍由模块登记；面板按钮由面板的登记项生成，面板按钮的外观（图标、颜色、悬停提示）可以随模块状态变化，指示灯（如软驱读写灯）也由模块给出。

## 4. 各部分的内容

### 4.1 运行

显示区只有画面，按比例居中显示，周围是黑底。运行相关的操作在底部面板的“运行”面板里，点系统栏左侧的运行按钮展开。

“运行”面板没有分组标题，内容只有一行；主机型号、卡带、mapper 插件显示在系统栏左侧（卡带名后面跟着 mapper 插件，没有信息的不显示：没有开机时只有主机型号，显示已选机型，整机机型用 BIOS 开机时也只有主机型号），不在面板里：

| 内容 | 说明 |
| --- | --- |
| 控制 | 四个按钮排成一排：开机或断电、暂停或继续、软复位、硬复位 |
| 声音 | 同一行里按钮的右边：静音按钮、音量滑块与数值 |

- 运行按钮（系统栏左侧，只有图标）的图标实时显示运行状态：运行中是绿色三角形，暂停时换成暂停图标，没有开机或已断电是常色三角形；悬停提示是“运行：状态”（运行中、已暂停、已断电、未开机）。电源状态不再单独显示在系统栏里。
- 开机或断电是同一个按钮：通电时是“断电”；未通电时按“文件→选择机型”选中的机型开机：
  - 已选学习机机型（整机机型）：已添加 BIOS 就可以开机，不需要卡带，用 BIOS 装配主机并运行；当前装的是别的主机也用已选机型重新开机；没有 BIOS 时置灰。
  - 已选经典 FC：要先用“文件→打开卡带”选 NES 文件，选后直接开机；没有装入 FC 卡带时置灰；断电后按钮可点，直接上电（卡带还在）。
- 其他按钮的可用状态：没有开机时暂停与复位全部置灰；断电时暂停、软复位与硬复位置灰；通电（暂停或运行中）时全部可用。操作结束后焦点回到画面。
- 画面上的提示：没有开机显示“未开机”，下面分两行对齐写明怎么开机（学习机：“文件→选择机型”，再点“运行”→“开机”；经典 FC：“文件→打开卡带”，选好即开机）；断电显示“已断电”和一句开机说明；暂停显示“已暂停”。
- 机器带鼠标时，画面右下角提示“点击画面捕获鼠标，双击右键释放”，显示 4 秒后自动消失（首选项里打开“点击画面捕获鼠标”才有，见第 7 节）。
- 实现（`src/ui/runtime/`，模块 `runtime`）：控制器 `RuntimeController` 保存机器状态、最近打开的清单、机型清单、已选机型与音量，状态取自 `runtime.status`，收到 `runtime.stateChanged`、`cartridges.loaded`、`machines.changed` 事件以及核心进程重启时重读，所以面板没有展开时状态也是最新的；已选机型保存在界面状态里（见第 9 节），打开卡带成功后已选机型自动变成经典 FC；操作失败用通知给出。速度下拉待核心支持后做（核心目前没有速度请求）。

### 4.2 卡带库

不做（2026-11-15 用户决定）：卡带只经“文件→打开卡带”与“最近打开”打开，没有库文件夹、扫描与匹配状态表。学习机 BIOS 文件（mapper 171）没有匹配的插件，不能当卡带打开，要用“文件→选择机型”选机型后开机。

### 4.3 设备

设备在底部面板的“设备”面板里，点系统栏左侧的设备按钮展开；载入软盘、磁带等操作不切换显示区，运行画面一直在上面。设备面板始终列出全部设备（软驱 A、磁带机、打印机），与主机型号和卡带无关；设备都是被动使用的。软驱与磁带机是独立于主机的设备，一直可用，盘片与磁带随时可以载入与取出（没有开机、没有卡带也行）；打印机属于整机机型，当前主机没有时是沉默设备：照常显示一行，内容是空值，只有状态没有按钮。

设备面板每个设备一行，整齐排列，没有边框与表格线，行距紧凑，鼠标悬停时整行变底色（组件库的紧凑列表行）：

| 设备 | 一行里的内容 |
| --- | --- |
| 软驱 A、软驱 B | 名称、盘片（镜像名或“空”）、状态（无盘片、空闲、读写中并带磁道）；行尾三个只有图标的按钮：写保护（锁，按下态表示已写保护）、载入镜像、取出；没有“保存镜像”按钮，学习机写盘后核心自动把镜像写回文件。软驱是独立于主机的设备，没有开机、没有卡带时也可以载入与取出盘片 |
| 磁带机 | 名称、磁带（声音文件名或“空”）、位置（“当前 / 总时长”，总时长不知道时只写当前位置，没有磁带时为破折号）、状态（无磁带、已停止、播放中、录音中；状态列按内容定宽、紧挨行尾按钮，与软驱的状态右边缘对齐，磁带名与盘片名得到剩余的全部宽度）；行尾四个只有图标的按钮：取出、播放、录音、停止；没有“载入磁带”按钮，没有磁带时点“播放”选磁带。数据磁带与声像磁带走的是同一个磁带机，不分类型，也不显示电平 |
| 打印机 | 名称、状态：空闲、打印中、打印完成；没有按钮 |

- 按钮只有图标，名称在悬停提示与可访问名称里；“载入镜像”选择软盘镜像文件，没有磁带时点“播放”选择声音文件，都用系统的文件选择窗口。
- 没有盘片时，取出、写保护置灰。磁带机按下面的规则（“通电”指磁带机接在通电的主机上，现在只有开了机的经典 FC）：没有磁带时，“播放”始终可点（弹出选择磁带，选定后载入；已通电就马上开始播放，没通电只载入），“取出”置灰，“录音”要通电；有磁带时，“取出”始终可点（播放或录音中会先停止再取出），“播放”与“录音”要通电且已停止，没通电就置灰；播放或录音中只有“停止”与“取出”可用。取出磁带后“播放”又可以点；没通电时放入磁带后，“播放”立即置灰。录音停止后录到的文件自动成为磁带机里的磁带，可以直接播放。“录音”弹出系统的保存文件窗口（WAV），选定后立即开始录音，经主进程的 `media.openTapeRecording`。
- 打印机只显示实时状态：机器没有运行时为空闲，有数据时为打印中，输出一页后显示打印完成，下一页开始后回到打印中。每输出一页，用通知告知文件名；PNG 文件名按日期时间自动生成，不弹出保存窗口，保存位置在首选项的“打印机”里改。
- 软盘与磁带的载入、取出随时可以操作，与电源无关（没有主机、没有卡带时也可以载入盘片与磁带）；磁带的播放与录音要磁带机接在通电的主机上，断电时磁带机自动停止，磁带留在里面。
- 设备按钮的图标是软盘，软驱读写灯画在图标中间的圆上（组件库状态项的 `lamp.inIcon`）：任一软驱的马达在转时亮绿色，空闲、无盘片、断电或暂停时是暗色；亮灭取自核心报告的软驱真实状态（马达），界面不自己推测，不随读写闪动；软驱一直存在，所以灯一直显示。核心在马达开关变化时发 `media.changed`（软驱状态里的 `motor` 字段），控制器读到后经外壳的 `refreshCommands` 让系统栏重新渲染。
- 系统栏左侧在主机型号后面显示已载入的软盘镜像名（有未保存的修改时注明，悬停提示是“软驱 A 的盘片”）；只有一个软驱时直接显示镜像名，有多个软驱时每项前面带驱动器名（“A: 镜像名”）；没有载入盘片的软驱不显示，取出后立即消失。
- 实现（`src/ui/media/`，登记见 06 第 3 节）：软驱一行显示盘片（有未保存的修改时注明“（有未保存的修改）”，没有盘片是“空”）与状态，按钮有“写保护”“载入镜像”（经主进程的 `media.openFloppy`，弹出系统文件选择窗口）“取出”“写保护”；打印机一行只有状态。小霸王 2000 目前只有一个软驱 A；设备面板里始终有软驱 A、磁带机与打印机三行，没有开机或主机没有打印机时，打印机是沉默设备（只显示“空闲”），不再提示“没有设备”；软驱与磁带机一直可用，见上面的规则。
- 软驱与打印机的读写状态、磁道随机器运行不断变化，核心不推送，所以设备面板展开期间每 500 毫秒读取一次（`media.floppyStatus`、`media.printerStatus`，内容没有变化时不重新渲染），收起后停止；盘片变化（`media.changed`）、电源或运行状态变化时立即重新读取。
- 操作失败时用通知给出核心返回的说明；打印机每输出一页，用通知告知“打印机输出了第 N 页：文件名”（`media.printed`），一页无法保存时用通知给出原因（`media.printFailed`）；软盘镜像自动写回文件失败时用通知给出原因（`media.floppySaveFailed`，核心每 5 秒重试，成功前只通知一次）；这些由常驻组件接收，设备面板没有展开时也会收到。
- 本阶段没有做：软盘里的文件管理（原来设计在右边栏）暂不做，登记在待办备忘；“取出”不弹确认框（学习机写盘后镜像已自动写回文件，取出前还会把尚未写回的修改先写回）。
- 磁带机的状态（位置、播放完后自动停止）随机器运行变化，和软驱一样在设备面板展开期间每 500 毫秒读取一次（`media.tapeStatus`）；载入、取出、播放、录音、停止后核心发 `media.changed`（`device` 为 `tape`）立即重新读取，主机开机或断电时随运行状态事件重新读取。磁带机状态里的 `connected` 表示它是否接在通电的主机上（现在只有开了机的经典 FC，学习机的磁带接口登记在待办备忘）：播放与录音按钮据此可用或置灰。没有磁带时点“播放”经主进程的 `media.openTape` 弹出系统文件选择窗口（声音文件与所有文件），载入成功后若 `connected` 为 `true`，界面接着发 `media.tapePlay` 开始播放。

### 4.4 mapper 插件

“设置→mapper 插件”打开的对话框（已实现，`mappers` 模块登记，代码在 `src/ui/mappers/`；对话框 `mappers.plugins`，宽 760、高 560，命令 `mappers.open`，没有快捷键）。

- 顶部一行：搜索框（按名称、标识、发布者、说明筛选，不分大小写）、来源筛选（全部来源、预装、用户安装）、“安装插件”按钮。
- 下面是表格：名称（第二行是说明）、版本、匹配、主机型号、来源（预装、用户安装）、状态（已启用、已停用）；点一行展开它的清单摘要并把这一行显示为选中，再点同一行收起摘要并取消选中，同一时间只展开一项；没有符合条件的插件时提示“没有符合条件的插件”。开发目录这个来源以后再做（见 03 第 7 节）。
- 选中一行后，表格下方显示这个插件的清单摘要（标题是插件名称）：标识、版本、发布者、说明（没有则不列）、匹配、主机型号、外设（没有则不列）、存储区、寄存器范围、状态声明（没有内容的写“无”）；标题行右侧是“停用”或“启用”（随当前状态切换）与“卸载”按钮。预装插件只能停用，“卸载”置灰，悬停提示写明原因；用户安装的可以卸载，卸载前用确认对话框询问。
- “安装插件”经主进程的 `mappers.openPackage` 弹出系统文件选择窗口（只显示 `.emap`，也可选所有文件），选定的文件交给 `mappers.install`；成功后新插件出现在列表里并被选中，已有同标识的用户插件时直接替换；取消选择时什么都不发生。
- 安装与卸载成功用通知告知（“已安装插件：名称 版本”“已卸载插件：名称”），失败时用通知给出核心的说明；启用与停用没有成功通知，失败时有；页面不显示操作结果。停用的插件不参与匹配，见 03 第 7 节。
- 数据：经 `mappers.list` 与 `mappers.info` 读取，订阅 `mappers.changed`，核心重启后重新读取，所以在别处（如调试服务）安装或卸载也会立即反映。

### 4.5 首选项

左侧是分组导航（默认宽度就是最小宽度 140px，可拖宽到 320px），右侧是设置行（名称与说明在左，控件在右）。对话框的主题类由主窗口同步过来，而最小尺寸的主窗口会被对话框整个盖住，Windows 上 Chromium 会把被盖住的窗口当作不可见而停掉渲染，主题切换就停在主窗口里、到不了对话框，所以主进程启动时关掉窗口遮挡检测（`disable-features=CalculateNativeWinOcclusion`）。

| 分组 | 设置项 |
| --- | --- |
| 外观 | 主题 |
| 画面 | 画面比例（4:3、8:7）、缩放方式（适应窗口、整数倍）、显示全部 240 行 |
| 更新 | 启动时检查更新（开关，默认开启；有新版本时自动下载，下载好后在“帮助”菜单里重启安装，见第 5 节与 01 第 11 节） |
| 声音 | 缓冲大小（低延迟、标准、稳定）、启动时静音 |
| 输入 | 点击画面捕获鼠标（开关，默认开启，只对带鼠标的机型起作用，已实现，见第 7 节）；接入 Family BASIC 键盘（开关，默认关闭，给经典 FC 接上 Family BASIC 键盘，学习机用自己内置的键盘，不受影响，机器菜单里也有同名勾选项，已实现，见第 7 节）；手柄的键位不在首选项里，在“设置→手柄设置”对话框里设置，见 4.6 |
| 机型与 BIOS | 全部整机机型的 BIOS：添加、替换、移除，见下 |
| 调试服务 | 启用、端口、令牌（核心自动生成，可以改写，清空后重新生成）、调试输出目录（随写文件的请求一起做） |

| 路径 | 用户插件目录（只读）、开发中的插件目录 |

- 设置项由各模块登记，首选项模块汇总，规则同如见；首选项页不显示操作结果，改动立即生效并保存。
- 实现（阶段 3c）：设置项在核心里登记（`preferences` 模块提供 `PreferenceService`，其他模块取用它登记自己的设置项，取值保存在用户数据目录的 `config/preferences.json`，请求与事件见 04 第 4.8 节）；界面只经 `preferences.list`、`preferences.set`、`preferences.reset` 读取、修改与恢复默认，不自己保存任何设置。对话框内容（`src/ui/preferences/`）左侧是分组导航，右侧是设置行（名称与说明在左，控件在右）：选择类用下拉框，开关用开关，整数用输入框（按回车或失焦提交，不是整数或超出范围时只把输入框标红并给出说明，不发请求）；修改立即保存，保存成功后才显示新值；取值与出厂默认值不同时，设置行右侧出现“恢复默认”；保存失败时用外壳通知给出核心返回的说明，控件保持原值；页面不显示操作结果。在别处改了取值（核心发 `preferences.changed`）页面立即跟着变，核心进程重启后重新读取。登记为对话框 `preferences.preferences`（组件库的独立窗口对话框，宽 720、高 520）与命令 `preferences.open`（`Ctrl+,`），菜单在“设置”下，没有按钮。
- 本阶段登记四个分组：外观（主题）、画面（画面比例、缩放方式、显示全部 240 行）、声音（缓冲大小、启动时静音，另有不显示的音量）、调试服务（启用、端口、令牌；令牌是文字输入框，按回车或失焦保存，规则见 04 第 4.6、4.8 节）；输入、路径等分组随各自的功能一起做，没有功能时不占位。应用升级又加了“更新”分组（只有“启动时检查更新”一项，核心登记，排在“画面”之后，默认开启，见 04 第 4.8 节）。学习机阶段又加了“输入”分组（由 `input` 模块登记，排在“机型与 BIOS”之前）与“打印机”分组（核心登记）以及页面自己提供的“机型与 BIOS”分组（见下），“机型与 BIOS”排在“声音”之后。出厂默认值：主题跟随系统，画面比例 8:7，缩放方式适应窗口，显示全部 240 行为开，缓冲大小标准，启动时静音为关，音量 100，调试服务关闭、端口 5688，打印机图片保存位置为空（保存到用户数据目录下的 `printer-output`）。
- 声音：缓冲大小改后立即生效（低延迟、标准、稳定对应的水位见 01 第 7 节）；音量不在首选项里显示，由运行面板的音量滑块修改并保存（拖动过程中每次变化都保存，重启后保持）；静音不保存，每次启动由“启动时静音”决定；调试服务的 `output.setVolume` 修改音量同样会保存。

“机型与 BIOS”分组（已实现，由页面自己提供，不是设置项，数据经 `machines` 模块，见 04 第 4.7 节；代码在 `src/ui/preferences/BiosSettings.tsx` 与 `use-bios.ts`）：

- 列出全部整机机型：小霸王 97、小霸王 2000、步步高软驱一号、步步高 98；经典 FC 不需要 BIOS，不在列表里。每个机型一行：名称、BIOS 状态（未添加，或文件名与大小）、按钮。
- 分组上方的说明：BIOS 文件会复制到软件的 BIOS 目录，开机时直接使用，原文件可以删除或移动。
- 按钮：没有添加时是“添加 BIOS 文件”；已添加时是“替换”和“移除”。“添加 BIOS 文件”与“替换”弹出系统文件选择窗口，选定的文件复制进 BIOS 目录（替换时新文件复制成功后才删旧文件）；“移除”删除 BIOS 目录里的文件，不影响原文件，也不弹确认框。
- 尚未支持的机型整行置灰，状态处写“暂未支持”，按钮不可用；目前只有小霸王 2000 可用。
- 添加与移除的结果、文件不符合机型的错误都用通知，不在页面里显示；BIOS 变化后“文件→选择机型”立即更新。
- 原型里点击按钮只改示意数据，并用通知说明真实操作的效果，没有真实读写文件。
- 实现：添加或替换经主进程的 `machines.openBios`（弹出选择窗口，只显示 `.nes`），移除经 `machines.removeBios`；通知文字是“已添加 机型名 的 BIOS：文件名”“已替换 机型名 的 BIOS：文件名”“已移除 机型名 的 BIOS”，用户取消选择时没有通知；清单随 `machines.changed` 与核心重启后重新读取。BIOS 大小按 KB 四舍五入显示（512 KB 的 PRG 加 16 字节文件头显示为 512 KB）。

“打印机”分组（已实现，核心登记，见 04 第 4.8 节）：只有一项“图片保存位置”，是文本框加“选择”按钮；“选择”弹出系统的选择文件夹窗口（经主进程的 `preferences.pickDirectory`），选定后立即保存，取消时什么都不发生；文本框留空表示保存到用户数据目录下的 `printer-output`，也可以直接输入路径（按回车或失焦保存）。页面据设置项的 `picker` 字段（取值 `directory`）决定要不要显示“选择”按钮，不认识具体的设置项。

### 4.6 手柄设置

“设置→手柄设置”打开的对话框（已实现，`input` 模块登记，代码在 `src/ui/input/`；对话框 `input.gamepadSettings`，宽 640、高 560，命令 `input.openGamepadSettings`，没有快捷键与按钮）。键盘与鼠标在整机机型里由机型自己决定，这里只设置“手柄”：红白机一直有效，学习机在红白机兼容模式下才有效（DOS 下键盘整个交给机器），实体手柄在哪种机器上都有效。

- 手柄绑定全局一份，不分机型与卡带。手柄有 10 个键：上、下、左、右、A、B、连发 A、连发 B、选择、开始；连发键按住时每 2 帧翻转一次对应的 A 或 B。
- 对话框顶部是一段说明，下面是“玩家 1”“玩家 2”两个页签（对应手柄口 1、2），页签下是该玩家的设置，最下面是“恢复默认”。一个玩家的设置是一张手柄图（`PadDiagram`，版面见 `pad-layout.ts`）：手柄外形里画着 10 个键（十字键的四个方向、选择、开始、连发 B、连发 A、B、A），每个键是图上的一个按钮，上面写键名和当前的绑定；图上方是“输入来源”的分段切换（键盘、实体手柄），图下方是一行说明加“清除”按钮。键盘与实体手柄是同一个手柄键上互相独立的两份绑定，切换来源只改变图上显示和设置的是哪一份，不改数据，也不清除另一份。
- 点图上的键就选中它并开始设置（学习），按钮上变成“请按键”并用强调色边框；学习中再点同一个键、点“清除”、切换来源或玩家页签都取消学习，点另一个键则改为学习那个键。学完或取消后这个键保持选中（底色同列表选中项），下方说明行显示“键名：当前绑定”，“清除”解除选中键在当前来源下的绑定（没有选中键或没有绑定时不可点）。
- “键盘”来源：键上显示当前的物理键（如 X、↑、右 Shift，没有绑定显示“未绑定”），点击后按下键盘上的键即成为绑定（Esc 取消）。一个物理键只能绑给一个手柄键：绑给新的键时，原来绑着它的键（含另一个玩家的）自动解除。
- “实体手柄”来源：图上方出现“使用的手柄”下拉框，先选一个系统发现的手柄（选项是已连接的手柄，同一个设备标识连着多个时标“第几个”；已指定但现在没接上的显示“未连接”；选“不使用”取消）；手柄接上后要按一下它的任意按钮，浏览器才会把它交给页面。没有指定手柄或手柄未连接时图上的键都不可点，说明行提示原因（已绑定的键仍可用“清除”解除）。学习方式同键盘：点键后按下手柄上的一个按钮，或把一个摇杆推到底（以点击那一刻的状态为基准，开始前就按着的按钮不算），即绑定为“按钮 n”或“轴 n 正向/负向”；换成别的手柄时原来的按钮绑定清空（不同手柄排布不同），同一个手柄只能属于一个玩家（指定给另一个玩家时从原来的玩家名下取消）。
- 出厂默认：玩家 1 的键盘为方向键（上、下、左、右）、Z（B）、X（A）、C（连发 B）、V（连发 A）、右 Shift（选择）、回车（开始）；玩家 2 的键盘没有绑定；两个玩家都没有指定实体手柄。
- 每次改动立即保存（请求 `input.setBindings`，把两个玩家的全部绑定一起提交；保存成功后才显示新的内容），“恢复默认”用 `input.resetBindings`；保存失败用外壳通知给出核心返回的说明，页面保持原样，页面不显示操作结果。在别处改了绑定（核心发 `input.bindingsChanged`）页面立即跟着变，核心重启后重新读取。切换玩家页签、更换手柄、恢复默认时取消正在进行的学习。
- 对话框是独立的窗口：键盘事件与手柄读取都挂在对话框自己的窗口上（不是主窗口），学习期间按下的键不会触发页面里的其他操作。

## 5. 菜单与快捷键

## 6. 底部面板与系统栏

- 运行按钮的图标与悬停提示实时显示运行状态，规则见 4.1；设备按钮的图标上有软驱读写灯，见 4.3。
- 调试模式项（`src/ui/debug/`，登记见 06 第 3 节）：调试服务开启时在右侧、通知按钮的左边显示绿色文字“调试模式”，没有开启或还没读到状态（核心启动中、核心不可用）时不显示；端口、连接数放在悬停提示里（如“调试服务：ws://127.0.0.1:5688，2 个连接”）；开启但没有监听（如端口被占用）时文字仍是“调试模式”，用警告色，提示里写原因。状态来自 `debug.status`，收到 `debug.statusChanged` 或核心重启后重新读取。点击执行命令 `preferences.open` 打开首选项对话框，不定位到“调试服务”分组。令牌在首选项的文字输入框里显示与修改，系统栏不显示令牌。
- 通知按钮是组件库的通知中心按钮，通知固定在右下角、系统栏之上；系统栏的高度变化时通知让出的高度随之变化。

## 7. 画面显示

- 画面由 WebGL 画布显示（在 Worker 里渲染），比例可选 4:3 与 8:7，缩放方式为适应窗口或整数倍，边缘用黑底；只影响显示，不影响模拟。阶段 3b 已实现：“4:3”是整帧的显示宽高比为 4:3，“8:7”是像素宽高比 8:7（256x240 的整帧显示宽高比约 1.219，即 128:105，对 224 行的可见区域恰好接近 4:3）；“整数倍”是画面高度取帧高度的整数倍（按设备像素算），宽度随比例，窗口放不下就取最大的整数倍，一倍也放不下时退回适应窗口；组件的三个属性（画面比例、缩放方式、显示全部行）默认是 8:7（画面不变形）、适应窗口与显示全部，运行页从首选项“画面”分组取值，改后立即生效（不需要重新开机）。“显示全部 240 行”关闭时，画面上下各裁掉 8 行（只显示第 8 到 232 行，共 224 行），显示比例、缩放与鼠标坐标都按裁剪后的 256x224 计算，鼠标坐标仍是整帧上的行号（所以最上边是 8、最下边是 232）；裁剪只影响显示，不影响模拟。渲染、背压与延迟测量见 01 第 7 节。
- 显示区里居中放一个“画面框”：框的宽高比固定为标准帧（256x240）在当前画面比例下的显示宽高比（默认 128:105；关闭“显示全部 240 行”时按 256x224 计算，8:7 为 64:49，4:3 不变），尽量放大，框外是页面底色，黑底只在框里；画面与“已暂停”等提示都在框里。画布在设备像素尺寸变化（改变窗口大小、设备像素比变化）时，渲染 Worker 立即按上一帧重画，不等下一次刷新，避免画布被清空后闪一下。
- 点击画面捕获鼠标，双击鼠标右键释放；只有机器带鼠标时才捕获。实现（首选项“输入”分组的“点击画面捕获鼠标”，默认开启，设置项 `input.captureMouse`）：开启且机器带鼠标（由核心在 `runtime.status` 的 `mouse` 里给出：整机机型在 6576 模式下自带串口鼠标，学习机进入 FC 兼容模式后没有，已捕获的会立即释放、之后点击画面不再捕获；经典 FC 只有卡带的 mapper 插件在清单的 `devices` 里声明了 `mouse` 才有，没有声明的点击画面不会捕获，见 03 第 4.1 节）时，第一次点击画面只用来捕获（浏览器的指针锁定，主进程的权限策略只放行应用自己页面的 `pointerLock`，其余权限仍然全部拒绝，见 01 第 7 节），不把这次按下送给机器；捕获期间指针隐藏，鼠标事件只有相对位移（CSS 像素按画面的显示比例换算成标准帧的像素），位置从画面中心开始累加并限制在整帧范围内；双击右键（400 毫秒内两次，第二次不送给机器）释放（键盘独占时 Esc 属于机器，不会释放；没有键盘独占的平台上按 Esc 也会释放），释放时上报一次离开并松开所有鼠标按键，之后没有再次捕获前鼠标的移动、按键与滚轮都不送给机器（里面的鼠标不跟着动）；开启且机器在运行或暂停时，画面右下角显示提示“点击画面捕获鼠标，双击右键释放”，4 秒后自动消失，机器断电或重新开机后再次显示。
- 全屏用 `F11`（画面区持有焦点并独占键盘时，F11 与其他外壳快捷键都属于机器，需要先点画面以外的地方，或改用菜单）；全屏时只显示画面。
- 键盘、鼠标与游戏手柄按原始事件采集并上报，界面不做键位映射：键盘与游戏手柄由核心按“手柄绑定”（4.6）变成手柄口的按键，其余键盘与鼠标事件交给卡带的 mapper 脚本或整机机型，见 01 第 7 节与 03 第 6.5 节。键盘按物理键位（`KeyboardEvent.code`）采集，只在画面区获得焦点时采集，页面显示时自动聚焦，操作运行面板的按钮（开机、暂停、复位等）后焦点回到画面（拖动音量滑块与点静音除外）；Windows 上画面区获得焦点期间独占键盘：所有物理按键（包括 Esc、Tab、F 键、Ctrl 与 Alt 组合）都只交给机器，外壳与页面收不到按键，实现见 01 第 7 节“键盘独占”；离开的方式是点画面以外的地方、窗口失去激活（如 Alt+Tab、点别的窗口）或关闭窗口，Win 键、Ctrl+Alt+Del 与 Alt+Tab 仍由系统处理；没有独占时（其他平台）F1 到 F24、Tab、Escape 与带 Ctrl、Alt、Meta 的组合键不上报；焦点在输入框等可编辑元素上时不采集；窗口失焦、页面隐藏、卸载时松开全部按键。鼠标事件带标准帧坐标、位移、按键位与滚轮，捕获鼠标（指针锁定）期间只有相对位移（见本节上一条）；游戏手柄每个画面帧读一次，变化时上报（带设备标识 `Gamepad.id`）。整机机型（小霸王 2000）上，没有被手柄绑定截下的原始事件由主机直接处理：键盘事件按物理键位转成学习机键盘的扫描码（不认识的键丢弃），鼠标的位移与左右键交给串口鼠标（用画面坐标系下的相对位移，不足 1 个单位的小数留到下一次，离开画面时松开按键）；不经 mapper 脚本，学习机的 BIOS 与程序自己决定怎么用。学习机进入红白机兼容模式后键盘不再整个交给机器，按手柄绑定当手柄用。已在 SB-DOS 里用键盘输入命令验证（输入的文字显示在命令行里、能运行程序）；鼠标在 SB-Win98 演示盘里显示指针，未用真实鼠标操作核对。

- 主题：深色、浅色、跟随系统，在首选项的“外观”里改；系统主题变化时，跟随系统的立即生效。阶段 3a-1 只做了跟随系统：界面按系统的深浅色给 `html` 加主题类，窗口底色与系统窗口按钮的颜色由主进程同步，系统主题变化立即生效；阶段 3c 接入首选项：主进程启动时读取 `appearance.theme` 并订阅 `preferences.changed`，把取值设为 Electron 的 `nativeTheme.themeSource`（`system`、`dark`、`light`），界面仍然只监听 `prefers-color-scheme`，所以改主题立即生效，窗口底色与系统窗口按钮的颜色随之同步；窗口创建后等第一次读到主题（最多 2 秒，读不到按跟随系统）再显示，避免先显示错误的主题再闪一下。

## 9. 界面状态的保存

| 状态 | 保存 |
| --- | --- |
| 窗口位置 | 保存，保存在 `config/shell-state.json`，细节见 01 第 9 节 |
| 窗口大小、是否最大化 | 不保存，每次启动都是最小尺寸，也不恢复最大化 |
| 主题、首选项各项 | 保存 |
| 底部面板高度 | 保存；没有保存过时用默认高度 126px，保存的高度低于最小高度时按 126px 显示 |
| 已选机型（文件→选择机型） | 保存，同在 `config/shell-state.json` 的布局里；没选过时是经典 FC |
| 底部面板的展开状态与当前面板 | 不保存，每次启动都是关闭 |
| 底部面板的“自动收缩”开关 | 保存，每个面板各一项，同在 `config/shell-state.json` 的布局里（`autoCollapsePanels`：开着的面板标识清单）；没设置过都是关闭 |
| 最近打开的卡带、库文件夹 | 保存；最近打开的卡带最多 10 个，由主进程保存在 `config/recent-cartridges.json`，界面只拿到编号与显示名，见 01 第 9 节 |
| 文件选择窗口的起始目录 | 保存；载入软盘镜像、打开卡带、添加 BIOS、安装插件、载入磁带、保存录音、选择文件夹各记各的上次目录，下次同一用途的窗口从那里打开（不再总是回到系统默认的目录），保存在 `config/last-directories.json`，目录被删除或改名时系统退回默认位置 |

## 10. 界面原型

- 位置：[prototype/index.html](prototype/index.html)，用浏览器直接打开；样式在 `prototype/styles/`，脚本在 `prototype/scripts/`。
- 原型还是旧布局（活动栏、边栏、标签页、右边栏、状态栏），没有随界面简化更新，布局与行为以第 1 至 9 节为准；原型的令牌取值与 rujian-ui-kit 一致，但样式和脚本是手写的，只用于确认过当时的效果，不再维护。原型的画面与表格数据仅为示意，不代表真实的匹配规则与画面。
- 正式界面用 React 与 rujian-ui-kit 实现，已实现的范围：
  - 外壳（`src/ui/shell/`）：标题栏与菜单、显示区、底部面板、系统栏、对话框、通知、全屏、快捷键；规则见第 2、3、5、6 节，登记方式见 06 第 3 节。
  - 运行（`src/ui/runtime/`）：运行画面（WebGL、Worker、两种比例、两种缩放方式、键盘、鼠标与手柄采集）、运行面板、选择机型与最近打开等菜单、画面提示。
  - 设备（`src/ui/media/`）：软驱与打印机，见 4.3。
  - 首选项（`src/ui/preferences/`）：对话框，分组见 4.5。
  - 手柄设置（`src/ui/input/`）：对话框，见 4.6。
  - mapper 插件（`src/ui/mappers/`）：对话框，见 4.4。
  - 系统（`src/ui/system/`）：“帮助”菜单（帮助文档、打开日志目录、检查更新、关于 Ember）、升级控制器 `update-controller.ts`、关于对话框，见第 5、8 节。
  - 调试模式项（`src/ui/debug/`）。
- 还没做：机器菜单的“截图”、运行的速度（待核心支持）、系统栏的帧率（核心的运行状态里只有帧数与周期数的累计值，界面不自己推算）、用户修改快捷键、软盘文件管理。
- 本次修改后已目测（开发版冒烟截图，Windows，深色主题，窗口为最小尺寸 480x463，经 `--cartridge=` 打开 nestest）：运行面板展开时的外观（四个控制按钮、音量，系统栏里的主机型号、卡带、mapper 插件、运行按钮的按下态与绿色的“调试模式”）；最小窗口下的标题栏与系统栏；“文件”菜单与“最近打开”子菜单、浅色主题的标题栏与系统栏、首选项对话框（独立窗口，“外观”分组）在 560x529 时看过，尺寸改小后没有重看；后来又目测了（最小窗口、深色主题）：“设置”菜单与“选择机型”子菜单的弹层位置（不压在系统窗口按钮下面，子菜单两侧放不下时靠右）、没有开机时系统栏的主机型号、手柄设置对话框（键盘来源的手柄图、选中键的底色与说明行、实体手柄来源在没有指定手柄时的置灰状态）。
- 未目测：自动收缩开关在标题栏里的外观、设备面板（用真实 BIOS 开机后的软驱行、图标里的读写灯、悬停底色）、运行按钮暂停时的暂停图标、“未开机”“已断电”“已暂停”的画面提示在新布局下的外观、浅色主题下的对话框与底部面板、手柄图上学习中的强调色边框与实体手柄真实接入后的设置、首选项的其他分组、拖动调整面板高度、窄窗口下面板内容的换行、键盘操作与焦点轮廓、多显示器、macOS。
