# 调试客户端工具

调试服务的官方客户端工具在 VS Code 扩展 fcdev 里（源码在仓库的 `vscode/`，目录 `vscode/src/*/debug-client/`）：调试命令与 Copilot 工具共用同一个调试客户端，不单独发布 npm 包。调试服务本身（协议、认证、请求与事件）见 [04-调试服务.md](04-调试服务.md)，本文只写客户端工具的设计。

## 1. 决策

| 决策项 | 结论 |
| --- | --- |
| 位置 | 仓库的 `vscode/`，属于 fcdev 扩展，按扩展的分层（`contracts`、`shared`、`logic`、`infra`、`entry`）存放；不属于 Ember 应用，不进入应用的打包 |
| 发布 | 随 fcdev 扩展发布，不单独发布 |
| 开放 | 协议是开放的，其他语言与工具可以不经扩展直接连接；接口文档是随 Ember 分发的帮助文档里的“调试接口手册”（`ember/help/`，见 06 第 10 节） |
| 接口来源 | `schema/*.schema.json` 是唯一来源：`npm run schema` 生成 OpenRPC 文档到 `vscode/debug/openrpc.json`、TypeScript 类型到 `vscode/src/contracts/debug-client/generated/api.ts`（都是生成物，不手改）；客户端不手写请求与事件的类型 |
| 运行时依赖 | 无；传输用 Node 22 以上自带的全局 WebSocket |
| 对外形式 | 命令“fcdev：显示调试服务地址”“fcdev：查看调试请求说明”“fcdev：调用调试请求”“fcdev：保存调试截图”“fcdev：监视调试事件”，与 Copilot 工具 `emu_connect`、`emu_launch`、`emu_run`、`emu_inspect` 等；扩展不对外导出客户端的代码接口 |
| 自动发现 | 读端点文件 `<用户数据目录>/run/debug-endpoint.json`（04 第 2.5 节），并确认写它的进程还在；也可以用环境变量或工具参数直接指定 |

## 2. 目录

```text
vscode/
  debug/openrpc.json                       OpenRPC 接口文档（生成），调试命令列出请求与说明用它
  src/
    contracts/debug-client/                连接器、会话、传输与端点的抽象；generated/api.ts 是请求与事件的类型（生成）
    shared/debug-client/                   错误类型、JSON-RPC 报文类型、请求清单、命令参数解析、协议参考生成
    logic/debug-client/                    二进制帧解码、RPC 会话、客户端（EmberDebugClient）、连接器（EmberConnector）
    infra/debug-client/                    WebSocket 传输、端点文件、接口文档读取
    entry/debug-client/                    调试命令的注册
  vscode/tools/gen/gen-debug-api-docs.mjs             生成协议参考到 ember/help/api/（不提交）
  test/real-emulator/                      对真实 Ember 的联调测试
ember/help/api/                            协议参考（生成，在 Ember 的帮助文档源码里，不提交）：总览加每个模块一页
```

## 3. 依赖规则

遵守扩展的分层规则（见 `vscode/docs/` 与 `vscode/test/structure.test.ts`）：

- `contracts` 只引用 `contracts` 与 `shared`；`shared` 只引用 `shared`；`logic`、`infra`、`entry` 可以引用 `contracts`、`shared` 与 `platform`。
- `logic` 不引用 `infra`：客户端经 `Transport` 抽象通信，WebSocket 实现在 `bootstrap` 里注入。
- 只有 `entry`、`platform`、`bootstrap` 可以引用 `vscode`；客户端本身不依赖 VS Code。
- `vscode/` 不引用 Ember 应用的其他源码，应用也不引用它；两者之间只有 `schema/` 生成的接口文档与类型这一条联系（生成脚本在 Ember 里，把文件写进扩展）。

## 4. 客户端

- `EmberDebugClient`：连接并握手；`request` 按方法名发类型化请求；`subscribe`/`unsubscribe`、`on`/`onAny`/`waitFor` 处理事件；`closed`、`close`。
- `RpcSession`：给请求编号、匹配响应、转发通知、超时、连接关闭时让等待中的请求失败；收到不合协议的报文时以 1002 关闭连接。
- 二进制帧由 `frame-codec` 解码，剩余字节放回 `result.data` 或 `params.data`（`Uint8Array`）。
- 错误只有两类：`EmberRequestError`（服务端的错误响应，带模块错误码）与 `EmberConnectionError`（连接类，带种类与关闭码）。
- 事件默认不推送，客户端必须先 `subscribe`；`on` 不自动订阅。

## 5. 调试命令

- “调用调试请求”从接口文档列出请求供选择，参数写成 `key=value`（值按 JSON 解析，不是 JSON 就当字符串；`0x8000` 与 `$8000` 是十六进制数）或一个 JSON 对象；结果写到输出通道“fcdev 调试”，结果里有二进制数据时询问是否保存。
- 连接先按设置 `fcdev.emulator.debugPort` 找扩展启动的 Ember（用户数据目录按端口区分），没有端点文件再找 Ember 自己的用户数据目录。
- 用户可见的错误（参数写法、连接、请求失败）直接提示原因，其余记日志。

## 6. 构建、测试与联调

- 在 `vscode/` 里 `npm run check`：类型检查、oxlint、测试、构建与工具测试。Ember 目录里的 `npm run vscode:check` 等同于它，也包含在 Ember 的 `npm run check` 里。
- 自动测试用假传输层，不连真实的 Ember；对真实 Ember 的联调测试在 `vscode/test/real-emulator/`，用环境变量 `FCDEV_TEST_EMULATOR` 指向 `Ember.exe`，没有设置时跳过。
- 协议参考页由 `npm run help:build` 调用 `vscode/tools/gen/gen-debug-api-docs.mjs` 生成到 `ember/help/api/`。

## 7. 与调试服务的关系

- 修改请求、事件或数据类型后，`npm run schema` 更新 `vscode/debug/openrpc.json` 与 `vscode/src/contracts/debug-client/generated/api.ts`；协议参考页在构建帮助文档时自动重新生成，不提交。
- 协议规则（关闭码、限制、保活、事件队列）以 04 为准，改动协议相关代码时对照它。
