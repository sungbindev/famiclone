# 调试客户端工具

调试服务的官方客户端工具并入 fcdev 包（源码在仓库的 `packages/fcdev/debug-sdk/`，构建到 `packages/fcdev/dist/debug/`，随 `fcdev` 一同发布，不单独发布 npm 包）：SDK、终端客户端（`fcdev debug`）。调试服务本身（协议、认证、请求与事件）见 [04-调试服务.md](04-调试服务.md)，本文只写客户端工具的设计。

## 1. 决策

| 决策项 | 结论 |
| --- | --- |
| 位置 | 仓库的 `packages/fcdev/debug-sdk/`，属于 `fcdev` 包（TypeScript 源码、测试、脚本与配置自成一个子工程，脚本写在 fcdev 的 `package.json` 里，以 `debug-sdk:` 开头，依赖由仓库根目录的 npm 工作区统一安装），不属于 Ember 应用，不进入应用的打包 |
| 发布 | 不单独发布：构建产物 `packages/fcdev/dist/debug/`（不入库，`prepack` 时构建）随 `fcdev` 包发布；许可证 Apache-2.0，与 `fcdev` 同一份 |
| 开放 | 协议是开放的，其他语言与工具可以不经这个包直接连接；接口文档是随 Ember 分发的帮助文档里的“调试接口手册”（`ember/help/`，见 06 第 10 节） |
| 接口来源 | `schema/*.schema.json` 是唯一来源：`npm run schema` 生成 OpenRPC 文档与 TypeScript 类型到 `packages/fcdev/debug-sdk/generated/`（不提交）；SDK 不手写请求与事件的类型 |
| 运行时依赖 | 无；传输用全局的 WebSocket（Node 22 以上、浏览器都有），参数解析用 `node:util` |
| 终端客户端 | SDK 里的可执行入口（构建后是 `dist/debug/cli.js`），由 `fcdev debug` 运行，共用 SDK 的客户端、端点发现与接口文档读取 |
| 自动发现 | 读端点文件 `<用户数据目录>/run/debug-endpoint.json`（04 第 2.5 节），并确认写它的进程还在；也可以用环境变量或参数直接指定 |

## 2. 目录

```text
packages/fcdev/
  debug-sdk/                调试 SDK 的源码（构建到 ../dist/debug/，不入库）
    generated/              由 npm run schema 生成（不提交）：api.ts（类型）、openrpc.json（接口文档）
    scripts/
      build.mjs             esbuild 打包与声明文件
      docs.mjs              生成协议参考到 ember/help/api/（不提交）
      live-check.mjs        对运行中的 Ember 的真实联调
    src/
      index.ts              库的入口（不引用 Node 内置模块）
      node.ts               Node 入口：connectToEmber、端点文件读取
      contracts/            传输层的抽象（Transport、TransportFactory）
      shared/               错误类型、JSON-RPC 报文类型
      logic/                二进制帧解码、RPC 会话、客户端、接口文档读取、协议参考生成
      infra/                WebSocket 传输、端点文件
      entry/                组装：connect、connectToEmber、随包的接口文档
      cli/                  终端客户端 fcdev debug
    test/                   测试与假传输层
  dist/debug/               构建产物（不入库）：index.js、node.js、cli.js 与 types/
ember/help/api/             协议参考（生成，在 Ember 的帮助文档源码里，不提交）：总览加每个模块一页
```

## 3. 依赖规则

| 层 | 可以引用 |
| --- | --- |
| `contracts` | 无 |
| `shared` | 无 |
| `logic` | `contracts`、`shared`、`generated` |
| `infra` | `contracts`、`shared` |
| `entry` | 全部层（组装根） |
| `cli` | `entry`、`logic`、`shared`、`infra` 的端点发现类型 |

- `logic` 不引用 `infra`：客户端经 `Transport` 抽象通信，默认的 WebSocket 实现由 `entry/connect.ts` 注入。
- 库的入口只含平台无关的代码；`node:` 内置模块只出现在 `infra/endpoint-file.ts`、`cli` 与 `src/node.ts` 的导出链里。
- `packages/fcdev/debug-sdk/` 不引用 Ember 应用的其他源码，应用也不引用它；两者之间只有 `generated/` 这一条由 Schema 生成的联系（生成脚本在 Ember 里，把文件写进 SDK 的 `generated/`）。
- `src/cli` 的版本号取 `fcdev` 的 `package.json`（构建时内嵌）。

## 4. SDK

- `EmberDebugClient`：`open`（给定传输层工厂）连接并握手；`request` 按方法名发类型化请求；`api` 是按模块分组的接口（代理，`api.runtime.run(...)` 等同于 `request('runtime.run', ...)`）；`subscribe`/`unsubscribe`、`on`/`onAny`/`waitFor` 处理事件；`closed`、`close`。
- `RpcSession`：给请求编号、匹配响应、转发通知、超时、连接关闭时让等待中的请求失败；收到不合协议的报文时以 1002 关闭连接。
- 二进制帧由 `decodeBinaryFrame` 解码，剩余字节放回 `result.data` 或 `params.data`（`Uint8Array`）。
- 错误只有两类：`EmberRequestError`（服务端的错误响应，带模块错误码）与 `EmberConnectionError`（连接类，带种类与关闭码）。
- 事件默认不推送，客户端必须先 `subscribe`；`on` 不自动订阅。

## 5. 终端客户端

命令 `endpoint`、`methods`、`describe`、`call`、`screenshot`、`watch`；对环境的依赖（连接、输出、文件、时间）都经 `CliContext` 传入，测试用假传输层驱动；退出码 0 成功、1 失败、2 用法错误。用法见 `packages/fcdev/debug-sdk/README.md`。

## 6. 构建、测试与联调

- 在仓库根目录运行 `npm install` 一次；在 `packages/fcdev/` 里 `npm run debug-sdk:check` 依次生成 Schema 代码、类型检查（TypeScript 6）、oxlint、esbuild 构建（三个入口：库、Node 入口、终端客户端，加声明文件）与测试。Ember 目录里的 `npm run debug-sdk:check` 等同于它，也包含在 Ember 的 `npm run check` 里。
- `npm run debug-sdk:docs`（在 `packages/fcdev/` 里）在 `ember/help/api/` 生成协议参考（`npm run debug-sdk:docs:protocol` 只做这一步），并用 TypeDoc 在 `packages/fcdev/debug-sdk/docs/api/` 生成 SDK 的接口参考（都不提交）；Ember 的 `npm run help:build` 直接运行 `debug-sdk/scripts/docs.mjs`。
- 自动测试用假传输层，不连真实的 Ember。
- 联调：`packages/fcdev/debug-sdk/scripts/live-check.mjs` 对运行中的 Ember 检查连接、请求、事件、截图二进制帧、终端客户端；需要先构建，并用环境变量 `EMBER_LIVE_ROM` 指定一个 NES 文件，用 `EMBER_USER_DATA` 或 `EMBER_DEBUG_URL` 与 `EMBER_DEBUG_TOKEN` 指向开启了调试服务的 Ember。

## 7. 与调试服务的关系

- 修改请求、事件或数据类型后，`npm run schema` 更新 `packages/fcdev/debug-sdk/generated/`；协议参考页在构建帮助文档（`npm run help:build`）时自动重新生成，不提交。
- 协议规则（关闭码、限制、保活、事件队列）以 04 为准，改动协议相关代码时对照它。
