# 待办：mapper 移植

FC 卡带的 mapper 已经大批量做成官方插件，本文记录没有做完的部分：没有做的插件、已做插件的功能缺口、要补的宿主能力和验证缺口。其他事项见 [待办备忘.md](待办备忘.md)。做完一项，就把它写进 [03-mapper插件规范.md](03-mapper插件规范.md)（第 9 节的台账与第 4、6 节的规范），并从本文删掉。

## 1. 现状

| 项 | 数量 |
| --- | --- |
| 台账里的 mapper 号 | 284 |
| 已有插件的号 | 264（共 232 个插件） |
| 没有插件的号 | 20（17 个插件未做；4 号的 MMC3 已做，只缺 McAcc 变体） |

- 范围：不含 99 与 171（街机 VS 系统、学习机 BIOS 不是卡带）、UNIF 板名的 mapper、FDS、NSF、StudyBox、FNS，也不含各种外设与游戏数据库；这些不属于待办。

## 3. 要补的宿主能力

### 3.1 卡带声音（暂不做）

- 现状：`MapperCartridge` 只给 CPU 与 PPU 的总线与 IRQ，没有声音输出；主机的 APU 混音（`apu-2a03`）只混内部声道。
- 要做：新增卡带声音的契约，让卡带按采样率给出单声道采样，各主机型号把它并入 APU 的混音，音量比按芯片；各芯片做成 `mapper-chips/` 下的电路（实现 `MapperCircuit` 或新契约），插件经 `circuits` 引用；VRC7 要 YM2413 的 FM 合成。
- 关联：`mmc5`、`namco163`、`vrc6`、`vrc7`、`sunsoft-fme7`、`unl-drip-game`、`rainbow`。这是对外的新设计（契约、混音与界面音量），做之前先出方案并确认。

### 3.2 闪存与存档（暂不做）

- 现状：`un-rom512`（带闪存的变体）与 `cheapocabra` 的闪存命令序列没有处理；卡带的 PRG ROM 不可写。
- 要做：让 PRG ROM 可写，按闪存的命令序列（解锁、擦除、编程）修改，并按差异存档。
- 关联：`un-rom512`、`cheapocabra`、`rainbow`；与 3.11 的存档文件一起做。

### 3.3 mapper 电路的组合与新模式

- `mmc3` 电路增加 McAcc 的计数模式：A12 下降沿计数、每 8 次计 1 次；`$C001` 写入清零小计数器（`mc-acc`）。
- 让 `mmc2` 电路与 `mmc3` 电路能叠加在同一块卡带上：MMC3 的页寄存器经 MMC2 式的锁存选择 R0、R1、R2、R4（`mmc3-165`）；做法可以是新增一个组合电路类型，也可以让电路互相读状态，做之前先定。
- `fk23-c` 的 IRQ 带延迟与 CPU 周期钩子，核对 `mmc3` 电路能否满足，不能时增加选项。

### 3.4 脚本读 CPU 工作 RAM

- 现状：脚本只能经 `ctx.peek(地址)` 读卡带自己的 CPU 侧窗口，读不到主机的工作 RAM。
- 要做：增加只读、无副作用的读主机工作 RAM 的接口（地址范围限工作 RAM），脚本经它读（`dragon-fighter` 读 `$6A`、`$FF`）；返回值要在 03 里写明读取的是现在的内容，不触发总线副作用。
- 关联：`dragon-fighter`。

### 3.5 按条件过滤的显存地址观察

- 现状：脚本导出 `onA12` 时只在 A12 上升沿回调；要逐次观察每个显存地址变化，脚本逐次回调太慢（每次几微秒，一帧要数万次）。
- 要做：宿主按条件过滤后再回调，条件由清单声明，如“地址从非名称表区进入名称表区”（`oeka-kids`）、“名称表地址位 11 变化”（`dance2000`）。声明式条件由宿主原生判断，只在条件成立时回调脚本。
- 另需决定：`jy-company` 的“PPU 读”与“CPU 写”计数源（要计数每一次 PPU 读、每一次 CPU 写）是不是也走这套机制，还是做成电路（3.10）。
- 关联：`oeka-kids`、`dance2000`、`jy-company`。

### 3.6 开放总线位

- 现状：回调脚本的寄存器读只能返回整个字节，没有被芯片驱动的位按 0，真机上是总线残留值。
- 要做：给脚本一个“只驱动部分位”的返回方式（如返回值加掩码），或 `ctx.openBus`（读最近一次总线上的值）。
- 关联：`dance2000`（读寄存器时按位返回开放总线）；已做插件的缺口见 4.2。

### 3.7 读 PPU 的扫描线与周期

- 要做：增加只读的 `ctx.ppu`（扫描线、周期），脚本在写寄存器时用来判断当前位置；还要能在“指定扫描线的某个周期之后”触发回调（`nanjing` 在扫描线 127、239 的 256 周期之后切图案页），做成宿主的扫描线定时事件，不逐次观察显存地址；时刻要与 PPU 的实际推进对齐，不能是上一帧的值。
- 关联：`nanjing`。

### 3.8 读 ROM 的同时改变读出值

- 现状：寄存器读与窗口读二选一；寄存器的读范围不能盖住 `$8000-$FFFF`（每次取指都进脚本会把模拟拖慢到不可用），所以不能让“读地址被 DIP 开关改写”的 mapper 工作。
- 要做：窗口读增加声明式的地址改写，如“地址低 4 位替换为某个状态的值”，由宿主原生执行，不进脚本；条件（如模式为 `$10`、标志为 1）经状态声明。
- 关联：`bmc70in1`、`eh8813-a`。

### 3.9 插件设置页（暂不做）

- 现状：`ctx.settings.get` 只返回清单的出厂默认值，没有设置页，卡带上的 DIP 开关固定在默认位置。
- 要做：设置页与保存（03 第 4.7 节、05 第 4.5 节）；做好后 `ctx.settings.get` 返回用户的选择，插件脚本不用改。设置按插件保存，要考虑用户改了之后正在运行的卡带如何生效。
- 关联：已做插件见 4.1；未做的插件 `bmc70in1`、`eh8813-a`、`jy-company`、`unl-drip-game` 都读 DIP。

### 3.10 PPU 读与 CPU 写的逐次观察

- 仅 `jy-company` 需要：IRQ 的计数源之一是每次 PPU 读，另一个是每次 CPU 写。逐次观察要由宿主原生计数（做成电路，或做成声明式计数源），不能每次回调脚本。做之前先对照实现范围决定是否支持这两种源。

### 3.11 电池 RAM 与 EEPROM 的存档文件（暂不做）

- 现状：清单里带电池的存储区只在内存里保留，断电（关机或换卡带）后丢失；核心没有存档文件。这是核心整体缺的能力，不只影响 mapper 插件。
- 要做：按卡带保存与读取存档文件（位置、命名、保存时机、换卡带与退出时的写回、文件损坏的处理）；`bandai-fcg` 的 EEPROM 数据放在同一份存档里；与 3.2 的闪存差异存档一起做。
- 影响的已做插件见 4.3。

## 4. 已做插件的功能缺口

插件的主体功能（换页、镜像、IRQ 计数等）都已实现并有测试向量；下面是依赖没做的宿主能力而与真机有差别的部分。

### 4.1 DIP 开关固定为默认值（缺 3.9）

`mapper-83`、`yoko`、`unl-d1038`、`bmc8157`、`bs5`、`mmc3-bmc411120-c`、`bmc-hpxx`、`mmc1-105`、`sachen74-ls374-n`：清单已经声明 `settings`，脚本经 `ctx.settings.get` 读，目前永远是默认值，多合一卡的游戏选择、难度这类功能受限。

### 4.2 寄存器读时开放总线位为 0（缺 3.6）

TXC 系列（`sachen-136`、`sachen-147`、`txc22000`、`txc22211-a`、`txc22211-b`、`txc22211-c`）、`bandai-fcg`、`mapper-83`、`yoko`：读寄存器时芯片没有驱动的位固定为 0，真机上是总线残留值；个别游戏依赖这些位时会出错。

### 4.3 存档不落盘（缺 3.11）

带电池的存储区：`mmc1`（含文件头标明带电池的所有变体）、`mmc3`、`farid-slrom`、`mmc1-105`、`taito-x1005`、`taito-x1017`、`racermate`、`sachen9602`，以及其他 `storage` 里用 `prgAny`、`prgNvram` 并且文件头标明带电池的插件。`bandai-fcg` 的 EEPROM（24C01、24C02 的读写状态机已实现）同样只在内存里。

### 4.4 闪存命令没有处理（缺 3.2）

`un-rom512`（带闪存的变体）、`cheapocabra`：游戏用闪存存档的功能不能用，按普通 ROM 处理。

### 4.5 外设没有做

Datach 的条码读取器（`bandai-fcg` 的 157）、卡拉 OK 的麦克风（188）、手写板（96）、自行车（168）没有做；`devices` 目前只有 `mouse`。要做时在清单的 `devices` 增加外设名，并在界面与输入里增加对应的采集。

## 5. 验证缺口

- 所有官方插件只有测试向量验证：向量按芯片的行为写出“写这个寄存器后这个地址映射到哪一页”，再由运行器核对；没有用真实游戏或测试 ROM 验证过，向量与真机不一致的地方只能靠以后用游戏发现。
- MMC3 的 A12 滤波：电路用“A12 先低过 4 次显存访问”，不是按 PPU 周期数；有公开的 MMC3 测试 ROM 时核对，放进 `core/test/data/` 并写入 README。
- `onA12`（A12 上升沿回调）的滤波与 MMC3 电路用同一个规则，同样没有用测试 ROM 验证。
- 计数器类硬件用 `ctx.timer` 与 `onTimer` 实现，没有做成声明式的 `counters`（03 第 6.4 节已写明）；有测试 ROM 时核对 IRQ 的触发时刻。
