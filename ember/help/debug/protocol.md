# 连接与报文

调试服务是 WebSocket 服务，报文是 JSON-RPC 2.0。接口是开放的，可以用任何语言、任何工具连接；官方的客户端见[客户端工具](clients.md)。

## 连接与握手

- 地址 `ws://127.0.0.1:<端口>/`，路径必须是 `/`，可选子协议 `ember-debug.v1`。
- 服务端检查升级请求：方法必须是 GET；`Host` 必须是 `127.0.0.1`、`localhost` 或 `[::1]` 加服务的端口；`Origin` 没有（命令行与脚本）或指向本机才允许，否则返回 403。
- 升级成功后 5 秒内必须发 `debug.hello` 并带正确的令牌，否则以关闭码 4001 关闭连接。没有先握手就发别的请求、或令牌不对，先回 `debug.unauthorized` 错误响应，再以 4001 关闭。
- 在首选项里更换令牌后，已建立的连接以关闭码 4002 关闭，之后的握手按新令牌检查。

### 关闭码

| 关闭码 | 含义 |
| --- | --- |
| 1000 | 正常 |
| 1001 | 服务停止 |
| 1002 | 协议错误 |
| 1003 | 客户端发了二进制消息 |
| 1007 | 文本不是 UTF-8 |
| 1008 | 空闲超时 |
| 1009 | 消息太大 |
| 4001 | 令牌不对或没有握手 |
| 4002 | 令牌已更换 |

## 报文

每条消息一个文本帧（UTF-8），参数按名称传递，`params` 是对象，可以省略。

| 报文 | 字段 |
| --- | --- |
| 请求 | `jsonrpc`（固定 `"2.0"`）、`id`（整数或字符串）、`method`（`<模块>.<操作>`）、`params` |
| 成功响应 | `jsonrpc`、`id`、`result` |
| 错误响应 | `jsonrpc`、`id`（请求无法解析时为 `null`）、`error`：`code`（整数）、`message`（说明）、`data.code`（模块里登记的错误码，如 `runtime.noCartridge`） |
| 事件（通知） | `jsonrpc`、`method`（`<模块>.<事件>`）、`params`（事件数据），没有 `id` |

```text
-> {"jsonrpc":"2.0","id":1,"method":"debug.hello","params":{"client":"my-tool","token":"<令牌>"}}
<- {"jsonrpc":"2.0","id":1,"result":{"protocol":1,"coreVersion":"0.1.0","appVersion":"0.1.0","session":1}}
-> {"jsonrpc":"2.0","id":2,"method":"runtime.run","params":{"frames":300,"wait":true}}
<- {"jsonrpc":"2.0","id":2,"result":{"frames":300,"stopped":"completed"}}
-> {"jsonrpc":"2.0","id":3,"method":"nobody.home"}
<- {"jsonrpc":"2.0","id":3,"error":{"code":-32601,"message":"没有登记：nobody.home","data":{"code":"core.unknownRequest"}}}
```

- 没有 `id` 的请求是通知：照常执行，不回响应。不支持批量请求（数组），发数组返回 -32600。
- `rpc.discover` 没有参数，返回描述全部请求与事件的 OpenRPC 文档，工具可以据此生成客户端。

### 错误码

| `error.code` | 含义 |
| --- | --- |
| -32700 | 报文不是合法的 JSON |
| -32600 | 不是合法的 JSON-RPC 请求 |
| -32601 | 方法不存在（`core.unknownRequest`） |
| -32602 | 参数不合格（`core.invalidParams`） |
| -32603 | 核心内部错误（`core.internal`，详情写进错误日志，不返回给客户端） |
| -32000 | 其余业务错误，具体看 `error.data.code` |

## 二进制帧

结果或事件数据里顶层的 `data` 字段如果是二进制（如截图、内存内容），整条消息改发一个二进制帧，不再发文本帧：

| 部分 | 内容 |
| --- | --- |
| 前 4 字节 | 大端的无符号整数 N，JSON 报文的字节数 |
| 接下来的 N 字节 | JSON-RPC 报文（UTF-8），其中没有 `data` 字段，其余字段照常 |
| 其后的全部字节 | `data` 的原始内容 |

客户端收到二进制帧后，按 N 取出 JSON 报文，再把剩余字节当作 `result.data`（响应）或 `params.data`（事件）。客户端发给服务端的二进制帧不接受（关闭码 1003）。

## 限制、保活与事件队列

- 一条请求最大 4 MB，超过关闭连接（1009）。最多 32 条连接。
- 同一条连接上的请求按到达顺序逐个处理：一个请求（如带 `wait` 的 `runtime.run`）没有返回之前，后面的请求排队。要并行就开多条连接。
- 服务端每 30 秒发一次 ping，90 秒没有收到该连接的任何数据就关闭（1008）；客户端发 ping 服务端立即回 pong。
- 事件默认不推送，要先用 `debug.subscribe` 订阅。每条连接排队等待发送的事件最多 1024 条，超过后丢弃新事件，队列空下来后发一条 `debug.eventsDropped`（带丢弃的条数）。响应不会被丢弃。读得慢的客户端只丢自己的事件，不拖慢模拟和其他连接。
- 连接断开时，这条连接订阅的事件自动取消，正在处理的请求被取消（`core.cancelled`），模拟器的运行状态不变。

## 端点文件

调试服务开始监听后，会在用户数据目录写端点文件 `run/debug-endpoint.json`，令牌更换时更新，服务停止或核心退出时删除。命令行与智能体的工具读它就能自动连接，不用手抄端口和令牌。

```json
{ "url": "ws://127.0.0.1:5688/", "port": 5688, "token": "<令牌>", "pid": 12345, "coreVersion": "0.1.0", "appVersion": "0.1.0", "startedAt": "2026-11-14T08:00:00Z" }
```

文件里有令牌，位置在当前用户的目录下。Windows 上用户数据目录默认是 `%APPDATA%\Ember`。
