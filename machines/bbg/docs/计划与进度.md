# 步步高工程：计划与进度

## 目标

整理步步高（BBG）BIOS 与 DOS 的原厂源码：写出能汇编它们的汇编器，还原缺失的符号文件，核对源码与 ROM 的关系；以此为基础，把 BIOS 移植到小霸王 SB2000 上运行。移植后的 BIOS 与加载器是 SB-DOS 下的程序，在 [apps/sb2000/bbg-bios](../../../apps/sb2000/bbg-bios/docs/计划与进度.md) 和 [apps/sb2000/bbg-loader](../../../apps/sb2000/bbg-loader/README.md)。

## 阶段

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 1 | 建工程骨架与路径常量 | 已完成 |
| 2 | GABBG 方言汇编器，用测试固定语法 | 已完成 |
| 3 | 还原 `tvdef.asm`，三份原厂源码汇编后未定义符号为 0 | 已完成 |
| 4 | 用原厂 `Bios.asm` 构建 NES ROM，在步步高模拟器里加载 DOS 启动盘，直到出现命令提示符 | 已完成（见下节） |
| 5 | 探测程序 `apps/sb2000/fcprobe`：进入 FC 模式后验证 RAM 可写、软驱可读、键盘有输入 | 已完成，结论是 FC 模式走不通（见下节） |
| 6 起 | 6576 模式移植、加载器、中文显示等 | 在 [apps/sb2000/bbg-bios](../../../apps/sb2000/bbg-bios/docs/计划与进度.md) |

## 原厂源码的完整性

资料是 BBGDOS 源代码，共 3 份汇编源码与 3 个二进制：

| 文件 | 类型 | 内容 | 状态 |
| --- | --- | --- | --- |
| `Bios.asm` | 源码，7412 行 | ROM BIOS，位于最后一页（`$C000-$FFFF`）：启动、中断、分页、软驱、键盘、基本显示、BIOS 调用 | 完整；汇编后 16118 字节，除缺符号文件外自成一体；本工程的 `src/bios/Bios.asm` 由它移植而来 |
| `Command.asm` | 源码，5337 行 | 命令解释器（中文版），不含硬件寄存器访问 | 完整，只调用 BIOS 与 DOS |
| `Smcdos.asm` | 源码，5843 行 | 中文显示驱动，直接写 PPU 与分页寄存器 | 完整 |
| `Bbgdos.sys` | 二进制，14822 字节 | BBGDOS 内核（英文版），起始地址 `$7C00` | **没有源码**：文件系统、内存页管理、DOS 调用（`$580C`）、扩展 BIOS 显示功能都在这里 |
| `Command.sys` | 二进制，15614 字节 | 命令解释器（英文版） | 与 `Command.asm` 不是同一版本 |
| `Smdos.sys` | 二进制，16647 字节 | 另一个内核变体，起始地址 `$7C00` | 没有源码 |

缺失的 `tvdef.asm`：三份源码都 `include tvdef.asm`，里面是系统调用入口、BIOS 与 DOS 功能号、出错码、文件通道结构和固定地址，以及宏 `orgrun`、`orgreal`。使用手册里有功能号与出错码，源码注释里有固定地址，所以能还原；已还原到 [../src/include/tvdef.asm](../src/include/tvdef.asm)，三份源码汇编后未定义符号为 0。

`bbg1_bios.rom`（128KB）的前 7 页是字库点阵数据，第 8 页才是 `Bios.asm` 对应的代码。

## 已查明的结论

- 汇编语法与常见 6502 汇编器的差别：表达式没有优先级，从左到右计算；立即数前缀 `<` 取高字节、`>` 取低字节，与常规相反；`^` 取相对页号；`orgrun` 改运行地址而字节顺序存放。
- 原厂 `Bios.asm` 与 `bbg1_bios.rom` 不是同一次构建，只有 605 字节相同；但把不含绝对地址的指令按 6 条一组去查，274 组里有 239 组（87%）出现在 BIOS 1.0 ROM 里，在 BIOS 2.0 ROM 里是 192 组（70%）。这说明汇编器的编码正确，且三者是同一份代码的不同版本，不需要反汇编 ROM。
- `Command.sys` 里是英文提示串，与中文版 `Command.asm` 只有 7/184 组相同，`Smcdos.asm` 与两个 `.sys` 基本不同。所以不能用这三个 `.sys` 文件验证 `Command.asm`、`Smcdos.asm`。
- 原厂 `Bios.asm` 里有 `;comment %` 开关，去掉分号就把调试监控器（经并口与 PC 调试）相关的 7 个代码块整块注释掉，冷启动入口改走复位向量，这是正式版的配置；移植时按它处理。
- 推测值：`DosGetDOSVersion` 取 16、`StackTooDepth` 取 `$2B`，手册与源码都没有给出。

## 阶段 4 的结果：原厂 `Bios.asm` 能构建并启动到 DOS

方法：把 `Bios.asm` 汇编结果放进 128KB ROM 的最后一页，前 7 页取自 `bbg1_bios.rom`，在步步高调试版模拟器里加载它和 `dos启动盘.IMG`（构建与启动用的 `build-nes.mjs`、`boot.mjs` 已被 `BIOS.BBG` 的构建取代并删除，结论仍有效）。

| 项目 | 原版 `bbg1_bios.rom` | 由 `Bios.asm` 构建 |
| --- | --- | --- |
| 开机系统检测画面（蓝底“系统检测、内存”） | 有，左上角有“步步高”徽标 | 有，没有徽标 |
| 从软盘装载 BBGDOS | 显示 `Starting BBGDOS...` | 同左 |
| 回车通过日期、时间提示 | 进入 `A:\>`，显示 `BBGDOS Version 3.0` | 同左 |
| DOS 显示的默认日期 | 1996-09-14 | 2043-05-23（原因未查，BIOS 返回的版本年月两者相同：97 年 1 月） |

## 阶段 5 的结果：FC 兼容模式走不通

方法：SB-DOS 下运行探测程序 `fcprobe`，它关中断、把扩展 RAM 的第 3 个 128K 窗口预置成 `$AA`、改写向量，再写 `$5006`、`$4301` 进入 FC 模式，CPU 复位后执行放在扩展 RAM `$6100` 的探测桩，结果写到 `$7F00` 起，由 `node tools/probe-fc.mjs` 读出并打印。

| 项目 | 结果 |
| --- | --- |
| `$9100`、`$A100`、`$C100`、`$E100` 写 0 | 写后仍是预置的 `$AA`，写入无效：`$8000-$FFFF` 在 FC 模式下不是可写内存 |
| `$0300`、`$5100`、`$6800`、`$7000` 写 `$5A` | 读回 `$5A`，可写：内部 2K、`$5000-$5FFF` 的 2K、`$6000-$7FFF` 的 8K |
| 标准 PPU 名表 `$2000` 写读 | 可写 |
| 图案表 `$0000` 经 `$2007` 写 `$A5` | 读回 `$00`，不可写：CHR 是只读的 |
| DMA 把扩展 RAM 的 `$AA` 复制到图案表 | 读回 `$00`，DMA 无效（Ember 实测如此，未在真机验证） |
| 软驱 | 可访问 |
| 键盘 | 注入回车时 `$4020` 是 `$FF`、`$4033` 是 0；注入 A 后 `$4020` 为 `$1E`（Ember 实测如此，未在真机验证） |

结论：FC 模式下程序装载区不能写、CHR 不能由 CPU 写，步步高 BIOS 与 DOS 依赖的程序装载和 CHR 写入都做不到；6576 模式里这两件事都可行，所以改用 6576 模式。以上均为 Ember 实测，未在真机验证。
