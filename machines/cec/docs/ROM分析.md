# 中华学习机 CEC-I：ROM 分析

中华学习机 CEC-I 是兼容苹果 II+ 的 6502 学习机，不是 FC 体系：没有 PPU 与 APU，不插卡带，软驱是苹果 Disk II 格式的 5.25 英寸低密度软驱。本文记录对它的 ROM 芯片文件的分析，以及据此推断出的地址译码与软开关，Ember 的 `cec1` 机型（见 `ember/docs/02-硬件模块.md` 第 6.13 节）按这里的结论实现。没有真机与电路资料，所有结论来自 ROM 的反汇编、开机自检程序和在模拟器里运行软盘的结果，没有经过真机核对。

## 文件

芯片文件在 `reference/study_roms/中华学习机/`：

| 文件 | 大小 | 内容 |
| --- | --- | --- |
| `1.1a-U7.bin`、`1.21-U7.bin` | 32KB | 主板 ROM U7：低 16K 是 LOGO 语言，高 16K 是 `$C000-$FFFF` 的监控、CEC-BASIC 与内部 ROM |
| `1.1a-U35.bin`、`1.21-U35.bin` | 32KB | 汉字系统 ROM U35：低 16K 是汉字表（含拼音表），高 16K 是 `$C000-$FFFF` 的汉字程序与槽 ROM |
| `p6.bin` | 256KB | 只有前 256 字节有内容，其余全是 `$FF`：苹果 Disk II 的 P6 状态机 ROM（开头 `18 D8 18 08 0A 0A 0A 0A`），Ember 直接按位模拟，不使用它 |

两个版本大小相同，结构相同，差别在 U7 的 LOGO、BASIC 与内部 ROM 的少量字节，以及 U35 复位向量：1.1a 的复位向量是 `$FFE0`，1.21 是 `$FFF0`，都是 `JMP ($03F2)`。Ember 的 ROM 文件把 U7 放在前、U35 放在后，拼成 64KB（`ember/roms/cec1_v1.1a.bin`、`cec1_v1.21.bin`）。

## ROM 的内容

U7 高 16K 对应 CPU 地址 `$C000-$FFFF`：

- `$D000-$FFFF`：苹果 II+ 的监控（复位向量 `$FA62`，NMI `$03FB`，IRQ `$FA40`）与改过的 Applesoft（CEC-BASIC，关键字表里多了 `MUSIC`、`PLAY`）；复位程序先调用 `$D300` 做初始化，再扫描 `$C7` 到 `$C1` 各槽的 `$CnFD-$CnFF` 是不是“CEC”标志（`C3 C5 C3`），都不是时按槽 6 引导。
- `$C100-$CFFF`：内部 ROM（内部 ROM 开关打开时可见）：开机自检、BASIC 的附加表与出错信息、`$C700` 处一份槽 6 的引导程序，以及把 LOGO 与汉字系统从 ROM 拷进 RAM 的装载程序。

U35 高 16K：`$C300` 是槽 3 的汉字卡驱动，`$C600` 是标准的 Disk II 引导 ROM（`A2 20 A0 00 A2 03 86 3C ...`），`$D000-$FFFF` 是汉字程序，页首有“VERSION1.21 ZHONG HUA XUE XI JI”。

开机自检（U7 内部 ROM 的 `$CB80` 起，开机时按住 Ctrl 再按 V 进入）逐项检查 RAM、语言卡两个 bank 与四块 ROM 的异或校验，校验表在 `$CDFB`：`$43`（LOGO）、`$AF`（CEC-BASIC）、`$FE`（汉字表）、`$98`（汉字程序）、`$AC`（CECWL）、`$00`（空）。对 1.21 逐块计算：U7 低 16K 为 `$43`，U7 高 16K 的 `$D000-$FFFF` 为 `$AF`，U35 低 16K 为 `$FE`，U35 高 16K 的 `$D000-$FFFF` 为 `$98`，与表对应。第五项 CECWL 是 `$4000-$7FFF` 经 `$C0B0` 低 4 位选 16 个 16K bank（共 256KB）的一块 ROM，不在这些文件里，空座时读 0，自检显示 NULL。

## 地址译码的推断

自检程序与装载程序把四块 ROM 拿“辅存读开关”和“辅助零页开关”当切换手段：

| 访问 | 可见内容 |
| --- | --- |
| `$8000-$BFFF`，辅存读开关（`$C002` 关、`$C003` 开）为 1，`$C0B0` 位 5 为 1 | U7 低 16K（LOGO） |
| 同上，`$C0B0` 位 5 为 0 | U35 低 16K（汉字表） |
| `$4000-$7FFF`，辅存读开关为 1 | 字库 ROM 的第 `$C0B0 & $0F` 个 16K bank；没有字库读 0 |
| `$C100-$CFFF`，内部 ROM 开关（`$C006` 关、`$C007` 开）为 1 | U7 高 16K 的同址内容 |
| 同上，开关为 0 | U35 高 16K 的同址内容（槽 ROM，空白页是 `$FF`）；`$C3xx` 在槽 3 开关（`$C00A` 关、`$C00B` 开）为 0 时也读 U7 |
| `$D000-$FFFF`，辅助零页开关（`$C008` 关、`$C009` 开）为 1 | U35 高 16K（汉字程序），不管语言卡的读状态 |
| 同上，开关为 0 | 语言卡读 RAM 时是语言卡存储，否则 U7 高 16K |

装载程序（`$C647` 起）依次把 LOGO 拷到 `$3000-$6FFF`、汉字表的前 5K 拷到 `$7000` 起、汉字程序拷到 `$8400` 起与 `$1BF0` 起，之后 LOGO 与汉字系统都在 RAM 里运行；拷贝时先把辅存读开关与写开关置 1、拷贝每个字节前后又关掉，所以写入总是进主存。Ember 把辅存写开关只当作记状态的开关。

`$C0B0` 的用法：开机自检时 `$00`（读汉字表、`$4000-$7FFF` 扩展 ROM 的 bank 0 起）、`$20`（选 LOGO）、`$00-$0F`（选字库 bank）；复位后写 `$10`，汉字系统另有一处把 `($04FB & $10) | $EF` 写进去，位 4 的作用没有查明。

软开关用到苹果 IIe 的写开关（`$C000-$C00F`）与 `$C010`，没有读 IIe 的状态（`$C011-$C01F`）；`$C020` 磁带输出、`$C030` 扬声器、`$C050-$C057` 显示、`$C060-$C067` 磁带输入与按键与模拟手柄、`$C070` 手柄触发、`$C080-$C08F` 语言卡（自检用写访问打开写允许，所以读写都算一次访问）。`$C0AE`、`$C0AF` 是汉字系统等待输入的串口（先写 `$03`、`$11`，读 `$C0AE` 位 0 等数据，读 `$C0AF` 取数），`$C090` 与 `$C1C1` 是打印口。

## 软驱与盘片

软驱接口在槽 6：`$C0E0-$C0EF` 是 Disk II 的 16 个软开关，ROM 里的引导程序与 DOS 3.3 的读写盘程序按它工作。`reference/floppy-images/cec/` 里的镜像：

- `143360` 字节：35 道、每道 16 个扇区；`163840` 字节：40 道（CEC-I 的驱动器能走到第 40 道）。
- 扇区顺序有 DOS 顺序与 ProDOS 顺序两种，按镜像内容认出：DOS 3.3 的卷目录表在第 17 道第 0 扇区，ProDOS 的卷目录头在块 2。DOS 顺序下的逻辑扇区到物理扇区的对应表是 `{0,13,11,9,7,5,3,1,14,12,10,8,6,4,2,15}`。
- 目录里还有 `XLB.dsk`（107520 字节）这种大小不对的镜像，Ember 认不出格式，读盘时读到杂波。

`CEC-I/` 里的盘有的用了未公开的 6502 指令：`CJHZWZBJ.dsk`（超级汉字文章编辑系统）的引导扇区用 `$AB`（LAX 立即数，A 与 X 都取立即数）和 `$0F`（SLO 绝对）算出跳转地址，所以 Ember 的 CPU 核补了 `$AB`。

## 在 Ember 里验证过的

- 1.21 开机显示 ZHONG HUA XUE XI JI / VERSION1.21 并到 BASIC 的 `]` 提示符；开机自检里 RAM、BNK1、BNK2 通过，ROM1、ROM2、AUX1、AUX2 分别认出 LOGO、CEC-BASIC、HZTABLE、HZPROGRAM。
- Apple DOS 3.3 系统盘与 DOS 3.3 的 160K 盘从软驱引导，`CATALOG` 列出目录，`SAVE` 写盘后 `CATALOG` 看到新文件。
- `loderunner.dsk` 的高分辨率游戏运行；`CJHZWZBJ.dsk` 引导并显示封面（菜单里的汉字依赖字库，字库不在这些文件里，显示为空白）；`ZHJXTPCEC-DOS.dsk` 的音乐程序翻转扬声器。

## 没有查明的

- `$C0B0` 位 4 的作用；汉字字库（CECWL，256KB）的内容与 bank 选法；串口 `$C0AE`、`$C0AF` 的收发；制式与时钟；字符发生器（Ember 用自带字库代替）；LOGO 语言与汉字输入没有逐项验证。
