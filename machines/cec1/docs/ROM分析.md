# 中华学习机 CEC-I：ROM 分析

中华学习机 CEC-I 是兼容苹果 II+ 的 6502 学习机，不是 FC 体系：没有 PPU 与 APU，不插卡带，软驱是苹果 Disk II 格式的 5.25 英寸低密度软驱。本文记录对它的 ROM 芯片文件的分析，以及据此推断出的地址译码与软开关，再按《中华学习机 CEC-Ⅰ 技术参考手册》（硬件、软件两册）与 1.21 版使用介绍核对后的结论，Ember 的 `cec1` 机型（见 `ember/docs/02-硬件模块.md` 第 6.13 节）按这里的结论实现。手册是扫描件，文字经识别得到，识别有错字，与 ROM 行为对不上时以 ROM 为准；没有真机，所有结论没有经过真机核对。

## 文件

芯片文件：

| 文件 | 大小 | 内容 |
| --- | --- | --- |
| `1.1a-U7.bin`、`1.21-U7.bin` | 32KB | 主板 ROM U7：低 16K 是 LOGO 语言，高 16K 是 `$C000-$FFFF` 的监控、CEC-BASIC 与内部 ROM |
| `1.1a-U35.bin`、`1.21-U35.bin` | 32KB | 汉字系统 ROM U35：低 16K 是汉字表（含拼音表），高 16K 是 `$C000-$FFFF` 的汉字程序与槽 ROM |
| `p6.bin` | 256KB | 只有前 256 字节有内容，其余全是 `$FF`：苹果 Disk II 的 P6 状态机 ROM（开头 `18 D8 18 08 0A 0A 0A 0A`），Ember 直接按位模拟，不使用它 |

两个版本大小相同，结构相同，差别在 U7 的 LOGO、BASIC 与内部 ROM 的少量字节，以及 U35 复位向量：1.1a 的复位向量是 `$FFE0`，1.21 是 `$FFF0`，都是 `JMP ($03F2)`。Ember 的 ROM 文件把 U7 放在前、U35 放在后，拼成 64KB（`ember/roms/cec1_v1.1a.bin`、`cec1_v1.21.bin`）。

主板上一共有六块 ROM，这个目录只有前两块：

| 芯片 | 容量 | 内容 | 状态 |
| --- | --- | --- | --- |
| U7、U35 | 各 32KB（27256） | 见上 | 已有 |
| U33（CECWL1）、U34（CECWL2） | 各 128KB（1Mbit 掩模） | 汉字字库：16×16 点阵，每个字模 32 字节，U33 存左半（偶地址）、U34 存右半（奇地址） | 没有，Ember 内置开源字库（GNU Unifont）代替 |
| 显示码 ROM（2732） | 4KB | 1K 反相字符、1K 正常字符，后 2K 是图形转换用的数据 | 没有，Ember 用苹果 IIe 增强版的视频 ROM 字形代替 |
| 键盘码表（2716） | 2KB | 键盘 KB3600（69 键）的键码表 | 没有，Ember 按手册第 3.25 表的键码实现 |

Ember 的 ROM 文件在 U7、U35 之后可以再接 U33 与 U34 的原始内容（各 128KB，U33 在前），共 320KB。

## ROM 的内容

U7 高 16K 对应 CPU 地址 `$C000-$FFFF`：

- `$D000-$FFFF`：苹果 II+ 的监控（复位向量 `$FA62`，NMI `$03FB`，IRQ `$FA40`）与改过的 Applesoft（CEC-BASIC，关键字表里多了 `MUSIC`、`PLAY`）；复位程序先调用 `$D300` 做初始化，再扫描 `$C7` 到 `$C1` 各槽的 `$CnFD-$CnFF` 是不是“CEC”标志（`C3 C5 C3`），都不是时按槽 6 引导。
- `$C100-$CFFF`：内部 ROM（内部 ROM 开关打开时可见）：开机自检、BASIC 的附加表与出错信息、`$C700` 处一份槽 6 的引导程序，以及把 LOGO 与汉字系统从 ROM 拷进 RAM 的装载程序。

U35 高 16K：`$C300` 是槽 3 的汉字卡驱动，`$C600` 是标准的 Disk II 引导 ROM（`A2 20 A0 00 A2 03 86 3C ...`），`$D000-$FFFF` 是汉字程序，页首有“VERSION1.21 ZHONG HUA XUE XI JI”。

开机自检（U7 内部 ROM 的 `$CB80` 起，开机时按住 Ctrl 再按 V 进入）逐项检查 RAM、语言卡两个 bank 与四块 ROM 的异或校验，校验表在 `$CDFB`：`$43`（LOGO）、`$AF`（CEC-BASIC）、`$FE`（汉字表）、`$98`（汉字程序）、`$AC`（CECWL）、`$00`（空）。对 1.21 逐块计算：U7 低 16K 为 `$43`，U7 高 16K 的 `$D000-$FFFF` 为 `$AF`，U35 低 16K 为 `$FE`，U35 高 16K 的 `$D000-$FFFF` 为 `$98`，与表对应。第五项 CECWL 是 `$4000-$7FFF` 经 `$C0B0` 低 4 位选 16 个 16K 页（共 256KB）的汉字字库（U33 与 U34），不在这些文件里，空座时读 0，自检显示 NULL。

## 地址译码的推断

自检程序与装载程序把四块 ROM 拿“辅存读开关”和“辅助零页开关”当切换手段：

| 访问 | 可见内容 |
| --- | --- |
| `$8000-$BFFF`，辅存读开关（`$C002` 关、`$C003` 开）为 1，`$C0B0` 位 5 为 1 | U7 低 16K（LOGO） |
| 同上，`$C0B0` 位 5 为 0 | U35 低 16K（汉字表） |
| `$4000-$7FFF`，辅存读开关为 1 | 汉字字库：芯片地址是 `($C0B0 & $0F) × 8192 + 页内偏移 ÷ 2`，偶偏移读 U33、奇偏移读 U34，CPU 读到的字节与芯片里的位序相反（芯片里的 `$01` 读到 `$80`）；没有字库读 0 |
| `$C100-$CFFF`，内部 ROM 开关（`$C006` 关、`$C007` 开）为 1 | U7 高 16K 的同址内容 |
| 同上，开关为 0 | U35 高 16K 的同址内容（槽 ROM，空白页是 `$FF`）；`$C3xx` 在槽 3 开关（`$C00A` 关、`$C00B` 开）为 0 时也读 U7（两个开关里只要有一个置成内部 ROM，`$C3xx` 就在内部 ROM；复位后是内部） |
| `$D000-$FFFF`，语言卡读 RAM 且辅助零页开关（`$C008` 关、`$C009` 开）为 1 | U35 高 16K（汉字程序，辅存里的 12K ROM），用法是 `LDA $C080`、`STA $C009` |
| 同上，开关为 0 | 语言卡存储 |
| 同上，语言卡读 ROM（不管辅助零页开关） | U7 高 16K |

写的译码：`$0000-$3FFF` 写主存；`$4000-$BFFF` 在辅存写开关（`$C004` 关、`$C005` 开）为 0 时写主存，为 1 时写进了辅存里的 ROM，丢弃；`$D000-$FFFF` 在语言卡写允许且辅助零页开关为 0 时写语言卡存储，其余丢弃。辅存的 `$0000-$3FFF` 与主存是同一块 RAM，所以辅存读写开关对 `$0200-$3FFF`、辅助零页开关对 `$0000-$01FF` 没有效果。

语言卡（`$C080-$C08F`）的开关逻辑（手册）：读 ROM 使能 = A0 异或 A1，RAM 写使能 = A0，第一个 bank = A3。Ember 按手册实现：奇数地址的访问允许写、偶数地址的访问禁止写，不要求连续两次访问。

装载程序（`$C647` 起）依次把 LOGO 拷到 `$3000-$6FFF`、汉字表的前 5K 拷到 `$7000` 起、汉字程序拷到 `$8400` 起与 `$1BF0` 起，之后 LOGO 与汉字系统都在 RAM 里运行；拷贝时先把辅存读开关与写开关置 1、拷贝每个字节前后又关掉，所以写入总是进主存。Ember 把辅存写开关只当作记状态的开关。

`$C0B0` 的用法（手册：槽 3 的设备选择区 `$C0B0-$C0BF`，只有一个锁存器）：位 0 到 3 是字库页号，位 4 为 1 允许彩色、为 0 只显示单色（复位后写 `$10`，汉字系统用 `($04FB & $10) | $EF` 把彩色与否交给 `$04FB`，汉字方式下默认是单色），位 5 选 `$8000-$BFFF` 读 LOGO（1）还是汉字表（0）。开机自检时写 `$00`（读汉字表、字库页 0）、`$20`（选 LOGO）、`$00-$0F`（选字库页）。

软开关是苹果 IIe 的那一套（手册把它们分成内存切换、内部 ROM 与 I/O 切换、`$D000-$FFFF` 选择、显示缓冲区选择四类）：写 `$C000-$C00F`（偶数关、奇数开：80STORE `$C000/$C001`、RAMRD `$C002/$C003`、RAMWRT `$C004/$C005`、内部 ROM `$C006/$C007`、ALTZP `$C008/$C009`、SLOTC3ROM `$C00A/$C00B`），读 `$C011-$C01F` 取状态（位 7）；`$C000` 读键盘、`$C010` 清键盘标志；`$C020` 磁带输出、`$C030` 扬声器、`$C050-$C057` 显示；`$C060` 磁带输入；`$C061-$C063` 是游戏接口的三个 TTL 开关量 SW0 到 SW2（按下读到位 7 为 1，不是 Shift）；`$C064-$C067` 四个模拟量，`$C070` 触发计时；`$C080-$C08F` 语言卡；`$C0AE`、`$C0AF` 是汉字系统等待输入的串口（先写 `$03`、`$11`，读 `$C0AE` 位 0 等数据，读 `$C0AF` 取数）。

制式与时钟（手册）：主时钟 14.318 MHz，经分频得到 7.159 MHz 的视频点钟与 3.58 MHz 的色度参考，6502 约 1.023 MHz；TCA650 PAL 编码器只把输出转成 PAL 视频，机内的扫描仍是苹果 II 的 262 行、约 60 Hz，Ember 的时钟与此一致。

## 汉字字库的寻址

汉字程序（U35 的 `$ECCD` 起）按区位算出字模序号 N：ASCII 的 N 就是它的码；区位字的 N = 256 + 94 × 区序号 + 位 - 1，区 1 到 9 的区序号是 0 到 8，区 16 到 87 的是 9 到 80（区 10 到 15 走用户自定义例程，不读字库）；N 除以 512 是 `$C0B0` 的页号，N 除以 512 的余数乘 32 加 `$4000` 是 CPU 读字模的地址。每个字模 32 字节：16 行，每行左半在偶地址（U33）、右半在奇地址（U34），读到的字节位 0 在最左；ASCII 只用左半。用合成的字库探测出这些细节：把字模写成已知图案，进入汉字方式后读 HGR 第 2 页，字节位置与图案对应。Ember 的内置字库（GNU Unifont，SIL OFL 1.1）按这个布局重排，开机封面用区位 2-1 当空白填充，所以这个字模留空。

## 键盘

KB3600 共 69 键，键码由 2716 的表给出（手册第 3.25 表）：字母不按 Shift 是小写，Shift 或 CapsLock 按下后大写，Ctrl 加字母是 `$01-$1A`；数字与符号按美式键盘排列；Ctrl 加 6 是 `$1E`，Ctrl 加 Shift 加减号是 `$1F`，`\ [ ]` 加 Ctrl 是 `$1C-$1D`、`$1B`；专用键不随 Shift 与 Ctrl 变化：中文 `$1F`、西文 `$11`、F1 `$01`、F2 `$0C`、F3 `$17`、F4 `$14`、F5 `$06`、ESC `$1B`、TAB `$09`、Quit `$03`、Return `$0D`、空格 `$20`、TEST `$16`，左 `$08`、右 `$15`、上 `$0B`、下 `$0A`。Ctrl+Reset+TEST 进入自检（本目录前面写的 Ctrl 加 V 是自检程序里的另一个入口），Ctrl+Reset 是热启动；1.21 版增加 Ctrl+Reset+西文 同时按下的冷启动。

Ember 的键位：F1 到 F5 对应 F1 到 F5，F6 是中文，F7 是西文，F8 是 TEST，Pause 是 Quit，其余按 PC 键盘的物理位置对应。

## 汉字系统

汉字系统在主板上，可选装，占用槽 3；主板只有一个 50 针的苹果兼容扩展槽，手册里只提到打印机接口卡，没有 80 列卡与 80 列文本。进入：中文键、`PR#3`、监控里 `3 Ctrl-P`（或 `Ctrl-K`）；退出：西文键、`TEXT`、`PRINT CHR$(17)`、监控里 `C33AG`。汉字屏是高分辨率第 2 页，一行 17 个汉字（或 34 个 ASCII）、共 10 行，带一行状态提示；F1 字母、F2 拼音、F3 区位、F4 与 F5 用户扩充输入，Ctrl-O 切换状态提示；BASIC 里汉字是 3 字节（`$7F`、区、位）；汉字方式下用户程序的 HIMEM 是 `$9200`；槽 3 的接口入口在 `$C3A4`、`$C3AB`、`$C3B2`、`$C3B9`、`$C377`、`$C380`、`$C389`、`$C392`、`$C39B`，工作单元 `$038F-$03CF`，标志单元 `$03AE`；`$04FB` 为 1 时汉字方式保留彩色。

## 打印机接口卡

手册里的打印机接口卡插在槽 1（数据寄存器 `$C090`，ROM `$C100-$C1FF`，扩充 `$C800-$CFFF`）：写 `$C090` 经 74LS373 锁存后由选通脉冲（约 1 微秒的负脉冲）送给打印机；状态经 74LS251 送到数据线位 7：读 `$C1C0` 是 Ack（经反相）、读 `$C1C4` 是 Busy（高表示忙，等到低才送下一个字节）。接口卡自带的 2716 驱动程序没有收集到，Ember 在 `$C100` 起放一段 26 字节的重写驱动（`PR#1` 用：去掉高位、等 `$C1C4` 不忙、写 Ember 扩展的文本口 `$C091`，回车后追加换行，返回时 A 不变；文本口把 ASCII 排成位图行再交给虚拟针式打印机，因为它只认位图）；汉字系统自带的打印例程（U35）直接写 `$C090`，并读 `$C1C1` 等忙（手册里 `$C1C1` 没有接信号，Ember 读到 0，即不忙）。

## 软驱与盘片

软驱接口在槽 6：`$C0E0-$C0EF` 是 Disk II 的 16 个软开关，ROM 里的引导程序与 DOS 3.3 的读写盘程序按它工作。盘片镜像：

- `143360` 字节：35 道、每道 16 个扇区；`163840` 字节：40 道（CEC-I 的驱动器能走到第 40 道）；这两种是按扇区存放的 `.dsk`、`.do`、`.po`。
- `232960` 字节（35 道、每道 6656 个半字节）：`.nib`，直接存磁盘上的半字节，同步字节只有 `FF`。Ember 把每个半字节展开成 8 位，每道 53248 位，转一圈约 213 毫秒；写盘后从磁道里读出半字节再存回去（不足 6656 个的用 `FF` 补齐）。
- `.woz`（WOZ1 与 WOZ2，5.25 英寸）：带四分之一磁道表的位序列。读头在半磁道位置 n 时查表的第 2n 项，表里没有数据的位置读到杂波；写盘后把磁道位反向填回镜像（位数不变）。弱位、磁通型磁道等防拷贝特性没有模拟。
- 扇区顺序有 DOS 顺序与 ProDOS 顺序两种，按镜像内容认出：DOS 3.3 的卷目录表在第 17 道第 0 扇区，ProDOS 的卷目录头在块 2。DOS 顺序下的逻辑扇区到物理扇区的对应表是 `{0,13,11,9,7,5,3,1,14,12,10,8,6,4,2,15}`。

`CEC-I/` 里的盘有的用了未公开的 6502 指令：`CJHZWZBJ.dsk`（超级汉字文章编辑系统）的引导扇区用 `$AB`（LAX 立即数，A 与 X 都取立即数）和 `$0F`（SLO 绝对）算出跳转地址，所以 Ember 的 CPU 核补了 `$AB`。

## 在 Ember 里验证过的

- 1.21 开机显示 ZHONG HUA XUE XI JI / VERSION1.21 并到 BASIC 的 `]` 提示符；开机自检里 RAM、BNK1、BNK2 通过，ROM1、ROM2、AUX1、AUX2 分别认出 LOGO、CEC-BASIC、HZTABLE、HZPROGRAM（这是按手册修正译码前的结果，修正后没有重新跑自检）。
- Apple DOS 3.3 系统盘与 DOS 3.3 的 160K 盘从软驱引导，`CATALOG` 列出目录，`SAVE` 写盘后 `CATALOG` 看到新文件。
- `loderunner.dsk` 的高分辨率游戏运行；`CJHZWZBJ.dsk` 引导并显示封面（菜单里的汉字依赖字库，字库不在这些文件里，显示为空白）；`ZHJXTPCEC-DOS.dsk` 的音乐程序翻转扬声器。
- 按手册修正后：`DOS 3.3 System Master.woz`（WOZ）引导到 `]` 提示符；`CPM60K.nib`（nib）引导并显示“CAN'T FIND Z80 SOFTCARD”（需要 Z80 卡，是应有的提示）；`F6` 进入汉字方式后显示开机封面，`F2` 拼音输入 `ni` 得到“妮霓倪泥尼拟”，选 1 后写入当前行（内置字库）；`PR#1` 后输出的字符经重写的驱动写到文本口 `$C091`，排成位图行后冲出得到 PNG；开机时按住 Ctrl 与 F8（TEST，`$16`）进入内存自检，各项通过，AUX3（字库校验）显示 UNKNOWN；1.21 的复位程序（`$D300`）读 `$C063`，位 7 为 1 时清除 `$03F3`、`$03F4`、`$047B` 冷启动，Ember 把“西文”键（F7）接到 `$C063`；在没有 DOS 的 BASIC 下输入 `LG` 进入 LOGO（手册：未装 DOS 时 `LG`，已装 DOS 时先 `MAXFILES 1` 再 `LG`），显示“CHINESE EDUCATION COMPUTER / LOGO / VERSION 1.1 / 1987.6”与提示符“?”，`FD 50` 画出海龟与线段；汉字方式下 `POKE 1659,1`（打印方式，手册里写作 `POKE 165n`，实为 `$067B`）后输入汉字，汉字程序经 `$C090` 送出 ESC L 位图，得到 A4 的 PNG；`.nib`（由 DOS 3.3 的 `.dsk` 转出）与 `.woz` 的盘 `SAVE` 后重新载入 `CATALOG` 能看到新文件；`$C0B0` 为 0 时低分辨率画面变成灰度；`PR#3` 进入汉字方式后程序运行、显示开关为高分辨率第 2 页、`$C0B0` 被汉字程序写成 0（单色）；合成的 320KB ROM（U33 与 U34 填已知图案）经 `$C0B0` 选页读出的字节与交织、位序相反的预期一致；辅存写开关为 1 时对 `$4000-$BFFF` 的写被丢弃、对 `$0200-$3FFF` 的写进主存；`$C1C0-$C1C7` 读到打印机状态。

## 没有查明的

- 汉字字库（U33、U34）的原始字形、显示码 ROM（2732）与键盘码表（2716）的内容；打印机接口卡自带的驱动程序；串口 `$C0AE`、`$C0AF` 的收发；字符发生器（Ember 用自带字库代替）；`Alien Rain.nib` 等带复制保护的 `.nib` 引导后画面是杂乱的低分辨率图形，其他 `.nib` 都正常，推测是保护程序依赖真机的磁盘时序或硬件，不处理；Ctrl+Reset 的冷启动与自检组合键要在模拟器里手动点复位按钮验证。
