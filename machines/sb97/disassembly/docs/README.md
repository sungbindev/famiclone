# SB97 BIOS 静态分析结论

本文是对 [SB97.nes](../../../../reference/rom/小霸王/SB97.nes) 做静态反汇编得到的结论，工具与用例在 [../tools/](../tools/) 和 [../test/](../test/)。除“文件”一节外，其余都是由代码推断，没有经过真机核对；真机核对结果写进“待核对”一节后，再改成“已确认”。

## 文件

| 项 | 内容 |
| --- | --- |
| 文件头 | NES 2.0，PRG 1MB（64 页，每页 16KB），没有 CHR，CHR-RAM 8KB，垂直镜像，文件头里的 mapper 号是 366（不是学习机 BIOS 常见的 171） |
| 页地图 | `node tools/sb97-scan.mjs pages`：第 0、1、4、5、8、9、63 页是代码；第 21-28、48-62 页是高熵数据（压缩数据或加密数据，未判明）；第 32-47 页含点阵字库；第 3 页的向量位置是 `10 90 90 82 82 7E` 这类字模形状的字节，疑似字库，被代码判别误判，判别只是线性扫描的统计，需要人工确认 |

## 分页（推断，待核对）

| 项 | 内容 |
| --- | --- |
| 固定页 | 第 0 页在 `$C000-$FFFF`：向量 RESET 为 `$FF00`，`$FFE0` 起是跳转表（`JMP $C0C2`、`$DB2B`、`$DB44`、`$FF1D`），`$C0C2` 是系统调用分发器 |
| 可换页 | 写 `$5000` 选一页放进 `$8000-$BFFF`，页号 0-63；固件在零页 `$C0` 里保存当前页号作为影子；写 `$5000` 的 114 次访问全部在第 0 页和第 63 页 |
| 系统调用 | 功能号放 `$0100`，`JSR $FFE0`：`$10` 以下的功能经 RAM 表 `$013D` 起（每项 3 字节：页号、地址低、地址高）取目标；`$10-$6F` 的目标地址取自 `$C000` 起的表；`$70-$7F` 切到第 63 页（`$3F`）、入口 `$8000` |
| 启动流程 | RESET `$FF00` 先 `JSR $D9BE`（关 PPU、清零页 0、`$0300`、清显存，`$5200` 写 0），再用功能号 `$1F` 调一次，之后把页 1 选进窗口调用 `$BFFD`，页 1 在 `$BFFD` 放了 `JMP $BBA7` |
| 启动应用 | `$D8EF` 起把 32 字节复制到 `$030A` 并跳进去执行：`$5200` 位 2 置 1、`$5000` 写入 `$C1`（页号）、`JMP ($00C2)`；复制到 RAM 的原因是切换后固定页不再可见 |
| 第 5 页 | 向量 NMI `$FF9D`、RESET 与 IRQ 都是 `$C000`，开头是 `LDX #$FF / TXS / LDA #0 / STA $80 / JMP $8116`：像是一个应用在 `$C000` 放入自己的入口，具体何时被映射到 `$C000` 未查明 |

## 寄存器（推断，待核对）

| 地址 | 访问 | 推断 | 依据 |
| --- | --- | --- | --- |
| `$2000-$2007`、`$4014`、`$4015`、`$4000-$4007` | 读写 | 标准 PPU、精灵 DMA、APU | 只用到标准寄存器 |
| `$4016`、`$4017` | 读写 | 与步步高相同的键盘矩阵：写 `$4016` 值 `$05` 回到起点、`$04` 前进并读前半边、`$06` 翻转读后半边，读 `$4017` 位 1-4（按下为 0），13 个位置 | 第 0 页 `$D569` 起的扫描程序，与 [02-硬件模块.md](../../../ember/docs/02-硬件模块.md) 6.9 节的 `keyboard-bbk` 一致；`$C359` 起另有标准手柄读取 |
| `$5000` | 只写 | PRG 页选择（`$8000-$BFFF`） | 见“分页” |
| `$5200` | 只写，影子在 `$0117` | 整机控制位：位 1 在 PPU 传输时清零、位 2 在启动应用时置位、位 3 在 `$D67D` 清零，含义未查明 | 修改 `$0117` 再写 `$5200` 的成对访问 |
| `$5300` | 读写 | 数据口：读位 7 为“就绪”，就绪时写数据，数据来自逐字节读取的多页 ROM，`$0F` 作为结束标记；像是语音或声音芯片的数据口 | 第 0 页 `$D7FE`、`$D81B` 起的流程 |
| `$5501` | 只写 | 软驱控制器的 DOR：写 `$18` 复位（位 2 为 0）、`$1C` 释放复位（位 2、3、4 为 1：非复位、DMA、电机） | 第 63 页 `$9889` 起的初始化 |
| `$5604` | 只读 | 软驱控制器的主状态寄存器：`AND #$C0` 后与 `$C0` 比较（请求就绪且方向为读出）、与 `$80` 比较 | 第 63 页 `$9506`、`$9529` |
| `$5605` | 只读 | 软驱控制器的数据（读） | 同上 |
| `$5505` | 只写 | 软驱控制器的数据（写） | 第 63 页 `$9547` |
| `$6000-$7FFF` | 读写 | 8KB 的 RAM（统计里有第 3 页的访问，第 3 页疑似字库，被误判为代码，这部分访问不可信；第 5、63 页的访问可信） | 第 5 页与第 63 页的访问 |

## 可复用的已有模块

按上面的推断，主板之外的功能可以直接复用 Ember 已有的模块：`keyboard-bbk`、`fdc-upd765`、`floppy-drive`、`printer-escp`（若有并口）、`speech-lpc`（若 `$5300` 确是语音）、`BbkInputPort`（`$4016`、`$4017`）。需要新写的是 `sb97` 主板的存储译码、`$5000`、`$5200`、`$5300` 与软驱寄存器的地址译码。

## 待核对

1. 制式：PPU 是 NTSC、PAL 还是 Dendy，决定时钟与 vblank 位置。
2. `$5200` 各位的含义；`$5300` 是否为语音、其他位与结束标记 `$0F` 的含义。
3. 第 5 页何时被映射到 `$C000`，以及 `$C000-$FFFF` 的固定页是否能换。
4. 软驱的寄存器译码（读与写落在不同地址）、软驱 DMA 是否存在、有没有 `$FF98` 一类的中断位。
5. 第 21-28、48-62 页的数据格式，以及 BIOS 是否对它们做校验或解压。
6. 内部 RAM 与 `$6000-$7FFF` 的实际大小，显存（CHR-RAM）是否有分页。
7. 有没有鼠标、并口、扩展卡槽。
