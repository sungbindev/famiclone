# 命令行与构建

本文说明 `fcdev` 的命令、构建规则、配置文件 `fcdev.json` 和构建流程。模拟器相关命令的细节见 [02-模拟器与调试](02-模拟器与调试.md)，反汇编见 [03-反汇编](03-反汇编.md)。

## 1. 命令

命令正常结束返回 0；出错时向标准错误写“错误：”加说明与建议，返回 1。

`fcdev` 装在项目的 `node_modules` 里，没有加入系统的 `PATH`，在终端里要写成 `npx fcdev <命令>`（全局安装 `npm install -g fcdev` 后可以直接写 `fcdev <命令>`）；`package.json` 的 `scripts` 里直接写 `fcdev <命令>`。下面的表格和本文其余地方都省略 `npx`。

| 命令 | 作用 |
| --- | --- |
| `fcdev build [路径]` | 构建，规则见第 2 节 |
| `fcdev disk [路径]` | 构建并把产物放进磁盘镜像；只有声明了磁盘能力的目标可用，镜像放在产物旁边，文件名与程序名相同，扩展名为 `.img`，卷标为 `FCDEV` |
| `fcdev run [路径]` | 构建后在 Ember 里运行 |
| `fcdev debug <参数…>` | 把参数原样交给 Ember 调试 SDK 的终端客户端（`call`、`screenshot`、`watch` 等） |
| `fcdev disasm <文件>` | 反汇编成 ca65 工程，并回读校验 |
| `fcdev sync` | 生成 IDE 配置，见第 6 节 |
| `fcdev info [--json]` | 显示目标、工具链与头文件目录 |
| `fcdev api [词] [--json]` | 查询目标的 C 接口文档，见第 5.1 节 |
| `fcdev docs [词] [--json]` | 查询使用文档的本机路径，见第 5.2 节 |

通用选项：

| 选项 | 说明 |
| --- | --- |
| `--target <名>` | 指定目标，覆盖 `fcdev.json` 里的 `target` |
| `--debug` | `run` 以调试模式启动 Ember |
| `--port <端口>` | `run` 的调试端口，1 到 65535，默认 5699 |
| `--json` | `info` 输出机器可读格式 |
| `-h`、`--help` | 显示帮助 |
| `-v`、`--version` | 显示版本 |

`--verbose` 能被解析，目前没有命令使用它。`disasm` 的选项见 [03-反汇编](03-反汇编.md)。`debug` 把命令名之后的全部参数原样交给调试 SDK，不再解析选项；它按环境变量 `FCDEV_DEBUG_PORT`（默认 5699）找到 `run --debug` 启动的 Ember，细节见 [02-模拟器与调试](02-模拟器与调试.md)。

## 2. 构建单位

| 命令 | 含义 |
| --- | --- |
| `fcdev build` | 等于 `fcdev build .`，以终端当前目录为项目 |
| `fcdev build abc` | 把目录 `abc` 作为一个项目：递归收集其中全部 `.c`、`.s`、`.asm`，编译后链接成一个程序，程序名取配置里的 `name`，未配置时取目录名 |
| `fcdev build abc/aaa.c` | 只编译并链接这一个文件，它自己是一个程序，程序名取文件名（不含扩展名） |

- 入口是 `main`（汇编写 `.export _main`），不设置入口文件。缺少或重复时 `ld65` 报错，`fcdev` 补一句提示。
- 收集目录时跳过 `build`、`node_modules`、以 `.` 开头的目录，以及配置里的输出目录；目录里没有源文件时报错。
- 程序名按目标的 `nameRule` 校验（例如 DOS 8.3），不符合就报错，不静默截断。
- 目标取自构建路径向上查找到的最近一个 `fcdev.json`，`--target` 可覆盖；两者都没有时报错，不默认猜测。
- 项目根是 `fcdev.json` 所在目录；找不到配置时是终端当前目录。
- 目录里有多个独立的单文件程序时，不能用一次 `build 目录` 批量构建，只能逐个指定文件。

`info` 与 `sync` 以终端当前目录向上查找 `fcdev.json`，不接受路径参数。

## 3. 配置文件 `fcdev.json`

| 项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `target` | 字符串 | 无 | 目标名 |
| `name` | 字符串 | 目录名 | 目录构建时的程序名 |
| `out` | 字符串 | `build` | 输出目录，相对项目根 |
| `optimize` | 布尔 | `true` | 给 `cc65` 加 `-Oirs` |
| `define` | 对象 | 空 | 预定义宏，值为字符串或数字 |
| `include` | 字符串数组 | 空 | 额外头文件目录，相对项目根 |
| `toolchain` | 字符串 | 空 | 自备 cc65 的根目录，优先于工具链包 |
| `firmware` | 字符串 | 无 | 固件（BIOS、ROM）文件路径；目标的运行方案要求固件时必填 |
| `emulator` | 字符串 | 空 | 自备 Ember 的可执行文件路径，不设时读环境变量 `FCDEV_EMULATOR`，再没有时用随包的 Ember |
| `targetOptions` | 对象 | 空 | 目标专用选项，由各目标定义并校验 |

- 配置里出现未知项、类型不对、`define` 的值不是字符串或数字时，报错并列出可用的项。
- `out`、`include`、`toolchain`、`firmware`、`emulator` 里的相对路径都以配置文件所在目录为基准。
- `targetOptions` 里出现目标没有定义的选项、类型不对或超出目标规定的范围时报错。

## 4. 构建流程

### 4.1 产物位置

| 内容 | 位置 |
| --- | --- |
| 产物 | `<项目根>/<out>/<目标>/<程序名><扩展名>`，程序名按目标的 `nameRule` 规范化 |
| 中间文件 | `<项目根>/<out>/obj/<目标>/<程序名>/` |

中间文件目录里有每个源文件对应的 `.o`、依赖文件 `.d`，C 文件还有编译出的 `.s` 与汇编依赖文件 `.asm.d`；目标声明了源文件编码时（如 sb2000），还有每个源文件转码后的副本 `.gb2312.c` 或 `.gb2312.s`；链接产物 `<程序名>.bin`、`<程序名>.map`、`<程序名>.dbg`；多页程序还有展开后的链接配置 `<程序名>.cfg`；以及指纹文件 `stamp.json`。`.o` 的文件名取源文件相对目录的路径，去掉扩展名，目录分隔符换成 `__`。

### 4.2 单个程序

1. 对每个 `.c`：`cc65` 输出 `.s` 与依赖文件（`--create-dep`）。
2. 对每个 `.s`（含上一步生成的）：`ca65` 汇编成 `.o`，同样输出依赖文件。

目标声明了源文件编码时（sb2000 声明了 GB2312），上面两步编译的是转码后的副本，错误信息仍指向原文件；转换规则见 [sb2000 开发指南](sb2000/01-开发指南.md) 第 5 节。

3. `ld65`：按目标的链接配置，依次链接启动代码、用户的 `.o`、开启的目标选项所带的目标文件，最后链接目标声明的库；生成 `.bin`、`.map`、`.dbg`。目标声明了多页（换页）程序且库页个数大于 0 时，链接配置按库页个数展开，写在中间文件目录里，打包器也不再检查映像大小上限。
4. 打包器把 `.bin` 做成最终产物。

工具参数：

| 工具 | 参数 |
| --- | --- |
| `cc65` | `-t <cc65Target> --cpu <cpu> -g`，`optimize` 为真时加 `-Oirs`，每个头文件目录一个 `-I`，每个宏一个 `-D 名=值`，`--create-dep`，`-o` |
| `ca65` | `-t`、`--cpu`、`-g`，每个汇编引入目录同时给 `-I` 与 `--bin-include-dir`，`-D`，`--create-dep`，`-o` |
| `ld65` | `-C <链接配置> -m <map> --dbgfile <dbg> -o <bin>`，再接 `-u` 强制引入、目标文件、库 |

头文件目录依次是：目标的 `include`、配置的 `include`、源文件的公共根目录；汇编引入目录同理，用目标的 `asminclude`。预定义宏是目标的 `defines` 加配置的 `define`，后者覆盖前者。

工具的输出（`文件(行): Error: 信息` 格式）原样写到标准错误，供 VS Code 问题匹配器使用。调用工具时设置环境变量 `CC65_HOME` 为工具链根目录。

### 4.3 增量构建

- 某个 `.o` 存在，且比它的源文件与依赖文件里列出的所有文件都新，就不重编。
- 指纹由 `fcdev` 版本、工具链版本（`cc65 --version` 的输出）、整个目标定义、目标选项、`optimize`、`define`、`include` 和源文件列表算出，记在 `stamp.json`。指纹变了，先删掉整个中间文件目录再全部重编。
- 构建成功后才写 `stamp.json`。
- 构建结束输出产物大小，以及本次重新编译与沿用的文件数。

### 4.4 工具链定位

按顺序查找，找到即停：

1. 配置项 `toolchain`。
2. 环境变量 `FCDEV_CC65_HOME`。
3. 工具链包 `fcdev-cc65`。

目录里必须有 `bin` 下的 `cc65`、`ca65`、`ld65`，否则报“不是完整的 cc65 目录”。都找不到时报错并写明三种解决办法。不使用 `PATH` 里的 cc65，避免版本不一致。

## 5. 信息命令

`fcdev info` 输出项目根目录、配置文件、目标、工具链（目录、来源 `config`、`env` 或 `package`，版本）、输出目录、头文件目录和汇编引入目录。`--json` 输出同样内容的 JSON，供 VS Code 扩展等工具读取。

头文件目录依次是目标的 `include`、配置的 `include`、工具链的 `include`；汇编引入目录同理，最后是工具链的 `asminc`。

### 5.1 接口文档查询

`fcdev api` 读目标 `include` 目录下头文件里带 `/** */` 文档注释的函数（注释写法见 [sb2000/01-开发指南](sb2000/01-开发指南.md) 第 6 节），不需要工具链。目标来自 `fcdev.json` 或 `--target`；目标没有带文档注释的函数时报“没有 C 接口文档”，目前只有 `sb2000` 有。

| 用法 | 结果 |
| --- | --- |
| `fcdev api` | 列出全部模块、各模块的函数个数与头文件 |
| `fcdev api <函数名>` | 完整文档：签名、所在头文件、系统调用、说明、每个参数、返回值 |
| `fcdev api <模块名>` 或 `fcdev api <头文件名>` | 该模块的函数与一行说明，如 `fcdev api file` |
| `fcdev api <功能号>` | 用到该系统调用的函数，写法 `$7B` 或 `$7B/$09`（不分大小写，`$` 可以省略） |
| `fcdev api <词>` | 名称或说明里包含该词的函数 |

查询依次按函数名、模块名、功能号、关键词匹配，先匹配上的为准；一个都没有匹配上时报“没有找到”。`--json` 输出机器可读的结果：不带查询词时是模块列表，否则是匹配到的函数。

### 5.2 文档查询

`fcdev docs` 查询随主包发布的使用文档（主包的 `docs/` 目录），只读、不联网、不需要 `fcdev.json` 和工具链。

| 用法 | 结果 |
| --- | --- |
| `fcdev docs` | 列出全部主题（主题名、标题、一句话说明）与本机文档目录 |
| `fcdev docs <主题>` | 该文档的标题、说明与本机绝对路径，如 `fcdev docs syscall` |
| `fcdev docs <词>` | 按文件名（去掉序号与扩展名也可）或主题、标题、说明里的关键词查找；只匹配到一份时同上，多份时列出摘要 |

- 查询依次按主题名、文件名、关键词匹配，先匹配上的为准；一份都没有匹配上时报“没有找到”。`--json` 输出机器可读的结果：不带查询词时是全部文档，否则是匹配到的文档，每项含 `topic`、`title`、`summary`、`file`、`localPath`。
- 文档目录不存在时报错，提示改读在线文档。

## 6. `fcdev sync`

生成 IDE 的 C/C++ 配置，让智能提示找到 cc65 与目标的头文件：

- `.vscode/c_cpp_properties.json`：只写或更新名为 `fcdev` 的配置，保留其他配置；该配置含 `includePath`、`defines`（`__CC65__`、`__<目标>__`、目标和配置里的宏，以及给编辑器用的空宏 `__fastcall__`、`__cdecl__`，它们不参与构建）、`cStandard` 为 `c89`。已有文件没有 `configurations` 数组时报错。
- 项目根的 `compile_flags.txt`：第一行是标记 `-DFCDEV_GENERATED`，之后是 `-I` 与 `-D` 行。已有同名文件但第一行不是该标记时，视为用户自己的文件，不覆盖。
