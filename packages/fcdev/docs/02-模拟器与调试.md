# 模拟器与调试

`fcdev` 的 `run`、`debug` 命令使用模拟器 Ember。Ember 随 `fcdev` 一起安装（Windows 64 位，在依赖包 `fcdev-ember` 里），不用另外下载，也不用指明它的位置（见第 1、2 节）；调试服务由 Ember 提供，`fcdev` 用随包的调试 SDK 与它通信。Ember 的调试协议与全部请求见 Ember 帮助文档里的“调试接口手册”，SDK 的用法见该手册的“客户端工具”页。

Ember 运行 NES 程序，也运行学习机整机（SB2000）；学习机的启动方式见第 3 节与第 6 节。

## 1. Ember 的位置

- `fcdev-ember` 包里有 `Ember.exe`。第一次用到时，`fcdev` 把它复制到用户级目录 `%LOCALAPPDATA%\fcdev\ember\`（环境变量 `FCDEV_EMBER_HOME` 可以改目录），之后只运行这一份：全机共用，Ember 自带的升级会覆盖它，`npm install` 不影响它。
- 包里的 Ember 版本比副本新时替换副本，前提是副本没有被 Ember 升级过（副本旁的 `installed.json` 记着复制时的版本与校验值，文件与记录不同就不动）；Ember 正在运行时替换不了，继续用旧副本，下次再换。用户级目录写不进去时直接运行包里的程序。
- Ember 目前只有 Windows 64 位版，其他平台没有随包的 Ember，要自备（见第 2 节）。

## 2. 定位 Ember

按顺序查找，找到即停：

1. 配置项 `emulator`。
2. 环境变量 `FCDEV_EMULATOR`。
3. 随包的 Ember（用户级副本，见第 1 节）。

都找不到时报“找不到 Ember”，指定的路径不存在时报“找不到 Ember：路径”。`fcdev` 不去 `PATH` 里猜。自备的 Ember 用前两种方式指定。

## 3. `fcdev run`

先确认目标能运行、能找到 Ember，再构建并启动 Ember。目标没有运行方案时报错。

| 运行方案 | 做法 |
| --- | --- |
| `rom` | Ember 直接加载产物（`.nes`），不需要固件 |
| `firmware-disk` | 学习机方案：加载 `fcdev.json` 里 `firmware` 指定的 BIOS，把程序放进磁盘镜像挂到软驱 0 并开机；没有设置 `firmware` 时在构建之前报“需要固件”，见下面与第 6 节 |

- 学习机（`firmware-disk`）没有命令行入口，不论是否带 `--debug` 都经调试服务启动（独立的用户数据目录与调试端口，同下一条）：依次 `machines.setRom`（Ember 把 ROM 复制进自己的 ROM 目录）、`machines.boot`（上电、不运行）、`media.floppyInsert`（放入 `fcdev disk` 生成的镜像，程序名取镜像里的程序）。没有 `--debug` 时，再让机器运行到 SB-DOS 询问日期，回车跳过日期与时间，输入程序名并回车，随后 `runtime.resume`，命令行断开调试连接并返回，Ember 留在运行状态；有 `--debug` 时停在开机状态，程序还没有被运行，要在 SB-DOS 里输入程序名才运行。程序名只能用字母与数字，不合适时用 `fcdev.json` 的 `name` 改名。

- 没有 `--debug`：用 `--cartridge=<产物>` 启动 Ember，窗口打开并开始运行，命令行立即返回。用的是 Ember 平时的用户数据目录（首选项、键位映射等设置照常生效），遵守 Ember 的单实例规则，见第 5 节。
- 有 `--debug`：用独立的用户数据目录（系统临时目录下的 `fcdev-ember/<端口>`）、`--debug-port=<端口>` 与随机生成的令牌启动 Ember，不带 `--cartridge`；连上调试服务后用 `cartridges.load` 载入产物，上电但不运行（`powerOn` 为真、`resume` 为假）；之后用 `fcdev debug` 继续。独立的用户数据目录让调试用的 Ember 能和平时在用的 Ember 同时运行，互不影响设置；调试实例（带 `--debug-port` 启动）不会自行升级重启，调试中途不会被打断。
- `--port` 指定调试端口，默认 5699。调试模式启动前先检查端口是否被占用，被占用就报错，不去连接，避免连到别的 Ember；启动后最多等 30 秒，等到调试服务可连接并成功载入程序，超时则结束 Ember 进程并报错；Ember 在就绪前退出时立即报错。
- Ember 进程与命令行脱离，命令行退出后窗口保持打开；工作目录是 Ember 所在目录。
- Ember 没有“退出”请求，调试结束后关闭它的窗口，或按 `run` 打印的进程号结束进程。

## 4. `fcdev debug`

```bash
npx fcdev debug call runtime.status
npx fcdev debug call runtime.run frames=60 wait=true
npx fcdev debug screenshot screen.png
npx fcdev debug methods
```

- `debug` 之后的全部参数原样交给随包的调试 SDK 的终端客户端（命令有 `endpoint`、`methods`、`describe`、`call`、`screenshot`、`watch`，选项见 `npx fcdev debug --help`），它的输出与退出码就是 `fcdev` 的输出与退出码（0 成功，1 失败，2 用法错误）；`fcdev` 自己不解析调试命令。
- 找到 Ember：没有显式指定位置时，用环境变量 `FCDEV_DEBUG_PORT`（默认 5699）推出 `fcdev run --debug` 用的用户数据目录，读那里的端点文件取得地址与令牌。设置了环境变量 `EMBER_DEBUG_URL`、`EMBER_DEBUG_TOKEN`、`EMBER_DEBUG_ENDPOINT`、`EMBER_USER_DATA` 之一，或在命令里给了 `--url`、`--token`、`--endpoint-file`、`--user-data-dir`，就按显式指定的位置找，可以连到平时在用的 Ember。
- 命令的工作目录就是终端当前目录，`screenshot` 的相对路径相对终端当前目录；`call` 里的 `file` 参数（如 `inspector.traceStart` 的文件名）由 Ember 写进它的调试输出目录，调试模式下是用户数据目录里的 `debug-output`，结果里的 `file` 给出完整路径。
- 请求默认最多等 60 秒；`runtime.run` 带 `wait=true` 运行很多帧时用 `--timeout <毫秒>` 加长。
- 调试 SDK 随 `fcdev` 一起安装，已经构建好，不用另外构建。

### 4.1 常用操作

| 要做的事 | 命令 |
| --- | --- |
| 看运行状态与卡带 | `call runtime.status` |
| 运行 N 帧并等运行结束 | `call runtime.run frames=N wait=true` |
| 单步 | `call runtime.step unit=instruction count=N`（`unit` 还有 `cycle`、`scanline`、`frame`） |
| 继续运行、暂停 | `call runtime.resume`、`call runtime.pause` |
| 复位 | `call runtime.reset kind=soft`（或 `hard`） |
| 看寄存器与芯片状态 | `call inspector.getState`、`call inspector.snapshot` |
| 读内存 | `call inspector.readMemory space=cpu address=0x8000 length=16 --out 文件`（数据是二进制，用 `--out` 保存；`call inspector.listSpaces` 列出全部空间） |
| 断点 | `call inspector.addBreakpoint kind=execute address=0x8000` |
| 截图 | `screenshot 文件.png` |
| 记录指令轨迹 | `call inspector.traceStart kind=instruction file=trace.txt`，运行后 `call inspector.traceStop id=<编号>`；文件用于 `fcdev disasm --trace` |
| 记录代码与数据标记 | `call inspector.cdlStart`，运行后 `call inspector.cdlSave file=prg.cdl` |
| 注入按键 | `call input.key code=KeyW down=true`（`code` 是 `KeyboardEvent.code`，由卡带的 mapper 脚本翻译）、`call input.pad port=0 buttons=1` |
| 订阅事件 | `watch runtime.* --timeout 5000` |

全部请求、参数与错误码用 `fcdev debug methods` 与 `fcdev debug describe <请求>` 查看。

## 5. 限制

- 学习机的运行方式是自动在 SB-DOS 里输入程序名，靠固定的帧数等待 DOS 启动（开机运行 900 帧后直接按两次回车，调试服务里不限速、几秒完成）；换了别的 BIOS 或磁盘时提示的出现时间不同，就会输错位置，这时用 `--debug` 启动，自己用 `fcdev debug` 操作。
- 不带 `--debug` 的 `fcdev run` 遵守 Ember 的单实例规则：平时用的 Ember 已经在运行时，新启动的进程只会把已有窗口提到前面，不会载入新程序（Ember 首选项里开启“允许同时运行多个实例”后不受此限，会打开新窗口）；这时先关闭 Ember，或改用 `--debug`（独立的用户数据目录，不受影响）。学习机目标不受影响，它总是用独立的用户数据目录。
- 不随包发布任何 BIOS 或 ROM，由用户经 `firmware` 提供（学习机目标必填）。

## 6. 学习机在 Ember 里的调试

学习机用 `--debug` 启动后，机器已开机、磁盘在软驱 0 里、没有运行，操作与 NES 相同，另有：

| 要做的事 | 命令 |
| --- | --- |
| 在 SB-DOS 里敲键 | `call input.key code=KeyA down=true`，运行几帧后 `down=false`；回车是 `Enter`，不要连续几帧不运行就松开，BIOS 来不及读到 |
| 手柄、鼠标 | `call input.pad port=0 buttons=1`、`call input.mouse kind=move dx=10 dy=5`、`call input.mouse kind=down buttons=1` |
| 把软驱里被程序改写的盘片存回镜像文件 | `call media.floppySave drive=0` |
| 取出、重新放入盘片 | `call media.floppyEject drive=0`、`call media.floppyInsert drive=0 path=<镜像>` |
