# cc65 工具链

`fcdev` 用 cc65 编译与链接，不使用使用者机器上自带的 cc65。cc65 的源码在本仓库的 `cc65/` 目录，由本仓库维护；构建脚本把它编成工具与运行库，组装成工具链包 `fcdev-cc65` 随 npm 发布。工具链怎么被主包找到，见 [02-命令行与构建](02-命令行与构建.md) 第 4.4 节。

## 1. 源码目录 `cc65/`

- 最初导入自上游 [cc65/cc65](https://github.com/cc65/cc65) 的提交 `357f64e4e3c733d54b82bc155afc841fd8d9ee8d`（2025-08-24）。导入后由本仓库维护，可以直接修改。
- 是删减版，只保留 `fcdev` 构建 `cc65`、`ca65`、`ld65`、`ar65`、`da65`，以及 `none`、`nes` 两个目标的运行库所需的文件。`cc65/README-FCDEV.txt` 写明“本目录为删减版”并给出导入的提交，这是 zlib 许可证对修改版的要求。
- 许可证为 zlib，见 `cc65/LICENSE`。

保留的内容：

| 位置 | 内容 |
| --- | --- |
| `src/` | `cc65`、`ca65`、`ld65`、`ar65`、`da65` 与共用的 `common` |
| `libsrc/` | `common`、`runtime`、`none`、`nes`，以及它们的公共部分依赖的 `conio`、`dbg`、`em`、`joystick`、`mouse`、`serial`、`tgi`、`zlib` |
| `include/`、`asminc/` | 头文件与汇编引入文件 |
| `cfg/` | `none.cfg`、`nes.cfg`、`module.cfg` |
| 各级 `Makefile`、`LICENSE` | 构建与许可 |

已删除：`test/`、`targettest/`、`doc/`、`samples/`、`util/`、持续集成与贡献说明文件、其他机型的库与头文件，以及 `co65`、`od65`、`sp65`、`grc65`、`chrcvt65`、`cl65`、`sim65`、`dbginfo` 等不用的工具。删减后必须仍能编出 `none.lib` 与 `nes.lib`；缺什么就从上游补回。

## 2. 构建

```bash
node tools/build-cc65.mjs
```

`tools/build-cc65.mjs` 做的事：

1. 把 `cc65/` 整个复制到 `build/cc65-work`，在副本里构建，不污染源码目录。
2. 在 `src` 里构建 `ar65`、`ca65`、`cc65`、`da65`、`ld65`，版本串显式传 `BUILD_ID=Git <提交前 7 位>`；不传时 `Makefile` 会取当前目录所在仓库（也就是 `fcdev`）的提交号，版本输出会指向错误的提交。
3. 在 `libsrc` 里构建 `none` 与 `nes` 两个运行库。
4. 组装工具链包：`bin/` 放五个可执行文件，另有 `include/`、`asminc/`、`cfg/`、`lib/none.lib`、`lib/nes.lib`、`LICENSE`。
5. 写 `manifest.json`（上游地址、提交、各文件的 SHA-256）与 `package.json`（版本与主包同步）。

用 `mingw32-make` 与 `gcc` 构建，环境变量 `FCDEV_MAKE` 可指定 make 程序。上游提交号常量 `CC65_COMMIT` 写在构建脚本里。

## 3. 工具链包

- 包名 `fcdev-cc65`（与目录名相同），主包把它列为 `optionalDependencies`，版本精确一致。
- 入库的只有 `package.json`；`bin/`、`include/`、`asminc/`、`lib/`、`cfg/`、`LICENSE`、`manifest.json` 都是生成物，由 `.gitignore` 排除。
- 主包找不到工具链包时，提示可用环境变量 `FCDEV_CC65_HOME` 指向自备的 cc65 目录。
- `npm run release:check` 校验工具链包里的文件与清单一致，且没有清单之外的文件；源码目录里的路径和清单由 `test/cc65-tools.test.mjs` 检查，见 [08-测试与验证](08-测试与验证.md)。

## 4. 升级与修改

- 修改 `cc65/` 里的源码后，重新运行 `node tools/build-cc65.mjs`，再运行 `npm test`。
- 要换到上游的新提交时：从上游取回上面“保留的内容”对应的文件，更新 `tools/build-cc65.mjs` 里的 `CC65_COMMIT` 和 `cc65/README-FCDEV.txt` 里的提交号，重新构建并运行全部测试。
- 统一换行符的脚本不要扫描 `cc65/`：里面有 Latin-1 和 Shift-JIS 编码的文件，按 UTF-8 读写会损坏。`virtuanes/` 也一样。
