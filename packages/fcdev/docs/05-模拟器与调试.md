# 模拟器与调试

`fcdev` 的 `run`、`debug` 命令使用本仓库的模拟器 Ember。Ember 不随 npm 包提供，需要自备（见第 1 节）；调试服务由 Ember 提供，`fcdev` 用调试 SDK（npm 包 `ember-debug-sdk`，是 `fcdev` 的依赖，随 `fcdev` 一起安装）与它通信。Ember 的设计与调试协议见仓库的 `ember/docs/`（第 04 篇是调试服务），SDK 的用法与全部请求见 `packages/ember-debug-sdk/README.md` 与它生成的协议参考。

Ember 目前只能运行 NES 程序；学习机整机（SB2000 等）还没有接入，见第 6 节。

## 1. Ember 的获得

- 在仓库的 `ember/` 目录运行 `npm run package`（Windows 用 `npm run package:win`），输出在 `ember/out/Ember-win32-x64/ember.exe`（构建与打包步骤见 `ember/docs/06-构建与模块登记.md`）。
- 把这个文件的路径交给 `fcdev`，见第 2 节。

## 2. 定位 Ember

按顺序查找，找到即停：

1. 配置项 `emulator`。
2. 环境变量 `FCDEV_EMULATOR`。

都没有设置时报“找不到 Ember”，指定的路径不存在时报“找不到 Ember：路径”。`fcdev` 不去 `PATH` 里猜。

## 3. `fcdev run`

先确认目标能运行、能找到 Ember，再构建并启动 Ember。目标没有运行方案时报错。

| 运行方案 | 做法 |
| --- | --- |
| `rom` | Ember 直接加载产物（`.nes`），不需要固件 |
| `firmware-disk` | 学习机方案，Ember 暂不支持，报“Ember 暂不支持运行 … 目标的程序” |

- 没有 `--debug`：用 `--cartridge=<产物>` 启动 Ember，窗口打开并开始运行，命令行立即返回。用的是 Ember 平时的用户数据目录（首选项、键位映射等设置照常生效），遵守 Ember 的单实例规则，见第 6 节。
- 有 `--debug`：用独立的用户数据目录（系统临时目录下的 `fcdev-ember/<端口>`）、`--debug-port=<端口>` 与随机生成的令牌启动 Ember，不带 `--cartridge`；连上调试服务后用 `cartridges.load` 载入产物，上电但不运行（`powerOn` 为真、`resume` 为假）；之后用 `fcdev debug` 继续。独立的用户数据目录让调试用的 Ember 能和平时在用的 Ember 同时运行，互不影响设置。
- `--port` 指定调试端口，默认 5699。调试模式启动前先检查端口是否被占用，被占用就报错，不去连接，避免连到别的 Ember；启动后最多等 30 秒，等到调试服务可连接并成功载入程序，超时则结束 Ember 进程并报错；Ember 在就绪前退出时立即报错。
- Ember 进程与命令行脱离，命令行退出后窗口保持打开；工作目录是 Ember 所在目录。
- Ember 没有“退出”请求，调试结束后关闭它的窗口，或按 `run` 打印的进程号结束进程。

## 4. `fcdev debug`

```bash
npx fcdev debug call runtime.status
npx fcdev debug call runtime.run frames=60 wait=true
npx fcdev debug screenshot screen.png
npx fcdev debug methods
```

- `debug` 之后的全部参数原样交给调试 SDK 的终端客户端 `ember-debug`（命令有 `endpoint`、`methods`、`describe`、`call`、`screenshot`、`watch`，选项见 `npx fcdev debug --help`），它的输出与退出码就是 `fcdev` 的输出与退出码（0 成功，1 失败，2 用法错误）；`fcdev` 自己不解析调试命令。
- 找到 Ember：没有显式指定位置时，用环境变量 `FCDEV_DEBUG_PORT`（默认 5699）推出 `fcdev run --debug` 用的用户数据目录，读那里的端点文件取得地址与令牌。设置了环境变量 `EMBER_DEBUG_URL`、`EMBER_DEBUG_TOKEN`、`EMBER_DEBUG_ENDPOINT`、`EMBER_USER_DATA` 之一，或在命令里给了 `--url`、`--token`、`--endpoint-file`、`--user-data-dir`，就按显式指定的位置找，可以连到平时在用的 Ember。
- 命令的工作目录就是终端当前目录，`screenshot` 的相对路径相对终端当前目录；`call` 里的 `file` 参数（如 `inspector.traceStart` 的文件名）由 Ember 写进它的调试输出目录，调试模式下是用户数据目录里的 `debug-output`，结果里的 `file` 给出完整路径。
- 请求默认最多等 60 秒；`runtime.run` 带 `wait=true` 运行很多帧时用 `--timeout <毫秒>` 加长。
- 需要调试 SDK 已构建：本仓库里先运行 `npm run build -w packages/ember-debug-sdk`（需要 Ember 的 Schema 生成物，见 SDK 的说明）；用 npm 安装的 `fcdev` 已自带构建好的 SDK。

### 4.1 常用操作

| 要做的事 | 命令 |
| --- | --- |
| 看运行状态与卡带 | `call runtime.status` |
| 运行 N 帧并等运行结束 | `call runtime.run frames=N wait=true` |
| 单步 | `call runtime.step unit=instruction count=N`（`unit` 还有 `cycle`、`scanline`、`frame`） |
| 继续运行、暂停 | `call runtime.resume`、`call runtime.pause` |
| 复位 | `call runtime.reset kind=soft`（或 `hard`） |
| 看寄存器与芯片状态 | `call inspector.getState`、`call inspector.snapshot` |
| 读内存 | `call inspector.readMemory space=cpu address=0x8000 length=16 --out 文件`（数据是二进制，用 `--out` 保存；`call inspector.listSpaces` 列出全部空间） |
| 断点 | `call inspector.addBreakpoint kind=execute address=0x8000` |
| 截图 | `screenshot 文件.png` |
| 记录指令轨迹 | `call inspector.traceStart kind=instruction file=trace.txt`，运行后 `call inspector.traceStop id=<编号>`；文件用于 `fcdev disasm --trace` |
| 记录代码与数据标记 | `call inspector.cdlStart`，运行后 `call inspector.cdlSave file=prg.cdl` |
| 注入按键 | `call input.key code=KeyW down=true`（`code` 是 `KeyboardEvent.code`，由卡带的 mapper 脚本翻译）、`call input.pad port=0 buttons=1` |
| 订阅事件 | `watch runtime.* --timeout 5000` |

全部请求、参数与错误码用 `fcdev debug methods` 与 `fcdev debug describe <请求>` 查看。

## 5. 与旧模拟器的差异

`fcdev` 不再支持 VirtuaNES 调试版与它的文本命令协议（`run 60`、`shot`、`bp x`、`trace`、`cdl` 等），以下是行为上的变化：

- `fcdev debug` 的参数是 `ember-debug` 的命令，不再是旧的单行命令；旧命令里相对路径要换成绝对路径的处理也不再需要。
- `fcdev disasm --trace` 读 Ember 的指令轨迹（`kind=instruction`，每行是 nestest 日志的写法，行首是四位十六进制的指令地址），不再读旧模拟器行首为 `T` 的轨迹；`--cdl` 的格式不变（Mesen 的位定义）。
- 旧命令里 Ember 没有对应请求的：存档（`savestate`、`loadstate`，已登记在 Ember 的待办里）、软驱与磁带相关命令（学习机整机接入后再有）。
- 仓库里的 `virtuanes/` 保留作学习机阶段的参考，`fcdev` 不再使用它；其中的调试服务协议见 `virtuanes/README.md`。

## 6. 限制

- 学习机目标（SB2000 等）暂时不能用 `fcdev run`：Ember 还没有支持学习机整机。现在可以用 `fcdev build` 构建、`fcdev disk` 生成软盘镜像；SB2000 运行库的测试也因此暂时跳过（`packages/fcdev/test/sb2000-library.test.mjs`），Ember 支持后用调试服务重写测试里的会话类即可恢复。
- 不带 `--debug` 的 `fcdev run` 遵守 Ember 的单实例规则：平时用的 Ember 已经在运行时，新启动的进程只会把已有窗口提到前面，不会载入新程序；这时先关闭 Ember，或改用 `--debug`（独立的用户数据目录，不受影响）。
- 不随包发布任何 BIOS 或 ROM，由用户经 `firmware` 提供（学习机目标接入 Ember 后才会用到）。
