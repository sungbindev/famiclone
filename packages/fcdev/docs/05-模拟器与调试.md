# 模拟器与调试

`fcdev` 自带一个调试用模拟器：VirtuaNES 调试版，带调试服务，能运行 NES 游戏，以及 SB2000 等学习机的固件与程序。它的源码在本仓库的 `virtuanes/` 目录，由本仓库维护；构建脚本把它编成模拟器包 `@rujianjs/fcdev-emulator` 随 npm 发布。模拟器的改动清单见 `virtuanes/README.md`，调试服务的命令表见第 5.1 节。

## 1. 模拟器包

- 基于 Win32 与 DirectX。许可证 GPL-3.0-only，包里附许可文件。
- 模拟器是 32 位程序，`bin/` 里随带 `vcruntime140.dll`、`msvcp140.dll`（应用本地部署）。
- 包内容：`bin/VirtuaNES.exe`、`bin/Chinese.vlp`、两个运行库、`LICENSE`、`manifest.json`、`package.json`。入库的只有 `package.json`，其余是生成物。
- 模拟器运行时会在 `bin/` 里写 `VirtuaNES.ini` 与 `save/`，发布前要删除；`release-check` 会把它们当作清单之外的文件报错。

构建：

```bash
node tools/build-emulator.mjs
```

`tools/build-emulator.mjs` 需要 Visual Studio（含“使用 C++ 的桌面开发”）。它调用 `virtuanes/build.ps1 -Configuration Release`（编译输出在仓库根目录的 `build/virtuanes/Release/bin/`），把 `VirtuaNES.exe` 与 `Chinese.vlp` 复制进 `bin/`，再用 `vswhere` 找到 Visual Studio 里 32 位的 VC++ 运行库一并放入，最后写 `LICENSE`、`manifest.json`（当前提交、`virtuanes/` 有无未提交改动 `sourceDirty`、各文件的 SHA-256）与 `package.json`。编译前先关闭正在运行的模拟器。

## 2. 定位模拟器

按顺序查找，找到即停：

1. 配置项 `emulator`。
2. 环境变量 `FCDEV_EMULATOR`。
3. 模拟器包 `@rujianjs/fcdev-emulator` 里的 `bin/VirtuaNES.exe`。

指定的路径不存在时报“找不到模拟器”。自备的模拟器需要支持同样的调试服务才能用调试命令。

## 3. `fcdev run`

先构建，再按目标的运行方案启动模拟器。目标没有运行方案时报错。

| 运行方案 | 做法 |
| --- | --- |
| `rom` | 模拟器直接加载产物，不需要固件；没有 `--debug` 时启动后立即返回 |
| `firmware-disk` | 要求 `fcdev.json` 配置 `firmware`；构建并生成磁盘镜像，以调试模式启动模拟器，依次发 `disk <镜像>`、`reset`、`live`；等 DOS 启动后在提示符下输入程序名 |

- `--debug` 时不发 `live`，模拟器停在调试服务，只在收到 `run` 命令时运行；`firmware-disk` 方案总是以调试模式启动，因为要用调试服务挂载镜像。
- `--port` 指定调试端口，默认 5699。
- 调试模式启动前先检查端口是否被占用，被占用就报错，不去连接，避免连到别的模拟器；启动后最多等 30 秒，等到调试服务回应 `running=1`，超时则结束模拟器进程并报错。
- 模拟器进程与命令行脱离，命令行退出后窗口保持打开，工作目录是模拟器所在目录（语言包按相对文件名加载）。
- 非调试模式下沿用模拟器的单实例规则：已有普通模拟器窗口时，会把程序交给它打开。

## 4. `fcdev debug`

```bash
fcdev debug run 60
fcdev debug shot screen.png
```

- 把命令原样转发给调试服务，打印应答；应答首行以 `OK` 开头时退出码为 0，否则为 1。
- 端口取环境变量 `FCDEV_DEBUG_PORT`，默认 5699。
- 模拟器的工作目录与终端不同，所以命令里的相对路径先换成绝对路径：`shot`、`disk`、`trace`、`io`、`disklog`、`calllog`、`savestate`、`loadstate` 的第一个参数，以及 `cdl save` 的前缀；`off` 不处理；`disk` 的路径可含空格，取剩余全部。
- `run`、`step` 的应答超时是 10 分钟，其余命令 30 秒。

## 5. 调试服务协议

- 模拟器只在设置了环境变量 `FCDEV_DEBUG_PORT` 时启动调试服务，只监听 `127.0.0.1`。
- 一行一个命令；应答若干行文本，以单独的 `.` 行结束；应答首行以 `OK` 或 `ERR` 开头。一次只处理一条命令。
- 客户端在 [src/emulator/debug-client.mjs](../src/emulator/debug-client.mjs)：`DebugClient.connect` 连接（5 秒超时），`send` 发命令并等应答。
- `fcdev` 只经这套协议与模拟器通信，协议保持稳定；以后把内核集成进 VS Code 时，只要协议不变，`fcdev` 不用改。
- 命令表见下面的第 5.1 节。`live` 命令由 `fcdev` 新增：把模拟器切换为自由运行，供 `fcdev run` 把窗口交给用户操作。

### 5.1 命令表

直接发给服务的路径必须是绝对路径；数字默认按十六进制解析（地址、扫描码、寄存器），帧数、长度、次数按十进制。

| 命令 | 说明 |
| --- | --- |
| `status` | 运行状态、寄存器与 bank 寄存器 |
| `run <帧数>` | 运行指定帧数，遇到断点提前停止 |
| `step <条数>` | 单步指定条数的指令 |
| `bp x\|r\|w <地址> [结束地址]` | 添加执行、读、写断点；`bp list`、`bp del <编号\|all>` |
| `regs [pc=.. a=.. x=.. y=.. s=.. p=..]` | 读取或修改寄存器 |
| `read <空间> <地址> <长度>` | 读内存；空间为 `cpu`、`rom`、`pram`、`vram`、`cram`、`eram`、`wram`、`ram` |
| `write <空间> <地址> <十六进制字节>` | 写内存 |
| `resolve <地址>` | 把 CPU 地址解析为物理空间与偏移 |
| `key <扫描码> <0\|1>`、`key clear` | 按下或松开键盘键（DirectInput 扫描码） |
| `mouse move <dx> <dy>`、`mouse btn <掩码>` | 鼠标移动与按键 |
| `shot <文件.png>` | 截图 |
| `trace <文件> [最大行数]`、`trace off` | 记录每条指令与中断 |
| `io <文件> [最大行数] [w]`、`io off` | 记录 `$2000-$4FFF` 的读写；加 `w` 只记录写 |
| `pad <0-3> <十六进制掩码>`、`pad <0-3> clear` | 注入手柄按键（A=01、B=02、Select=04、Start=08、上=10、下=20、左=40、右=80），与真实输入合并 |
| `disklog <文件> [最大行数]`、`disklog off` | 记录软驱控制器读写的 LBA |
| `calllog <文件> <pc> <地址:长度[,...]> [最大次数] [skip=地址=值[,...]]`、`calllog off` | 每次执行到 `pc` 就记录寄存器、栈顶与内存段；`skip` 表示该地址字节等于值（十六进制）时不记录；可添加多条，`off` 全部关闭 |
| `cdl on\|off\|clear\|save <前缀>` | 代码数据标记，保存为 `<前缀>-rom.cdl`、`<前缀>-pram.cdl` |
| `disk <镜像>`、`savedisk` | 挂载或保存软盘镜像 |
| `fdc eject\|insert\|wp <0\|1>\|noindex <0\|1>\|seekfail <0\|1>\|dead <0\|1>\|bad <逻辑扇区...>\|clear\|status` | 软驱故障注入。`eject`、`insert` 取出、放回盘片（取出后控制器对 READ ID 报找不到地址标志）；`wp` 写保护；`noindex` 没有索引脉冲（READ ID、读写、格式化命令一直不结束）；`seekfail` 磁头卡住（SEEK、RECALIBRATE 不移动，已在 0 磁道时回 0 磁道仍成功）；`dead` 控制器收到命令字节后不再处理；`bad` 指定的逻辑扇区（十进制）读时报数据校验错，写不受影响；`clear` 关闭全部故障、放回盘片并取消写保护；`status` 显示当前状态。`disk` 挂载新镜像时也会清掉全部故障 |
| `audio fast\|real` | 声音播放速度：`fast` 时语音与 DAC（开机音乐、WAV）不再等声卡按真实时间播放，采样直接丢弃，模拟器内部时序不变；`real` 为默认的真实时间。开关是全局状态，复位后保持；验证工具只在开机阶段打开，开机完成后恢复 |
| `reset`、`softreset`、`savestate <文件>`、`loadstate <文件>` | `reset` 是硬复位（回到 BIOS），`softreset` 只复位 CPU、手柄与 APU、保留映射器状态（游戏中的软复位）；另有状态存取 |
| `live` | 切换为自由运行：模拟器按正常速度连续运行，不再由 `run` 授权帧数；此后只建议使用 `key`、`pad`、`mouse`、`shot`、`quit`，读写内存与断点类命令与模拟线程并行，结果不可靠。`fcdev run` 用它把窗口交给用户操作 |
| `quit` | 关闭模拟器 |

## 6. 对 `virtuanes/` 的约定

- 改动处按文件头约定标明，改动清单写在 `virtuanes/README.md` 的“相对上游的改动”。
- 调试模式（设置了 `FCDEV_DEBUG_PORT`）下，`WinMain.cpp` 不把命令行转交给已运行的实例，调试模式的模拟器可以与用户平时用的普通实例同时运行。
- `WinMain.cpp` 含 Shift-JIS 编码的内容，不要用编辑工具整体改写。
- 不随包发布任何 BIOS 或 ROM，由用户经 `firmware` 提供。
