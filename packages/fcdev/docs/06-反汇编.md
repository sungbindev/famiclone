# 反汇编

`fcdev disasm` 把 NES 程序或平铺二进制反汇编成 `ca65` 可直接汇编的源码，并保证汇编回去后与原映像逐字节一致。代码在 `packages/fcdev/src/disasm/`。

## 1. 做法

指令解码与源码文本输出交给 cc65 自带的 `da65`，不改 `da65` 的 C 代码；前端脚本负责分析，并把分析结果写成 `da65` 的信息文件。只有实测发现信息文件无法表达时，才修改 `da65` 的 C 源码，并把每处修改写进 `cc65/README-FCDEV.txt`。

流程（`disassembler.mjs`）：

1. 读取输入，判断格式，取出映像（字节、第一个字节的地址、中断向量）。
2. 收集入口：中断向量、`--entry`、`--trace` 里的地址、CDL 里每段连续代码的起点。没有任何入口时报错。
3. 静态追踪，标出每个字节是指令的操作码、操作数还是未知。
4. 生成 `da65` 信息文件。
5. 运行 `da65 -i <信息文件> --multi-pass`，得到 ca65 源码。
6. 回读校验：用 `ca65`、`ld65` 重新汇编，与原映像逐字节比较；不一致就报错，指出第一个差异的偏移与地址，不输出“成功”。

## 2. 命令

```bash
npx fcdev disasm <文件> [--format ines|binary] [--base 地址] [--entry 地址] [--cdl 文件] [--trace 文件] [--symbols 文件] [--out 目录]
```

| 选项 | 说明 |
| --- | --- |
| `--format ines\|binary` | 输入格式；缺省时按文件头判断，以 `NES` 加 `$1A` 开头为 iNES，否则为平铺二进制 |
| `--base <地址>` | 平铺二进制的加载地址，十六进制，可带 `$` 或 `0x`；平铺二进制必须给 |
| `--entry <地址>` | 追踪代码的入口，可重复；iNES 自动使用中断向量 |
| `--cdl <文件>` | CDL 文件，其中代码段的起点也当作入口 |
| `--trace <文件>` | Ember 的 `inspector.traceStart`（`kind=instruction`）记录的指令轨迹，执行过的指令地址都当作入口 |
| `--symbols <文件>` | 符号文件，给地址起名字 |
| `--out <目录>` | 输出目录，默认 `build/disasm/<输入文件名>` |

平铺二进制要有入口：用 `--entry`，或用 `--cdl`、`--trace` 提供运行记录；不会自动取程序头部的 `JMP`。

输出目录里的文件：

| 文件 | 内容 |
| --- | --- |
| `<名>.bin` | 反汇编的映像（iNES 只含 PRG） |
| `<名>.info` | `da65` 信息文件 |
| `<名>.s` | ca65 源码 |
| `<名>.roundtrip.*` | 回读用的目标文件、链接配置与结果 |

`<名>` 取输入文件名（不含扩展名），非字母、数字、下划线、连字符的字符换成下划线。回读不一致时这些文件仍然保留。命令成功时输出映像大小、指令条数与字节数，以及“回读校验通过”；追踪中放弃某一路的警告最多显示 10 条。

## 3. 输入

### 3.1 映像

- iNES：只支持映射器 0（NROM），PRG 为 16K 或 32K。32K 映在 `$8000`，16K 映在 `$C000`；跳过 trainer；从 PRG 末尾读出 NMI、复位、IRQ 三个向量。其他映射器报错，可先导出某个 bank，用 `--format binary` 并指定加载地址。
- 平铺二进制：按 `--base` 放置，不得超出 `$FFFF`，不能为空。

### 3.2 CDL

每个字节一个标志，位 0 表示被当作代码执行过，位 1 表示被当作数据读取过。支持 FCEUX 与 Mesen 的格式；Mesen CDLv2 开头多出的 9 个字节会自动跳过；只取与 PRG 对应的前 PRG 大小个字节，比 PRG 短时报错。

### 3.3 指令轨迹

Ember 的 `inspector.traceStart`（`kind=instruction`）记录的日志：每行是 nestest 日志的写法，行首是四位大写十六进制的指令地址，后面跟指令字节（如 `C000  4C F5 C5  JMP $C5F5 ...`）。`io`、`irq` 与调用记录的行不是指令行，一律忽略；旧模拟器行首为 `T` 的轨迹不再识别。轨迹里的地址都是真实执行过的指令开头，比 CDL 的“代码字节”更精确。生成方法：`npx fcdev debug call inspector.traceStart kind=instruction file=trace.txt`，运行一段时间后 `npx fcdev debug call inspector.traceStop id=<编号>`，结果里的 `file` 是完整路径（文件写在 Ember 的调试输出目录）。

### 3.4 符号文件

每行“名字 = 地址”或“名字 地址”，地址为十六进制，可带 `$` 或 `0x`；以 `;` 或 `#` 开头的行是注释，空行忽略。名字必须是合法的 ca65 标识符。同一地址有多个名字时只用第一个。中断向量对应的地址自动命名为 `reset`、`nmi`、`irq`。

信息文件里总是引入 NES 的 `fcnes.inc`，所以 PPU 寄存器地址会显示成符号名；对平铺二进制也一样。

## 4. 静态追踪

规则（`analysis.mjs`）：

- 顺序执行继续；条件分支两路都追；`JMP` 只追目标；`JSR` 追目标并假定会返回。
- `RTS`、`RTI`、`BRK` 与间接 `JMP` 结束这一路。
- 遇到非法操作码、超出映像末尾或与已识别的指令重叠时，放弃这一路并记入警告。
- 没被追到的字节都按数据输出，这不影响回读校验。
- 入口都追完后，查找经地址表分发的跳转（`address-tables.mjs`），表里的目标成为新入口，再继续追，直到没有新表。识别的写法（窗口为加载指令之后的 10 条顺序指令）：
  - `LDA 表,X/Y` 与 `LDA 表+1,X/Y` 成对，窗口里有间接 `JMP`：字表，目标就是表里的值；
  - 一对加载指令、两条 `PHA` 与一条 `RTS`：目标是表里的值加 1，表可以是字表，也可以是低、高字节分开的两张表；
  - 间接 `JMP (地址)` 的地址在映像内、那里还是未识别的字节：那里是字表。
  表项必须落在映像里、是官方操作码、不在已识别指令的中间，否则表在这一项结束，单张表最多 128 项；字表占的字节按 `AddrTable` 输出，分开的两张表保持为数据。

指令表在 `opcode-table.mjs`，共 151 条官方指令，数据取自 `da65` 的 `cc65/src/da65/opc6502.c`；非官方（非法）操作码不在表里。

## 5. 信息文件

`info-writer.mjs` 把整个映像划分成首尾相接、互不重叠的段，没有遗漏，否则 `da65` 会把没说明的字节默认当成代码：

| 段类型 | 用于 |
| --- | --- |
| `Code` | 追踪到的指令 |
| `ByteTable` | 没被追到的字节 |
| `AddrTable` | iNES 末尾 6 字节的中断向量表，以及识别出的字表 |

另有 `GLOBAL`（输入输出文件名、起始地址、CPU）、`ASMINC`（符号定义文件）与 `LABEL`（用户符号与中断向量名）。

## 6. 验证与限制

验证（见 [08-测试与验证](08-测试与验证.md)）：`fcdev` 自己构建的 NES hello 与 SB2000 的 `.EXE`，以及一个真实的 NROM 游戏（超级马里奥，由环境变量 `FCDEV_TEST_NES_ROM` 提供）回读都与原文件逐字节一致。静态追踪追不到表驱动之外的间接调用，所以马里奥只追到约 2320 字节代码，其余按数据输出，回读仍一致；补充 CDL 或 `trace` 能扩大覆盖。步步高 DOS 下的 GBASIC（`.CMD`，26896 字节，平铺二进制加载地址 `$7B00`）加入地址表识别后，代码从 6905 字节增到 8980 字节，再加一个经人工确认的入口 `$880F` 增到 10361 字节；再用模拟器的 `trace ... unique` 记录下运行 BASIC 语句、图形编辑与退回 DOS 时执行过的地址，并补三个经单独追踪确认的入口，增到 14843 字节（剩余约 12000 字节主要是图形数据与关键字表），回读一致。

限制：

- iNES 只支持 NROM。
- 只识别上述几种写法的地址表；用立即数拼出地址再存进指针的跳转、调用方自己写进工作区的分发、直接访问表项的对象表都追不到，也不把数据识别成字符串，未追到的字节都是 `ByteTable`。
- 旧模拟器（VirtuaNES）自带的 CDL 只对 SB2K 映射器有效。
- SB2000 固件页的 CDL 验证没有做。
- `da65` 输出的源码是 CRLF 换行。
