# 创建包与模板

`create-fcdev` 是 `npm create fcdev` 运行的包：在空目录生成开发结构与示例程序，之后用 `npm run build` 构建。代码在 `packages/create-fcdev/`，只依赖 Node，不引入其他依赖。

## 1. 命令

```bash
npm create fcdev@latest [目录] [-- 选项]
```

| 选项 | 说明 |
| --- | --- |
| `[目录]` | 默认当前目录，`.` 表示当前目录；不存在时会创建 |
| `--target <名>` | 目标，如 `nes`、`sb2000`；缺省时交互询问 |
| `--template <语言>` | `c` 或 `asm`；缺省时交互询问 |
| `--no-install` | 不运行 `npm install` 与 `npm run sync` |
| `-h`、`--help` | 显示帮助 |
| `-v`、`--version` | 显示版本 |

- 交互用 `node:readline`，让用户输入序号或名称选择；输入不合法时重新询问，同一问题最多 3 次。
- 不能交互（例如在脚本里）又没同时给出 `--target` 与 `--template` 时报错。
- 目标目录必须为空（允许已有 `.git`），否则报错退出，不覆盖已有文件。
- 没有该目标与语言的模板时报错，并列出可用的目标。

## 2. 流程

1. 解析参数，确定目标与语言。
2. 检查目录并复制模板，写入公共文件、`package.json` 与 `fcdev.json`。
3. 没有 `--no-install` 时运行 `npm install`，再运行 `npm run sync` 生成 IDE 配置；任何一步失败都报错，项目文件已经生成，提示用户在目录里手动重试。
4. 打印下一步：目录不是当前目录时先写 `cd`，用了 `--no-install` 时再写 `npm install` 与 `npm run sync`，之后逐行打印模板 `template.json` 的 `notes`；`notes` 列出该模板可用的全部命令（`build`、`start`、`disk`、`npx fcdev docs`，SB2000 的 C 模板另有 `npx fcdev api`）。

模板内置在创建包里，不从网络下载。

## 3. 生成的项目

```text
<项目>/
  package.json     名称取目录名；scripts: build、start、sync（模板的 template.json 声明了额外脚本时再加，目前 SB2000 模板有 disk）；devDependencies 的 fcdev 与创建包同版本
  fcdev.json       { "target": "...", "name": "hello" }
  .gitignore       node_modules/、build/、compile_flags.txt、.vscode/c_cpp_properties.json
  README.md        该模板的使用说明，其中的 {{name}} 换成项目名
  src/hello.c      或 src/hello.s
```

- 脚本：`build` 是 `fcdev build src`，`start` 是 `fcdev run src`，`sync` 是 `fcdev sync`，SB2000 模板另有 `disk` 是 `fcdev disk src`。
- 包名由目录名转小写，非法字符换成连字符；没有可用字符时用 `fcdev-app`。
- 程序名固定为 `hello`，同时是 `fcdev.json` 的 `name`，也是 DOS 里要输入的命令。
- `.gitignore` 在模板里叫 `gitignore`（不带点），因为 npm 发布时会丢掉 `.gitignore`，生成项目时改名。
- `.vscode/c_cpp_properties.json` 与 `compile_flags.txt` 由 `fcdev sync` 生成，含本机路径，所以被忽略。

## 4. 模板

每个模板是 `templates/<目标>-<语言>/` 目录，包含：

| 文件 | 说明 |
| --- | --- |
| `template.json` | `target`、`language`、`title`，可选 `scripts`（额外的 npm 脚本）与 `notes`（创建完成后提示的说明）；目录名必须等于 `<target>-<language>` |
| `README.md` | 生成项目的说明，可用 `{{name}}`；末尾有“文档”一节，写明开发文档随 `fcdev` 安装在 `node_modules/fcdev/docs/`，并给出对应目标的 `npx fcdev docs <主题>` |
| `src/hello.c` 或 `src/hello.s` | 示例程序 |

目录名以 `_` 开头的是公共文件目录，不是模板，目前只有 `_common/gitignore`。

四个模板：

| 模板 | hello world |
| --- | --- |
| `nes-c` | 设置调色板，`nes_print` 在屏幕中间显示 `HELLO, NES!`，打开画面后死循环 |
| `nes-asm` | 同样的行为，汇编直接写 PPU 寄存器，`.include "fcnes.inc"`，导出 `_main` |
| `sb2000-c` | `sb_puts` 显示英文与中文（GB2312）各一行，`sb_getkey` 等键后返回 |
| `sb2000-asm` | 同样的行为，汇编调用 `_sb_puts`、`_sb_getkey`，导出 `_main` |

## 5. 新增模板

新增机型的目标后，在 `templates/` 下加 `<目标>-c` 与 `<目标>-asm` 两个目录，写 `template.json`、`README.md` 与示例程序；目标需要额外脚本或提示时写进 `template.json`。模板必须能用 `fcdev build` 构建成功，`npm run release:verify` 会逐个验证，见 [09-发布](09-发布.md)。
