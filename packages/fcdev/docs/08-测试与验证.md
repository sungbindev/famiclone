# 测试与验证

本文说明测试的分层、运行方法和用到的环境变量。测试用 Node 内置的 `node:test`，不引入测试框架。

## 1. 运行

| 命令 | 作用 |
| --- | --- |
| `npm test` | 运行全部测试；运行前自动执行 `npm run build:libs` 编译各目标的运行库 |
| `npm run boundaries` | 检查主包的分层依赖，见 [01-软件架构设计](01-软件架构设计.md) 第 5 节 |
| `npm run check` | 依赖边界检查加测试 |
| `npm run release:check` | 发布前检查，见 [09-发布](09-发布.md) |
| `npm run release:verify` | 打包后在临时目录里创建、安装并构建四个模板 |

测试文件在 `packages/fcdev/test/`、`packages/create-fcdev/test/` 与仓库根的 `test/`，文件名以 `.test.mjs` 结尾。

VS Code 扩展是独立的 npm 项目，测试在 `vscode/test/`，用 vitest；在 `vscode/` 目录运行 `npm run check`，见 [10-VS Code扩展](10-VS%20Code扩展.md) 第 5 节。

找不到 cc65 工具链时，需要真实工具的用例会跳过，并在跳过说明里写明原因；纯逻辑的用例不受影响。

## 2. 环境变量

| 变量 | 作用 |
| --- | --- |
| `FCDEV_CC65_HOME` | 指向自备的 cc65 目录；没有工具链包时用它跑集成测试 |
| `FCDEV_EMULATOR` | 指向自备的模拟器 |
| `FCDEV_TEST_FIRMWARE` | 指向 SB2000 的 BIOS 文件（仓库里有一份：`machines/sb2000/reference/rom/SB2K_BIOS.NES`）；设置后额外运行“SB2000 程序在模拟器里运行”的用例 |
| `FCDEV_TEST_NES_ROM` | 指向一个 NROM 的 `.nes` 文件；设置后额外对它做完整反汇编与回读 |
| `FCDEV_SKIP_GUI_TESTS` | 设为 `1` 时跳过会打开模拟器窗口的用例 |

## 3. 测试分层

| 层次 | 文件 | 内容 |
| --- | --- | --- |
| 单元测试 | `args-parser`、`config`、`build-helpers`、`targets-packagers`、`fat12-image` | 参数解析、配置查找与未知项报错、源文件收集、依赖文件解析、工具参数、目标字段校验、程序名规则、各打包器、FAT12 镜像 |
| 命令行与构建 | `cli`、`build`、`toolchain` | 帮助、版本、错误输出与退出码、`build`、`info`、`sync`；构建计划的路径规则；增量与错误提示；工具链定位的优先级与不完整报错 |
| 目标 | `sb2000`（主包） | 构建 C 与汇编程序，文件头、大小与内存布局，运行库一个函数一个目标文件、链接只带用到的函数，多页程序的文件页序、库页不够与超过上限的提示，`disk` 命令，缺少固件的提示 |
| 模拟器 | `emulator`、`sb2000`、`sb2000-library` | 调试客户端的应答解析与超时、模拟器定位、端口检查、`debug` 命令的路径换算；真实模拟器里运行 NES 程序并截图；设置固件后运行 SB2000 程序，以及运行库每个模块的测试程序（约 15 个用例，共数百项检查，文件与磁盘类用例把镜像读回核对；换页的用例覆盖 9 个库页与上限 113 个库页），见 [sb2000/01-开发指南](sb2000/01-开发指南.md) 第 12 节 |
| 反汇编 | `disasm` | 映像读取、CDL 与轨迹解析、静态追踪、信息文件、回读校验；对 `fcdev` 自己构建的 NES 与 SB2000 程序做完整反汇编；设置 `FCDEV_TEST_NES_ROM` 时对真实游戏做反汇编 |
| 创建包 | `create`（`create-fcdev`） | 参数解析、模板列表、项目生成、目录检查、交互选择、安装流程；四个模板都能用 `fcdev` 构建 |
| 接口文档 | `api-command`（主包）、`sb2000-api`（仓库） | `fcdev api` 命令的各种查询与错误提示、头文件文档注释的解析、系统调用标签的匹配；SB2000 接口检查（函数文档完整、有且只有一处实现、每个功能号被封装或写明不封装的原因）；入库的 `api-reference.md` 与头文件生成的结果一致 |
| 仓库 | `cc65-tools`、`sb2000-header`、`structure` | `cc65/` 里的必要路径与工具链包的校验值；入库的 `sb2000-symbols.h` 与生成结果一致；分层检查对违规的识别 |
| 文档 | `docs-command`（主包） | `fcdev docs` 命令的列表、按主题名、文件名与关键词查询、`--json`、错误提示；文档主题登记与 `docs/` 目录里的文件一一对应（包内其他位置的登记项文件必须存在），主题名合法且不重复，架构文档的文档清单列全了每个主题 |

集成测试用真实的 cc65 构建四个模板，检查产物头部与大小。

## 4. 模拟器验证

- NES hello 与 SB2000 的 C、汇编 hello 在模拟器里运行，用调试服务的 `shot` 命令截图，核对屏幕文字：NES 显示 `HELLO, NES!`，SB2000 显示 `Hello, SB2000!` 与“你好，小霸王！”并能返回 DOS。
- SB2000 的程序运行环境验证（V01 到 V10）的结论见 [sb2000/02-系统调用手册](sb2000/02-系统调用手册.md) 第 9 节。
- 运行库测试程序的停靠点用写断点实现（对全局变量 `sb_test_stop` 设断点），不对函数入口设执行断点，原因见 [sb2000/01-开发指南](sb2000/01-开发指南.md) 第 12 节。
- 用调试服务验证时一律显式指定端口，避免连到别的模拟器；只结束本仓库启动的模拟器进程。

## 5. 反汇编验证

`fcdev` 自己构建的 NES hello 与 SB2000 的 `.EXE`，以及一个真实的 NROM 游戏（超级马里奥）回读后都与原文件逐字节一致，详见 [06-反汇编](06-反汇编.md) 第 6 节。

## 6. 安装验证

`npm run release:verify`（`tools/verify-install.mjs`）：

1. 把四个包用 `npm pack` 打成 `.tgz`。
2. 在临时目录里从本地 `.tgz` 安装 `create-fcdev`，不访问 npm 仓库，也不执行 `npm publish`。
3. 对四个模板分别：用 `create-fcdev` 创建项目（`--no-install`），从本地 `.tgz` 安装 `fcdev` 与工具链包，运行 `npm run build`，检查产物头部：NES 为 iNES 文件头，SB2000 为 `4C ?? ?? AA 55`。
4. 调试 SDK 单独装进临时目录，确认 `ember-debug-sdk` 与 `ember-debug-sdk/node` 两个入口能加载，`dist/cli.js`、`dist/mcp.js` 在。
5. 结束后删除临时目录；加 `--keep` 可保留，便于查看。

只验证构建，不启动模拟器。

## 7. 注意事项

- 带真实模拟器的用例运行后会在模拟器所在目录里生成 `VirtuaNES.ini` 与 `save/`，不用删。
- 没有目测的界面输出，汇报时写明。
