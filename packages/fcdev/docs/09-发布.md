# 发布

本文说明四个 npm 包的发布顺序、前提、检查和元数据。npm 的登录与 `npm publish` 由用户执行，不在代码或文档里记录任何凭据。

## 1. 包与版本

| 包 | 说明 |
| --- | --- |
| `@rujianjs/fcdev-cc65` | 工具链包，目录 `packages/fcdev-cc65` |
| `@rujianjs/fcdev-emulator` | 模拟器包，目录 `packages/fcdev-emulator` |
| `fcdev` | 主包，对两个包写精确版本的 `optionalDependencies` |
| `create-fcdev` | 创建包；生成的项目依赖与它同版本的 `fcdev` |

- 四个包同一个版本号，由 `release-check` 检查；`fcdev` 对工具链包与模拟器包的依赖版本必须与之相同。
- 工具链包与模拟器包的包名带 `@rujianjs` 作用域，目录名不带。作用域包默认不能公开发布，所以它们的 `package.json` 写了 `publishConfig.access` 为 `public`，`release-check` 会检查这一项，以及这两个包的包名是否都在 `fcdev` 的 `optionalDependencies` 里。
- 不带作用域的名字发布时被 npm 的垃圾包名检测拦截（403），所以改用作用域，见 [01-软件架构设计](01-软件架构设计.md) 的 D02。
- 工具链包与模拟器包的 `package.json` 由构建脚本生成，版本取主包的版本。修改版本号后，要重新运行 `node tools/build-cc65.mjs` 与 `node tools/build-emulator.mjs`。
- 每个包的 `package.json` 写 `license`、`engines`（`node >=22`）、`files`，不写 `repository`、`homepage`、`bugs`（源码不公开，写了也打不开）。作者与邮箱为 `sungbin`、`sungbin@3578.cn`。

## 2. 发布前提

1. 所有改动已提交。
2. 在已提交的状态下重新运行 `node tools/build-emulator.mjs`，使模拟器包清单里的 `sourceDirty` 为 `false`。`sourceDirty` 只看 `virtuanes/` 目录有没有未提交的改动。
3. 工具链包与模拟器包都已构建：`node tools/build-cc65.mjs`、`node tools/build-emulator.mjs`；各目标的运行库已构建（`fcdev` 的 `prepack` 会自动重建）。
4. `npm run release:check` 不带 `--allow-dirty` 通过。
5. `packages/fcdev/CHANGELOG.md` 里已经写好本版本的更新说明（四个包共用一份，标题写成 `## <版本号>（日期）`）；只写面向使用者的功能性变化，按功能分组，一条一句话。VS Code 扩展与模拟器各有自己的 `CHANGELOG.md`（`vscode/`、`virtuanes/`），版本号独立，有改动才升。

## 3. 检查

`npm run release:check`（`tools/release-check.mjs`）只检查，不修改任何文件，也不执行 `npm publish`：

- 四个包的版本一致，都写了 `license`，`fcdev` 对工具链包与模拟器包的依赖版本一致；这两个包的包名都在 `fcdev` 的依赖里，作用域包声明了公开发布。
- `fcdev` 的 `CHANGELOG.md` 在发布内容里，且有当前版本的标题。
- 每个目标都已构建运行库，且运行库在 `fcdev` 的发布内容里。
- `docs/` 目录下的全部开发文档都在 `fcdev` 的发布内容里（安装后在 `node_modules/fcdev/docs/`，`fcdev docs` 命令读取）。
- 工具链包里的文件与 `manifest.json` 记录的 SHA-256 一致，没有清单之外的文件；模拟器包里清单中的文件与记录一致，并且发布内容里只有清单中的文件。模拟器包的 `package.json` 的 `files` 逐个列出这些文件，所以调试时模拟器在 `bin/` 里生成的 `VirtuaNES.ini`、`save/` 等文件不会被发布，也不用删除。
- 模拟器清单的 `sourceDirty` 为 `true` 时报错；加 `--allow-dirty` 降为警告，只用于发布前的演练。
- 每个包的发布内容（`npm pack --dry-run`）包含 `LICENSE`、`package.json` 与必需的文件，且不含测试、`node_modules`、`.env`、密钥与证书文件、`.tgz`。

`npm run release:verify` 做安装验证，见 [08-测试与验证](08-测试与验证.md) 第 6 节。

## 4. 发布顺序

先发工具链包与模拟器包，再发 `fcdev`，最后发 `create-fcdev`：

1. `@rujianjs/fcdev-cc65`
2. `@rujianjs/fcdev-emulator`
3. `fcdev`
4. `create-fcdev`

`npm publish` 需要先登录 npm，可能还要二次验证。可以先对每个包运行 `npm publish --dry-run`，核对内容清单与体积。

## 5. 包的体积

`npm publish --dry-run` 的结果（版本 0.1.0）：

| 包 | 文件数 | 包大小 |
| --- | --- | --- |
| `fcdev` | 71 | 64 kB |
| `create-fcdev` | 23 | 15 kB |
| `@rujianjs/fcdev-cc65` | 223 | 1.9 MB（解压 6.2 MB） |
| `@rujianjs/fcdev-emulator` | 7 | 0.7 MB（解压 1.8 MB） |

体积随内容变化，以实际运行 `npm publish --dry-run` 的结果为准。

## 6. 发布脚本

`tools/release.mjs` 把上面的步骤串起来，不暂存、不提交：

| 命令 | 作用 |
| --- | --- |
| `npm run release:prepare -- <版本号>` | 升版本号：改主包与创建包的 `version`、主包对两个包的精确依赖，重新构建两个包并生成它们的 `package.json`，再运行 `npm install` 刷新锁文件。完成后由使用者自己提交 |
| `npm run release:publish -- --dry-run` | 演练：跑全部测试、重建模拟器包、`release:check`、`release:verify` 与各包的 `npm publish --dry-run`，不登录、不真正发布；已经发布过的版本只警告并跳过试发布 |
| `npm run release:publish` | 正式发布：工作区必须已提交、`npm` 已登录、四个包的该版本都未发布；通过同样的检查和试发布后，输入 `yes` 确认，再按第 4 节的顺序发布，最后用 `npm view` 核对。验证码由 npm 在终端里询问 |

两个命令都可以加 `--allow-dirty`，允许工作区有未提交的改动，只用于演练。
