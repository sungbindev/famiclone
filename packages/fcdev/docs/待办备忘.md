## 2. VS Code 扩展

扩展的智能感知与 ca65 语法高亮已完成，见 [10-VS Code扩展](10-VS%20Code扩展.md)。发布到 VS Code 市场需要发布者账号，由用户操作，本仓库只负责生成 `.vsix`。下面是还没做的功能：

| 功能 | 说明 |
| --- | --- |
| 任务 | 任务提供者 `fcdev`：构建、运行；问题匹配器识别 `cc65`、`ca65` 的 `文件(行): Error: 信息`，报错可跳转到源码行 |
| 命令 | 新建项目（调用 `create-fcdev`）、构建当前文件、构建当前目录、构建项目、运行、切换目标；状态栏显示当前目标 |
| 找工具 | 项目里没有安装 `fcdev` 时提示一键安装；现在只在日志里写明原因 |

| 真实 VS Code 里的显示效果 | 扩展已做完，类型检查、测试与构建通过；悬停、补全、高亮在真实 VS Code 里的显示效果待用户核对 |

## 3. 模拟器

| 事项 | 说明 |
| --- | --- |
| 内核集成进 VS Code 面板 | 只要 Ember 的调试服务协议不变，`fcdev` 不用改 |
| 学习机目标在 Ember 里运行 | Ember 支持学习机整机后：`fcdev run` 接回 `firmware-disk` 方案（`machines.boot`、`media.floppyInsert`）；`sb2000-library` 测试重写会话类后恢复（见 `test/sb2000-runner.mjs` 文件头）；补回“SB2000 程序在 Ember 里运行”的用例；核对 `sb2000/01-开发指南` 里依赖旧调试命令的示例程序说明 |
| 已有 Ember 时 `fcdev run` 载入不进程序 | Ember 单实例，第二个进程只把已有窗口提到前面，不处理 `--cartridge`；需要 Ember 的 `second-instance` 处理它，或 `fcdev` 改用已开启的调试服务载入 |
| 存档（`savestate`、`loadstate`） | 旧模拟器有、Ember 没有，已登记在 Ember 的待办里，做完后通过 `fcdev debug call` 直接可用 |
| 外设读数与真机对齐 | `hwtest` 在真机与模拟器上仍有差异的读数（`$4015` 位 4、`$4022` 开机值、`$4026`、`$4016`、`$4017`、`$4033` 位 6、`$3FFF`），具体数值见 [03-硬件说明](sb2000/03-硬件说明.md) 的“真机与模拟器仍有差异的行为”；程序不应依赖这些值，是否对齐由用户决定。|
| `runnes` 与 `play` 的 DMA 写法 | 两个程序借用程序窗口 2（`$A000`）做 DMA 目的，真机上失败，模拟器对齐真机后也失败（`runnes` 现在用库函数 `sb_dma_to_cpu`，目的在窗口时函数直接返回出错、不复制）；改成先 DMA 到 ERAM 缓冲再用 CPU 搬（参考 `apps/sb2000/bbk-loader`） |

## 4. 目标

| 事项 | 说明 |
| --- | --- |
| 步步高、裕兴的目标 | 缺少资料，动手前先用资料与模拟器确认程序格式、内存布局、系统调用与固件要求 |
| NES 的其他映射器 | 现在只支持 `nes.cfg` 的 NROM |
| SB2000 的退出码 | `main` 的返回值没有实现为退出码：`$6308` 是运行库显示消息用的 `LIB_GROUP`，DOS 外壳不读取程序返回时的它，系统里没有退出码这个约定；要不要提供自己的约定（如写到某个 ERAM 单元）以后再定 |
| SB2000 没封装的系统调用 | 见 [api-reference.md](../targets/sb2000/api-reference.md) 末尾的覆盖表与 `api-unwrapped.json`：文件系统内部步骤、`$41`-`$44`、`$31`、`$34`、`$66`、`$65` 与 `$6D` 的部分子功能、`$74`/`$75` 的 NMI 发送与播放列表等；有需要时再封装并补测试 |

## 5. 反汇编

| 事项 | 说明 |
| --- | --- |
| 其他映射器 | 现在只支持 NROM 与平铺二进制；其他映射器需要目标提供地址映射 |
| 跳转表识别 | 已识别 `LDA 表,X` 加间接 `JMP`、`PHA`/`RTS` 的表和 `JMP (地址)` 指向的表；例程内联的跳转表（`JSR` 之后紧跟地址表）、立即数拼出的分发指针还追不到，这部分按数据输出；补全覆盖靠运行记录：模拟器 `trace ... unique` 在步步高机型上可用，CDL 只对 SB2K 映射器有效，对步步高 RAM 里的程序没用。立即数拼出的指针可以让 `fcdev` 列出“可能的入口”供人工确认，还没做 |
| 地址表与字符串识别 | 现在没追到的字节都是 `ByteTable` |
| SB2000 固件页的 CDL 验证 | 没有做；模拟器自带 CDL 只对 SB2K 映射器有效 |
