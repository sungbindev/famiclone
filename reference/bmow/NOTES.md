# Floppy Emu 固件反汇编笔记（Model B，固件 250225A）

## 文件

| 文件 | 说明 |
| --- | --- |
| `bin/femu.bin` | 官方统一固件（AVR 程序 + CPLD 数据），184361 字节（0x2D029），与官网 `femu-250225A.zip` 内的 `femu.bin` 逐字节相同 |
| `bin/firmware.xvf` | 官方包里没有单独列出，这里的是从 `femu.bin` 0x20000 起截出的 CPLD XVF 数据（53289 字节 = 0xD029）；与包内 `femu.bin` 同段相比有少量字节差异（0x85、0x94 等处 0x11 对 0x01），来源待确认 |
| `tools/avr-gcc-16.1.0-x64-windows/` | ZakKemble avr-gcc-build v16.1.0-1 的 Windows 工具链（含 avr-objdump、avr-as、avr-ld、avrdude、make），用于反汇编与以后重汇编补丁 |

## femu.bin 布局（按文件偏移，已核对）

| 范围 | 内容 | 依据 |
| --- | --- | --- |
| 0x00000–0x0008B | AVR 中断向量表（35 个 `jmp`，ATmega1284 风格） | 反汇编：复位向量 `jmp 0x1FDE`（字节地址） |
| 0x0008C–0x01FD7 | 数据：菜单/错误字符串、5×7 字库、键盘扫描表等 | 字符串 `NO SD CARD` 0xAC、`Apple II 5.25 Floppy` 0x2CE、`140K NIB` 0x11AA、`FEMU.BIN` 0x1CB0、版本 `250225A` 0xCEF |
| 0x01FD8–0x12EFF | AVR 程序代码（约 68 KB） | 0x1FDE 起是标准 GCC 启动代码（清 SREG、设栈 0x40FF、拷 .data、清 .bss、调 main 0x3B54）；代码里 `lds/sts 0x33xx–0x3Bxx` 与 16 KB RAM 一致 |
| 0x12F00–0x1EFFF | 全 0 填充 | 逐块统计 |
| 0x1EFF8–0x1EFFF | `DD DD DD DD 00 01 00 00`，疑似容器头/校验 | 待确认 |
| 0x1F000–0x1FFFF | 全 FF（4 KB） | 逐块统计 |
| 0x20000–0x2D028 | CPLD 的 XVF 编程数据（53289 字节） | 与 `firmware.xvf` 同格式，开头 `07 20 12 00 …` |

复位向量按字节地址 0x1FDE 指向 0x1FDE 处的启动代码，说明 AVR 程序在文件里就是按“文件偏移 =  flash 字节地址”摆放的（向量表在 0，代码在 0x1FD8 之后，中间夹着数据）。

## RAMPZ 远指针机制（已确认，解释了"搜不到字符串引用"）

- 启动代码 0x1FF4：`ldi r16,1; out 0x3b,r16` 设 RAMPZ=1，随后 `elpm` 从 Z=0x2BE4 拷 .data，实际读 flash 字节地址 **0x12BE4**。即 .data 初值在文件 0x12BE4–0x12DB5（210 字节）→ RAM 0x0100–0x03D1；BSS 0x03D2–0x3B04 清零。
- 0x12308 是远指针蹦床：16 位地址左移、进位送 RAMPZ，`elpm`+`ijmp`。≥64KB 的 flash 数据都经它或 RAM 副本间接访问，**不会以 ldi lo/hi 立即数对出现**，所以按字节对穷举字符串地址全部落空。
- 布局修正：代码 0x1FD8–0x12BE3；.data 初值+表+字符串 0x12BE4–0x12EFF。

| RAM 0x3846 | 磁道/半磁道相关计数（0x43FE 处 swap 后取高半字节，上限 4） |

## 已确认的关键机制（详见 方案文档.md）

- **NIB 大小判定**：类型识别函数 0xC842，0xC912 处 `cp/cpc` 比较文件大小 r4:r7 == 0x38E00（232960）→ 类型 19（NIB）。266240（0x41000）不匹配，落未知类型。文件大小在 0xC8A0 从目录项 Z+28..31 载入。
- **磁道数通用计算**：0x6604 `ldi r26,0; ldi r27,0x1A`（6656）后调除法 0x12346，磁道数 = 文件大小 ÷ 6656。266240→40、232960→35，自动得出，不写死。
- **几何表已含 40 磁道**：flash 0x17A7 每磁道 nibble 数表（40 字节）、0x18F7 磁道偏移表（40 个 16 位 LE，0..438）。40 磁道 NIB 进入 NIB 路径后现有代码即可处理。
- **顶层模式**：RAM 0x33FE（3–8）；EEPROM 地址 2 持久化（读 0x12B7A/写 0x12BA8）；模式名表 flash 0x5ED（步长 23、6 项，首字符为模式号 ASCII）；菜单模式数 0x30F4/0x32BA `ldi 6`；模式兼容检查 0x5C28；磁盘初始化 0x6400（模式 4/8/7 置 0x381C=1）；类型识别读模式 0xC8A8；参数设置 0x423C。
- **类型 19 分发点**（复用 NIB 时不改）：0x457C、0x49E0、0x4AC0、0x4BA8、0x6526、0x6AB2、0x6C24、0x6C5A、0x6CFA、0x6ED0、0x7FD4、0x8068、0x862C、0x86FC、0x89FE、0x11268。
- **空闲 flash**：0x12F00–0x1EFF7 全 0（约 48 KB），新代码放这里。

## 尚未定位的点

- `emumode.txt` 的读取与模式名→模式号映射函数（0xEE00 区域是数据非字符串，解析在别处）。
- 菜单模式 ID 数组 RAM 0x3D2 的填充循环与上限常量。
- EEPROM 地址 2 的模式合法范围校验。
- 0x1EFF8 的 `DD DD DD DD 00 01 00 00` 标记含义；firmware.xvf 与内嵌 XVF 的 0x11↔0x01 差异来源。

## 方向（用户已确认）

新增**顶层模式 9「Pyramid 40-track 5.25」**，复用类型 19 的 NIB 路径：只新增模式号/名称/参数与一条大小判定分支（模式 9 认 266240），NIB 流水线零改动。完整方案见 `方案文档.md`，经用户确认后再改固件。刷入：SD 卡根目录放 `femu.bin`，SELECT+PREV 按住再按 RESET。
