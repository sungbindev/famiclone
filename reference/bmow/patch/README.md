# Floppy Emu 固件补丁：新增模式 9（金字塔 40 磁道 NIB）

给 BMOW Floppy Emu Model B 统一固件 `femu.bin`（250225A）新增一个顶层模拟模式 **9**，用来挂载金字塔 PEC-9588 的 40 磁道 5.25 寸 `.nib` 镜像（266240 字节 = 40 × 6656）。复用现有类型 19（NIB）流水线，现有 6 个模式与所有镜像类型行为不变。

**模式 9 已加入按键模式菜单的第 3 位**（Settings → Disk Emulation Mode 列表：3 Apple II 3.5、4 Apple II 5.25、**9 Pyramid 40-track**、8 Dual 5.25、5 Smartport、7 Smartport Unit 2、6 Unidisk 3.5），像其他模式一样按键选择，不需要任何 SD 卡文件。

## 功能核心

模式 9 行为等同模式 4（Apple II 5.25），差别有两处：NIB 大小识别认 266240（40 磁道）；NIB 读头限幅从 35 道放宽到 40 道（原固件实时伺服路径钳在 35 道，见下「NIB 读头 40 道限幅」节）。磁道数由现有 `文件大小 ÷ 6656` 自动算出，几何表已含 40 项。选中后存入 EEPROM[2] 持久化，以后开机自动是模式 9。

补丁点（原函数用 `jmp` 跳入空闲 flash 0x12F00 的蹦床，被替换指令在蹦床里复现）：

| 补丁点 | 原指令 | 作用 |
| --- | --- | --- |
| 0x283A | `cpi r24,4; brne` | 模式名显示分发：模式 9 同模式 4 |
| 0x3342 | `cpi r24,8; brcs` | emumode.txt 数字范围接受 9（原厂可选机制，保留兼容） |
| 0x5C34 | `cpi r24,7; breq` | 模式兼容检查：模式 9 类型 15..24 合法 |
| 0x6414 | `cpi r25,7; breq` | 磁盘初始化：模式 9 置 5.25 标志 0x381C=1 |
| 0xC912 | `cp r4,r1; ldi r18,0x8E` | NIB 大小识别：模式 9 认 266240，其余模式仍认 232960 |
| 0x3DAE | `cpi r24,9` → `cpi r24,10` | main 模式合法范围由 3..8 扩到 3..9 |
| 0x3142 | `cp/cpc/brne` | 菜单构建循环：前 2 项后插入模式 9 于第 3 位，原第 3–6 项后移到第 4–7 位 |
| 0x31F2 | `lds r24,0x3D9` → `0x3B06` | 菜单项数计数器迁到空闲 RAM（0x3D9 让给第 7 项数组槽） |
| 0x32B4 | 名称查找循环尾 | 选模式后状态栏：模式 9 用远地址绘制器画名称 |
| 0x3114 | `subi r30,0x2D` → `0x2E` | 原循环存行 1、2 的槽地址改新基址（槽 = 0x3D2+行号） |
| 0x31C8 | `subi r30,0x2E` → `0x2F` | PREV 读上一槽的地址改新基址（读 0x3D1+下标） |
| 0x31FC | `subi r30,0x2D` → `0x2E` | NEXT 读下一槽的地址改新基址（`ldd Z+1` 落在 0x3D3+下标） |
| 0x8C62 | `ld r18,Z; cpi r18,0x8C` | NIB 读头限幅（主循环）：模式 9 改走 160/159（40 道）限幅 |
| 0x47C8 | `ld r24,Z; cpi r24,0x8C` | NIB 读头限幅（定时器中断）：同上 |
| 0x4B8C | `lds r19,0x35EB` → `jmp 蹦床` | 写会话启动：上一段写的收尾未完成时有界宽限重试（最多 200 半字节），超时仍走原故障路径报错 |

## 菜单扩项的实现

模式名表（flash 0x5ED，6 项 × 23 字节）结束于 0x677，紧接图形函数 0x2A4C 读取的图标数据，低 64KB 又没有足够大的安全空闲区放第 7 项；而字符串绘制器 0xE902 只用 `lpm`（仅低 64KB）。为此：

- 第 7 项名称 `"9 Pyramid 40-track"` 放高 flash **0x13400**（保证空闲区）。
- 把字符串绘制器 0xE902–0xEA5A **克隆**一份到 **0x13900**，5 处 `lpm r24,Z` 改成 `elpm r24,Z`（无自增，0x9184→0x9186），两处字库基址改指字库副本；尺寸不变，内部相对跳转全部保留。
- 字库（OLED 0x1EA3 / 非 OLED 0x1CB9）整段复制到 **0x13500**，克隆绘制器在 RAMPZ=1 下读它。
- `draw_far` 包装：调用克隆前设 RAMPZ=1、调用后恢复，并保存 r16。
- 菜单构建蹦床 `T_menu`：原循环绘前 2 项（表项 0、1 → 行 1、2）后 r29==3，直接进插入块（不再回原循环）：插入模式 9 于行 3（存数组 0x3D5、设光标、远地址画名称、记选中下标），再把表项 2..5 用原绘制器绘于行 4 起；保留原硬件门控（模式 7 需 0x3413!=0、模式 8 需 0x3413>=2，缺硬件跳过不占行），项数按实际绘制行数计算。循环变量只用绘制函数保留的寄存器（r14–r17 表指针/表尾、r29 行、r28 模式号；r18–r27、r30:r31 跨 call 会被破坏）。项数计数器从 RAM 0x3D9 迁到 0x3B06（0x3D9 成为第 7 个数组槽，0x3DA/0x3DB 的另一变量不受影响）。
- **槽位基址统一（2026-11-27 修复）**：原固件的槽地址是 `0x3D3+行号`（行 1→0x3D4 … 行 6→0x3D9，项数也写 0x3D9 与末槽重叠），PREV 读 `0x3D2+下标`、NEXT 读 `0x3D4+下标`。扩到 7 项后新基址改为 `0x3D2+行号`（行 1→0x3D3 … 行 7→0x3D9），`T_menu` 之外还必须同步改三处原指令的 `subi` 立即数：0x3114（原循环存行 1、2）、0x31C8（PREV 读槽）、0x31FC（NEXT 读槽）。首版漏了这三处：行 3 的“9”写进 0x3D5 覆盖行 2 的“4”，NEXT 按旧地址读到隔一项的槽（1→3→5 跳项），PREV 实际往下走、在第 7 行再按读到 0x3DA（另一变量）当模式号 → 非法模式死机。现三处已改，构建脚本对这三处及 0x3DAE、0x31F2 校验原字节后才写入。
- 名称查找蹦床 `T_lookup` 扫完 6 项未中且模式==9 时，用 `draw_far` 画名称。

原有模式名表、图标数据、字库、RAM 变量**一个字节都不改**；所有新内容都在原全 0 空闲区。

## NIB 读头 40 道限幅（2026-11-27 修复真机 I/O ERROR）

真机现象：模式 9 下 CATALOG 经常 I/O ERROR、SAVE 失败，出错一次后磁盘操作全部失败。根因：原固件的 NIB 路径把读头位置（四分之一磁道单位，`>>2` 后查几何表）钳在 **140（35 道×4）**，超出写 139；WOZ 与部分 DSK 类型才走 160/159（40 道）限幅。几何表虽有 40 项、磁道数虽算出 40，读头却走不到 35–39 道：金字塔 LM-DOS 的 VTOC 是 40 道，INIT 要格式化 0–39、文件分配优先用 18 道往外的空间，访问 ≥35 道时读头被钳在 34.75 道——读到的地址场磁道号对不上 → I/O ERROR；写把 35–39 道的内容反复砸在 34 道上，盘上数据实际损坏，后续读写连环出错。

修复：两处对称的限幅点（主循环 0x8C62、定时器中断 0x47C8，各替换 `ld+cpi` 4 字节为 `jmp`）先查模式：模式 9 直接跳原 160/159 限幅入口（0x937E / 0x4820，它们自己再查 <160 则继续、否则写 159）；其余模式复现原 `cpi 140` 分支，行为不变。下溢（位置绕回 ≥251）归零的回零校准在别处，不动。

**旧盘不能复用**：在 35 道钳位下 INIT/SAVE 过的镜像，34 道附近内容已损坏；重刷后要用全新的 266240 字节全 0 `.nib`（如 `../../floppy-images/pec9588/blank.nib` 的副本）重新 INIT。

## 写会话启动竞态（2026-11-27 修复偶发 SAVE I/O ERROR、重试即成功）

真机取证（fail1/fail2.nib + 操作照片）：偶发首次 SAVE 报 I/O ERROR，立刻重试即成功；失败那次的数据没落盘但目录已更新。

**标志的真实含义（已逐点核实）**：`0x35EB` 位 2 在写会话启动时置位（0x4B98），在主循环的写收尾处理里清零（0x8694）。写捕获入口 `0x4AB4`（定时器中断逐半字节调用）在新会话首半字节处（0x4B8C）查它：若仍置着，说明**上一段写在主循环里的收尾还没跑完**。DOS 连续写扇区时两扇区间只隔约 40 个半字节（约 1.3ms），主循环此时若正忙（上一道的 SD 写回、屏幕刷新），收尾赶不上，原固件就置写故障标志 `0x381F` 并**中止整段写入**——主机继续写但固件不再接收，校验读回失败报 I/O ERROR；重试时收尾早已完成故成功。是否撞上取决于主循环当时的忙闲，故偶发。

**修复：有界宽限，不掩盖错误**。`0x4B8C` 的 `lds r19,0x35EB`（4 字节）改跳蹦床 `T_wstart`：收尾未完成时最多丢弃 200 个半字节（≈6.4ms，计数器在空闲 RAM 0x3B07）等收尾；窗口内完成→会话正常启动并清零计数；**窗口耗尽→清零计数并走原故障路径（0x5064），照样报错**。持续性错误一个不吞，只豁免已被真机实验证实重试即成功的瞬态情况；若收尾慢到拖过地址场，丢的首扇区也会像原来一样被校验发现。丢弃的前导同步半字节（FF）无害，捕获状态机在地址场重新同步。此处 r24:r25=6656、r18=类型号是活寄存器，蹦床用 r24 先 push/pop；0x3B07 不在启动清零范围内，上电残值若 ≥200 则首次直接走原故障路径（等于原行为，安全），此后计数总被清零。首版「无限期丢弃等待」会把持续性错误变成静默丢数据，已撤销重做。

## 诊断版（当前 build/femu.bin，2026-11-27）

新样本 fffffffff.nib：连续 5 次 SAVE 成功（18–22 道全对），第 6 次起连续失败；失败的 23 道**连写回都没有**（间隙指纹仍是 Ember 原始 984），与 fail1/fail3「写回了但全 0」是两种形态，静态读码已无法唯一区分是哪道守卫拒写还是捕获静默丢数。为此当前构建是**诊断版**：写行为与宽限修复版完全相同，只加观察——

- 各拒写出口与关键事件计数（封顶 9，空闲 RAM 0x3B08–0x3B0E）：**P**=相位拒写（0x4D6C）、**W**=写保护（0x3400）、**S**=残留故障标志（0x381F）、**G**=宽限超时、**R**=宽限重试、**B**=写会话启动、**C**=磁道提交（0x653E）。
- 中断里的钩子只加计数（约 20 周期）；显示在主循环钩子（0x7DAE）里做：Floppy Emu 自己的小屏**底行（行 7）一字排开 P W S G R B C**，像素列 0/16/32/48/64/80/96，字符串 "X0"–"X9" 在高 flash 0x13C00。进模拟画面立即画出全 0（影子初始化 0xFF 强制首绘）；此后计数总和变化立即重画，另每 65536 次主循环强制重画（16 位计数 0x3B11:0x3B12），不会被固件自身的清行/活动刷新抹掉。
- 用法：刷诊断版 → 全新空盘（Ember INIT）→ 反复 SAVE 直到复现 I/O ERROR → **拍 Floppy Emu 小屏**（不是学习机屏幕，计数在小屏底行）连同学习机报错画面一起发来。判读：G>0＝宽限超时（收尾/SD 忙）；P>0＝相位守卫；S>0＝残留故障；W>0＝写保护；全 0 但 B 增 C 不增＝捕获静默丢数（另一类根因）。
- 诊断钩子与计数在定位后移除，再出正式修复版。

新样本 fff.nib（刷首版诊断版后，保存前副本 new.nib）：全新盘 SAVE HELLO 连续 3 次失败，逐字节对比**只有目录道 17 变了 52 字节，所有数据道一个字节都没写**——目录写回成功、数据道整道被拒，与「相位守卫拒写后置粘滞标志 0x381F、整道中止」的形态吻合（粘滞标志只在写模式切换沿清，故同道后续全被拒；换道写目录时切换沿清了标志所以目录能写）。首版诊断的屏幕显示本身有缺陷（见下），计数没拍到，本版修好显示后重测。

**首版诊断显示没看到的根因（已修）**：光标函数 0xE4C2 的列参数是**像素**（OLED 0–127）不是字符列，首版按字符间距 0/3/6/9 摆，约 12 像素宽的标签互相叠死；且「总和变化才重画」导致首屏全 0 从不画、画过一次后又被固件自身的清行（0x8848/0x8AD6 绘 21 个空格清行 3/6）与活动刷新抹掉。现改为：七计数全画在行 7（底行，固件模拟画面不用，模拟画面用行 0/3/4/6 与活动行）、像素列距 16、首屏强制画、周期重画。计数 RAM 0x3B08–0x3B12 已核对原固件无直接/指针引用（BSS 清到 0x3B04）。

构建注意：这版 avr-as 的宏展开会把**输入文件路径里的反斜杠**当转义处理（带 .macro 的源文件用绝对 Windows 路径会报 bad escaped character），build.mjs 已改为切到补丁目录用相对文件名汇编（与换行符无关，CRLF/LF 均可）。

## 构建

```
node patch/build.mjs
```

脚本自动：汇编 `patch.s` → 链接到 0x12F00（`patch.ld`）→ 提取 `.text` → 用 `avr-nm` 取蹦床地址生成 `jmp` → 生成第 7 项数据/字库副本/克隆绘制器 → 拼回 `bin/femu.bin` 副本 → 逐字节校验 → 输出 `build/femu.bin`。

校验内容：输出与原件等长；除补丁点与写入区外逐字节一致；CPLD 段完全不动；所有写入区（蹦床/第 7 项/字库/克隆）原为全 0；克隆 lpm 站点数==5；布局不重叠。任一不满足即报错退出，不写输出。

工具链在 `../tools/avr-gcc-16.1.0-x64-windows/bin/`（avr-as、avr-ld、avr-objcopy、avr-nm）。

## 刷入与验证（用户在真机做）

1. 把 `build/femu.bin` 复制到 SD 卡根目录，文件名 `femu.bin`。
2. 按住 SELECT+PREV 再按 RESET，进入固件更新（官方 readme 流程）。
3. 开机进文件菜单 → **Settings** → **Disk Emulation Mode**，列表第 3 位应是 **"9 Pyramid 40-track"**；NEXT/PREV 逐行移动（1→2→3→…→7，不跳项、末行按 PREV 往回走不重启），选它按 SELECT。存 EEPROM 后以后开机自动模式 9。
4. 挂**全新的** 266240 字节 40 磁道全 0 `.nib`（如 `../../floppy-images/pec9588/blank.nib` 的副本；旧版固件写过的盘已损坏，不能复用）应识别为 NIB（模式 4 下同一文件认不出，可据此确认模式 9 生效）；金字塔机器里 `INIT` 格式化后 `CATALOG`、`SAVE`/`LOAD` 应反复稳定成功（含存到 35–39 道的大文件）。
5. 切回其他模式：同一菜单选 3–8 即可。回归：模式 4 挂 232960 字节 35 磁道 `.nib` 仍正常；其余模式与类型不变。

不需要 emumode.txt。原厂 emumode.txt 机制仍保留（卡上有该文件时进 Disk Emulation Mode 会按文件设模式），不用它就不建文件。

Ember 侧已验证 266240 字节 40 磁道 `.nib` 可 INIT→SAVE→LOAD→RUN，可作镜像正确性参照。

## 风险

- 无硬件实测，刷入由用户做。改坏可用官方 `femu.bin`（`../bin/femu.bin` 逐字节一致）经同一 SD 卡流程重刷恢复。
- 菜单第 7 项的名称显示依赖克隆绘制器与字库副本，已反汇编核对编码与跳转，但真机显示效果（字形、选中高亮）需用户目测确认。
- 模式 9 只认 266240 的 NIB（35 磁道 232960 在模式 9 下不被接受），这是有意的模式区分；模式 4 仍只认 232960。
