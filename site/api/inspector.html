请求

请求 简介
inspector.listSpaces 列出全部内存空间：总线视角的 cpu 与 ppu，主板与芯片里的存储，以及卡带上的存储区（cart.<存储区标识>）
inspector.readMemory 读一段内存，不改变主机的任何状态：cpu 与 ppu 空间里寄存器类地址读出 0（不读寄存器，所以不会清标志），卡带脚本的寄存器也不会被回调
inspector.writeMemory 写一段内存
inspector.resolve 解析一个总线地址：它落在哪块存储区的哪个偏移，或哪个寄存器
inspector.getState 读状态：cpu（寄存器与周期数）、ppu（扫描线、点、帧数、滚动寄存器、标志）与卡带的脚本状态（mapper）
inspector.snapshot 取得完整快照：各模块的状态、断点与监视项，以及此刻的 CPU 周期数，都在同一个时刻读出，是一致的
inspector.watch 监视一个状态项：它的取值变化时发事件 inspector.stateChanged
inspector.unwatch 取消监视
inspector.disassemble 从 address 起反汇编 count 条指令（CPU 总线上的地址）
inspector.cdlStart 开始代码与数据标记（CDL）：给卡带 PRG-ROM 的每个字节打标记，标记清零后，运行与单步执行的每条指令都记：Code（0x01，被当作指令执行，含操作数字节）、Data（0x02，被指令当数据读取，不含只写的存储指令、栈与中断向量）、JumpTarget（0x04，JMP 或成立的分支的目标）、SubEntry（0x08，JSR 的目标）
inspector.cdlStop 停止标记，已有的标记保留到下一次 cdlStart 或换卡带
inspector.cdlSave 把当前的标记写成调试输出目录下的文件：PRG-ROM 每个字节一个标记字节，没有文件头，位定义同 Mesen
inspector.traceStart 开始跟踪，内容记在内存里，traceStop 时写成调试输出目录下的文件
inspector.traceStop 结束跟踪并把内容写成文件
inspector.callLogStart 开始调用记录：每次执行到 address 这条指令之前记一行，含寄存器、周期数、栈顶的若干字节（SP 之上，栈顶在前）与指定的内存段
inspector.callLogStop 结束调用记录并把内容写成文件
inspector.addBreakpoint 添加断点
inspector.listBreakpoints 列出全部断点，按编号升序
inspector.removeBreakpoint 删除一个断点
inspector.clearBreakpoints 删除全部断点
inspector.updateBreakpoint 修改断点的启用状态或条件，没有给出的项不变
inspector.callStack 读调用栈，最里层的在前
inspector.profilerStart 开始子程序统计：统计清零，之后经过的 CPU 周期按子程序与中断处理程序累计（含与不含它们调用的下层）
inspector.profilerStop 停止子程序统计并返回结果，结果保留到下一次 profilerStart
inspector.profilerGet 读子程序统计的当前结果，不停止统计
inspector.eventsStart 开始事件记录：记录清零，之后运行与单步产生的事件（对 $2000-$5FFF 寄存器的读写、对 $8000 以上的 mapper 寄存器的写、CPU 响应 IRQ、NMI 与 BRK）连同发生时 PPU 的帧、扫描线与点记在内存里，容量满了丢弃最早的
inspector.eventsStop 停止事件记录，已有的事件保留到下一次 eventsStart 或换卡带
inspector.eventsGet 读事件记录里的事件，按发生的先后排列，记录进行中与停止后都可以读
inspector.getPalette 读 64 个颜色号现在显示的颜色：按主机当前的 PPU（6576 模式与 FC 兼容模式各用自己的）和 $2001 的颜色强调与灰度位换算
inspector.traceRead 读一项正在进行的跟踪或调用记录的一段内容，不结束记录
inspector.setState 修改一个模块的状态：目前只有 cpu 可以改（pc、a、x、y、sp、status，只在指令之间生效），其余模块只读

结果

错误码：inspector.noCartridge、inspector.notPowered、inspector.unsupported、inspector.unknownSpace、inspector.outOfRange、inspector.readOnly

inspector.traceStart

只经调试服务开放（界面不能发起）

开始跟踪，内容记在内存里，traceStop 时写成调试输出目录下的文件。kind：instruction 每执行一条指令记一行（地址、指令字节、反汇编、寄存器与周期数，写法同 nestest 日志；芯片寄存器的取值显示 00）；io 每次访问 $2000-$5FFF（芯片、手柄口、卡带扩展寄存器）以及对 $8000 以上的写（mapper 寄存器）记一行（方向、地址、值、发起访问的指令地址与周期数）；irq 每次 CPU 响应 IRQ、NMI 或 BRK 记一行（种类、返回地址、处理程序地址、周期数）。单步与运行产生的内容都记，调试写内存不记。同时进行的记录最多 8 项，记录属于当前的主机，装入新卡带后作废。需要已开机。

参数

名称 类型 必填 说明
kind "instruction" | "io" | "irq" 是 跟踪的种类
file string（长度 1..100） 否 文件名，只能含字母、数字、点、下划线、短横线与空格，不含目录；省略时按种类与编号生成（trace-编号.txt、calllog-编号.txt）。文件写在调试输出目录
maxLines integer（1..1000000） 否 最多记录的行数，满了就不再记录，默认 100000
unique boolean 否 只对 instruction 有效：每个地址只记第一次，默认 false
ring boolean 否 环形：行数满了以后丢弃最早的行继续记录，可以用 traceRead 边记边读；为 false（默认）时行数满了就不再记录

结果

字段 类型 必填 说明
id integer（1..） 是 记录编号

错误码：inspector.noCartridge、inspector.notPowered、inspector.unsupported、inspector.invalidFileName、inspector.recordingLimit

示例

在 VS Code 的命令“FCDEV：调用调试请求”里输入：

inspector.traceStart kind=<"instruction" | "io" | "irq">

inspector.traceStop

只经调试服务开放（界面不能发起）

结束跟踪并把内容写成文件。需要已开机。

参数

名称 类型 必填 说明
id integer（1..） 是 traceStart 返回的记录编号

结果

字段 类型 必填 说明
file string 是 保存的文件的完整路径
lines integer（0..） 是 写入的行数
truncated boolean 是 是否因为行数满了而少记了

错误码：inspector.noCartridge、inspector.notPowered、inspector.unsupported、inspector.noRecording、inspector.fileFailed

示例

在 VS Code 的命令“FCDEV：调用调试请求”里输入：

inspector.traceStop id=<integer>

inspector.callLogStart

只经调试服务开放（界面不能发起）

开始调用记录：每次执行到 address 这条指令之前记一行，含寄存器、周期数、栈顶的若干字节（SP 之上，栈顶在前）与指定的内存段。内容记在内存里，callLogStop 时写成调试输出目录下的文件。同时进行的记录最多 8 项，记录属于当前的主机，装入新卡带后作废。需要已开机。

参数

address integer（0..65535） 是 入口地址；root 为 0
calls integer（0..） 是 调用次数：完成的调用，加上读取时还没有返回的那一次；root 为 1
inclusiveCycles integer（0..） 是 含被它调用的子程序与中断处理程序的 CPU 周期数；递归时里层的周期被重复计入
exclusiveCycles integer（0..） 是 不含被它调用的子程序与中断处理程序的 CPU 周期数

DebugEvent

事件记录里的一个事件。

字段 类型 必填 说明
frame integer（0..） 是 帧序号：从 0 起，每帧从第 0 行开始（与状态里的 ppu.frame 不同，它在画面完成的那一行就加 1）
scanline integer（0..） 是 扫描线
dot integer（0..） 是 点；按行处理的 PPU（6576）恒为 0
kind "read" | "write" | "irq" | "nmi" | "brk" 是 种类：read、write 是读写 $2000-$5FFF 的寄存器或写 $8000 以上的 mapper 寄存器；irq、nmi、brk 是 CPU 响应中断
address integer（0..65535） 是 read、write 是被访问的地址；irq、nmi、brk 是处理程序的地址
value integer（0..255） 是 read、write 读到或写入的值；其余为 0
pc integer（0..65535） 是 read、write 是发起访问的那条指令的地址；irq、nmi、brk 是返回地址
cycles integer（0..） 是 事件发生时的 CPU 周期数
