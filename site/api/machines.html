连接、认证与报文规则见连接与报文，全部请求见请求与事件总览。

请求

请求 简介
machines.list 机型清单，顺序固定为 fc、sb97、sb2000、bbg1、bbg98、pec9588、pec586、yuxing
machines.setRom 读取并检查 ROM 文件，复制进 ROM 目录（新文件写好之后才删旧文件，失败时原有的 ROM 不变）
machines.setRoms 读取目录里的 .bin 文件（不含子目录，按文件名排序），按内容的校验值认出各是哪个机型的 ROM，把还没有 ROM 的机型的 ROM 添加进来
machines.removeRom 删除机型的 ROM 文件
machines.boot 整机机型开机：读入已设置的 ROM，装配该机型的主机，已有的卡带与主机被替换，任何一步失败都不改动原有的

machines.list

机型清单，顺序固定为 fc、sb97、sb2000、bbg1、bbg98、pec9588、pec586、yuxing。

参数

（无）

结果

字段 类型 必填 说明
machines machines.MachineInfo[] 是 机型项

错误码：无专有错误码（参数不合格返回 core.invalidParams）

示例

在 VS Code 的命令“fcdev：调用调试请求”里输入：

machines.list

machines.setRom

界面里只能由主进程发起，调试服务可以调用

读取并检查 ROM 文件，复制进 ROM 目录（新文件写好之后才删旧文件，失败时原有的 ROM 不变）；成功后发 machines.changed。

参数

名称 类型 必填 说明
machine string（长度 1..） 是 机型标识
path string（长度 1..） 是 ROM 文件的路径，由外壳根据用户选择的文件给出，调试服务直接给出

结果

字段 类型 必填 说明
machine machines.MachineInfo 是 更新后的机型项

错误码：machines.notFound、machines.romNotNeeded、machines.unsupported、machines.fileNotFound、machines.fileUnreadable、machines.romInvalid、machines.romAccessFailed

示例

在 VS Code 的命令“fcdev：调用调试请求”里输入：

machines.setRom machine=<string> path=<string>

machines.setRoms

界面里只能由主进程发起，调试服务可以调用

读取目录里的 .bin 文件（不含子目录，按文件名排序），按内容的校验值认出各是哪个机型的 ROM，把还没有 ROM 的机型的 ROM 添加进来；已有 ROM 的机型保持不变，认不出的文件跳过；有添加时发 machines.changed。

参数

名称 类型 必填 说明
path string（长度 1..） 是 目录的路径，由外壳根据用户选择的目录给出，调试服务直接给出

结果

字段 类型 必填 说明
added machines.MachineInfo[] 是 添加了 ROM 的机型项（更新后）
skipped machines.RomSkipped[] 是 没有添加的文件

错误码：machines.fileNotFound、machines.fileUnreadable、machines.romAccessFailed

示例

在 VS Code 的命令“fcdev：调用调试请求”里输入：

machines.setRoms path=<string>

machines.removeRom

删除机型的 ROM 文件；没有 ROM 时没有效果也不报错；删除后发 machines.changed。

参数

名称 类型 必填 说明
machine string（长度 1..） 是 机型标识

结果

字段 类型 必填 说明
machine machines.MachineInfo 是 更新后的机型项

错误码：machines.notFound、machines.romNotNeeded、machines.romAccessFailed

示例

在 VS Code 的命令“fcdev：调用调试请求”里输入：

machines.removeRom machine=<string>

machines.boot

整机机型开机：读入已设置的 ROM，装配该机型的主机，已有的卡带与主机被替换，任何一步失败都不改动原有的；成功后发 runtime.stateChanged（原因 load），不发 cartridges.loaded。

参数

名称 类型 必填 说明
machine string（长度 1..） 是 机型标识
powerOn boolean 否 开机后是否上电，默认 true
resume boolean 否 上电后是否直接运行，默认 true；powerOn 为 false 时无效

结果

字段 类型 必填 说明
machine machines.MachineInfo 是 开机的机型项
state runtime.RuntimeState 是

错误码：machines.notFound、machines.cartridgeRequired、machines.unsupported、machines.noRom、machines.romInvalid、machines.romAccessFailed

示例

在 VS Code 的命令“fcdev：调用调试请求”里输入：

machines.boot machine=<string>

事件

事件要先用 debug.subscribe 订阅才会收到，以 JSON-RPC 通知送达。

machines.changed

整机机型的 ROM 添加、替换或移除。

字段 类型 必填 说明
machine string 是 机型标识

数据类型

RomFile

已添加的 ROM 文件：文件名与大小。

字段 类型 必填 说明
fileName string 是 文件名，不含路径
size integer（0..） 是 文件大小（字节），等于机型的 ROM 容量
label string 是 界面上显示的 ROM 版本：认得出的 ROM 是版本名或型号名（如 V9.0-98、98型），认不出时是文件名

RomSkipped

从目录添加时没有添加的文件：文件名与原因。

字段 类型 必填 说明
fileName string 是 文件名，不含路径
reason "unrecognized" | "exists" | "duplicate" 是 原因：unrecognized 认不出是哪个机型的 ROM；exists 这个机型已经有 ROM，保持不变；duplicate 目录里有更靠前的文件已是这个机型的 ROM

MachineInfo

一个机型：标识、显示名称、是否需要 ROM、是否已支持与已添加的 ROM。

字段 类型 必填 说明
id string 是 机型标识：fc、sb97、sb2000、bbg1、bbg98、pec9588、pec586、yuxing
name string 是 显示名称
needsRom boolean 是 是否需要 ROM；fc 为 false，其余整机机型（学习机）为 true
supported boolean 是 是否已支持；未支持的机型不能添加 ROM，也不能开机
rom machines.RomFile 否 已添加的 ROM；没有添加、或不需要 ROM 时没有这一项
