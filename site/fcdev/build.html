本文说明 FC Dev 扩展怎样构建程序：任务与命令、构建规则、配置文件 fcdev.json、构建流程。模拟器相关的细节见 02-模拟器与调试，反汇编见 03-反汇编，新建项目见 04-新建项目与模板。

构建用随扩展发布的 cc65 工具链，不使用系统里已装的 cc65，也不需要 Node 项目与 package.json：打开含 fcdev.json 的文件夹，扩展就能工作。扩展只支持 Windows 64 位。

1. 任务、命令与工具

1.1 任务

任务类型是 fcdev，在 .vscode/tasks.json 里这样写： 

{
  "version": "2.0.0",
  "tasks": [
    { "label": "FCDEV：构建", "type": "fcdev", "command": "build", "path": "src", "problemMatcher": "$fcdev", "group": { "kind": "build", "isDefault": true } }
  ]
}
字段 说明
command 必填：build 构建（目标声明了磁盘能力且配置了 diskName 时，同时生成磁盘镜像，见 4.5），run 构建后在模拟器里运行
path 构建路径，规则见第 2 节；相对工作区文件夹，缺省为文件夹本身
target 指定目标，覆盖 fcdev.json 里的 target
debug run 以调试模式启动模拟器
  • 扩展为工作区里每个含 fcdev.json 的项目提供两个任务（构建、运行），在“终端 → 运行任务”里直接选；构建路径取项目的 src 目录，没有 src 时取项目目录。
  • 任务在终端面板里运行，输出就是工具的原始输出；问题匹配器 $fcdev 识别 文件(行): Error: 信息 与 文件:行: Error: 信息，错误出现在“问题”面板，点击跳到源码行。
  • 任务成功输出产物大小，以及本次重新编译与沿用的文件数；失败输出“错误：”加说明与建议，退出码为 1。

1.2 命令

命令 作用
FCDEV：构建项目 构建活动文件所属的项目；有 src 目录就构建它，没有就构建项目目录；工作区里有多个项目又没有活动文件时让你选；配置了 diskName 的有磁盘能力的目标同时生成磁盘镜像
FCDEV：构建当前文件 只构建活动的 .c、.s、.asm 文件，它自己是一个程序
FCDEV：构建当前目录 构建活动文件所在的目录，目录整体是一个程序
FCDEV：显示项目信息 在“FC Dev 项目信息”输出通道里显示项目根目录、配置文件、目标、工具链、输出目录、头文件目录与汇编引入目录
FCDEV：同步 C/C++ 智能感知配置 见第 6 节

构建命令都经上面的任务运行。

1.3 Copilot 工具

扩展给 Copilot 提供的 fcdev_build（构建，配置了 diskName 的有磁盘能力的目标同时生成磁盘镜像）与 fcdev_info（项目信息）与命令等价；fcdev_new_project、fcdev_api、fcdev_docs 见 04-新建项目与模板 与第 5 节。构建会写项目的输出目录，调用前会弹出确认。

2. 构建单位

构建路径 含义
工作区文件夹本身（path 缺省） 以这个文件夹为项目
一个目录，如 src 把目录作为一个项目：递归收集其中全部 .c、.s、.asm，编译后链接成一个程序，程序名取配置里的 name，未配置时取目录名
一个文件，如 src/hello.c 只编译并链接这一个文件，它自己是一个程序，程序名取文件名（不含扩展名）
  • 入口是 main（汇编写 .export _main），不设置入口文件。缺少或重复时 ld65 报错，扩展补一句提示。
  • 收集目录时跳过 build、node_modules、以 . 开头的目录，以及配置里的输出目录；目录里没有源文件时报错。
  • 程序名按目标的 nameRule 校验（例如 DOS 8.3），不符合就报错，不静默截断。
  • 目标取自构建路径向上查找到的最近一个 fcdev.json，任务的 target 可覆盖；两者都没有时报错，不默认猜测。
  • 项目根是 fcdev.json 所在目录；找不到配置时是任务的工作区文件夹。
  • 目录里有多个独立的单文件程序时，不能用一次目录构建批量构建，只能逐个指定文件。

3. 配置文件 fcdev.json

项 类型 默认值 说明
target 字符串 无 目标名
name 字符串 目录名 目录构建时的程序名
out 字符串 build 输出目录，相对项目根
optimize 布尔 true 给 cc65 加 -Oirs
diskName 字符串 无 构建时生成的磁盘镜像文件名，只对声明了磁盘能力的目标有效：写了就生成镜像（文件名不带 .img 或 .dsk 时自动补 .img，不能含路径分隔符），不写就不生成，见 4.5
define 对象 空 预定义宏，值为字符串或数字
include 字符串数组 空 额外头文件目录，相对项目根
firmware 字符串 无 固件（BIOS、ROM）文件路径；目标的运行方案要求固件时必填；rom 目标把它当底固件，构建时把链接输出覆盖进去
diskImage 字符串 无 磁盘镜像文件路径：运行方案是 firmware 的目标（rom）运行时把它放进软驱 0，见 rom/01-开发指南；磁盘能力声明了 baseImage 的目标（bbg、cec1）把它当系统盘，构建磁盘镜像时在其上添加文件，见 4.5
linkConfig 字符串 无 自定义 ld65 链接配置，相对项目根；写了就替换目标自带的链接配置，见 3.1
targetOptions 对象 空 目标专用选项，由各目标定义并校验
  • 配置里出现未知项、类型不对、define 的值不是字符串或数字时，报错并列出可用的项。toolchain 与 emulator 不是配置项：工具链随扩展发布，模拟器的位置在扩展设置里指定（见 02-模拟器与调试）。
  • out、include、firmware、diskImage、linkConfig 里的相对路径都以配置文件所在目录为基准。
  • targetOptions 里出现目标没有定义的选项、类型不对或超出目标规定的范围时报错。

3.1 自定义链接配置

程序需要目标自带布局之外的内存排布时（例如整机映像要链接在 $8000-$FFFF），在 fcdev.json 里写 "linkConfig": "路径"：

  • 构建用这份配置链接，原样使用，不做多页模板的展开；启动代码、库与目标选项带的目标文件仍按目标定义链接，所以配置里要有它们用到的内存区与段（以目标自带的 link.cfg 为底稿修改）。
  • 内存区的起始地址由配置决定，不同内存区的地址可以重叠；输出文件里各内存区按配置里的先后顺序排列。
  • 产物大小由配置决定，不再检查目标的大小上限（如 SB2000 的 16384 字节），文件头等其他检查不变。
  • 文件不存在时报错；与大于 0 的 targetOptions.banks 同时出现时报错。

4. 构建流程

4.1 产物位置

内容 位置
产物 <项目根>/<out>/<目标>/<程序名><扩展名>，程序名按目标的 nameRule 规范化
磁盘镜像 <项目根>/<out>/<目标>/<diskName>，见 4.5
中间文件 <项目根>/<out>/obj/<目标>/<程序名>/

中间文件目录里有每个源文件对应的 .o、依赖文件 .d，C 文件还有编译出的 .s 与汇编依赖文件 .asm.d；目标声明了源文件编码时（如 sb2000），还有每个源文件转码后的副本 .gb2312.c 或 .gb2312.s；链接产物 <程序名>.bin、<程序名>.map、<程序名>.dbg；多页程序还有展开后的链接配置 <程序名>.cfg；以及指纹文件 stamp.json。.o 的文件名取源文件相对目录的路径，去掉扩展名，目录分隔符换成 __。

4.2 单个程序

  1. 对每个 .c：cc65 输出 .s 与依赖文件（--create-dep）。
  2. 对每个 .s（含上一步生成的）：ca65 汇编成 .o，同样输出依赖文件。

目标声明了源文件编码时（sb2000 声明了 GB2312），上面两步编译的是转码后的副本，错误信息仍指向原文件；转换规则见 sb2000 开发指南 第 5 节。

  1. ld65：按目标的链接配置（项目写了 linkConfig 时用项目的，见 3.1），依次链接启动代码、用户的 .o、开启的目标选项所带的目标文件，最后链接目标声明的库；生成 .bin、.map、.dbg。目标声明了多页（换页）程序且库页个数大于 0 时，链接配置按库页个数展开，写在中间文件目录里；多页程序与自定义链接配置的产物，打包器都不再检查映像大小上限。
  2. 打包器把 .bin 做成最终产物。
  3. 目标有磁盘能力且配置了 diskName 时，把产物与 disk 目录里的文件放进磁盘镜像，见 4.5。

工具参数：

工具 参数
cc65 -t <cc65Target> --cpu <cpu> -g，optimize 为真时加 -Oirs，每个头文件目录一个 -I，每个宏一个 -D 名=值，--create-dep，-o
ca65 -t、--cpu、-g，每个汇编引入目录同时给 -I 与 --bin-include-dir，-D，--create-dep，-o
ld65 -C <链接配置> -m <map> --dbgfile <dbg> -o <bin>，再接 -u 强制引入、目标文件、库

头文件目录依次是：目标的 include、配置的 include、源文件的公共根目录；汇编引入目录同理，用目标的 asminclude。预定义宏是目标的 defines 加配置的 define，后者覆盖前者。

工具的输出（文件(行): Error: 信息 格式）原样写进任务终端，供问题匹配器识别。调用工具时设置环境变量 CC65_HOME 为工具链根目录。

4.3 增量构建

  • 某个 .o 存在，且比它的源文件与依赖文件里列出的所有文件都新，就不重编。
  • 指纹由扩展版本、工具链版本（cc65 --version 的输出）、整个目标定义、目标选项、optimize、define、include 和源文件列表算出，记在 stamp.json。指纹变了（包括扩展升级后第一次构建），先删掉整个中间文件目录再全部重编。
  • 构建成功后才写 stamp.json。

4.4 工具链

工具链在扩展目录的 toolchain 里（cc65、ca65、ld65、ar65、da65 与 none、nes 两个运行库），随扩展一起升级；缺少 cc65、ca65、ld65 任一个时报错，提示重新安装扩展。不使用 PATH 里的 cc65，也不接受其他位置的工具链，避免与目标运行库的版本不一致。

4.5 磁盘镜像

目标声明了磁盘能力（target.json 的 disk，目前是 sb2000、sb97、yuxing、bbg 与 cec1）且 fcdev.json 配置了 diskName 时，每次构建成功后都会生成 1.44MB 的 FAT12 磁盘镜像（cec1 是 Apple DOS 3.3 的 140KB 镜像，见下）：

  • 镜像放在产物旁边，文件名取 diskName（如 "diskName": "sb97-run-game.img"），卷标为 FCDEV。diskName 与程序名无关，程序名仍按目标的 nameRule 校验。
  • 镜像里先是这一次构建的程序，再是项目根目录下 disk 目录里的全部文件（按文件名排序，内容原样放入）。用户的使用说明、数据文件都放在这里；用 WinImage 等软件打开镜像就能看到。新建项目的模板自带一份 disk/README.TXT（UTF-8 带 BOM、CRLF 换行，记事本与 WinImage 都能正确显示中文）。
  • disk 目录里的文件名必须符合 8.3 规则，不能有子目录（镜像只支持根目录），不能与程序重名（不分大小写），总大小不能超过软盘容量，否则构建报错。没有这个目录时镜像里只有程序。
  • 没有写 diskName 时构建只生成产物，不生成镜像。运行（run）需要镜像时仍会生成，放在中间文件目录的 run.img，不进产物目录。
  • 步步高（bbg）的 DOS 在软盘上，镜像不是空白的 1.44MB 盘，而是复制 fcdev.json 的 diskImage（带 DOS 的系统盘镜像）后在根目录加入程序与 disk 目录里的文件：系统盘的引导扇区、卷标与原有文件不变，同名文件被替换，空间或根目录项不够报错；没有设置 diskImage 时构建只生成产物，运行时才报错。细节见 bbg/01-开发指南。
  • 中华学习机（cec1）的 DOS 3.3 也在软盘上，镜像复制 fcdev.json 的 diskImage（DOS 3.3 系统盘，.dsk，DOS 扇区顺序）后加入程序（二进制文件）与 disk 目录里的文件（文本文件）；同名的锁定文件不替换，报错。细节见 cec1/01-开发指南。
  • 不支持磁盘镜像的目标（nes）不生成镜像，disk 目录也不会被读取。

5. 查询

  • 命令“FCDEV：查询 C 接口”与工具 fcdev_api 读目标 include 目录下头文件里带 /** */ 文档注释的函数（注释写法见 sb2000/01-开发指南 第 6 节），不需要工具链。目标取自活动文件所属项目的 fcdev.json；目标没有带文档注释的函数时报“没有 C 接口文档”，目前只有 sb2000 有。

    查询词 结果
    留空 列出全部模块、各模块的函数个数与头文件
    函数名，如 sb_file_open 完整文档：签名、所在头文件、系统调用、说明、每个参数、返回值
    模块名或头文件名，如 file 该模块的函数与一行说明
    功能号，如 $7B 或 $7B/$09（不分大小写，$ 可以省略） 用到该系统调用的函数
    其他词 名称或说明里包含该词的函数

    查询依次按函数名、模块名、功能号、关键词匹配，先匹配上的为准。

  • 命令“FCDEV：打开使用文档”与工具 fcdev_docs 查询随扩展发布的使用文档（扩展的 docs/ 目录，主题登记在 docs/topics.json），只读、不联网、不需要 fcdev.json。命令列出全部主题，选一份用 Markdown 预览打开；工具不带查询词时列出全部主题，查询词依次按主题名、文件名、关键词匹配，只匹配到一份时返回全文，多份时列出摘要。

6. C/C++ 智能感知配置

扩展自动生成 IDE 的 C/C++ 配置，让智能提示找到 cc65 与目标的头文件：

  • .vscode/c_cpp_properties.json：只写或更新名为 fcdev 的配置，保留其他配置；该配置含 includePath、defines（__CC65__、__<目标>__、目标和配置里的宏，以及给编辑器用的空宏 __fastcall__、__cdecl__，它们不参与构建）、cStandard 为 c89。已有文件不是合法的配置时报错，不改写它。
  • 项目根的 compile_flags.txt：第一行是标记 -DFCDEV_GENERATED，之后是 -I 与 -D 行。已有同名文件但第一行不是该标记时，视为用户自己的文件，不覆盖。

头文件目录在扩展目录里，路径随扩展版本变化：打开项目、fcdev.json 变化、工作区文件夹增减时自动同步，每次都按当前路径改写，内容没变时不写盘；命令“FCDEV：同步 C/C++ 智能感知配置”手动同步。设置 fcdev.intelliSense.autoSync（默认开启）可关闭自动同步。
