模拟器与调试

扩展的“运行”“调试运行”命令与任务、Copilot 工具 fcdev_run、emu_launch 使用模拟器 Ember。Ember 不随扩展发布，要在设置里指明它的位置（见第 1 节）；调试服务由 Ember 提供，扩展内置调试客户端与它通信。Ember 的调试协议与全部请求见 Ember 帮助文档里的“调试接口手册”。

Ember 运行 NES 程序，也运行学习机整机（SB2000、SB97、裕兴、步步高、中华学习机 CEC-I）；整机的启动方式见第 2 节与第 6 节。

1. Ember 的位置

  • 用户设置 fcdev.emulator.path 填 Ember 可执行文件（Ember.exe）的路径。没有设置、或指向的文件不存在时，运行与调试相关的功能会报错并提示来这里设置；扩展不去 PATH 里猜，也不自带 Ember。
  • 这个设置只能在用户设置里指定，工作区设置不能指定要运行的程序，避免打开别人的工作区时被指向恶意的可执行文件。
  • 设置 fcdev.emulator.debugPort 是调试服务的端口，默认 5699；调试运行与 emu_launch 用它启动 Ember，调试命令与 emu_connect 也按它找到这个 Ember。不是 1 到 65535 的整数时按默认端口处理。
  • 两项设置每次使用时读取，改了立即生效。

2. 运行

命令“FCDEV：运行”、任务 run、Copilot 工具 fcdev_run 先确认目标能运行、能找到 Ember，再构建并启动 Ember。目标没有运行方案时报错。

运行方案 做法
rom Ember 直接加载产物（.nes），不需要固件
firmware-disk 整机方案（SB2000、SB97、裕兴、步步高、CEC-I）：加载 fcdev.json 里 firmware 指定的 BIOS（ROM），把程序放进磁盘镜像挂到软驱 0，按目标声明的机型（run.machine）开机；没有设置 firmware 时在构建之前报“需要固件”，见下面与第 6 节
firmware 整机 ROM 工程（rom 目标）：把构建出的整块固件当作 targetOptions.machine 机型的 BIOS，fcdev.json 里有 diskImage 就挂到软驱 0，开机后直接运行，不输入程序名；没有 machine 时在构建之前报“需要指定整机机型”，见 rom/01-开发指南 第 5 节
  • 整机（firmware-disk）没有命令行入口，不论是否调试运行都经调试服务启动（独立的用户数据目录与调试端口，同下一条）：依次 machines.setRom（Ember 把 ROM 复制进自己的 ROM 目录）、machines.boot（上电、不运行）、media.floppyInsert（放入构建生成的磁盘镜像，里面有程序与项目 disk 目录下的文件；没有配置 diskName 时构建不生成镜像，运行前另外生成到中间文件目录）。普通运行时，再让机器进入 DOS 并输入程序名、回车，随后 runtime.resume，扩展断开调试连接，Ember 留在运行状态；调试运行时停在开机状态，程序还没有被运行，要在 DOS 里输入程序名才运行。程序名只能用字母与数字，不合适时用 fcdev.json 的 name 改名。
  • 进入 DOS 的操作按机型不同：学习机 SB2000 开机运行 900 帧，SB-DOS 询问日期与时间，回车跳过两次；SB97 开机运行 200 帧后按空格跳过开机画面，等 300 帧菜单稳定后按左键选中“DOS”，回车进入，再等 120 帧出现提示符；裕兴开机运行 300 帧后按空格进主菜单，等 120 帧后按下键 3 次选中“学DOS”，回车，等 300 帧让“DOS入门”动画播完，按空格，等 120 帧后按下键 2 次选中“三.DOS系统操作”，回车进入，再等 120 帧出现提示符，输入程序名时补上扩展名 .EXE（裕兴的 DOS 必须写扩展名）；步步高（机型 bbg1）开机运行 1200 帧（让系统盘的 AUTOEXEC.BAT 跑完），按两次回车跳过可能出现的日期与时间（已在提示符下时只是两个空行），再等 60 帧输入程序名，不补扩展名；中华学习机 CEC-I（机型 cec1）开机运行 900 帧（DOS 3.3 从系统盘启动到命令行约 670 帧，没有日期与时间的提示），输入 BRUN 、程序名并回车。没有这样的流程的机型（如金字塔、步步高 98）给了要运行的程序时报 DOS_MACHINE_UNSUPPORTED，只开机。按键都是按下 8 帧、松开 8 帧。
  • 普通运行（NES）：用 --cartridge=<产物> 启动 Ember，窗口打开并开始运行，任务立即结束。用的是 Ember 平时的用户数据目录（首选项、键位映射等设置照常生效），遵守 Ember 的单实例规则，见第 5 节。
  • Ember 进程与扩展脱离，VS Code 关闭后窗口保持打开；工作目录是 Ember 所在目录。
  • 运行成功后输出“已启动 Ember（进程号），加载 ……”。Ember 没有“退出”请求，用完后关闭它的窗口，或按输出的进程号结束进程。

3. 调试运行

命令“FCDEV：调试运行”、任务 run 加 "debug": true、fcdev_run 的 debug 参数：

  • 用独立的用户数据目录（系统临时目录下的 fcdev-ember/<端口>）、--debug-port=<端口> 与随机生成的令牌启动 Ember，不带 --cartridge；连上调试服务后用 cartridges.load 载入产物，上电但不运行（powerOn 为真、resume 为假）；之后用第 4 节的调试命令继续。独立的用户数据目录让调试用的 Ember 能和平时在用的 Ember 同时运行，互不影响设置；调试实例（带 --debug-port 启动）不会自行升级重启，调试中途不会被打断。
  • 启动前先检查端口是否被占用，被占用就报错，不去连接，避免连到别的 Ember；启动后最多等 30 秒，等到调试服务可连接并成功载入程序，超时则结束 Ember 进程并报错；Ember 在就绪前退出时立即报错。
  • 每次启动前清掉上一次留下的端点文件，保证客户端读到的是这一次的地址与令牌。

4. 调试命令

命令 作用
FCDEV：调用调试请求 选一个请求，输入参数后调用；结果写到“输出”面板的“FC Dev 调试”
FCDEV：查看调试请求说明 选一个请求或事件，显示参数、结果、错误码与示例
FCDEV：保存调试截图 把当前画面保存为 PNG
FCDEV：监视调试事件 订阅事件并逐行写到输出，取消或连接关闭时停止
FCDEV：显示调试服务地址 显示正在运行的 Ember 的调试服务地址（令牌打码）
  • 找到 Ember：先按设置 fcdev.emulator.debugPort 找调试运行启动的 Ember（读那个端口对应的用户数据目录里的端点文件，取得地址与令牌），没有端点文件再找 Ember 自己的用户数据目录，可以连到平时在用的 Ember（它要开启了调试服务）。也可以设置环境变量 EMBER_DEBUG_URL、EMBER_DEBUG_TOKEN、EMBER_DEBUG_ENDPOINT、EMBER_USER_DATA 指定位置。
  • “调用调试请求”的参数写成 key=value（值按 JSON 解析，不是 JSON 就当字符串；0x8000 与 $8000 是十六进制数），或一个 JSON 对象。结果里有二进制数据（如读内存）时询问是否保存成文件。
  • file 参数（如 inspector.traceStart 的文件名）由 Ember 写进它的调试输出目录，调试运行时是用户数据目录里的 debug-output，结果里的 file 给出完整路径。
  • 请求默认最多等 60 秒。
  • Copilot 的 emu_* 工具用同一个调试客户端，见 03-反汇编 与扩展的 README。

4.1 常用操作

下表的“请求”都用命令“FCDEV：调用调试请求”调用，括号里是参数。

要做的事 请求
看运行状态与卡带 runtime.status
运行 N 帧并等运行结束 runtime.run（frames=N wait=true）
单步 runtime.step（unit=instruction count=N；unit 还有 cycle、scanline、frame）
继续运行、暂停 runtime.resume、runtime.pause
复位 runtime.reset（kind=soft，或 hard）
看寄存器与芯片状态 inspector.getState、inspector.snapshot
读内存 inspector.readMemory（space=cpu address=0x8000 length=16；数据是二进制，结果里会询问是否保存；inspector.listSpaces 列出全部空间）
断点 inspector.addBreakpoint（kind=execute address=0x8000；还有 read、write、irq、nmi、brk、reset，后四种不给 address；可加 condition）、inspector.updateBreakpoint（启用、禁用、改条件）
看调用栈、调色板 inspector.callStack、inspector.getPalette
统计子程序占用的周期 inspector.profilerStart，运行后 inspector.profilerGet 或 inspector.profilerStop
记录 PPU 与 mapper 寄存器的读写、中断的扫描位置 inspector.eventsStart，运行后 inspector.eventsGet，inspector.eventsStop
截图 命令“FCDEV：保存调试截图”
记录指令轨迹 inspector.traceStart（kind=instruction file=trace.txt；加 ring=true 为环形，可用 inspector.traceRead 边记边读），运行后 inspector.traceStop（id=<编号>）；文件用 disasm_import_record 导入反汇编工程
记录代码与数据标记 inspector.cdlStart，运行后 inspector.cdlSave（file=prg.cdl）
注入按键 input.key（code=KeyW down=true；code 是 KeyboardEvent.code，由卡带的 mapper 脚本翻译）、input.pad（port=0 buttons=1）
订阅事件 命令“FCDEV：监视调试事件”（如 runtime.*）

全部请求、参数与错误码用命令“FCDEV：查看调试请求说明”查看。

5. 限制

  • 学习机的运行方式是自动在 SB-DOS 里输入程序名，靠固定的帧数等待 DOS 启动（开机运行 900 帧后直接按两次回车，调试服务里不限速、几秒完成）；换了别的 BIOS 或磁盘时提示的出现时间不同，就会输错位置，这时用调试运行启动，自己用调试命令操作。
  • 普通运行（NES）遵守 Ember 的单实例规则：平时用的 Ember 已经在运行时，新启动的进程只会把已有窗口提到前面，不会载入新程序（Ember 首选项里开启“允许同时运行多个实例”后不受此限，会打开新窗口）；这时先关闭 Ember，或改用调试运行（独立的用户数据目录，不受影响）。学习机目标不受影响，它总是用独立的用户数据目录。
  • 不发布任何 BIOS 或 ROM，由用户经 firmware 提供（学习机目标必填）。

6. 学习机在 Ember 里的调试

学习机调试运行后，机器已开机、磁盘在软驱 0 里、没有运行，操作与 NES 相同，另有：

要做的事 请求
在 SB-DOS 里敲键 input.key（code=KeyA down=true），运行几帧后 down=false；回车是 Enter，不要连续几帧不运行就松开，BIOS 来不及读到
手柄、鼠标 input.pad（port=0 buttons=1）、input.mouse（kind=move dx=10 dy=5、kind=down buttons=1）
把软驱里被程序改写的盘片存回镜像文件 media.floppySave（drive=0）
取出、重新放入盘片 media.floppyEject（drive=0）、media.floppyInsert（drive=0 path=<镜像>）
