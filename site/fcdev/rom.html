整机 ROM 工程开发指南

本页目录

用 fcdev 构建整机的 ROM 工程：机型的 BIOS、固件的汇编源码，产物是整块固件映像，在 Ember 里作为该机型的固件开机运行。目标名是 rom，一个目标适用于所有机型，机型、固件布局和软盘镜像都写在项目自己的 fcdev.json 里。只支持 ca65 汇编，没有 C 运行库、启动代码和库：BIOS 自己就是启动代码。本文只写已经在模拟器里验证过的用法，没验证的在第 7 节列出。

1. 目标定义

项 值
目标名 rom
cc65Target none，只用 ca65 与 ld65，不链接启动代码与库
链接配置 缺省的 link.cfg：$8000-$FFFF 共 32K，空隙填 $FF，向量在 $FFFA；实际项目都用 fcdev.json 的 linkConfig 指向自己的链接配置
汇编引入 无；用 fcdev.json 的 include 加目录
预定义宏 __ROM__
打包器 rom-overlay：见第 3 节
产物 <out>/rom/<程序名>.bin
程序名规则 不限制
磁盘镜像 不生成；运行时用 diskImage 挂一张现成的镜像
运行方案 firmware：产物当作固件，开机运行，见第 5 节

2. 项目配置

fcdev.json 里和整机 ROM 工程有关的项（其余项见 01-构建 第 3 节）：

项 说明
target 写 rom
name 目录构建时的程序名，也是产物 .bin 的主名；不写时取目录名
linkConfig 项目自己的链接配置：把各段放在机型 BIOS 的地址上，空隙用 fill = yes 填满，产物是 BIOS 部分的字节
include 汇编里 .include 用到的目录
firmware 底固件：完整的固件文件，BIOS 以外的部分取自它，见第 3 节；没有时产物就是整块固件
diskImage 运行时放进软驱 0 的磁盘镜像；不写时软驱是空的
targetOptions.machine 机型，运行时必填：sb2000、sb97、bbg1、bbg98、pec9588、pec586、yuxing
targetOptions.offset 链接输出在整块固件里的偏移，字节，默认 0
targetOptions.size 整块固件必须正好等于的大小，字节；0 表示不检查，默认 0

路径项（linkConfig、include、firmware、diskImage）的相对路径都以 fcdev.json 所在目录为基准。

3. 底固件与覆盖

整机的固件常常比 BIOS 源码覆盖的范围大：例如 BBG 的 bbg1 固件是 128K，源码只对应最后 16K（$C000-$FFFF），前 112K 是字库点阵。固件文件不入库，所以用 firmware 指向本机的完整固件当底，构建时把链接结果覆盖进去：

  1. ld65 按 linkConfig 生成 BIOS 部分的字节（长度由链接配置决定）。
  2. 读 firmware（底固件），复制一份，把 BIOS 部分放到偏移 offset 处，得到整块固件，写成产物；底固件文件本身不变。

检查：

  • size 不为 0 时，底固件必须正好是 size 字节，否则报 PACKAGE_SIZE_MISMATCH。
  • BIOS 部分放到 offset 处超出底固件时，报 PACKAGE_TOO_LARGE。
  • offset 不为 0 而没有写 firmware 时，报 PACKAGE_BASE_MISSING，提示写 firmware。
  • firmware 指向的文件不存在时，报 FIRMWARE_MISSING。
  • 源码覆盖整块固件时（例如整机的反汇编工程），不写 firmware，offset 保持 0，用 size 要求大小正好相等。

4. 构建

和其他目标一样：任务“fcdev：构建”、命令“构建项目”、工具 fcdev_build。构建路径取项目的 src 目录，目录里递归收集的全部 .s、.asm 汇编后一起链接；汇编的符号文件（.inc）不会被收集，用 include 指定它所在的目录，源码里再 .include。

示例（步步高 bbg1，machines/bbg/fcdev.json）：

{
  "target": "rom",
  "name": "bbg",
  "linkConfig": "link.cfg",
  "include": ["src/include"],
  "firmware": "../../ember/roms/bbg1_bios.bin",
  "diskImage": "../../reference/floppy-images/bbg/系统类/DOS.IMG",
  "targetOptions": { "machine": "bbg1", "offset": 114688, "size": 131072 }
}

114688 是 128K 减 16K，也就是 BIOS 在固件里的偏移。产物是 build/rom/bbg.bin，共 131072 字节。

5. 运行

任务“fcdev：运行”、命令“运行”、工具 fcdev_run：

  1. 构建，得到整块固件。
  2. 启动 Ember 并经调试服务依次：machines.setRom（把产物设为 machine 机型的固件）、machines.boot（上电）、diskImage 有值时 media.floppyInsert（放进软驱 0）。
  3. 不给 debug 时，随后 runtime.resume，机器直接运行，不输入程序名，扩展断开连接，Ember 留在运行状态；给 debug 时停在开机状态，之后用调试命令继续，见 02-模拟器与调试。

没有写 targetOptions.machine 时，在构建之前报 MACHINE_MISSING。Ember 把固件复制进自己的 ROM 目录。

6. 注意

  • 固件与软盘镜像是用户自己的文件，不随扩展发布，也不要提交进仓库。
  • 链接配置的内存区要都带 fill = yes，产物才会按地址排满；缺少时各段首尾相接，向量和段都会错位。
  • 分 bank 的映像（多个 bank 都映射在同一个 CPU 地址）：每个 bank 一个内存区，起始地址相同也可以，全部写 file = %O，链接器按内存区的先后顺序把它们首尾拼成一个产物。反汇编工程生成的 link.cfg 在段首尾相接时就是这样写的，可以直接用（见 03-反汇编）。
  • 新建项目命令没有这个目标的模板：整机 ROM 工程都有现成的源码，手写 fcdev.json 即可。

7. 还没有验证的内容

  • 除 bbg1 外的机型：machine 的取值取自 Ember 支持的机型，只有 BBG 的 BIOS 工程做过构建，构建结果在 Ember 里以 bbg1 开机、从软盘 DOS.IMG 启动到 DOS 提示符已验证。
  • C 语言：没有运行库，也没有启动代码，不支持。
  • 真机运行：只在 Ember 里验证过。
