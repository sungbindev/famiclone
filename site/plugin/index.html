这本手册教你给 Ember 写 mapper 插件：让模拟器能运行一种它还不认识的 FC 卡带，或者按你的想法改写某种卡带的行为。

mapper 插件是什么

红白机卡带上除了存放程序和图案的 ROM，还有一颗 mapper 芯片，负责把 CPU 与 PPU 的地址对应到 ROM 的哪一段、响应寄存器的写入、产生中断。不同卡带的 mapper 芯片各不相同。Ember 本身不内置任何 mapper，每一种都由一个插件描述；安装包里预装了覆盖常见卡带的一批官方插件。

打开 .nes 文件时，Ember 读文件头里的 mapper 号和变体，找到匹配的插件，再按插件的描述造出这张卡带。找不到匹配的插件时卡带不能打开，提示里会写出缺少的 mapper 号和变体，这就是需要你写插件的时候。

一个插件由两部分组成：

部分 内容
清单 manifest.json 描述卡带的硬件：有哪些存储区、地址怎么分段、有哪些寄存器、匹配哪些文件。能写成声明的都写在这里，由 Ember 直接执行
脚本 main.js 可选。清单写不出的逻辑用 JavaScript 补充，如要计算的寄存器、定时中断

很多简单的 mapper 只要清单就够了，不需要脚本。

能做什么，不能做什么

插件可以：

  • 声明卡带上的 ROM 与 RAM（含带电池的 RAM），文件里没有 CHR 时改用 CHR RAM。
  • 把 CPU 与 PPU 的地址范围划成窗口，窗口指向存储区的某一块，寄存器写入时切换。
  • 处理寄存器的读和写，控制名称表的连法，产生中断（按 CPU 周期定时，或按 PPU 地址线 A12 计数）。
  • 接上磁带机，处理键盘与鼠标事件。

插件不能：

  • 访问文件、网络、进程与系统时间；脚本只能通过 Ember 给的 ctx 对象和硬件打交道。
  • 修改主机本身：主机型号、主板上的存储、芯片内部都不由插件决定。
  • 描述学习机整机。学习机的 ROM 不是卡带，不走插件，见机型与 ROM。

开发流程

  1. 打开游戏，从提示里记下 mapper 号和变体。
  2. 写清单，描述存储区、窗口和寄存器。
  3. 清单不够用的地方再写脚本。
  4. 把文件打成 .emap 包，在“设置→mapper 插件”里安装。
  5. 重新打开卡带试运行；有问题时用调试服务观察状态。

目前的限制

  • 没有开发工具包：脚本是单个 JavaScript 文件，没有类型声明和现成的测试工具，包要自己用压缩软件打。
  • 不能直接加载未打包的插件目录，改了要重新打包并安装。
  • 清单里的设置项（settings）还没有设置页，脚本读到的永远是清单里的默认值。
  • 带电池的 RAM 只在这次运行里保持，不会保存成存档文件。
  • 卡带还没有声音输出，带扩展声音的 mapper 做不了。
  • 脚本能访问的主机设备只有磁带机。
  • 脚本的 ctx.log.warn 目前不会显示在任何地方，排错时看卡带状态，见测试与排错。
