插件包与安装

包里放什么

插件包是扩展名为 .emap 的 zip 文件，根目录只能有下面三个文件，文件名要完全一致（区分大小写）：

文件 内容 是否必需
manifest.json 清单，见清单：基本字段与匹配 必需
main.js 脚本，单个 ES 模块，默认导出一个对象，不能再引用别的文件 清单里有要脚本处理的内容时必需
icon.png 图标，PNG，正方形，边长不小于 64 像素 可选

限制：

  • 包里不能有其他文件、文件夹和符号链接，所以压缩时要选中里面的文件，不要把外面那层文件夹一起压进去。
  • main.js 不超过 1 MB，manifest.json 不超过 256 KB，整个包不超过 2 MB。
  • 不能加密，只支持 zip 的存储与 Deflate 两种压缩方式（常见压缩软件的默认设置都满足）。
  • 文件名里不能有路径、盘符、反斜杠和 ..。

不需要脚本的 mapper 可以没有 main.js；清单里声明了查表（tables）时，脚本必须导出对应的函数，见寄存器与状态。

打包

任何能生成标准 zip 的工具都行，打完把扩展名改成 .emap：

工具 做法
Windows 资源管理器 选中插件文件夹里的文件，右键“发送到→压缩(zipped)文件夹”，改名
PowerShell Compress-Archive -Path .\插件目录\* -DestinationPath 标识.zip，再 Rename-Item 标识.zip 标识.emap
7-Zip 等 选中文件，添加到压缩包，格式选 zip，不要设密码

包文件名建议与清单里的 id 相同，如 demo-bank.emap。

安装、替换与卸载

在“设置→mapper 插件”里操作，界面见mapper 插件：

  • 安装：点“安装插件”选择 .emap 文件。安装时会检查包的结构与大小、清单是否合规、接口版本、host 里是否有 Ember 认识的主机型号，有 main.js 时还会真的加载一次脚本；任何一项不通过都会拒绝，通知里写出原因。
  • 替换：再次安装同标识（id）的插件，直接替换已安装的那一个，不比较版本。改了插件重新打包安装即可，然后重新打开卡带。
  • 停用与启用：停用的插件不参与匹配。
  • 卸载：只能卸载自己安装的插件，预装的插件只能停用。

用户安装的插件放在 Ember 的用户数据目录下的 plugins 文件夹里，文件名是 <id>.emap。点“帮助→打开日志目录”打开的文件夹，它的上一级就是用户数据目录。

多个同标识的插件

预装目录和用户目录里有同一个 id 的插件时，版本高的生效（10.0.0 高于 9.0.0，按三段数字比较）；版本相同时用户安装的优先。

与其他插件的匹配冲突

两个不同 id 的插件都匹配同一个文件时，写出的匹配条件多的优先；条件一样多就会提示冲突，把不需要的那个停用即可。想用自己的插件取代官方的某个插件，最直接的做法是在“mapper 插件”里停用官方的那个，详见清单：基本字段与匹配。

安装失败时

错误码 常见原因
mappers.invalidPackage 包结构不对（多了文件或文件夹、缺 manifest.json、文件名大小写不对）、清单有不认识的字段或不合规的值、脚本顶层代码报错、清单声明的内容与脚本对不上
mappers.hostUnknown host 里没有 Ember 认识的主机型号，目前只有 fc
mappers.limitExceeded 脚本加载时超过内存、栈或时间限制

通知里的说明会指出具体是哪个字段或哪个文件。
