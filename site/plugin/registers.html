清单：寄存器与状态

这一页讲怎么在清单里声明寄存器、状态、查表、磁带接线、mapper 电路和设置项。原则是：能声明的都声明，由 Ember 直接执行，不进脚本；每帧要访问很多次的寄存器尤其应当声明，脚本每回调一次都有开销。

寄存器

registers 声明卡带上的寄存器地址范围，最多 64 项。

字段 说明
bus cpu 或 ppu
range 地址范围，如 $4100-$4107
read、write 这个范围怎么处理读、写：true 表示回调脚本；对象表示由 Ember 直接执行（声明式，见下）；不写或 false 表示不处理，读写落到窗口或开放总线

规则：

  • 只有落在声明范围内的访问才由寄存器处理，其余访问由窗口直接处理。
  • 同一条总线上的寄存器范围不能重叠；每项的 read、write 至少要有一个有处理。
  • 寄存器的地址范围受窗口同样的限制：CPU 侧在 $4020-$FFFF，PPU 侧在 $0000-$1FFF。
  • 寄存器范围可以与窗口的地址范围重叠：寄存器按读、写分别优先于窗口。声明了 read 的地址，读由寄存器回答；声明了 write 的地址，写只交给寄存器，窗口不再处理；没声明的方向仍落到窗口。例如只读的程序窗口上声明了 write，读取照常由窗口回答，写入交给寄存器。
  • 声明里引用的状态、窗口、表都必须存在。
  • 不要用回调脚本的读寄存器盖住整个 $8000-$FFFF：每次取指令都会进脚本，会把模拟拖慢到没法用。需要“读程序 ROM 的同时改变读出的值”的 mapper（比如读地址被开关改写的多合一卡）目前不支持。

读的声明

read 是对象时，value、open、state 必须且只能写一个：

字段 说明
value 驱动固定值，0 到 255
open 写 true：不驱动数据线，读到总线上最近的值
state 驱动这个状态的低 8 位
releaseIrq 可选。true 时每次读完撤销卡带的中断

示例：读 $A000-$BFFF 得到状态 pal，读 $5000-$5FFF 得到固定值 0 并撤销中断：

{ "bus": "cpu", "range": "$A000-$BFFF", "read": { "state": "pal" } }
{ "bus": "cpu", "range": "$5000-$5FFF", "read": { "value": 0, "releaseIrq": true } }

写的声明

write 是对象时，state、bank、update 至少写一个，或者只写 circuit；同一次写入按 state、bank、update 的顺序做：

字段 说明
state 把写入的数据（8 位）存进这个状态，按位宽截断
bank 数组（1 到 8 项），每项 { "window", "shift", "mask" }：把窗口切到 bank (数据 >> shift) & mask；shift 为 0 到 7，默认 0；mask 为 1 到 255，默认 255；bank 号再按窗口的规则取模
update { "table": 表标识, "into": 状态名 }：按表的索引查表，结果存进这个状态，见下面的“查表”
circuit 电路标识：把写入的地址与数据交给这个电路，再按电路的接线设置窗口，见下面的“电路”；与 state、bank、update 互斥

示例：写入值的低 3 位选程序窗口，高 4 位选图案窗口：

{
  "bus": "cpu",
  "range": "$8000-$FFFF",
  "write": {
    "state": "latch",
    "bank": [
      { "window": "prg-low", "shift": 0, "mask": 7 },
      { "window": "chr-0000", "shift": 4, "mask": 15 }
    ]
  }
}

调试读取

调试服务读内存时不会触发寄存器的回调：声明的固定值与状态可以直接读到，回调脚本的寄存器与 open 读不到值。

状态

state 声明卡带的内部寄存器，最多 64 项。

字段 说明
name 状态名，字母开头的 camelCase，不超过 32 个字符
bits 位宽，1 到 32
description 说明，1 到 200 个字符
initial 可选的复位值，不超过位宽
  • 脚本通过 ctx.state.名称 读写已声明的状态，不能增加属性，写未声明的状态会抛出 TypeError；写入时按位宽截断。
  • 上电复位时全部状态清零。写了 initial 的状态在每次复位（上电与软复位）都回到这个值；没写的只在上电时清零，软复位保持。
  • 声明式寄存器、查表与磁带计时都通过状态存取，所以不用脚本也能在调试服务里看到卡带的内部寄存器，见测试与排错。
  • 脚本自己用 let 存的变量，调试服务看不到，也不会随复位自动清零。需要观察或需要跟着复位走的数据，请声明成状态。

查表

tables 声明查表，最多 16 张。寄存器写入时按一组输入拼成索引，查出一个值存进状态。表项的内容由脚本算出，Ember 只在第一次遇到某个索引时调用一次脚本并缓存，之后同样的索引直接取缓存，所以逻辑方程可以写成好读的脚本，运行时仍是原生速度。

字段 说明
id 表标识，同一插件内不重复；脚本里的计算函数是 tables.<id>
index 索引的来源，数组（1 到 8 项），按顺序拼成索引，第一项在高位
bits 表项的位宽，1 到 32，脚本返回的值按它截断

索引的来源，每项 { "from": ... }：

from 其他字段 位数 取值
state name：状态名 状态的位宽 状态现在的值
address shift（0 到 15）、bits（1 到 16），shift + bits 不超过 16 bits 这次访问的地址的 [shift, shift + bits) 位
data shift（0 到 7）、bits（1 到 8），shift + bits 不超过 8 bits 这次写入的数据的 [shift, shift + bits) 位
tape 无 1 磁带数据线现在的电平，主机没有磁带机时为 0
  • 索引的总位数不超过 16，表最多 65536 项。
  • 脚本里的计算函数写成 export default { tables: { 表标识(ctx, ...各来源的值) { return 整数; } } }，参数按 index 的顺序给出各来源取出的值；返回 0 到 4294967295 的整数，不是整数或越界按脚本错误处理。
  • 计算函数必须是纯函数：同样的参数得到同样的结果，不读取会变的东西，不改变卡带状态，因为结果被缓存。
  • 声明了表而脚本没有导出对应的函数时，安装会被拒绝。

示例见官方插件 plq：

"registers": [
  { "bus": "cpu", "range": "$8000-$9FFF", "read": { "value": 0 }, "write": { "update": { "table": "pal", "into": "pal" } } }
],
"tables": [
  {
    "id": "pal",
    "index": [{ "from": "state", "name": "pal" }, { "from": "address", "shift": 1, "bits": 2 }, { "from": "data", "shift": 0, "bits": 4 }, { "from": "tape" }],
    "bits": 8
  }
]

export default {
  tables: {
    pal(ctx, reg, sel, data, tape) {
      return computeNext(reg, sel, data, tape);
    }
  }
};

磁带

tape 声明卡带与磁带机的接线，由 Ember 直接执行；主机没有磁带机时什么也不做。

字段 说明
comparator 数据线的比较器 { "low", "high", "invert" }：采样不低于 high 为 1、不高于 low 为 0，之间保持原值；invert 为 true 时输出取反；low、high 是 -32768 到 32767 的整数，且 low 小于 high；每次复位设置一次
timer 边沿计时 { "samples", "ticks", "scale", "irq" }：数据线每次翻转，把距上一次翻转的采样数累加进状态 samples；下降沿（翻转后为 0）时，把 samples 乘 scale[0] 除以 scale[1]（整数除法）加进状态 ticks，再把 samples 清零，irq 为 true 时拉低卡带的中断
  • comparator、timer 至少写一个；samples、ticks 是已声明的两个不同的状态（ticks 的位宽决定计时的回绕）；scale 是两个 1 到 65535 的整数；timer 的 irq 为 true 时，每次复位也撤销中断。
  • 采样率是 96 kHz，samples 的单位是 1/96000 秒。
  • 清单写不出的磁带逻辑，脚本可以用 ctx.device('tape') 与 onTapeEdge，见脚本接口。

电路

circuits 声明卡带上用到的 mapper 电路，最多 4 个。电路是 Ember 里已有的芯片逻辑，原生执行，适合每帧要处理成百上千次的逻辑（寄存器译码、按 PPU 地址线 A12 计数、图案页锁存）。插件只能按类型名选择，不能自己造电路。

字段 说明
id 电路标识，同一插件内不重复
type 电路类型：mmc3（MMC3：8 个页寄存器、镜像位、PRG RAM 保护位、按 A12 上升沿计数的扫描线中断）、mmc2（MMC2：8K 程序页，左右两个 4K 图案区各有两个页号，按取到 $FD、$FE 图块的地址切换）、mmc4（MMC4：16K 程序页，左半区锁存器认 8 个地址一组）
revA 可选。true 时 mmc3 的中断按 A 版行为（计数器从 0 重载到 0 不发中断），其他类型忽略
wire 可选，电路给窗口的接线

wire 的字段，都是可选的：

字段 说明
prg 窗口标识数组，依次对应电路从 $8000 起按页大小排列的程序页
chr 窗口标识数组，依次对应从 $0000 起的图案页
mirroring true 时电路的镜像位控制名称表（名称表是 four 或 custom 时不起作用；电路还没给出镜像时保持文件头的连法）
ram 窗口标识：按电路状态 ramProtect 的位 7（允许）、位 6（写保护）切换这个窗口的映射与写入

检查与规则：

  • wire 里的窗口必须存在；prg、ram 在 CPU 总线上，chr 在 PPU 总线上；数量不超过电路的页数；窗口大小等于电路给出的页大小。
  • 寄存器声明里引用的 circuit 必须存在。
  • 电路的中断线与脚本的 ctx.irq 在同一条卡带中断线上混合，任一来源为低即为低，互不覆盖；上电复位时电路复位。
  • 电路给出的页号按电路的位数计算，窗口按 bank 数取模，所以超出文件大小的页号自动回绕。

完整的 MMC3 卡带，一个声明就够，不需要脚本：

"registers": [
  { "bus": "cpu", "range": "$8000-$FFFF", "write": { "circuit": "mmc3" } }
],
"circuits": [
  { "id": "mmc3", "type": "mmc3", "wire": {
    "prg": ["prg-8000", "prg-a000", "prg-c000", "prg-e000"],
    "chr": ["chr-0000", "chr-0400", "chr-0800", "chr-0c00", "chr-1000", "chr-1400", "chr-1800", "chr-1c00"],
    "mirroring": true,
    "ram": "prg-ram"
  } }
]

页号需要再加工时（外部 bank 寄存器、掩码、偏移），不写 wire，由脚本用 ctx.circuit(id) 把写入交给电路，再取页号自己设置窗口，见脚本接口与常见写法。官方的 mmc3-* 系列插件都是这样做的。

电路的状态名

脚本用 ctx.circuit(id).get(名称) 读电路的内部状态：

类型 状态名
mmc3 selector、r0 到 r7、horizontalMirroring、irqLatch、irqCounter、irqEnabled、ramProtect（上电值 $80：允许、可写）
mmc2、mmc4 prg、left0、left1、right0、right1、leftLatch、rightLatch、horizontalMirroring

设置项

settings 声明用户可调的选项（可选，最多 32 项），脚本经 ctx.settings.get(key) 读取。

字段 说明
key 设置项的键，同一插件内不重复
label 显示名称
kind text、choice 或 switch
default 默认值：text、choice 是字符串，switch 是布尔值
description 说明，不超过 200 个字符
options choice 必写：数组，每项 { "value", "label" }，最多 32 项，default 必须是其中一个取值

目前还没有设置页，用户改不了，ctx.settings.get 总是返回清单里的默认值（卡带上的拨码开关因此固定在默认位置）。设置页做好之后，脚本不用改。
