# 6502 工具使用规则

## 先选流程

读完对应 skill 之前，不调用 `fcdev_*`、`emu_*`、`disasm_*` 工具。

| 要做的事 | 必须先读取 | 流程 |
| --- | --- | --- |
| 新建、编写、构建 NES、SB2000、SB97 或裕兴程序（项目里有 `fcdev.json`，或要新建这类项目） | skill `fcdev-app-development` | 它的“工作流程” |
| 运行、调试、截图、读写内存、注入输入，包括不属于 fcdev 项目的 NES 文件、整机与磁盘镜像 | skill `ember-emulator` | 它的“任务判定” |
| 反汇编（有 `disasm.json`、有映像文件，或要读懂已有的 6502 程序） | skill `disassemble-6502` | 它的八个步骤 |
| 同时涉及多项 | 全部相关 skill | 先用 todo 列出步骤，按依赖顺序做 |

## 直接调用工具，不自行检查

- Ember 的位置（用户设置 `fcdev.emulator.path`）、调试端口、工具链都由扩展读取并校验。不用文件搜索、目录列表、终端命令或读设置文件去确认它们。
- 工具报错时，错误里的 `code` 与 `hint` 是唯一依据，按 skill `ember-emulator` 的 `references/errors.md` 处理。
- 没有工具错误作依据时，不写“未构建”“未安装”“没有设置”这类结论。
- 路径、地址、帧数、文件名只取自用户的话、`fcdev.json`、工具返回值或项目文件；缺少时问用户，不凭印象补。
- 会弹确认的工具（`emu_launch`、写内存、保存截图、导入工作区之外的文件）直接调用，不先问用户。

## 模拟器的起步顺序

1. 调用 `emu_status`，不带参数。`connected` 为 `false` 时做第 2 步；为 `true` 时直接用这个会话，跳到第 4 步。
2. 调用 `emu_launch`，不带参数。成功后已经连接。
3. 报“端口已被占用”时调用 `emu_connect`；仍然连不上时停下，向用户汇报，由用户关闭占用端口的程序或指定另一个端口。
4. 用 `emu_load` 载入程序，再按 skill `ember-emulator` 的流程运行与观察。
5. 任务结束时按 skill 的“收尾”关闭会话。

## 不允许

- 不按进程名结束进程；只用 `emu_status` 的 `close` 与 `terminate` 结束自己启动的 Ember。
- 不修改用户设置，不代填 Ember 的位置。
- 不把没在模拟器里跑过的结果写成已验证；没跑过就写“未运行验证”及原因。
- 同一个工具因同一原因失败时，改正参数后最多重试 1 次；第二次仍失败就停下，汇报工具的错误原文与已完成的步骤，由用户决定。
- 不用等待命令或轮询代替运行；`emu_run` 运行结束才返回。

## 汇报

每个任务结束时写明：用了哪些工具与关键参数、每一步的结果（构建产物、`stopped` 原因、帧数、读到的值）、没有验证到的部分及原因。
