# 反汇编

命令“fcdev：反汇编映像文件”把 NES 程序、SB-DOS 程序或平铺二进制反汇编成一个 `ca65` 工程（工程文件、源码与链接配置），并保证用 `ca65`、`ld65` 重新汇编链接后与原映像逐字节一致。

这个命令只做一遍完整的反汇编。要编辑符号、注释、区域与模块，或用运行记录补全，用扩展给 Copilot 提供的反汇编与模拟器工具和智能体“6502 工程师”：它们读写同一个工程文件（`disasm.json`），命令生成的工程可以直接交给它们继续做。

## 1. 命令

在命令面板运行“fcdev：反汇编映像文件”：

1. 选映像文件。
2. 输入工程目录（绝对路径），默认是映像所在目录下的“<映像名>-disasm”。
3. 反汇编完成后提示映像大小说明、指令条数与工程目录，可以直接打开 `src/main.s`。

| 输入 | 说明 |
| --- | --- |
| 映像格式 | 按文件头判断：以 `NES` 加 `$1A` 开头为 iNES，否则为平铺二进制（`flat`）；SB-DOS 程序（`.EXE`）、分页 ROM 与带目标描述的输入要用工具 `disasm_open` 的 `format`、`target` 指定 |
| 加载地址 | 平铺二进制必须给；命令缺这个信息时向你询问，十六进制，可带 `$` 或 `0x` |
| 入口 | 追踪代码的入口；iNES 自动使用中断向量，SB-DOS 程序自动使用文件头的 JMP；平铺二进制没有入口时向你询问，可以写多个，用逗号分隔 |

CDL 文件、指令轨迹、符号文件与段列表这些细节用工具 `disasm_open`（`symbolSets`、`entries`、`segments` 等参数）与 `disasm_import_record`（导入指令轨迹、调用记录或 CDL）完成。

平铺二进制要有入口：命令里给入口，或用工具导入运行记录；不会自动取程序头部的 `JMP`。

命令成功时提示映像大小、指令条数、“回读与原映像一致”与工程目录。追踪中放弃某一路、记录里的地址不在映像里等警告写在日志里，可以用 `disasm_status` 查进度：符号个数（其中自动命名的个数）、没有说明的过程数、未解析的间接跳转与跨 bank 转移的处数。

## 2. 输出的工程

```text
<工程目录>/
  disasm.json         工程文件
  src/main.s          源码
  include/            符号声明、常量与符号集
  link.cfg            链接配置
  verify/             回读用的目标文件与产物
```

| 文件 | 内容 |
| --- | --- |
| `disasm.json` | 工程文件，文本 JSON：映像的路径（相对工程目录）、大小与摘要，布局，入口，区域，符号，符号集，最近一次回读的结果 |
| `src/main.s` | ca65 源码：被追踪到的代码按指令写，其余字节写成 `.byte`，长重复的字节写成 `.res` |
| `include/globals.inc` | 映像内全部符号的 `.global` 声明 |
| `include/constants.inc` | 映像外的地址（寄存器、RAM 变量）：引入符号集，并写出符号文件里的这类符号 |
| `include/fcnes.inc` | NES 的寄存器符号，总是引入，对平铺二进制也一样 |
| `link.cfg` | 每个映像段一个内存区；段按映像文件偏移排序后首尾相接时，所有区都输出到同一个文件（`file = %O`，产物就是映像本身），否则每段输出到 `verify/seg<段号>.bin` |

生成的源码用 `ca65 -I include` 汇编，再用 `ld65 -C link.cfg` 链接。回读校验就是这样做，并把每个段的输出与映像里对应的字节逐字节比较；不一致时命令报错，指出第一处差异的段与地址，工程目录仍然保留。

段首尾相接的工程（如学习机的 BIOS 映像），`link.cfg` 也可以直接交给 fcdev 的 `rom` 目标：新建 `fcdev.json`，写 `"target": "rom"`、`"linkConfig": "link.cfg"`、`"include": ["include"]`，`targetOptions` 里写机型与整块大小，构建出的产物与原映像逐字节一致，见 [整机 ROM 工程开发指南](rom/01-开发指南.md)。

源码里没有裸地址：被调用的地址叫 `sub_<地址>`，被跳转与分支的叫 `loc_<地址>`，映像内被读写的数据叫 `data_<地址>`，映像外被读写的叫 `var_<地址>`（符号集里有同值的常量时直接用它的名字）；中断向量的入口叫 `reset`、`nmi`、`irq`。目标落在指令中间时，符号放在那条指令的开头，引用处写成“符号加偏移”。`ca65` 不接受的写法（如 `jmp ($xxFF)`）与非官方操作码写成 `.byte`，并在行尾注释里写出反汇编文字。

映像文件本身不复制到工程目录，工程文件里记着它的路径与摘要；工程用文本 JSON，可以用 git 比较。命令每次重新生成全部文件，会覆盖输出目录里的同名文件。

## 3. 输入

### 3.1 映像

- iNES：支持映射器 0（NROM）、3（CNROM，PRG 同 NROM）、2（UxROM）、1（MMC1，按“最后 16K 固定在 `$C000`”的默认模式）、7（AxROM，32K 一个 bank）、4（MMC3，按默认模式：可换的 8K bank 只放 `$8000`，最后两个固定在 `$C000`、`$E000`）。NROM 与 CNROM 的 PRG 为 16K 或 32K（32K 映在 `$8000`，16K 映在 `$C000`）；换页的映射器每个 bank 一个段，bank 号从 0 起；跳过 trainer；从 PRG 最后一个 bank 的末尾读出 NMI、复位、IRQ 三个向量。其他映射器报错，需要先在模拟器里查出各窗口对应的 PRG 偏移，再用 `disasm_open` 的 `format` 为 `flat` 加 `segments` 给出布局；换页到 `$A000` 窗口的 MMC3 bank 也要这样调整（用 `emu_inspect` 的 `resolve` 与 `disasm_layout`）。
- SB-DOS 程序（`disasm_open` 的 `format` 为 `sbdos`，或 `target` 为 `sb2000`）：文件头必须是 `4C ?? ?? AA 55`；不超过 16K 的程序从 `$8000` 起放成一个段，入口是 `$8000`（文件头的 JMP）；超过 16K 的多页程序按开发指南里的页布局划段：文件页 0、1 是常驻部分（`$8000`，8K），页 2 是库页 1（`$A000`），页 3 是栈页（`$B000`），页 4 起是库页 2 起（都换进 `$A000`），bank 号就是库页号。
- 平铺二进制：按加载地址放置，不得超出 `$FFFF`，不能为空。
- 分页 ROM（`paged`）：按固定大小的页排列的 ROM（如学习机的 BIOS）；选项（页大小、固定映射、窗口）来自目标描述，只能在 Copilot 工具的 `disasm_open` 里用 `target` 选择，命令不提供选项。

### 3.2 CDL

每个字节一个标志，位 0 表示被当作代码执行过，位 1 表示被当作数据读取过。支持 FCEUX 与 Mesen 的格式；Mesen CDLv2 开头多出的 9 个字节会自动跳过；只取与映像在 CPU 地址空间里的字节（iNES 是 PRG）对应的前若干个字节，比它短时报错。

### 3.3 指令轨迹

指令轨迹（用 `emu_record` 记录，即 Ember 的 `inspector.traceStart`、`kind=instruction`，用 `disasm_import_record` 导入）的日志：每行是 nestest 日志的写法，行首是四位大写十六进制的指令地址，后面跟指令字节（如 `C000  4C F5 C5  JMP $C5F5 ...`）。`io`、`irq` 与调用记录的行不是指令行，一律忽略。轨迹里的地址都是真实执行过的指令开头，比 CDL 的“代码字节”更精确；不在映像里（RAM、别的 bank）的地址不当作入口，命令给出一条警告。生成方法：用 `emu_record` 开始记录指令轨迹，运行一段时间后停止，结果里的 `file` 是完整路径（文件写在 Ember 的调试输出目录），交给 `disasm_import_record`；也可以用命令“fcdev：调用调试请求”调 `inspector.traceStart` 与 `inspector.traceStop`。

### 3.4 符号文件

每行“名字 = 地址”或“名字 地址”，地址为十六进制，可带 `$` 或 `0x`；以 `;` 或 `#` 开头的行是注释，空行忽略。名字必须是合法的 ca65 标识符，不能与指令助记符、寄存器名或符号集里的常量同名。同一地址有多个名字时只用第一个。地址在映像里的符号是标签，在映像外的是变量。

## 4. 静态追踪

规则：

- 顺序执行继续；条件分支两路都追；`JMP` 只追目标；`JSR` 追目标并假定会返回。
- `RTS`、`RTI`、`BRK` 与间接 `JMP` 结束这一路。
- 遇到非法操作码、超出映像末尾或与已识别的指令重叠时，放弃这一路并记入警告。
- 目标不在映像里时不追，也不算警告。
- 没被追到的字节都按数据输出，这不影响回读校验。
- 入口都追完后，查找经地址表分发的跳转，表里的目标成为新入口，再继续追，直到没有新表。识别的写法（窗口为加载指令之后的 10 条顺序指令）：
  - `LDA 表,X/Y` 与 `LDA 表+1,X/Y` 成对，窗口里有间接 `JMP`：字表，目标就是表里的值；
  - 一对加载指令、两条 `PHA` 与一条 `RTS`：目标是表里的值加 1，表可以是字表，也可以是低、高字节分开的两张表；
  - 间接 `JMP (地址)` 的地址在映像内、那里还是未识别的字节：那里是字表。
  表项必须落在映像里、是官方操作码、不在已识别指令的中间，否则表在这一项结束，单张表最多 128 项；字表占的字节按地址表输出，分开的两张表保持为数据。

## 5. 限制

- iNES 的 MMC3、MMC1 等换页映射器只按默认模式划分布局；不在支持表里的映射器报错。
- 只识别上述几种写法的地址表；用立即数拼出地址再存进指针的跳转、调用方自己写进工作区的分发、直接访问表项的对象表都追不到，也不把数据识别成字符串，未追到的字节都按 `.byte` 输出。
- 命令只做一遍完整的反汇编，不编辑符号与注释；自动命名的符号保持 `sub_`、`loc_` 这类名字。
- SB2000 固件页的 CDL 验证没有做。
