# 步步高开发指南

用 FC Dev 为步步高多媒体学生电脑（BBGDOS）开发程序：构建出能在 DOS 提示符下运行的 `.CMD`。步步高目标只支持 ca65 汇编，没有 C 运行库。目标的定义与启动代码随 `fcdev` 包安装，在包里的 `targets/bbg/` 下。本文只写已经在 Ember 里用软驱一号的 ROM（`ember/roms/bbg1_bios.bin`）验证过的用法，没验证的在第 7 节列出。

## 1. 目标定义

| 项 | 值 |
| --- | --- |
| 目标名 | `bbg` |
| `cc65Target` | `none` |
| 链接配置 | `link.cfg`，段见第 3 节 |
| 启动代码 | `lib/crt0.o`：文件头里的装入地址，装入地址上的 `JMP`，初始化后调用 `_main`，`_main` 返回后调用 DOS 的“程序结束返回” |
| 库 | `lib/bbg.lib`：汇编运行库（DOS、文件、BIOS 调用的封装与文字输出），见第 4 节 |
| 汇编引入 | `asminc/bbg.inc`：系统调用入口、BIOS、DOS 与文件调用的功能号、文件通道块的布局、出错码、运行库函数的声明（由 `machines/bbg/src/include` 下的符号文件生成） |
| 预定义宏 | `__BBG__` |
| 打包器 | `flat-exe`，文件前 2 个字节必须是 `00 80`（装入地址 `$8000`），大小不超过 16386 字节 |
| 产物 | 大写主名的 `.CMD` |
| 程序名规则 | `dos-8.3` |
| 磁盘镜像 | `fat-floppy-overlay`，建在 `fcdev.json` 的 `diskImage`（系统盘镜像）上，见第 5 节 |
| 运行方案 | `firmware-disk`，机型 `bbg1`，需要固件（`ember/roms/bbg1_bios.bin` 那样的 128KB ROM 文件） |

## 2. 程序格式

- 步步高的 DOS 在软盘上，开机时由 ROM 从系统盘读入；ROM 里没有 DOS。
- CMD 是单页可执行程序：文件的前 2 个字节是装入地址（低字节在前），后面是程序内容；DOS 把内容装到这个地址并从这个地址开始执行（手册《系统篇》第四章 1.）。目标的装入地址是 `$8000`，所以文件开头是 `00 80`，第 3 个字节是启动代码的 `JMP`。
- 程序的入口是导出的 `_main`，由启动代码调用；`_main` 返回后启动代码调用 DOS 的“程序结束返回”（`X` 为 0、`Y` 为 0），回到命令行。
- 在 DOS 提示符下输入主名运行，不用写扩展名（`hello`，`.CMD` 已验证）；手册说 `.EXC`（多页程序，目标不生成）也能这样运行，没有验证。
- 官方系统盘里的汇编示例（`TSTPUTC.ASM` 等，在 `系统类/DOS.IMG` 里）也是装入 `$8000` 或 `$6500`，文件的第一条指令是 `JMP`。

## 3. 内存与段

| 内存区 | 地址 | 段 |
| --- | --- | --- |
| 零页 | `$0020-$007F` | `ZEROPAGE` |
| 程序（装在 DOS 分给程序的页里） | `$8000-$BFFF`（16K） | `STARTUP`、`CODE`、`RODATA`、`DATA`，`BSS` 紧接其后 |

- `BSS` 在程序所在的 RAM 里，不写进文件，也不会被清零，程序要自己赋初值；程序加 `BSS` 超过 16384 字节时链接报错，文件超过 16386 字节时打包报错。
- 程序所在的是 RAM，`DATA` 段可以直接读写，不用复制。
- 手册给出的地址分布（系统篇第一章）：`$0200-$07FF` 公共内存，`$5800-$5FFF` BIOS 工作区与调用入口，`$6100-$7FFF` 公共 RAM，`$8000-$BFFF` 分页区，`$C000-$FFFF` 公共 RAM（与分页区的最后一页是同一块）；BBGDOS 内核从 `$7C00` 起（见 `machines/bbg/docs/计划与进度.md`）。
- 零页 `$0020-$007F` 里 BIOS 与 DOS 的调用是否改写没有核对；官方示例用 `$FC-$FF` 当 BIOS 调用的参数。

## 4. 系统调用与运行库

### 4.1 调用入口

| 入口 | 地址 | 参数 | 返回 |
| --- | --- | --- | --- |
| BIOS 调用 `BIOS_ENTRY` | `$5800` | `A` 为功能号，`X`、`Y` 视功能而定 | 视功能而定 |
| 文件调用 `FILE_ENTRY` | `$5803` | `X` 为文件通道块地址高字节，`Y` 为低字节，`A` 不用设置；功能号在块的第 0 字节 | `A` 为出错码（0 成功），`C=1` 出错 |
| DOS 调用 `DOS_ENTRY` | `$580C` | `A` 为功能号，`X`、`Y` 视功能而定 | `C=0` 成功，`C=1` 出错且 `A` 为出错码 |

都用 `JSR` 调用，不保留寄存器。外设调用（`$5809`）没有分析，没有封装。

### 4.2 DOS 调用

下表的功能都在 Ember 里用运行库的测试程序验证过（`vscode/test/real-emulator/bbg-library.test.ts`）：

| 功能 | 常量 | 库函数 | 参数与结果 |
| --- | --- | --- | --- |
| 0 | `DOS_PROGRAM_RETURN` | `bbg_dos_exit` | 程序结束返回：`X` 返回码，`Y` 为 0 时直接回到命令行（`Y` 的位 0、位 1 按手册分别要求先初始化屏幕、先初始化系统资源，没有验证） |
| 1 | `DOS_READ_KEY_ECHO` | `bbg_dos_read_key_echo` | 读键盘并回显，`A` 返回字符码 |
| 2 | `DOS_DISPLAY_CHAR` | `bbg_dos_put_char` | 显示字符：`X` 是字符码；`$0D`、`$0A` 换行 |
| 3 | `DOS_INQUIRE_PAGES` | `bbg_dos_pages_alloc` | 申请内存页：`X` 为页数，0 只查询空闲页号；`C=0` 时 `A` 为起始页 |
| 4 | `DOS_DISPLAY_STRING` | `bbg_dos_put_string` | 显示以 `$` 结尾的字符串：`X` 为地址高字节、`Y` 为低字节（与手册的文字相反） |
| 5 | `DOS_RUN_PROGRAM` | `bbg_dos_run` | 运行程序：`$FF` 为盘号，`X:Y`（`X` 高）为 11 字节文件名，扩展名必须是 `CMD`、`EXC` 或 `GAM`，`$0100` 起是传给程序的参数；`C=0` 时 `A` 为程序的退出码 |
| 6 | `DOS_GET_KB_STRING` | `bbg_dos_get_line` | 输入一行并回显：缓冲区第 0 字节是最大字符数，第 1 字节返回字符数，文本从第 2 字节起 |
| 7 | `DOS_READ_KEY_NO_ECHO` | `bbg_dos_read_key` | 读键盘不回显，`A` 返回字符码 |
| 8 | `DOS_READ_KB_CLEAR` | `bbg_dos_read_key_clear` | 先清键盘缓冲，再执行 `$FF` 指定的键盘功能 1、6、7 |
| 9 | `DOS_INITIAL_SCREEN` | `bbg_dos_clear_screen` | 初始化屏幕，清屏 |
| 10 | `DOS_RELEASE_PAGES` | `bbg_dos_pages_free` | 释放内存页：`X` 为起始页号 |
| 11 | `DOS_GET_SET_DISP_MODE` | `bbg_dos_display_mode_get`、`bbg_dos_display_mode_set` | 取或设置显示方式：`$00` 英文，`$80` 中文 |
| 12 | `DOS_FILE_NAME_ACCESS` | `bbg_dos_convert_name` | 把 `D:FFFFFFFF.XXX` 转成 11 字节内部文件名，结果写回原地址，`A` 返回盘号 |
| 14 | `DOS_CHECK_KEYBOARD` | `bbg_dos_key_ready` | 测试键盘：`Z=1` 无键，`Z=0` 有键 |
| 15 | `DOS_RUN_PATH_PROGRAM` | `bbg_dos_run_path` | 同功能 5，文件名是以 0 结尾的路径加文件名（必须带扩展名） |
| 16 | `DOS_GET_DOS_VERSION` | `bbg_dos_version` | `A`=3，`X`=0 |

- DOS 调用不保留寄存器，循环里的位置要放在内存里（模板的 `hello.s` 用 `BSS` 里的 `index`，每显示一个字符加 1）。
- 功能 13（取并设置初始化屏幕向量）没有封装，没有验证。

### 4.3 文件调用

文件通道块是 48 字节（`FH_SIZE`）的内存，由程序提供，每个打开的文件一个。常用字段：`FH_COMMAND`（0，功能号）、`FH_DRIVE`（1，盘号：0 默认盘，1 为 A 盘）、`FH_PAGE` 与 `FH_BUFFER`（2、3-4，缓冲区或文件名所在页与地址）、`FH_BYTES`（5-6，读写长度）、`FH_POSITION`（7-10，读写位置）。文件名是 11 字节（主名 8 加扩展名 3，大写，空格补齐，`?` 是通配符）；路径是以 0 结尾的字符串，目录之间用 `\` 分隔。在 Ember 里验证过全部 24 个功能（`FILE_RESET` 到 `FILE_PATH_DELETE`）：

- 打开（`FILE_OPEN`）后块里 `FH_OPEN_ATTRIBUTE`、`FH_OPEN_DATE`、`FH_OPEN_TIME` 是文件的属性、日期与时间，`FH_FILE_SIZE` 是 4 字节的长度，读写位置为 0；不存在时 `A=ERR_FILE_NOT_EXIST`（`$02`）。
- 读写（`FILE_READ`、`FILE_WRITE`）从 `FH_POSITION` 开始，可跨扇区；读到文件末尾时 `FH_BYTES` 是实际读到的字节数；写时 `FH_BYTES` 为 0 表示在读写位置截断；返回后 `FH_BUFFER` 是缓冲区结束地址，`FH_POSITION` 前进。写不检查只读属性。
- 查找（`FILE_FIRST`、`FILE_NEXT`、`FILE_PATH_FIRST`）：结果在块里 `FH_DTA_*`（属性、时间、日期、长度、11 字节文件名）；没有更多文件时 `A=ERR_SEARCH_ENDING`（`$12`），查找时块不能改动，至少 48 字节。
- 绝对扇区（`FILE_READ_ABS`、`FILE_WRITE_ABS`）：`FH_POSITION` 是起始扇区号（从 0 起），`FH_BYTES` 是扇区数。
- 磁盘容量（`FILE_DRIVE_SIZE`）：`FH_SECTORS_PER_CLUSTER`、`FH_BYTES_PER_SECTOR`、`FH_FREE_CLUSTERS`、`FH_TOTAL_CLUSTERS`。
- 取当前目录（`FILE_GET_DIR`）返回的路径串在 DOS 的页里，内容不能改写。
- 功能 24（`FILE_SET_ATTRIBUTE`）手册没有列出，没有封装。

### 4.4 汇编运行库 bbg.lib

库里每个函数一个源文件（`targets/bbg/src/lib/<模块>/`），按模块分为 `dos`、`file`、`bios`、`text`；函数的入口、出口与备注见 [api-reference.md](../../targets/bbg/api-reference.md)，其中的“功能号覆盖表”列出每个 DOS、文件与 BIOS 功能号被哪个函数封装，没封装的写明原因。约定：

- 一个字节的参数放 `A`；一个 16 位参数（地址、数值）低字节放 `A`、高字节放 `X`；更多的参数写进零页单元 `bbg_arg0`、`bbg_arg1`（各 2 字节），盘号等第二个字节参数放 `Y`。
- 返回值在 `A`（16 位在 `A`、`X`），出错时 `C=1`、`A` 是出错码；不保留 `A`、`X`、`Y`。
- 库只使用 `bbg_arg0`、`bbg_arg1` 与几个内部零页单元，都在链接配置划给程序的 `$0020-$007F` 里。

示例（显示字符串，再读 `COMMAND.CMD` 的前 8 个字节）：

```asm
        .include "bbg.inc"
        .export _main

        .bss
fh:     .res FH_SIZE
buf:    .res 8

        .rodata
hello:  .byte "HELLO", 0
name:   .byte "COMMAND CMD"

        .code
_main:
        lda #<hello
        ldx #>hello
        jsr bbg_text_put_cstr
        jsr bbg_text_put_newline
        lda #<fh
        ldx #>fh
        jsr bbg_file_clear              ; 清零通道块，缓冲区页设成本程序所在页
        lda #<name
        sta bbg_arg0
        lda #>name
        sta bbg_arg0 + 1
        lda #<fh
        ldx #>fh
        jsr bbg_file_set_buffer         ; 文件名
        lda #<fh
        ldx #>fh
        jsr bbg_file_open
        bcs failed
        lda #<buf
        sta bbg_arg0
        lda #>buf
        sta bbg_arg0 + 1
        lda #<fh
        ldx #>fh
        jsr bbg_file_set_buffer         ; 读入的缓冲区
        lda #8
        sta bbg_arg0
        lda #0
        sta bbg_arg0 + 1
        lda #<fh
        ldx #>fh
        jsr bbg_file_set_length
        lda #<fh
        ldx #>fh
        jsr bbg_file_read
failed: rts
```

- 运行库的维护（生成、测试、接口检查）见 [docs/08-目标运行库维护](../../../docs/08-目标运行库维护.md) 的 BBG 一节。
- 完整的 DOS 与 BIOS 功能见手册《系统篇》第二章、第五章；`machines/bbg/src/include` 下是由反汇编核对过的符号文件，`machines/bbg/docs/api/` 是接口说明。

## 5. 磁盘镜像与系统盘

- 镜像不是空白数据盘：它要能开机并读入 DOS，所以建在系统盘镜像上。在 `fcdev.json` 里用 `diskImage` 指向系统盘镜像，构建时复制它，加入 `<NAME>.CMD` 和项目 `disk` 目录下的全部文件（文件名必须是 8.3 名字，不能有子目录），存成 `build/bbg/<diskName>`（要在 `fcdev.json` 里配置 `diskName`）；系统盘文件本身不改，引导扇区、卷标与原有文件原样保留，同名文件被替换。
- 没有设置 `diskImage` 时构建只生成程序，不生成镜像；要运行时才报“没有设置 diskImage”。
- 步步高的系统盘大多是装满的：`系统类/DOS.IMG` 没有空闲簇，放不下任何文件，运行会报“剩余空间不足”。同一目录里的 `001-3.IMG` 剩余约 592KB，没有 `AUTOEXEC.BAT`，开机后先问日期与时间，适合当底盘。
- 系统盘里有 `AUTOEXEC.BAT` 时，DOS 开机后先运行它，不问日期与时间；批处理最后要停在命令提示符（`bbgcdos/z4`、`pinyin`、`tishi` 这样的可以，会启动一个不返回的程序的不行）。
- 开机后 DOS 显示“Starting BBGDOS...”，读入 `COMMAND.CMD`，提示符是 `A:\>`。

## 6. 构建与运行

- 构建：任务“FCDEV：构建”，产物 `build/bbg/<NAME>.CMD`；设置了 `diskImage` 与 `diskName` 时还有 `build/bbg/<diskName>`。
- 运行：任务“FCDEV：运行”，需要在设置 `fcdev.emulator.path` 里指定 Ember，在 `fcdev.json` 里用 `firmware` 指定软驱一号的 ROM、用 `diskImage` 指定系统盘镜像。扩展依次添加 ROM、以 `bbg1` 开机、放入镜像，开机运行 1200 帧（让系统盘的批处理跑完），按两次回车跳过可能出现的日期与时间（已在提示符下时只是两个空行），再等 60 帧，输入程序名并回车。按键都是按下 8 帧、松开 8 帧。程序名只能用字母与数字。
- 手动运行（真机或模拟器）：挂载镜像开机，进入命令行后输入程序名。
- 样例：`apps/bbg/run-game` 是在 BBGDOS 下运行 NES 游戏的程序（`RUN MARIO`），用 DOS 的文件调用读文件、取命令行参数、直接操作分页寄存器，是本目标最完整的例子；它在 `fcdev.json` 里用 `linkConfig` 指定自己的链接配置，把进入游戏的跳板放在内部 RAM。

## 7. 还没有验证的内容

- 98 型（`bbg98`）的 ROM：目标的机型固定为 `bbg1`，只用软驱一号的 ROM 验证过。
- `DOS_DISPLAY_STRING`（功能 4）：手册写“`X` 低地址、`Y` 高地址”，实际是 `X` 高地址、`Y` 低地址；按手册的顺序调用会读到错误的地址而死机。用 `bbg_dos_put_string` 即可。
- 超过 16K 的程序、多页程序（`.EXC`）。
- BIOS 功能：只有运行库封装的几个（`BIOS_GET_PAGE`、`BIOS_GET_DRAM_SIZE`、`BIOS_DISPLAY_TTY`、`BIOS_GET_CURSOR`、`BIOS_GET_VERSION`）验证过，其余见 `api-reference.md` 的覆盖表。bbg1 的 BIOS 1.0 不实现手册里的 `BIOS_SET_PALETTE`（43）等功能号，调用时被忽略。
- 外设调用（`$5809`）。
- 命令行参数已由 `apps/bbg/run-game` 验证：`$0100` 是长度、`$0101` 起是参数（含程序名后的空格），`bbg_dos_run` 也是这样把参数交给被运行的程序；按手册，程序所在页之后的分页内存都归程序使用，`BIOS_GET_PAGE`（功能 2）取得程序所在的页。
- 零页与内部 RAM 里 DOS、BIOS 占用的单元。
- 真机运行：只在 Ember 里验证过；BIOS 源码是工程版，与 `bbg1_bios.bin` 不是同一次构建，大同小异。
