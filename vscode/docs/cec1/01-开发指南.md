# 中华学习机 CEC-I 开发指南

用 FC Dev 为中华学习机 CEC-I（苹果 II 类机器，ROM 1.1a 与 1.21）开发程序：构建出在 Apple DOS 3.3 下用 `BRUN` 运行的二进制文件，并放进 DOS 3.3 系统盘镜像。CEC-I 目标只支持 ca65 汇编，运行库只有显示与键盘的几个函数。目标的定义、启动代码与运行库随 `fcdev` 包安装，在包里的 `targets/cec1/` 下。本文只写已经在 Ember 里用 1.21 版 ROM 与 `DOS33.DSK`（Apple DOS 3.3 系统盘）验证过的用法，没验证的在第 7 节列出。

## 1. 目标定义

| 项 | 值 |
| --- | --- |
| 目标名 | `cec1` |
| `cc65Target` | `none` |
| 链接配置 | `link.cfg`，段见第 3 节 |
| 启动代码 | `lib/crt0.o`：装入地址上的第一条指令，初始化后调用 `_main`，返回后跳到 DOS 的热启动入口 |
| 库 | `lib/cec1.lib`：显示与键盘的函数，见第 4 节 |
| 汇编引入 | `asminc/cec1.inc`：监控程序入口、软开关、DOS 3.3 入口与库函数 |
| 预定义宏 | `__CEC1__` |
| 目标选项 | `loadAddress`：装入地址，默认 `$6000`，范围 `$0800` 到 `$8FFF` |
| 打包器 | `dos33-binary`：给链接输出加 DOS 3.3 二进制文件的 4 字节文件头（装入地址与长度，低字节在前） |
| 产物 | 大写主名、没有扩展名的文件，如 `build/cec1/DEMO` |
| 程序名规则 | `dos33`：字母开头，只用字母与数字，最多 30 个字符 |
| 磁盘镜像 | `dos33-floppy-overlay`：建在 `fcdev.json` 的 `diskImage`（DOS 3.3 系统盘）之上，见第 5 节 |
| 运行方案 | `firmware-disk`，机型 `cec1`，需要固件（`ember/roms/cec1_v1.21.rom` 那样的 64KB ROM 文件） |

## 2. 程序格式

- 程序是 DOS 3.3 的二进制文件（类型 B）：文件前 4 个字节是装入地址与长度（低字节在前），后面是程序内容。`BRUN 名字` 把内容装到这个地址，并从这个地址开始执行，所以启动代码 `crt0.s` 的第一条指令放在装入地址上。
- 程序的入口是导出的 `_main`，由启动代码调用；`_main` 返回后启动代码 `JMP $03D0`（DOS 的热启动入口），回到 BASIC 的命令行，内存里的 BASIC 程序保留。
- 不用 `RTS` 回到 DOS：DOS 3.3 进入程序之前把自己的几层调用退了栈，程序返回时它按进入 I/O 钩子时保存的栈指针（`$AA59`）重新使用这一段栈。程序只要调用一次 `COUT`（DOS 的钩子会重新保存栈指针），或者栈用得稍深，`RTS` 回去就会跑飞，在 Ember 里已经验证过。因此程序被 BASIC 程序里的 `BRUN` 调用时，也是回到命令行，而不是继续那个 BASIC 程序。
- 在命令行里运行：`BRUN DEMO`（不写扩展名，名字大写）。

## 3. 内存与段

| 内存区 | 地址 | 段 |
| --- | --- | --- |
| 零页 | `$001A-$001F` | `ZEROPAGE` |
| 程序 | 装入地址到 `$9200` | `STARTUP`、`CODE`、`RODATA`、`DATA`，以及紧接在后面的 `BSS` |

- 装入地址默认 `$6000`，在 `fcdev.json` 里用 `targetOptions.loadAddress` 改，写数字或 `"$0800"`、`"0x0800"` 形式的字符串，超出范围时构建报错：

  ```json
  { "target": "cec1", "targetOptions": { "loadAddress": "$0800" } }
  ```

  取 `$0800` 的程序会盖掉内存里的 BASIC 程序（BASIC 程序区从 `$0801` 起）；`$2000-$5FFF` 是高分辨率图形的两页，程序放在它们中间时不能同时用图形页。需要别的布局时，用 `fcdev.json` 的 `linkConfig` 指定自己的链接配置。
- `$9200` 是汉字方式下用户程序的上限（英文方式是 `$9600`，见 `machines/cec1/docs/ROM分析.md`），程序加上 `BSS` 超过它时链接报错。
- 程序所在的是 RAM，`DATA` 段可以直接读写，不用复制；`BSS` 紧接在程序后面，不写进文件，也不会被清零，要自己赋初值。
- 零页只划出 `$001A-$001F`（苹果 II 里没人用的单元），没有核对汉字系统是否改写这一段；运行库的内部指针用了其中 2 个字节。

## 4. 运行库与符号

在 `.s` 文件里 `.include "cec1.inc"`，用 `JSR` 调用。库函数的参数放 A，或 A（低）、X（高）；不保留 A、X、Y 与标志。

| 函数 | 入口 | 说明 |
| --- | --- | --- |
| `cec1_home` | 无 | 清屏并把光标移到左上角（监控程序的 HOME） |
| `cec1_put_char` | A = 字符的 ASCII 码 | 在光标处输出一个字符，库把位 7 置 1 再交给 COUT，`$0D` 是回车换行 |
| `cec1_put_cstr` | A（低）、X（高）= 字符串地址 | 输出以 0 结尾的字符串 |
| `cec1_newline` | 无 | 输出回车换行 |
| `cec1_put_hex8` | A = 字节 | 按两位十六进制输出 |
| `cec1_get_key` | 无；返回 A = 按键的 ASCII 码（7 位） | 等待按键，等待时显示光标 |
| `cec1_poll_key` | 无；返回 A = 按键的 ASCII 码，没有按键为 0 | 不等待地检查键盘，有按键就取走 |

`cec1.inc` 里还有：

- 监控程序入口：`MON_HOME`（`$FC58`）、`MON_WAIT`（`$FCA8`）、`MON_RDKEY`（`$FD0C`）、`MON_CROUT`（`$FD8E`）、`MON_PRBYTE`（`$FDDA`）、`MON_PRHEX`（`$FDE3`）、`MON_COUT`（`$FDED`）、`MON_BELL`（`$FF3A`）。这些地址与 Apple II 的监控程序相同，已核对 1.21 版 ROM 里这些地址的内容。
- 软开关：`KBD`（`$C000`）、`KBDSTRB`（`$C010`）、`SPKR`（`$C030`）、文本与图形开关 `TXTCLR`、`TXTSET`、`MIXCLR`、`MIXSET`、`LOWSCR`、`HISCR`、`LORES`、`HIRES`。
- DOS 3.3 入口：`DOS_WARM_START`（`$03D0`）、`DOS_COLD_START`（`$03D3`）、`DOS_FILE_MANAGER`（`$03D6`）、`DOS_RWTS`（`$03D9`）、`DOS_FM_PARAMETERS`（`$03DC`）、`DOS_RWTS_IOB`（`$03E3`）。

## 5. 磁盘镜像

DOS 3.3 在软盘上，所以镜像要建在一张带 DOS 3.3 的系统盘上：

- 在 `fcdev.json` 里用 `diskImage` 指向系统盘镜像：`.dsk`，DOS 扇区顺序，35 或 40 个磁道、每磁道 16 个扇区（143360 或 163840 字节）；用 `diskName` 指定生成的镜像文件名（文件名不带 `.img` 或 `.dsk` 时补 `.img`），镜像放在 `build/cec1/` 下。没有设置 `diskImage` 或 `diskName` 时只构建程序，不生成镜像。运行（`run`）需要镜像时仍会生成，放在中间文件目录的 `run.img`；Ember 按内容识别盘片格式，不看扩展名。
- 程序以二进制文件（类型 B）放进镜像；项目 `disk` 目录下的文件按文本文件（类型 T）原样放入，文件名转大写、1 到 30 个可见的 ASCII 字符、不含逗号，不能有子目录。
- 同名的文件先删除再写入；镜像里已有同名的锁定文件（目录里文件名前有 `*` 的）时不替换，报 `DISK_FILE_LOCKED`。DOS 3.3 系统盘的启动程序常常叫 `HELLO` 并被锁定，所以模板里程序叫 `demo`，不要叫 `hello`。
- 文件的数据扇区从磁道 18 往后取，用完再从磁道 16 往前取；磁道 0 与目录所在的磁道 17 不放文件数据。目录或空间不够时报 `DISK_FULL`，底盘不是 DOS 3.3 镜像（大小不对，或 VTOC 里的参数不对）时报 `DISK_BASE_INVALID`。底盘镜像本身不改。

## 6. 构建与运行

- 构建：任务“FCDEV：构建”，产物 `build/cec1/<NAME>`；`fcdev.json` 配置了 `diskImage` 与 `diskName` 时，同时生成磁盘镜像。
- 运行：任务“FCDEV：运行”，需要在设置 `fcdev.emulator.path` 里指定 Ember，在 `fcdev.json` 里用 `firmware` 指定 CEC-I 的 ROM（U7 与 U35 依次拼成的 64KB 文件），用 `diskImage` 指定系统盘镜像：

  ```json
  { "target": "cec1", "name": "demo", "firmware": "D:/rom/cec1_v1.21.rom", "diskImage": "D:/disk/DOS33.DSK" }
  ```

  扩展依次添加 ROM、以 `cec1` 开机、放入镜像，开机运行 900 帧（DOS 3.3 从系统盘启动到命令行约需 670 帧），再输入 `BRUN `、程序名并回车，按键都是按下 8 帧、松开 8 帧。系统盘启动后没有日期与时间的提示，所以不按回车。程序名只能用字母与数字。
- 手动运行（真机或其他模拟器）：挂载镜像开机，进入 DOS 3.3 的命令行后输入 `BRUN DEMO` 并回车。
- 模板的示例程序清屏、显示两行英文，按任意键后回到命令行，已在 Ember 里确认显示正确，并且回到了 `]` 提示符。

## 7. 还没有验证的内容

- ROM 1.1a：只用 1.21 验证过。
- `loadAddress` 取默认值 `$6000` 以外的值：只验证过文件头与链接的结果，没有在 Ember 里运行过。
- 汉字方式下运行程序（`HIMEM` 取 `$9200` 的依据是 `ROM分析.md`）、图形方式、磁带与打印机。
- 零页 `$001A-$001F` 在汉字系统与 DOS 3.3 下是否被改写。
- C 语言支持：没有 C 运行库，也没有 C 模板。
- 真机运行：只在 Ember 里验证过。
