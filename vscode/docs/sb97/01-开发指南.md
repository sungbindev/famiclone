# SB97 开发指南

用 fcdev 为小霸王 97 学习机（SB97）的 DOS 开发程序：构建出能在 DOS 提示符下运行的 `.EXE`。SB97 目标只支持 ca65 汇编，没有 C 运行库。目标的定义与启动代码随 `fcdev` 包安装，在包里的 `targets/sb97/` 下。本文只写已经在 Ember 里验证过的用法，没验证的在第 7 节列出。

## 1. 目标定义

| 项 | 值 |
| --- | --- |
| 目标名 | `sb97` |
| `cc65Target` | `none` |
| 链接配置 | `link.cfg`，段见第 3 节 |
| 启动代码 | `lib/crt0.o`：向量、签名，初始化后调用 `_main` |
| 库 | 无 |
| 汇编引入 | `asminc/sb97.inc`：硬件寄存器与 DOS 约定的地址 |
| 预定义宏 | `__SB97__` |
| 打包器 | `flat-exe`，映像必须正好 32768 字节，偏移 `$7FF8` 起的 2 个字节必须是 `AA 55` |
| 产物 | 大写主名的 `.EXE` |
| 程序名规则 | `dos-8.3` |
| 磁盘镜像 | `fat-floppy`，1.44MB，构建时默认生成，见 [01-构建](../01-构建.md) 4.5 |
| 运行方案 | `firmware-disk`，机型 `sb97`，需要固件（`ember/roms/sb97.bin` 那样的 1MB ROM 文件） |

## 2. 程序格式

- DOS 运行的是 32K 映像，映射在 `$8000-$FFFF`，文件大小是 32768 字节。
- 映像偏移 `$7FF8`、`$7FF9`（运行时的 `$FFF8`、`$FFF9`）是签名 `AA 55`，DOS 靠它认出可运行的程序；`$FFFA` 起是 NMI、复位、IRQ 三个向量。这些由 `crt0.s` 的 `VECTORS` 段提供，源文件不要再定义这个段。
- DOS 用 `JMP ($FFFC)` 启动程序。程序不能返回 DOS（官方软盘里的程序也是这样），`_main` 返回后 `crt0.s` 停在原地，要退出只能复位。
- DOS 把命令行的第一个参数写在 `$680E`（`DOS_ARGUMENT`），大写、以 0 结尾，最多 14 个字符；程序名后面的参数用它取。
- 官方软盘（`reference/floppy-images/sb97`）里的 `.EXE` 有 16K、32K、64K、128K 几种大小：32K 及以上的签名都在偏移 `$7FF8`，16K 的（只见到 `README.EXE` 一个）在 `$3FF8`。目前目标只做 32K 的。

## 3. 内存与段

| 内存区 | 地址 | 段 |
| --- | --- | --- |
| 零页 | `$0000-$00FF` | `ZEROPAGE` |
| 内部 RAM | `$0200-$07FF` | `BSS` |
| 工作 RAM（放代码） | `$6000-$6BFF` | `RAMCODE`：存在映像里，运行在这里，要自己复制 |
| 工作 RAM（缓冲） | `$6C00-$7FFF` | `WRAM`：不占映像 |
| 程序 | `$8000-$FFF7` | `CODE`、`RODATA` |
| 向量 | `$FFF8-$FFFF` | `VECTORS`（`crt0.s`） |

- `RAMCODE` 段用 `__RAMCODE_LOAD__`、`__RAMCODE_RUN__`、`__RAMCODE_SIZE__` 三个符号复制，写法见 `apps/sb97/game/src/nes.s`。需要在切换程序 RAM 页之后还能执行的代码放在这里。
- 内部 RAM 里 BIOS 功能占用的单元没有核对，调用 BIOS 功能的程序要自己确认。

## 4. 显示文字

SB97 的字库在 PPU 图案表 1，字符的 ASCII 码就是图块号。直接写 PPU 显示文字的步骤（模板的 `hello.s` 就是这样做的）：

1. `PPU_CTRL`、`PPU_MASK` 写 0，关闭显示。
2. 向名称表 0（`$2000` 起）写字符；清屏就写 960 个空格。
3. `PPU_SCROLL` 写两次 0，`PPU_CTRL` 写 `$10`（背景用图案表 1），`PPU_MASK` 写 `$08`（显示背景）。

## 5. 硬件寄存器

`sb97.inc` 里的项都用过并在模拟器里验证过：

| 名字 | 地址 | 说明 |
| --- | --- | --- |
| `PPU_CTRL`、`PPU_MASK`、`PPU_SCROLL`、`PPU_ADDR`、`PPU_DATA` | `$2000`、`$2001`、`$2005`、`$2006`、`$2007` | PPU |
| `PRAM_SEL` | `$5000` | 程序页选择，位 7 为 1 时选程序 RAM |
| `MIRROR` | `$5200` | 位 0 镜像，位 2 为 32K 模式 |
| `FDC_DCR`、`FDC_DOR`、`FDC_DATAW`、`FDC_MSR`、`FDC_DATAR` | `$5500`、`$5501`、`$5505`、`$5604`、`$5605` | 软驱控制器 uPD765 |
| `DOS_ARGUMENT` | `$680E` | 命令行的第一个参数 |

整机寄存器的完整说明见仓库里的 `machines/sb97/docs/README.md`。

## 6. 构建与运行

- 构建：任务“fcdev：构建”，产物 `build/sb97/<NAME>.EXE` 与 `build/sb97/<NAME>.img`。
- 运行：任务“fcdev：运行”，需要在设置 `fcdev.emulator.path` 里指定 Ember，在 `fcdev.json` 里用 `firmware` 指定 SB97 的 ROM。扩展依次添加 ROM、开机、放入镜像，开机运行 200 帧后按空格跳过开机画面，等 300 帧菜单稳定后按左键选中“DOS”，回车进入，再等 120 帧出现提示符，输入程序名并回车。按键都是按下 8 帧、松开 8 帧。程序名只能用字母与数字。运行任务只输入程序名，不带参数；要带参数就在 Ember 里手动输入。
- 样例：`apps/sb97/game` 是在 SB97 的 DOS 下运行 NES 游戏的程序（`RUN MARIO`），读软驱、解析 iNES 头、切换程序页，是本目标最完整的例子。

## 7. 还没有验证的内容

- 64K、128K 与 16K 的程序格式：目标只生成 32K 映像。
- C 语言支持：没有运行库，也没有 C 模板。
- 用 BIOS 功能读键盘、读文件等：模板与 `game` 都是直接操作硬件。
- 真机运行：只在 Ember 里验证过。
